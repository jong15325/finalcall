# 코딩 규율

무상태 에이전트가 검증된 코드베이스를 훼손하지 않도록 하는 규율.

## 원칙 2 — Simplicity First (단순성)
- **요청된 것만 구현한다.** 투기적 추상화·미사용 유연성·불가능한 시나리오 에러처리를 넣지 않는다.
- "senior 엔지니어가 과하다고 할까?" 테스트 — 그렇다면 단순화한다.
- 근거: 이 프로젝트는 과설계로 도메인 진입이 지연된 이력이 있다(프로세스 과중). 단순성 경계가 특히 유효하다.

## 원칙 3 — Surgical Changes (외과적 변경) [가장 중요]
- **건드려야 할 것만 수정한다.** 인접 코드·주석·포맷을 "개선"하지 않는다.
- 검증된 스켈레톤/기존 코드를 함부로 리팩터링하지 않는다. 이해하지 못한 코드를 부작용으로 바꾸지 않는다.
- 기존 스타일에 맞춘다(내 취향과 달라도).
- 무관한 dead code는 삭제하지 말고 **언급만** 한다.
- 내 변경이 만든 orphan(미사용 import 등)만 정리한다.
- 테스트: **모든 변경 라인이 요청에 직접 추적되어야 한다.**
- 근거: 스켈레톤 0~G가 완성·검증됐다. 무상태 에이전트가 맥락 부족으로 검증된 코드를 훼손하는 것을 방지한다.

## 원칙 4 — Goal-Driven Execution (목표 주도) [조절 적용]
- DoD를 검증 가능한 형태로 둔다. 가능하면 "실패 케이스 테스트 작성 → 통과" 형태로 표현한다.
- **과적용 금지**: 핵심 도메인(경매/입찰/정산 등)은 테스트 우선, 사소한 작업(문구 수정 등)은 판단껏. 모든 것에 테스트를 강요해 프로세스를 무겁게 하지 않는다.
