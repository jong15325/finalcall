## 1. 영역 3의 구성과 처리 현황

| 하위 주제 | 해법 | 상태 |
|---|---|---|
| 진행 상황 보고 형식 | 완료 보고 메시지(D-020) + 세션 재개 브리핑(D-022) + 템플릿(C-012) | 기채택/회부 중 |
| 에스컬레이션 외 정보 공유 채널 | outbox 메시지 버스(D-023) + ID 소유자 통지(D-024) | 기채택 |
| 이슈 트래킹 | 통합 추적 표 (C-013, 신규) | 본 문서 |
| 회고 | 게이트 회고 + 사고 회고 2종 (C-014, 신규) | 본 문서 |

진단: 보고·공유의 골격은 영역 2~3 선행분으로 이미 확정됐다. 남은 공백 2개 —
(a) 결정도 결함도 아닌 안건(보류·블로커·리스크)의 추적 장소가 인덱스 "보류 안건" 표
하나뿐이고 등재·해소 절차가 없다. (b) 프로세스 개선이 사고 후 즉흥적으로만 일어난다
(문서 소실 2건 → 커밋 규칙 제안이 실례 — 유효했지만 규약화된 경로가 아니었다).

## 2. C-013. 통합 추적 표 (인덱스 확장)

- decision-index.md의 "보류 안건" 표를 "추적 안건" 표로 확장. 열: 안건 / 유형(보류·블로커·리스크) /
  소유 / 해소 조건 / 상태.
- 신규 ID 접두어 없음 — 안건은 관련 결정 ID·게이트로 식별한다(ID 체계 증식 방지).
- 등재 경로: 역할이 메시지(정보 공유 또는 결정 요청)로 총괄에 보고 → 총괄이 등재.
  블로커는 "누구의 무엇을 기다리는지"를 소유 열에 명시.
- 해소 시 행을 삭제하지 않고 상태를 "해소(날짜, 결과 참조)"로 갱신, 게이트 통과 시점에
  해소분을 하단 "해소됨" 섹션으로 이동(표를 얇게 유지하면서 이력 보존).
- 기각 대안: 별도 issues.md — 추적 표면이 2개가 되면 어느 쪽이 정본인지 다시 규약이 필요.
  현 규모에서 표 1개로 충분하며 인덱스는 이미 전 역할 필독 문서다.

## 3. C-014. 회고 2종: 게이트 회고 + 사고 회고

### 게이트 회고 (정기, 경량)
- 시점: 게이트 통과 시(D-022 리추얼에 부착 — 새 이벤트 없음).
- 형식: 각 역할이 완료 보고 말미에 선택 2줄 — `keep: <유지할 것 1개>` / `change: <바꿀 것 1개>`
  (Plus/Delta 최소형). 강제 아님, 없으면 생략.
- 처리: 총괄이 취합해 management/notes/retro-G<N>.md에 기록. 채택할 개선만 D 발번,
  나머지는 폐기(기각 기록 의무 없음 — 회고 제안은 결정이 아니다).
- 덜어낸 것: 회고 회의·퍼실리테이션·투표(스크럼 원형) — 1인 구조에서 회의는 없다.
  형식도 Keep/Drop/Try 3열 대신 2줄로 축소.

### 사고 회고 (수시, blameless)
- 트리거: 규약 위반, 문서 소실·오염, 확정 계약 사고 등 "체계가 뚫린" 사건.
- 형식: management/notes/incident-NNN.md, 5개 항목 —
  사건 / 영향 / 원인(왜 사슬은 시스템에서 멈춘다. 특정 대화·사람 비난 금지) /
  재발 여부(이전 발생 있었나, 있었다면 이전 대책이 왜 못 막았나) /
  재발 방지 액션(소유·완료 조건 명시, 규칙 승격은 D 발번).
- 근거 실물: 오늘 문서 소실 2건(총괄 로그 절단, 컨설턴트 로그 절단)에 대해
  "D 발번 시점마다 커밋" 규칙이 즉흥 대응으로 나왔다 — 유효한 대응이었으나
  "이전 대책이 왜 못 막았나"를 묻는 절차가 없으면 같은 부류의 사고(파일 편집 중 절단)가
  다른 파일에서 재발해도 각각 일회성 대응에 그친다.
- 덜어낸 것: SRE 포스트모템의 심각도 등급·타임라인·회의 공유 — 규모 대비 과잉.
  "blameless + 재발 질문 + 액션 소유"라는 핵심만 차용.

## 4. 운영 흐름 요약 (영역 2~3 통합 후)

```
역할 작업 → 완료 보고(+회고 2줄) ─┐
역할 발견(이슈·리스크) → 메시지 ──┤→ 총괄: 인덱스·추적 표 갱신, 필요 시 D 발번
사고 발생 → 사고 회고(incident) ──┘
게이트 통과 → 전파 + 지식 동기화 + retro 취합 | 세션 재개 → 브리핑
사용자 개입은 두 가지뿐: "수신함 확인해" 지시, 게이트 시점 승인·동기화
```
