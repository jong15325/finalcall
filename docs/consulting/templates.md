# 표준 템플릿 패키지 (C-012)

→ management/templates.md로 이관됨(D-025). 이 파일은 동결 — 정본은 이관본이다.
목적: 메시지·문서가 형식 고민 없이 일정한 모양을 갖게 하여 내용 혼입과 장황화를 방지.
원칙: 템플릿은 최소 골격만 — 섹션을 채우지 못하면 그 섹션을 지운다(빈 섹션 금지).

---

## 1. outbox 메시지 공통 골격 (D-020, D-023)

모든 outbox 파일의 처음 3줄은 고정이다.

```
상태: SENT | ANSWERED → <결정 ID 또는 회신 파일 경로>
회신대상: <원본 파일 경로>          # 회신일 때만. 신규 발신이면 이 줄 삭제
# [<발신> → <수신>] <유형>: <제목>
```

유형은 4종만: 결정 요청 / 작업 지시 / 완료 보고 / 정보 공유.
파일명: `outbox/NNN-주제.md` (역할별 NNN 독립 증가).

## 2. 결정 요청

```
# [<발신> → <수신>] 결정 요청: <제목>

배경: <상대가 맥락을 모른다고 가정, 1~3줄>

안건 1. <제목>
- 선택지: (a) ... (b) ...
- 추천: <안> — <이유 1~2줄>

(안건 2, 3... 독립 안건은 묶되 번호로 부분 회신 가능하게)

회신: 필요 — 안건별 채택/기각/조건
신규 발번 ID: <없으면 "없음">
```

## 3. 작업 지시

```
# [<발신> → <수신>] 작업 지시: <제목>

목표: <1~2줄>
완료 기준: <검증 가능한 조건, 항목당 1줄>
하지 말 것: <범위 제한>
관련 문서: <경로만>

회신: 필요 — 완료 보고 / 불요
```

## 4. 완료 보고

```
# [<발신> → <수신>] 완료 보고: <제목>

결과: <1~2줄>
산출물: <경로 목록>
완료 기준 대비: <충족/미충족 + 미충족 사유>
다음 단계 제안: <있으면 1줄>

회신: 불요 (이견 시에만)
신규 발번 ID: <없으면 "없음">
```

## 5. 정보 공유 (ID 소유자 통지 D-024 포함)

```
# [<발신> → <수신>] 정보 공유: <제목>

요지: <3줄 이내. 상세는 경로 참조>
관련 ID: <언급·영향 ID>

회신: 불요
```

주의: 계약·스펙에 영향이 있으면 이 유형 금지 — 결정 요청으로 격상(D-020).

## 6. 결정 로그 항목 (가이드 4절 준수)

```
## <ID>. <제목 — 결정 내용이 드러나게>

상태: PROPOSED | ACCEPTED | ON-HOLD | SUPERSEDED(→ 대체 ID) · 소유: <역할> · 관련: <참조 키워드> · <날짜>

결정
- <무엇을 하기로 했는지. 원자적 1건>

이유
- <왜. 실물 근거가 있으면 명시>

기각된 대안
- <대안>: <기각 사유>
```

레퍼런스 줄은 외부 근거가 있을 때만. 에스컬레이션 후엔 상태 줄에 escalated-as만 추가, 본문 불변.

## 7. 작업 노트 머리 (유형 4)

```
# <주제> 작업 노트

성격: 미확정 분석/초안 — 타 역할 근거 인용 금지 (D-014 유형 4)
관련: <관련 ID·문서>
```

이하 자유 형식. 결정에 도달하면 로그로 옮기고 노트에는 "→ <ID>로 결정됨" 1줄.

## 8. inbox-log

```
# <역할> inbox-log (처리한 수신 메시지, D-023)

| 처리일 | 메시지 | 처리 내용 |
|---|---|---|
```

## 9. 세션 재개 브리핑 (총괄 전용, D-022)

```
# 현황 브리핑 <날짜>

진행: <현재 게이트와 상태 1~2줄>
대기 중 회신(SENT): <파일 — 누가 답해야 하는지>
ON-HOLD: <안건 — 회부 조건>
당신 관련: <수신자 ID 언급 신규 메시지, 없으면 생략>
다음 액션: <사용자가 할 일 1~3개>
```

## 10. defects / findings 항목 (QA·보안 — 영역 5에서 확정)

```
## <QA|SEC>-NNN. <제목>

심각도: Critical | Major | Minor · 상태: OPEN | FIXED | WONTFIX · <날짜>
재현/조건: <QA: 재현 절차, 보안: 공격 시나리오>
기대 vs 실제: <1~2줄>
관련: <계약 조항·결정 ID·코드 위치>
```
