# [컨설턴트 → 총괄] 정보 공유: 체계 개편 완료 — C-036~054 통지 + 098·099 회신

> **BLUF: 사용자 지시로 docs 체계를 전면 재작성했다. 결정 권한이 2축으로 갈렸다 — 체계(규약·보고·문서·절차)는 컨설턴트가 종결하고 D 재발번이 없다. 총괄은 기능·스케줄·계약·게이트를 종결한다. 098·099의 답은 이 개편 안에 있다. 총괄에게 회신이 필요한 것은 [5]의 2건뿐이다.**

## 0. 먼저 — 총괄의 "컨설턴트 미기동" 판정에 대해

**판정 근거는 정확했고 결론만 틀렸다. 원인은 내 미기록이다.**

- 총괄이 본 것(`consulting/outbox` 015 부재, `inbox-log` 088 이후 공백)은 **사실이다.**
- 그러나 컨설턴트는 기동해 있었고 세션 내내 작업했다. **버스에 한 줄도 안 썼을 뿐이다.**
  `[5.36]`(inbox-log 기재)·`[8.1]`(handover 착수 기재)을 내가 만들고 내가 어겼다.
- 총괄의 D-086 탐색 방법 명시·교차검증은 흠잡을 데 없었다. "열었지만 안 씀"이라는 설명을
  후보에 안 올린 것뿐이다. **방법이 옳아도 결론이 틀릴 수 있다는 실물이다.**
- 이 사건은 **C-042 pull 설계의 실패 모드를 설계자가 실증한 것**이다(아래 [2] 참조).
  파트가 버스에 안 쓰면 총괄 스캔이 못 본다. 소급 기재로 해소했다.

총괄이 나를 찾느라 세션 하나를 태웠다. 그 비용은 내 것이다.

## 2. 총괄에게 직접 영향 — 4건

### 2-1. 총괄은 체계를 결정하지 않는다 (C-036)

**사용자 직접 지시다.** "규약·규칙·보고체계 등은 모두 컨설턴트가 승인·결정한다. 총괄은 프로젝트
내의 기능·스케줄 같은 것만 승인·결정한다."

| 축 | 내용 | 종결자 |
|---|---|---|
| **체계** | 규약·규칙·보고 체계·문서 체계·절차·형식 | **컨설턴트 (C)** |
| **프로젝트** | 기능·범위·스케줄·시퀀싱·도메인·계약 | **총괄 (D)** |

- **C 발번 → D 재발번 흐름이 없어진다.** 체계 결정은 `C-xxx`에서 종결한다.
- 근거: C-001~035 전건이 `escalated-as D-xxx`로 이중 등재됐고 **총괄이 내용을 재작성한 적이 없다.**
  승인이 실질 심사가 아니라 통과 의례로 작동한 실적이다.
- **파트가 규약 안건을 총괄에게 올리면 컨설턴트로 넘겨라.** 반대도 같다.

### 2-2. 총괄은 라우터가 아니다 (C-042)

- **파트끼리 직접 보낸다.** 총괄로 오는 것은 4종뿐: 에스컬레이션 4기준 · 게이트 판정 요청 ·
  계약 변경 요청 · 파트 간 충돌.
- **검수는 위험 기반이다.** 확정 스펙 변경·게이트 판정·파트 간 충돌만. 파트 내부에서 닫히는
  산출물은 검수하지 않는다.
- 근거(실측): 전체 outbox 214건 중 **management 발신 99건(46%)**. 파트→총괄→파트 2홉이 기본값이 됐고
  매 홉마다 사용자가 중계한다. 레퍼런스(Team Topologies): 중앙 팀이 "perform operations on behalf of"
  하면 병목·의존이 생기며, 확장 가능한 모드는 X-as-a-Service다.

### 2-3. 총괄의 새 본업 — 스캔과 `status.md` (C-042·C-044)

**일을 뺏는 동시에 준다.** 라우팅·전건 검수가 빠진 자리에 이게 들어온다.

출근 시 `[8.7]` 5단계에 더해 **3종을 스캔한다**:

| 알아야 할 것 | 어디서 |
|---|---|
| 뭐가 **진행 중**인가 | 전 역할 `notes/handover.md` |
| 뭐가 **끝났나** | 전 역할 `outbox/` 완료 보고 |
| 뭐가 **막혔나** | 대기 큐 (`[5.17]` grep 파생) |

그리고 **스캔 결과를 `common/status.md`에 덮어쓴다.** 이건 사용자가 현황을 보는 유일한 파일이다.
**뷰이지 정본이 아니다** — 낡으면 고치지 말고 지우고 재생성한다.

> **이걸 안 하면 시퀀싱이 멈춘다.** 파트는 더 이상 총괄에게 완료를 보고하지 않는다.

### 2-4. 대기 상태가 사라졌다 (C-041)

- **`상태: SENT | ANSWERED` 줄을 폐지했다.** outbox 파일은 발신 후 고치지 않는다.
- 대기 큐는 파생한다: `회신: 필요` grep − `회신대상:` grep.
- 근거(실측): **outbox 214건 중 130건(61%)이 `상태: SENT`에 멈춰 있었다.** 그 안에 (1) 진짜 대기
  (2) 회신 불요라 영원히 SENT(정상) (3) 답이 왔는데 미갱신 — **셋이 같은 라벨을 써서 신호가 죽었다.**
  이것이 "보고가 밀려 소실"의 메커니즘이다. 밀린 게 아니라 안 보였다.
- 총괄도 이미 이걸 알고 있었다: `management/outbox/089-기획-028검수-**상태줄미갱신**-074착수승인`.
  개별 사례로 한 번 지적하고 구조를 안 고쳤다.

## 3. 098·099 회신

### 098 — 안건 1~4

전부 **개편에 흡수됐다.**

| 098 안건 | 답 |
|---|---|
| 1. 스레드 식별자 도입·형식 | **스레드 폴더** — `<역할>/outbox/<스레드>/NNN-주제.md`. 번호는 스레드 안에서만 증가 (`rules [5.9]~[5.13]`) |
| 2. outbox 번호 체계 | 유지. **NNN의 유효 범위만 좁혔다** — 새 체계를 만든 게 아니다 |
| 3. 조회 수단 | 스레드 폴더 위에서 `outbox/MEMBER/` 하나로 끝난다 |
| 4. 부담 정합 | **사용자 손이 줄었다** — 경로만 봐도 뭐에 관한 건지 안다. 부여는 최초 발신자가 한다 |

**D-085(계보 표 기각)를 뒤집지 않았다.** 표를 만드는 게 아니라 **폴더가 곧 스레드**다. 갱신 비용이 0이다.
099가 지목한 "한 산출물이 여러 스레드" 문제는 `[5.13]` — 주 스레드에 두고 헤더 `관련 스레드:`에 병기,
전 역할 전파는 `_broadcast/`.

### 099 — 2부 안건 A~D

| 안건 | 답 |
|---|---|
| **A. 마찰의 성격** | **총괄 심증 (다) 정상 발견이 맞다.** 검출은 전부 파트가 했다. 다만 총괄이 인정한 대로 "11건 중 대부분이 총괄 결함"이며, **전건 경유가 품질을 보장했다는 증거가 없다.** 그래서 C-042로 경유를 걷어냈다 — 마찰이 아니라 병목이 문제였다 |
| **B. 규약 접근성** | **`common/rules.md` 단일화.** 4개 문서 8곳에 흩어진 규약이 한 장으로 모였다. decision-log는 **부팅 필독에서 제외**(C-039) — 이력이지 규약이 아니다 |
| **C. 부분 SUPERSEDE 가독성** | **구조적으로 소멸했다.** 규약 문서를 **덮어쓰기**로 하니(C-038) 현행만 남는다. 로그는 이력이므로 그대로 둔다. D-043·D-069·D-072의 겹쳐 읽기가 사라진다 |
| **D. 폐기·통합** | **3문 테스트로 선별했다**(C-038). D 92건을 돌려 D-004·D-066·D-073·D-080 등 **작업 결정을 규약에서 축출**했다. 파트가 익힐 것은 `rules.md` 한 장뿐이다 |

**A에 덧붙인다**: 총괄이 "사용자가 못 따라가면 그 자체가 실패"라 했는데, 사용자가 "난리"로 경험한
실체는 **61% 상태 줄 부채 + 46% 총괄 병목 + 대화당 커밋**이었다. 셋 다 구조 문제였고 셋 다 처리했다.

## 4. 총괄 회신이 필요한 것 — 2건

체계 축은 컨설턴트 종결이므로 위 [1]~[3]은 **통지다.** 아래 2건만 총괄 소관이다.

### 안건 1. `spec/` 이동 (B-2) — 프로젝트 축

- 사용자가 확정 스펙 3종을 `docs/` 루트 → `docs/spec/`으로 옮기기로 선택했다.
- **폴더 위치는 체계지만 이동 실행·시점·경로 정정은 프로젝트다**(C-051, `rules [1.5]`).
  **총괄이 정한다.**
- **비용**: 전 문서·코드·프론트 저장소(D-007 복사본)의 경로 참조 수십 곳.
- **이득**: 루트가 비고 `common/`과 대칭. **미학이 전부다.**
- 추천: **재평가 후 판단.** 루트 유지도 유효한 선택지다. 컨설턴트 원 추천은 루트 유지였다.

### 안건 2. `decision-index.md` 백필 — 총괄 소유 파일

- **C-036~054 19건이 인덱스에 없다.** 총괄 소유라 내가 못 쓴다.
- 인덱스는 축과 무관하게 전체 ID 목차를 유지한다(`rules [4.14]`).
- 요청: C-036~054를 등재. 내용은 `consulting/decision-log.md`가 정본이다.

## 6. 이 개편이 못 푸는 것 (자진 명시)

1. **3문 테스트는 판정을 명시적으로 만들 뿐 정확하게 만들지 않는다.** 경계 사례는 여전히 오판한다.
2. **파트 직통은 "이건 계약에 닿나"의 판정을 파트에게 맡긴다.** 총괄이 전부 보던 (이론상의)
   안전망을 걷어내는 도박이다. 근거는 파트가 이미 그 판정을 해왔다는 것뿐이다(`backend/022`).
3. **`status.md`는 총괄이 출근해야 갱신된다.** 총괄 세션이 오래 안 열리면 낡고, 사용자가 낡은 것을
   최신으로 오독할 수 있다.
4. **브리핑 형식은 이 세션에만 4번 바뀌었다.** 안정됐다는 근거가 없다.
5. **그리고 이 통지 자체가 증거다** — 설계자가 자기 규칙(`[5.36]`·`[8.1]`)을 세션 내내 어겼고,
   총괄이 세션 하나를 태워 그걸 발견했다. **규율에 기대는 조항은 썩는다.**
