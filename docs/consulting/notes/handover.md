# 컨설턴트 세션 핸드오버 (2026-07-15)

성격: 세션 이전용 휘발성 맥락 — 파일에 있는 내용은 경로 참조만 (D-059)

## 진행 중

- 없음. 077 기동(파생 작업 순서 붕괴 체계) 완결 — C-031~035 전건 채택(D-082~086).
  현재 대기 모드(D-042) 유지. 안건 5(존치 여부)는 **사용자가 (a) 대기 모드 존치로 확정**, 추적표 종결.
- 대기 모드 중에도 처리하는 것: 사용자 직접 지시(대기 중엔 발번 없이 outbox 전달), 수신함 확인,
  총괄 소집 시 검수. 신규 설계·C 발번은 기동 지시가 있을 때만.
- 재기동 조건: 다음 구조적 결함 발생 시 총괄 회부.

## 대기 중 (회신·상태)

- **`outbox/008` 추신: ID 자기설명 규칙**(기호 첫 언급 시 한 줄 설명 병기) — **3일째 총괄 회신 없음**.
  본문 안건 1·2는 D-049로 기채택되고 추신만 016에서 "후속 회신 대기"로 남은 뒤 잊힌 것으로 보인다.
  탐색 방법: 전 docs 문자열 grep — 총괄 회신 파일 없음(D-086).
  실무상 이미 전 역할이 관행으로 실천 중이라 무해하나, 열린 항목이므로 다음 기동 시 정리 여부를 물을 것.
- 그 외 내 SENT 전건 ANSWERED(009·010·011·012·013·014). 블로커 없음.
- docs 커밋은 **D-061에 따라 사용자 실행**. 마지막 세션분 커밋이 미실행일 수 있다(제안 메시지는 전달 완료).
  `git log origin/master..master`로 미푸시 확인 권장. `.git/index.lock` 잔존 이력 있음 — 막히면 삭제부터 안내.

## 휘발성 맥락 (파일에 없는 판단 기준)

1. **설계 일관 원칙** — 새 제안 검토 시 이 잣대 유지:
   상태는 파일, 세션은 소모품 / 예외는 규칙을 침식(예외가 늘면 기본값이 틀린 것) /
   동기화·리추얼은 이벤트 기반, 시간 기반 배제 / 기술 내용은 실행 역할 소유(컨설턴트는 형식·절차만,
   D-006 위임 경계) / 모든 제안에 이유·기각 대안·레퍼런스 병기.
2. **최근 규약 8건(D-082~089)은 전부 같은 성격이다 — "방지가 아니라 발견 확률을 올리는 장치".**
   D-086도 D-089도 스스로 이 한계를 명시했다. 처방의 효과를 과장하지 마라 —
   **거짓 안심은 사각지대보다 위험하다**는 것이 이 세션의 반복된 교훈이고, 한계를 자진 명시한 회신이
   채택 신뢰도를 올린 실적이 있다(078·081).
3. **과설계 금지는 양방향으로 쓴다.** 보통은 규약 추가를 막는 잣대지만, C-035에서는 역방향으로 썼다 —
   "D-043이 이미 1호 사례다. 일반화하지 않으면 도구마다 D를 새로 발번한다. 일반화는 규약을 늘리는 쪽이
   아니라 증식을 막는 쪽이다." 이 논증이 총괄 심증을 뒤집었다.
4. **계열이 다르면 묶지 마라.** 표면 서술이 같아도(예: "도구를 믿었는데 못 봤다") 메커니즘이 다르면
   한 규약으로 묶는 순간 검증 불가능한 훈계가 된다. 실제로 사각지대 3계열은 각각 다른 결정이 덮었다
   (환경·질의방법 → D-086+D-043 / 기준 커버리지 → D-089). 묶었다면 D-089가 들어올 자리가 없었다.
5. **bash 마운트 stale은 이 환경의 상수다.** 파일 도구(Read/Edit)는 호스트에 정확히 쓰지만 bash 뷰는
   지연·불일치가 잦다. **부정 결과("없음"·"0건")는 반드시 호스트 Read/Grep으로 교차확인**(D-086·D-043 쌍).
   이 세션 자기 사례: 수신함 스캔이 처리 완료된 9건을 "미처리"로 오탐 — 믿었으면 재처리할 뻔했다.
6. **inbox-log 편집 시 마지막 행 끝에 앵커를 걸 것.** 앞 행 앵커로 신규가 위로 들어가는 순서 역전을
   2회 냈다(둘 다 정정). 사소하나 감사 추적 품질에 직결.
7. **D-089 `집행:` 필드는 아직 내 C에 적용된 적 없다**(소급 불요). 다음 C 발번이 첫 적용이다.
8. **사용자 운영 스타일**: 간결·직설 선호, 한 번에 하나씩, 추천안+이유 형식이 잘 통함. 추천을 대부분
   수용하되 실질적 보강을 함. **자기 의견을 냈다가 철회하고 "네가 판단해서 진행하라"고 넘기는 경우가 있다**
   (077 대응 시) — 그때는 방어적으로 사용자 안을 따르지 말고 근거로 판단할 것. 실제로 사용자 제안을
   조건부로 반박한 것이 더 나은 설계로 이어졌다.
9. **총괄 대화는 판단력이 좋다** — 배정 오류·오탐을 잡아낸 전적. 근거를 성실히 쓰면 조건부 수정으로
   돌아온다. **방어적으로 쓸 필요 없고, 총괄 심증이 틀렸다고 판단되면 정면으로 반박할 것** —
   078·081에서 총괄이 자기 심증 오류를 명시적으로 인정하고 내 분석을 채택했다.
10. **브리핑은 매 응답 필수**(D-049) + **초안 생성 응답엔 '초안 요지' 조건부 추가**(D-063).
    ID 첫 언급 시 한 줄 설명 병기(008 추신 — 미채택이나 관행으로 실천 중).
