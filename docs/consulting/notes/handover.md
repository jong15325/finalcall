# 컨설턴트 세션 핸드오버 (2026-07-12)

성격: 세션 이전용 휘발성 맥락 — 파일에 있는 내용은 경로 참조만 (outbox/009 규칙 3항)

## 진행 중

- 없음. 컨설팅 임무(D-012) 5개 영역 완결 — C-001~027 전건 채택(D-014~041).
  현재 상태: 대기 모드(D-042 — 신규 설계·C 발번 중단, 소집 시 응동, 종료 재검토는 G3 후).
- 대기 모드 중에도 처리하는 것: 사용자 직접 지시(발번 없이 outbox로 총괄 전달),
  수신함 확인, 커밋 대행(자기 폴더 한정), 총괄 소집 시 검수.

## 대기 중 (회신·상태)

- outbox/008 추신: ID 자기설명 규칙(기호 첫 언급 시 한 줄 설명 병기) — 총괄 회신 대기.
  본문 안건 1·2는 D-049로 기채택, 추신만 미처리.
- outbox/009: 세션 핸드오버 규칙(이 파일의 근거 규칙) — 총괄 회신 대기.
- git push 미실행 가능성 — 이 세션은 자격증명이 없어 커밋만 하고 push는 사용자 몫이었다.
  재개 시 `git log origin/master..master`로 미푸시 커밋 확인 권장.

## 휘발성 맥락 (파일에 없는 판단 기준)

1. 설계 일관 원칙 — 새 제안 검토 시 이 잣대를 유지할 것:
   상태는 파일, 세션은 소모품 / 예외는 규칙을 침식(예외가 늘면 기본값이 틀린 것) /
   동기화·리추얼은 이벤트 기반, 시간 기반 배제 / 기술 내용은 실행 역할 소유(컨설턴트는
   형식·절차만 — D-006 위임 경계) / 모든 제안에 이유·기각 대안·레퍼런스 병기.
2. D-043 교훈: 세션 마운트 뷰에서 파일이 깨져 보여도 호스트 원본은 온전할 수 있다.
   절단 의심 시 사용자에게 호스트 확인 요청 — 세션 뷰 단독 근거로 복구·보고하지 말 것.
3. 사용자 운영 스타일: 간결·직설 선호, 한 번에 하나씩, 추천안+이유 형식이 잘 통함.
   추천을 대부분 수용하되 실질적 보강을 함(pull 열람, 유동 커밋, 가시성 규칙, 이 핸드오버).
   보강 제안은 대개 "체계가 실전에서 새는 지점"을 짚는 것이니 진지하게 재설계할 것.
4. 총괄 대화는 판단력이 좋다 — 배정 오류(D-035 조기 기동)나 오탐(D-043)을 잡아낸 전적.
   회부 시 근거를 성실히 쓰면 조건부 수정으로 돌아온다. 방어적으로 쓸 필요 없음.
5. 브리핑(D-049)은 매 응답 필수 — 파일에 쓴 내용도 채팅에 요약 노출, ID 첫 언급 시
   한 줄 설명 병기(추신 규칙, 채택 전이지만 이미 실천 중).
