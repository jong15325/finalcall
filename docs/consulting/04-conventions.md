## 2. C-016. docs git 규약 (백엔드 저장소)

1. main 전용: docs/ 변경은 항상 main에 직접 커밋한다. 문서용 브랜치 금지.
   근거: 파일 버스(D-023)는 단일 파일 상태 전제 — 브랜치는 수신함을 가른다.
   문서 리뷰는 PR이 아니라 게이트·총괄 검수(D-019)가 담당한다.
2. 이벤트 기반 커밋(D-022와 일관): 다음 시점에 커밋 생성 —
   - D 발번 시(incident-001 방지 액션 1의 규약 승격)
   - 게이트 통과 시(전파·동기화와 동일 시점)
   - 사고 복구 직후
   - 역할 작업 블록 완료 시(완료 보고 발신 시점, outbox 파일 포함)
3. 주체(유동 운영, 사용자 확정): 작업 블록 종료 시 수정한 역할 대화가 커밋 메시지를
   컨벤션(CLAUDE.md 6절 형식·본문 템플릿)에 따라 작성해 제시한다. 기본 실행자는
   사용자(직접 커밋·푸시)이며, 사용자가 대행을 지시하면 해당 역할 대화가 자기 폴더
   변경의 커밋·푸시를 실행한다. 각 역할은 자기 폴더에만 쓰므로(D-015) 커밋이 자연히
   원자적이고 충돌하지 않는다.
   코드 커밋은 현행 유지(Claude Code 제안, 사용자 실행 — CLAUDE.md 2절. 코드까지
   대행 확장은 CLAUDE.md 2절 개정 필요, 총괄 판단 사항).
4. 메시지 형식: CLAUDE.md 6절 Conventional Commits 유지, type은 docs 고정,
   scope는 역할명 — `docs(<mgmt|design|backend|frontend|qa|security|consulting>): 한글 제목`
   예: `docs(consulting): 영역 4 git 컨벤션 설계안`
5. 혼합 금지: docs 변경과 코드 변경을 한 커밋에 섞지 않는다(atomic commit).

## 3. C-017. 프론트 저장소 git 규약

1. 백엔드와 대칭: Conventional Commits + 한국어 제목 + 커밋 본문 템플릿(CLAUDE.md 6절
   문구 재사용). 스켈레톤기 main 직접 커밋 → 도메인 개발기 feature/<도메인> → PR →
   main(Squash and Merge). GitHub Flow 경량 운용 — 별도 develop/release 브랜치 없음.
2. 스켈레톤 구축 커밋: `chore(skeleton): stage N - 설명` (백엔드 관행 재사용).
3. 계약 복사본 동기화 커밋 형식 고정:
   `docs(contract): api-contract v<N> 동기화 (원본 finalcall@<커밋 해시 앞 7자리>)`
   — 계약 변경 전파 체크리스트(D-007)의 "복사본 갱신"이 이 커밋으로 완결 증명된다.
4. 이 규약은 프론트 CLAUDE.md(영역 5 지침 초안)에 수록한다.

## 4. 블로커: 프론트 스택 미확정 (C-015 첫 적용)

- 프론트 코드 컨벤션은 의존(스택 결정)이 미확정 — 착수 금지, 추적 표 블로커 등재 요청.
- 스택 결정은 아키텍처·기술 선택(에스컬레이션 4기준)이므로 총괄·사용자 안건.
  컨설턴트는 결정 시 해당 스택의 컨벤션 레퍼런스 조사로 후속한다.

## 5. 회사 프로세스에서 덜어낸 것

- Git Flow(develop/release/hotfix): 버전드 릴리스가 없는 단일 운영 웹 서비스 + 1인 구조에
  과잉. 업계 권고도 소규모 팀은 GitHub Flow/트렁크 기반(THEJORD, Assembla 비교).
- 보호 브랜치·필수 리뷰어·CI 게이트: 리뷰어가 없다. PR squash는 도메인 개발기 코드에만.
- commitlint 등 도구 강제: 커밋 주체가 대화/사용자라 도구 이득이 작다. 규약 문서로 충분.

## 6. 레퍼런스

- 브랜치 전략 비교(Toptal, Assembla, THEJORD): 소규모/1인 → GitHub Flow 또는 트렁크 기반,
  Git Flow는 버전드 릴리스 전제일 때만
- Conventional Commits v1.0.0(conventionalcommits.org): type/scope 체계, scope는
  프로젝트 정의 명사
- Atomic commits(Nicolas Jourdan, kennyballou): 1커밋 = 1논리 변경, 유형 혼합 금지
- Google SRE postmortem 액션의 절차화: incident-001 방지 액션 1의 규약 승격 경로
