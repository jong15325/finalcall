## PF-001. 화면 명세·정보구조(IA) 베이스라인을 api-contract v1.2 기준으로 확정

상태: ACCEPTED · 소유: 프론트기획 · 관련: relates-to api-contract v1.2, domain-spec v0.4 · depends-on G3(계약 확정) · 2026-07-14

결정
- 라우트↔화면↔엔드포인트 대응과 도메인 feature 클라이언트 관점을 계약 v1.2 기준으로 정리한 화면 명세를 PF 산출물로 둔다(screen-spec.md, DRAFT v0). 프론트(F)·디자인(U)이 정합하는 클라이언트 측 단일 기준.

이유
- 계약이 v1.2로 확정(G3+6절 2건)됐으나 기존 디자인·프론트 산출물은 v1.1 기준. PF 상류 기획으로서 최신 계약에 정합된 화면 IA 기준선이 필요하다. 라우트↔엔드포인트 대응은 계약에서 파생돼 되돌리기 싼 결정(two-way door)이라 자율 확정.

기각된 대안
- ux-flows·screen-route-map를 그대로 기준 삼기: 둘 다 v1.1 기준이라 grade 잔존·응답 스키마 공백 미반영. 기준선으로 부적합.

## PF-002. 화면 표현에서 등급(grade) 축 제거 반영 — 디자인·프론트 정합은 총괄 격상

상태: ACCEPTED · 소유: 프론트기획 · 관련: relates-to D-073(등급 축 제거), api-contract v1.2 §3·§3.3 · escalated-as 총괄 (a) 집행(053 회신, 전파 054·055) · 2026-07-14

집행(053)
- 자기 문서(screen-spec) grade 제거분: ACCEPTED — D-073 집행이라 신규 D 없음.
- 타 역할 전파분: 총괄이 (a)로 집행 — 디자인 054(grade 제거·U-004 SUPERSEDE 지시)·프론트 055(grade 필터 제거 지시) 발신. PF 직접 발신 없이 전파 결과 참조.

결정
- PF 화면 명세에서 등급(grade) 축을 제거한다(카드·필터·뱃지·표시 필드 모두). 계약 §3 공통 필터·§3.3 응답 item 블록에 grade가 없고 D-073으로 도메인에서 제거됐기 때문.
- 디자인(U) 산출물(design-system §2.3 grade 토큰·GradeBadge, U-004 grade 색)과 프론트(F) screen-route-map §4 grade 필터는 v1.1 기준이라 grade가 잔존 → 정합 필요. 타 역할 소유 문서 영향이라 총괄로 격상(에스컬레이션 4기준 2: 경계 침범).

이유
- grade는 이미 D-073으로 확정 제거됐고 계약 v1.2에 반영됨. 화면 표현 정합은 도메인 연계라 '기획 경유'(D-072, 이제 PF) 대상. 디자인 U-004는 SUPERSEDE 후보이나 U 소유 결정이라 내가 갱신하지 않고 정합 요청.

기각된 대안
- 디자인·프론트 문서를 직접 수정: 타 역할 소유 문서 침범(쓰기 규칙 위반). 정보 공유·총괄 격상으로만 처리.
