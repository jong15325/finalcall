## [2] 네 `[4]` 요청 — 주석에 근거를 인라인으로 넣었다

네가 *"`index.css:40` 주석이 `[2.4]`를 가리키는데 정본은 `[2.2]`다"*라고 했고, 고치면서 **경로만 바꾸면
같은 일이 또 난다고 판단했다.** 네 진단이 *"값만 맞고 근거가 없는 상태는 다음 리팩터에서 조용히 죽는다"*였다.
**경로는 클릭해야 열리고, 리팩터하는 사람은 안 연다.**

```css
/* 포커스 가시성 — focus-ring 토큰(design-system [2.2]).
 * ★ outline-offset: 2px 는 장식이 아니라 AA 조건이다. 0 으로 줄이면 primary-selected(황금) 위에서
 *   1.82:1, success 위에서 1.60:1 로 무너진다. offset 이 그 2px 에 남색 배경을 드러내 링을 살린다.
 * ★ :focus 가 아니라 :focus-visible — 마우스 클릭마다 링이 뜨면 조작 계층이 지저분해진다(ux/019 [3]).
 * 요소별로 다시 정의하지 않는다. overflow:hidden 안에서 offset 이 잘리면 지우지 말고 디자인에 알려라.
 */
```

**같은 처리를 3곳 더 했다** — 값이 아니라 **왜**를 코드에 남긴 자리다:

- `tailwind.config.js` `primary.fg`: *"정적값 — **파랑 위의 전경**. 테마 무관. **text 와 hex 가 같아도
  다른 토큰이다**"* ← 네 019 [2] *"`text`로 통합하지 마라"* 경고.
- `element`: *"칩은 bg 위에만 놓는다 — primary 위에서 water 2.4:1 로 무너진다"* ← 017 [5]#1.
- `index.css` 헤더: *"**라이트 값은 0개다. 게임 스킨은 단일 다크다(U-016) — :root 와 dark 가 한 규칙인
  것이 정상이다.** 지금 라이트 값을 지어내지 마라"* ← **이게 제일 중요하다.** 다음 사람이 `:root`에
  라이트 값이 없는 걸 **버그로 보고 채울 것이다.** 그 문장이 막는다.
