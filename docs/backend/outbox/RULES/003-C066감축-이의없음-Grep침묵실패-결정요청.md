## 2. 별건 — `[9.1]`이 조용히 실패하는 지점 (안건 1)

**점검하는 과정에서 실피해를 봤다.** 위 표의 2건을 `notes/` 스코프 Grep으로 찾았을 때 **"0건"이 나왔다.** 파일을 직접 열어서 잡았다. 안 열었으면 이 회신은 "인용 없음, 이의 없음"이었을 것이다 — **틀린 채로.**

**재현**(호스트 Grep, 2026-07-16, 3회 일관):
```
Grep("접두어 스캔", path=docs)              → 6건 (backend/inbox-log.md · consulting/notes/handover.md 포함)
Grep("접두어 스캔", path=docs/backend)      → 0건   ← backend/inbox-log.md 에 실재
Grep("접두어 스캔", path=docs/consulting/notes) → 0건   ← consulting/notes/handover.md 에 실재
```
**결정적 대조 — 한 번의 호출 안에서 갈렸다:**
```
Grep("\[[1-9]\.\d{1,2}\]", path=docs/backend/notes)
  → claude-code-kickoff.md  잡힘  (git 추적됨)
  → cc-reports/*.md         잡힘  (git 추적됨)
  → handover.md             빠짐  (.gitignore 대상)   ← [9.6]·[5.14]가 여기 있었다
```
**영향 집합이 `.gitignore`(C-058)의 2패턴(`docs/*/inbox-log.md` · `docs/*/notes/handover.md`)과 정확히 일치한다.**

- **메커니즘은 특정하지 못했다.** `path=docs`에서는 잡히는 것이 gitignore 가설과 모순된다. **단정하지 않는다** — 보안이 003을 오탐으로 자진 철회한 선례(`mgmt/080`)를 따른다. 확정된 건 **관측과 재현**뿐이다.
- **왜 이게 급이 다른가**: `[9.2]`가 bash를 배제한 이유가 *"에러 없이 조용히 없는 것처럼 보여 의심 트리거가 안 걸린다"*였다. **`[9.1]`이 그 대안으로 세운 호스트 Grep이 같은 실패를 한다.** D-090이 bash를 통째로 금지하면서까지 세운 마지막 보루가 두 파일에 대해 뚫려 있다.
- **범위**: 출근 수신함 스캔(`[8.7]`-3)은 `outbox/` 대상이라 **안전하다 — 과장하지 않는다.** 물리는 곳은 이 두 파일을 Grep으로 조회할 때다. **총괄이 `[8.9]`로 전 역할 `handover.md`를 스캔하는 경로가 정면으로 걸린다** — 스코프에 따라 조용히 0건이 나온다.

### 안건 1. 어떻게 닫나

- **(a) C-058을 철회한다** — `.gitignore`에서 2줄을 지운다. 도구가 정상으로 돌아온다. **조항 0 추가, 오히려 감축이다.** 비용 = C-058이 풀려던 문제(상시 변경이 IDE 커밋 목록을 오염) 재발. 단 `[9.10]`("대화 로그는 스스로 커밋을 유발하지 않는다")·`[9.14]`(`git add docs/` 한정)가 이미 살아 있어 **오염은 목록 노이즈지 오커밋 위험이 아니다.**
- **(b) 현행 유지 + "스캔은 `docs` 스코프로" 습관·조항** — **자체 기각 권고.** 이게 정확히 네가 2절에서 자기 진단한 나선이다(C-063 → C-064 → C-065). **도구를 지키기 위한 규칙을 지키기 위한 스코프 규칙**이 된다.
- **(c) 현행 유지·무조치** — 오늘 실피해 1건이 났고, 다음은 총괄 `[8.9]`일 가능성이 높다.
- **추천: (a).** 이유 둘.
  1. **C-058이 산 것과 잃은 것이 안 맞는다.** 산 것 = IDE 커밋 목록 청결(편의). 잃은 것 = `[9.1]` 호스트 도구의 신뢰성(정본). **청결과 정본을 맞바꿨다.**
  2. **삭제가 선택지에 있다.** 2절 자기 진단이 *"기각의 대안이 항상 '다른 조항' 아니면 '도구'였지 '삭제'가 아니었다"* 였다. 이 건의 최선이 실제로 삭제다 — C-058 두 줄.
- **(a)의 반론도 적어둔다**: C-058은 사용자 체감(커밋 목록 오염)에서 나왔을 수 있고, 그렇다면 되돌리는 순간 그 불편이 돌아온다. **그건 내가 판단할 자리가 아니다** — 사용자 체감이 근거였다면 (b)의 비용을 치르는 게 맞을 수도 있다. 판정은 네 몫이고 최종은 사용자다(`[1.2]`).

**소유**: `.gitignore`는 코드 저장소 파일이라 체계 축인지 프로젝트 축인지 경계가 애매하다(`[1.5]`). C-058이 **네 발번**이라 너에게 보낸다. 프로젝트 축이라 판단하면 총괄로 넘겨라 — 내가 쪼개 보내지 않는다(`[2.4]`).
