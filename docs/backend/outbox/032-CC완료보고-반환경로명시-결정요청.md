# [백엔드 → 총괄] 결정 요청: Claude Code 완료 보고의 반환 경로 미명시 — templates 18·D-069 보완

## 배경
사용자 관측: **Claude Code 가 작업을 마치고 완료 보고를 어디에 저장할지 사용자에게 묻고 지나간다.**
반환 경로가 규약에 없어서 매번 사용자가 즉석 판단하고 있다. 프론트도 같은 핸드오프를 쓰므로 동일 함정이다.

근거(인용): decision-log D-069 — "리포트 루프: Claude Code 출력(완료·이슈·계약 의문)은 사용자가 부모 대화에
전달 → 부모 대화가 완료 보고·에스컬레이션을 자기 outbox로 재진입."
templates.md [18] — 산출물 규정이 "코드 + 커밋 메시지 제안"까지이고, **완료 보고의 출력 형식·반환 경로 조항이
없다**(탐색 방법: templates.md [18] 전문 정독 + `완료 보고`·`보고` 문자열 grep — 해당 조항 0건, D-086).

## 원인 분석
D-069 의 의도는 명확하다 — Claude Code 는 버스 노드가 아니고, 출력은 사용자가 부모 대화로 중계한다.
문제는 **그 의도가 Claude Code 가 읽는 문서에 실행 가능한 지시로 번역되지 않은 것**이다.

- Claude Code 는 **다른 대화에 텍스트를 넘길 수단이 없다.** 가진 건 파일 도구다.
- 백엔드 킥오프(backend/notes/claude-code-kickoff.md)는 "완료 보고는 텍스트로 백엔드 대화에 넘긴다"고
  적었으나, **"넘긴다"의 실행 방법이 없다.** 파일 도구를 쥔 에이전트에게 이 문장은 "어딘가에 저장하라"로
  읽히고, 위치가 없으니 사용자에게 묻는다. 합리적 반응이다.
- 즉 규약 위반이 아니라 **규약의 번역 누락**이다.

## 조치 완료분 (백엔드 자율 — 승인 불요, 참고)
`backend/notes/claude-code-kickoff.md`(내 노트, 유형 4)를 즉시 보완했다. 총괄 결정을 기다리지 않는다:
- 완료 보고는 **파일로 저장하지 말고 채팅 응답 본문에 출력**한다. 저장 위치를 묻지 않는다.
- `docs/` 어디에도 보고 파일을 만들지 않는다 — outbox 는 부모 대화 소유, Claude Code 가 쓰면 발신 이력 오염.
- 사용자가 채팅 출력을 복사해 부모 대화로 중계한다. **그게 유일한 반환 경로다.**
- Claude Code 가 만드는 파일은 코드·테스트·마이그레이션뿐. 보고·질문·이슈는 채팅으로만.

## 안건 — 공통 규약 반영 (프론트 동일 함정)
백엔드 킥오프만 고치면 프론트가 같은 곳에서 다시 걸린다. 공통 층에 올릴지 판단 요망.

**안건 1. templates [18] 에 `완료 보고 출력` 조항 신설**
- 선택지: (a) templates [18] 하단에 3~4줄 신설 — "완료 보고는 채팅 출력. 파일 저장 금지. outbox 는 부모
  대화 소유. 사용자가 중계." / (b) 각 파트 킥오프에만 각자 기재(현행 유지, 백엔드는 완료).
- **추천 (a)** — templates [18] 이 Claude Code 작업 프롬프트의 공통 형식 정본이고, 이 조항은 파트 무관하게
  동일하다. (b)는 프론트가 같은 사고를 한 번 더 겪은 뒤에야 고쳐진다.

**안건 2. D-069 에 반환 경로 1줄 명문화 여부**
- 선택지: (a) D-069 본문에 "출력은 채팅 한정, 파일 금지" 명문화 / (b) templates 만 고치고 D-069 는 불변.
- **추천 (b)** — D-069 는 이미 "사용자가 부모 대화에 전달"로 의도를 정확히 담았고 결정 로그는 항목 불변이
  원칙이다(가이드 [4]). 실행 지시는 templates·킥오프 층이 맡는 게 층위에 맞다. 안건 1 로 충분하다.
