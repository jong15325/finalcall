완료 기준 대비 (065 백엔드 항)
- 429 응답이 `[1.6]` envelope + `Retry-After` 준수: **충족** — SCG `RequestRateLimiter`는 예외가 아니라 `response.setComplete()`로 상태만 세팅·마감하므로 `ErrorWebExceptionHandler`로 잡히지 않는다. 응답 데코레이트 `GlobalFilter`(`HIGHEST_PRECEDENCE`)가 429일 때만 본문·헤더를 주입한다.
- 403 응답 code = `GATEWAY_403`: **충족** — `ErrorCode` 구현 신규 enum `GatewayErrorCode` 신설, `GatewayAccessFilter`가 `COMMON_006` → `GATEWAY_403` 정정.
- 도메인 ErrorCode enum·서비스 envelope 포맷 무변경: **충족** — `ErrorResponse`·`CommonErrorCode`·도메인 enum 무변경, `ErrorResponse.of(ErrorCode)` 기존 팩토리 재사용. 게이트웨이는 서비스 `ErrorResponse` 미의존(동형 DTO — B-026 독립 2앱).
- 범위 제한(라우팅·rate limit 정책 변경 금지): **충족** — `replenishRate` 등 정책값·라우팅 무변경, 포맷 정합만.
- 067 델타 3건: **전건 충족** — (1) 429 본문·`Retry-After` 구현 (2) 403 코드 교체 + `GatewayAccessIntegrationTest` 기대코드 동반 갱신 (3) 버스트 초과 429 동적 테스트 신설.
- 065 "대기 중이면 완료 보고에 대기 명시": **해당 없음** — MEMBER/001로 레인 해제됨.

검증
- 커밋 실재 확인(호스트 판단 금지 대상 아님 — git 오브젝트 조회, `[9.2]`·`[9.3]`): `git cat-file -e HEAD:<경로>`로 신규 4파일 전건 HEAD 실재. 403 델타 = `2ad3e1b`(3파일), 429 델타 = `4c94471`에 포함(아래 이슈 1).
- 테스트: service `GatewayAccessIntegrationTest` tests=4 / failures=0(`GATEWAY_403` 반영) · gateway `RateLimit429IntegrationTest` tests=1 / failures=0 / skipped=0(실제 429 트리거, envelope 4필드·`errors` 부재·`Retry-After`·필드 순서 단언). checkstyle·spotlessCheck 통과(maxWarnings 0).
- **검증 한계(투명성, D-086)**: `clean build` 미완주다. ① QueryDSL 생성물 clean-vs-compile 레이스(기존 알려진 현상, 본 변경 무관) ② `build/` 점유 잔여 java 프로세스로 `clean`이 `test-results` 삭제 실패. **증분 `build`(두 모듈)로 compile + 전 테스트 + checkstyle + spotlessCheck를 완주해 그린 확인**했다(clean 없이도 QueryDSL 재생성됨). 클린 재현이 필요하면 잔여 프로세스 종료 후 재실행을 권한다.

이슈 (2건 — 판정 요청 아님, 사실 통지)
1. **커밋 분리 실패 — `[9.26]` atomic 위반.** 025는 2커밋(429 / 403) 분리를 제안했으나, **429 델타 4파일이 024 커밋 `4c94471`("feat(member): 잔액 조회 API 추가")에 섞여 들어갔다.** 실측: `git show --stat 4c94471` → `gateway/build.gradle`·`RateLimitResponseGlobalFilter`·`GatewayErrorResponse`·`RateLimit429IntegrationTest` + member 6파일 = 10파일. 403만 `2ad3e1b`로 분리됐다.
   - **되돌리지 않는다** — 코드는 전건 HEAD 실재·빌드 그린이고, 이후 docs 커밋 20여 건이 쌓여 재작성 비용이 이득을 넘는다. 커밋 실행은 사용자 단일 전담(`[9.8]`)이라 내 실행 오류가 아니라 **내 제안이 실행 시점에 병합된 것**이다.
   - **영향**: 이력상 "member 잔액 조회 커밋"을 열면 gateway 429가 나온다. 향후 `git log -- gateway/`로 429 도입 시점을 추적하면 member 커밋이 답으로 나온다. 기능·계약 영향 0.
2. **`Retry-After` 값 결합도.** `Retry-After: 1`은 상수이며 라우트 `replenishRate=5`(초당 5토큰 → 다음 토큰까지 ceil(1/5)=1초, HTTP 정수 초 최소 단위) 기준임을 주석에 명시했다. **`replenishRate`를 1/s 미만으로 낮추면 이 값이 계약과 어긋난다.** 정책값·헤더값을 한 곳에서 파생시키려면 `@ConfigurationProperties`화가 필요한데 이는 065 범위 제한(정책값 변경 금지)과 맞닿아 임의 판단하지 않았다. **현 정책값에서는 정합** — 정책 조정 시 이 상수 재검토가 조건이다. 지금 결정을 요구하지 않는다(내 구현 기법 자율 범위, 정책이 바뀌는 시점에 내가 처리한다).
