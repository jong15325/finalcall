## 범위(포함)

1. 설정 파일 배치
   - `config/checkstyle/naver-checkstyle-rules.xml` — Naver 룰셋(rule-config)에서 가져온다.
     스페이스4 커스터마이즈: 하드탭 검사룰 `[indentation-tab]`(RegexpSinglelineJava `^\t* `) 제거 + `FileTabCharacter`(eachLine=true) 추가.
   - `config/checkstyle/naver-checkstyle-suppressions.xml` — 자동 생성 코드 제외(QueryDSL Q타입 등). 제외 대상 없으면 빈 suppressions로 두되 rules의 `suppressionFile` 참조는 유지.
   - `.editorconfig`(루트) — `charset=utf-8`, `end_of_line=lf`, `insert_final_newline=true`, `[*.java]` `indent_style=space`·`indent_size=4`·`trim_trailing_whitespace=true`·`max_line_length=120`.
   - `config/naver-eclipse-formatter.xml` — Naver eclipse formatter(rule-config)에서 가져오되 `tabulation.char=space`로 커스터마이즈(Spotless가 참조).

2. build.gradle
   - `checkstyle` 플러그인: `configFile=config/checkstyle/naver-checkstyle-rules.xml`, `configProperties=[suppressionFile: ...]`, `maxWarnings=0`. `toolVersion`은 Naver 룰 기준 8.24 이상.
   - `spotless` 플러그인 java: `eclipse().configFile('config/naver-eclipse-formatter.xml')` + `importOrder`(Naver 그룹 순서: static→java→javax→org→net→com) + `removeUnusedImports()` + `trimTrailingWhitespace()` + `endWithNewline()`. target에서 `build/`·생성코드 제외.
   - 컴파일 인코딩 UTF-8(`compileJava/compileTestJava.options.encoding='UTF-8'`).
   - `check`에 spotlessCheck·checkstyle 연결(위반 시 빌드 실패).

3. 기존 코드 일괄 정리
   - `./gradlew spotlessApply` 실행 → 결과를 **로직 무변경 순수 포맷**만 담은 단독 커밋으로 분리 제안.

## 구현 지침
- checkstyle 버전 호환: Naver 룰은 8.24 기준. Java 21 + Gradle 8.14.5에서 최신 checkstyle과 모듈 속성 충돌 가능 → 우선 8.24 계열로 고정. 상위 버전 강제 필요·룰 비호환 발생 시 임의 판단 말고 완료 보고 "이슈"로 올린다.
- Spotless eclipse formatter는 스페이스 버전 `config/naver-eclipse-formatter.xml` 참조. importOrder는 Naver 7.2 순서와 일치시킨다.
- 원격 룰셋 파일은 rule-config 저장소 원본을 그대로 배치 후 위 커스터마이즈만 최소 적용(원본 훼손 최소).
