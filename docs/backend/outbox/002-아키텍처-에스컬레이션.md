## 안건1. 게이트웨이/배포 토폴로지
- (A) 단일 서비스 유지(CLAUDE.md 현행). 게이트웨이 없음.
- (B) 단일 서비스 + SCG 게이트웨이만 전면 — 모듈 분리 없이 진입점 단일화(인증·레이트리밋·대기열 게이팅·직접접근 차단). 도메인은 모놀리식 유지.
- (C) 완전 MSA — gateway/auth/main/queue/common 분리(On-Race와 동형).
- 추천: (B). 이유: 대규모 트래픽·동시성 목표에 게이트웨이 이점(입찰 API 앞 통과토큰 게이트, 레이트리밋, 직접접근 403 차단)은 크다. 그러나 현 단계(G1/G2)·팀 규모에서 완전 MSA는 ERD·계약·운영 복잡도 과다이고, 경매 도메인은 item-auction-bid-settlement 강결합이라 서비스 분리 비용 대비 이득이 낮다. queue(대기열)만 후속 확장 필요 시 별도 분리 여지.
- 기각 이유: (A) 게이트웨이 이점 포기, (C) 현 단계 과설계.

## 안건2. 인증 모델 (안건1에 종속)
- (A) 서비스 자체 JWT 검증(CLAUDE.md F1 현행).
- (B) 게이트웨이 JWT 전담 → `X-User-Id`/`X-User-Role` 주입, 클라 위조 헤더 선제거(stripInternalHeaders), 뒤단 `X-Gateway-Token` 공유비밀로 직접접근 403 차단(On-Race 패턴).
- 추천: 안건1이 (B)/(C)면 인증 (B) 채택 — 뒤단 경량화·일관, 컨트롤러는 `@RequestHeader("X-User-Id")`. 단 보안 게이트에서 헤더 스푸핑 차단(stripInternalHeaders) 필수 검토(보안 역할 리뷰 요청). 안건1이 (A)면 인증도 (A) 유지.
