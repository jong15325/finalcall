## 휘발성 맥락 (파일에 없는 판단)

- **자산 경로 확보됨. U-012 이미지 블로커는 실질 해소다** — 총괄 추적표에는 아직 "사용자 제공 대기"로 열려 있을 수 있으나(091), 실제로는 사용자가 경로를 줬고 디자인이 직접 접근했다. 총괄 추적표 정정이 필요하면 알려라.
  - 아이템 아트: `D:\private_server\SP\tool\Survival-project-PGF-decompressor-main\src\images\global\card\card_image\gold_black` — 648개 = 9레벨 × 2크기(l 50×93 / s 26×28) × 4속성(earth·fire·water·wind) × 9종류(armor·axe·boots·bow·magic·pendant·shield·sword·wand). 속성·종류가 계약 `element`·`kind`와 일치.
  - UI 크롬: `...\src\images\interface\global\card_info\` — `wnd_cardinfo.png`(211×307 창 프레임) · 탭·버튼 normal/click 쌍 · **`card_info.xml`에 자식 좌표 정의**. 공통 버튼(ok·cancle·yes·no·x)·스크롤은 `interface\global\`.
- **실측 팔레트(게임 UI)**: 창 배경 `#001C33`(52%) · 패널/헤더 파랑 `#0667BD`(19%) · 테두리 밝은 파랑 `#3394DE` · 텍스트 크림 `#FAF7D5` · 이미지 슬롯 `#000000`. **상태 언어 = 기본 파랑 / 눌림 주황 `#E25706` / 활성 탭 황금 `#E2B206`**(normal·click 쌍 비교로 도출). 주의: normal 이미지의 `#0000FF`(3~6%)는 구형 투명 키 컬러로 보임 — 디자인 색으로 오인 금지. → **전부 U-020으로 정본화됨**(design-system [2]), 이 줄은 출처 기록으로만 남긴다.
- **element 4색은 아트 실측이 정본이다**(U-020): water `#19B2FF`(200°) · fire `#FF5500`(20°) · earth `#95B259`(80°, **올리브** — amber 아님) · wind `#66CCCC`(180°, **청록** — green 아님). 관례 추정이 2건 반증됐다. **water(200°)와 크롬 파랑(208°)이 8° 차, fire(20°)와 눌림 주황(22°)이 2° 차** — 그래서 3계층 규칙과 "element 칩은 `bg` 위에만"이 나왔다.
- **파생값이 위험 지점이다**(U-020 뿌리 점검). 실측 5색은 AA 전건 통과했는데 내가 손으로 만든 파생값에서 미달 1·오기 2가 나왔다. 대비비를 문서에 적을 때 **계산 없이 눈대중으로 적지 말 것** — 그 숫자도 D-086의 "주장"이다. 검증 스크립트 패턴은 outbox/016 뿌리 점검 참조.
- **자산 접근 방법**: `D:\private_server\...\gold_black`을 폴더 연결하면 호스트 Glob·bash 이미지 디코딩 둘 다 된다. PNG는 **청크 CRC 전건 검증**을 걸어라(마운트 절단 방어, U-018·outbox/014) — 이번 324파일 전건 무결성 확인됐다.
- **아트 단위 = typeCode × 레벨**(내 초기 추정 오답, 실측으로 정정 → 기획 **P-013**으로 확정). `gold_black` large 324개 md5 전수 → 고유 324, 중복 0. **레벨 배지가 PNG에 구워져 있다** — 웹이 `level`로 배지를 그리면 중복 표기.
  - **단, 아트 위임은 전면이 아니다(P-013 조건부).** 레벨은 시세 집계 축·필터 축(`minLevel/maxLevel`)이라 **목록에서 판독 가능해야 한다**는 도메인 요구가 걸린다. `s`(26×28)에 구워진 원게임 폰트 배지가 목록에서 판독되는지 **판정은 디자인 소관**(U-012 표현) — 불충분하면 계약 `level`로 표기한다. 상세(`l` 3x 이상)는 아트 위임으로 충분. **크기별로 갈리며 일괄 규칙이 성립하지 않는다.**
- **자산 경로는 계약 필드만으로 결정된다**: `gold_black/level{level}/{l|s}/{element}/{kind}.png` — **소비 필드 3개**(`level`·`element`·`kind`). 기획 031이 내 `{mainCategory}` 전제를 정정했다: 648 = 9레벨×2크기×4속성×9종류 산술에 mainCategory 차원이 없으므로 `gold_black`은 mainCategory 값이 아니라 **고정 세그먼트**다. 서버 이미지 필드 불요, `domain-spec [7]` 개정 불요 → **P-012로 확정**(계약 변경 0).
- **게임과 웹의 겹침은 생각보다 작다.** 게임은 *보여주는* UI, 웹은 *입력받는* UI다. **게임에 텍스트 입력 필드가 사실상 없다**(`input_btn_c/n` 2개뿐). 인벤토리 창도 자산에 없다(`inven|storage|item_box` 0건). 로그인·검색·가격·입찰 금액·필터·카운트다운·페이지네이션·토스트는 전부 디자인이 만든다. U-016이 "차용의 실체는 시각 언어"라 한 게 이 뜻.
- **U-016 실행 원칙**: 게임 버튼은 텍스트가 이미지에 구워져 있어 웹 카피를 못 만든다 → 크롬은 CSS 재현, 비트맵 차용은 아이템 아트 한정. 픽셀 아트라 `image-rendering: pixelated` + 원본 정수배(2x·3x) 확대. 50×93은 상세 주인공으로 작아 3x(150×279) 전제.
