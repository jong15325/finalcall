- **자산 경로 확보됨. U-012 이미지 블로커는 실질 해소다** — 총괄 추적표에는 아직 "사용자 제공 대기"로 열려 있을 수 있으나(091), 실제로는 사용자가 경로를 줬고 디자인이 직접 접근했다. 총괄 추적표 정정이 필요하면 알려라.

  - UI 크롬: `...\src\images\interface\global\card_info\` — `wnd_cardinfo.png`(211×307 창 프레임) · 탭·버튼 normal/click 쌍 · **`card_info.xml`에 자식 좌표 정의**. 공통 버튼(ok·cancle·yes·no·x)·스크롤은 `interface\global\`.
- **실측 팔레트(게임 UI)**: 창 배경 `#001C33`(52%) · 패널/헤더 파랑 `#0667BD`(19%) · 테두리 밝은 파랑 `#3394DE` · 텍스트 크림 `#FAF7D5` · 이미지 슬롯 `#000000`. **상태 언어 = 기본 파랑 / 눌림 주황 `#E25706` / 활성 탭 황금 `#E2B206`**(normal·click 쌍 비교로 도출). 주의: normal 이미지의 `#0000FF`(3~6%)는 구형 투명 키 컬러로 보임 — 디자인 색으로 오인 금지.
- **아트 단위 = typeCode × 레벨**(내 초기 추정 오답, 실측으로 정정). `gold_black` large 324개 md5 전수 → 고유 324, 중복 0. **레벨 배지가 PNG에 구워져 있다** — 웹이 `level`로 배지를 그리면 중복 표기. 레벨 시각 표기는 아트 위임, 계약 `level`은 필터·정렬·대체텍스트로만.
- **자산 경로는 계약 필드만으로 결정된다**: `{mainCategory}/level{level}/{l|s}/{element}/{kind}.png`. 4값 전부 계약 [3.3] item 블록 보유 → 서버 이미지 필드 불요, `domain-spec [7]`("시각 자산 관리 범위 밖") 개정 불요. 010 안건 1 추천 (a) 유지·강화.
- **게임과 웹의 겹침은 생각보다 작다.** 게임은 *보여주는* UI, 웹은 *입력받는* UI다. **게임에 텍스트 입력 필드가 사실상 없다**(`input_btn_c/n` 2개뿐). 인벤토리 창도 자산에 없다(`inven|storage|item_box` 0건). 로그인·검색·가격·입찰 금액·필터·카운트다운·페이지네이션·토스트는 전부 디자인이 만든다. U-016이 "차용의 실체는 시각 언어"라 한 게 이 뜻.
