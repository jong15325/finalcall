# [디자인 → 총괄] 결정 요청: 비주얼 방향 · 기본 테마

배경: G3 통과로 화면 설계 착수. 디자인 시스템 토큰 구조·컴포넌트 스펙은 확정했으나(design-system.md v0), 색 브랜드·기본 테마는 사용자 확정이 필요한 비주얼 방향이라 결정 요청한다. 어느 안이든 토큰 구조·컴포넌트 스펙은 동일하고 색값·기본 테마만 바뀐다.

안건 1. 비주얼 방향(톤·무드)
- 선택지:
  - (a) Dark Arena — 다크 우선, primary=일렉트릭 인디고, accent=amber(긴급). 게임 몰입·등급색 스캔성.
  - (b) Clean Marketplace — 라이트 우선, primary=트러스트 블루(토스 결제 톤과 조화). 자금 신뢰·접근성.
  - (c) Neon Night — 고대비 다크 + 네온. 강한 게임 임팩트, 단 자금 신뢰·대비 리스크.
- 추천: (a) Dark Arena — 타깃(게임 아이템 트레이더) 다크 선호, 어두운 표면에서 등급/속성 색이 가장 잘 읽히고 마감 임박·즉시구매 amber가 강조됨. 자금 신뢰는 라이트 테마 병행 + 절제된 채도로 확보. (근거: design-system.md 1절, 게임 레어리티 색 관례·다크 UI 대비 설계)

안건 2. 기본(초기 노출) 테마
- 선택지: (a) 다크 기본 + 라이트 토글 (b) 라이트 기본 + 다크 토글 (c) OS 설정 따름(prefers-color-scheme).
- 추천: (a) — 방향 A와 정합. 토큰은 이미 라이트/다크 양립 구조(U-005)라 전환 비용은 클래스 토글뿐. 방향 B 채택 시엔 (b) 권장.

안건 3. 아이템 등급(grade) 색 매핑 — 기획 확인 연계
- 배경: erd `grade`는 INT 축으로 값 목록이 스펙에 없음. design-system 2.3에서 5티어(gray→green→blue→purple→gold)로 잠정 매핑.
- 요청: 등급 단계 수·명칭 확정 필요(기획 소관). 확정값 전달 시 색 티어를 1:1 고정.
- 추천: 5티어 유지하되 실제 등급 수에 맞춰 스케일 조정. (계약 영향 없음 — 표시 매핑)
