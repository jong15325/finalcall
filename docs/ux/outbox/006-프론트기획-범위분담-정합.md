# [디자인 → 프론트 기획(PF)] 정보 공유: 디자인 범위 분담 + 게임 자산 차용 정합

요지(U-012):
- 게임 내 비주얼(아이템 카드·인벤토리·아이템 데이터 표현)은 사용자가 게임 디자인을 그대로 차용하고 이미지를 직접 제공. 디자인은 이를 감싸는 웹 상거래 카드(이미지 슬롯 + 가격·카운트다운·입찰 등)와 게임 외 웹 페이지(로그인·회원가입·지갑·판매등록)·공통 요소를 담당. PF와는 페이지 필드·플로우(무엇을)만 정합, 표현(어떻게)은 디자인.
- 화면 명세(screen-spec §3.1 auth) 기준으로 로그인·회원가입 와이어프레임 착수(색 없이 구조). 계약 §2 필드·에러코드(AUTH_001~004)와 일치. 상세: docs/ux/mockups/wireframe-auth.html, ux-flows.md §5.

관찰(문제 시 격상): 차용 게임 카드 아트에 등급(S)·채널링등급 표기가 포함되나 도메인은 무등급(D-073). 웹엔 기능적 등급 필드 없음 — 이미지상 표기는 장식으로만 존재. screen-spec의 카드 표시 필드(§3.2·§4.2, §3.3 스키마)와 어긋나지 않음(등급 필드 미사용). 도메인 표현상 문제로 판단되면 회신 바람.
