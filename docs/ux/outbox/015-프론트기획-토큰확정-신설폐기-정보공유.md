# [디자인 → 프론트, 기획] 정보 공유: 색 토큰 확정(실측) — 신설 3 · 폐기 3 (U-020)

2. 다만 **토큰 명칭이 일부 바뀐다**: 신설 `primary.pressed`·`primary.selected`·`on-accent-fg` / 폐기 `primary-50~700` 6단 스케일·`accent-500/600`·의미색 `-soft`/`-strong`. U-001(명칭 1:1) 규약상 통지 대상이다.
3. **프론트 스켈레톤이 아직 CC 미실행이면 지금이 반영 적기다**(frontend/007 기준). 이미 짰다면 값·명칭 교체 1회가 필요하다.

## 1. 왜 명칭이 바뀌나 — 게임의 상태 언어가 웹 관례와 다르다

웹 관례는 버튼 상태를 **명도**로 표현한다(`primary-500` → hover `600` → pressed `700`). 그래서 6단 스케일이 필요했다.

**게임은 hue로 표현한다.** normal/click 자산 쌍을 비교하니 눌림이 파랑의 어두운 톤이 아니라 **주황(#E25706)** 이고, 활성 탭은 **황금(#E2B206)** 이다. 이 언어는 명도 스케일로 표현되지 않는다 — `primary-700`에 주황을 넣으면 명칭이 거짓말을 한다.

또 게임 UI에 **옅은 파랑 층이 없다**. `primary-50/100/300`은 라이트 테마 배경용이었는데 단일 다크 스킨에서 쓸 자리가 없다 — 쓰지 않을 토큰을 정본에 두지 않는다.

## 2. 교체표 (프론트 반영용)

### 신설 3

| 토큰 | 값 | 용도 |
|---|---|---|
| `primary.pressed` | `#E25706` | active/pressed — 채우기가 주황으로 **hue 전환** |
| `primary.selected` | `#E2B206` | 선택된 탭·현재 페이지 |
| `on-accent-fg` | `#001C33` | `primary.pressed`·`primary.selected`·`warning` 위 텍스트 |

`on-accent-fg`가 필요한 이유: **주황·황금 위에 크림(`primary-fg`)을 얹으면 3.45:1 · 1.82:1로 WCAG AA를 크게 미달한다.** 게임은 버튼 텍스트가 이미지에 구워져 있어 이 문제를 겪지 않지만 웹은 겪는다. 전경을 남색으로 반전하면 4.61 / 8.74로 통과한다.

### 폐기 3

| 폐기 | 대체 |
|---|---|
| `primary-50 / 100 / 300 / 500 / 600 / 700` | `primary.DEFAULT #0667BD` · `primary.hover #0560AD` · `primary.pressed` · `primary.selected` · `primary.disabled #0A3A63` · `primary.fg #FAF7D5` |
| `accent-500 / 600` | `warning`(정보 계층) 또는 `primary.selected`(조작 계층)로 흡수. **Button `accent` variant도 폐기** — 즉시구매·입찰 CTA 강조는 색이 아니라 **크기·배치**(lg + 주 액션 위치)로 만든다 |
| 의미색 `-soft` / `-strong` | 해당 색 **12% 알파를 `bg` 위에 합성**(`-soft` 대체). `-strong`은 불요 — 4색 모두 `bg` 위에서 본문 AA를 이미 통과한다 |

### 값 교체 (명칭 불변)

```
bg #001C33 · surface #012A4A · surface-raised #013A63 · surface-slot #000000
border #3394DE · border-muted #14496E
text #FAF7D5 · text-muted #B8C4D9 · text-subtle #6B8CA6 · focus-ring #FAF7D5
success #4ADE80 · warning #E2B206 · danger #FF4D4D · info #3394DE
element: water #19B2FF · fire #FF5500 · earth #95B259 · wind #66CCCC
```

**element 4색이 종전값과 완전히 다르다.** 아트 픽셀 실측 결과 earth는 amber가 아니라 **올리브(80°)**, wind는 green이 아니라 **청록(180°)** 이었다. 종전값은 관례 추정이었고 실측이 반증했다.

CSS 변수 블록·Tailwind `theme.extend.colors` 전문은 `design-system.md` [2.6]에 그대로 복사 가능한 형태로 있다.

## 3. 프론트가 지켜야 할 제약 2건 (토큰만으론 표현 안 됨)

1. **element 칩은 `bg` 위에만 놓는다.** `primary`(패널 파랑) 위에 놓으면 water 2.4:1 · fire 1.78:1로 무너진다. element hue(200°)와 크롬 hue(208°)가 8° 차라 구조적이다.
2. **hover는 채우기만으론 지각되지 않는다.** `primary-hover`(#0560AD)는 기본색과 인접 대비 1.12다. **`border`를 #3394DE로 밝히는 것과 함께** 써야 한다. 밝히는 방향의 hover(#1E7FD4)는 크림 전경이 3.83:1로 AA를 깨서 채택하지 않았다.

## 4. 기획 앞 — skeleton-plan [4] 정합 확인

`skeleton-plan [4]`는 "색값은 잠정 A안, 확정 시 **값만 교체**"로 설계돼 있다. **그 설계는 유효하다** — 2분할 구조(테마 무관 정적값 / 테마 의존 CSS 변수)는 그대로다.

다만 위 명칭 변경분은 값 교체가 아니라 **키 변경**이라 skeleton-plan 본문이 `primary-600` 같은 구 명칭을 예시로 들고 있다면 정합이 필요하다. 기획 소유 문서라 디자인이 고치지 않는다 — 확인 후 필요하면 처리해 달라.

라이트 테마 값은 **정의하지 않았다**(U-005 ON-HOLD·후순위, 095 [6절]). CSS 변수 구조는 유지되므로 나중에 넣어도 구조 변경이 없다.
