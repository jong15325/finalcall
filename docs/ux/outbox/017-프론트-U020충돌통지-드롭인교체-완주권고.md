# [디자인 → 프론트] 정보 공유(긴급): U-020 토큰 명칭 변경이 진행 중인 스켈레톤과 충돌한다 — 완주 권고 + 드롭인 교체 블록

요지 3줄:
1. **내 U-020이 `skeleton-plan [4]`의 "토큰명·구조 고정, 값만 교체" 전제를 깼다.** 값뿐 아니라 **명칭**이 바뀐다(신설 3·폐기 3). 그 전제를 "구조 변경 불요"라고 적은 게 나(U-016 집행 표)이므로 **이 어긋남은 내 몫이다.**
2. **권고 = 완주 후 1회 교체**(D-083 완주 기본값). 중단하지 마라 — 아래 [3]에 근거를 계산해 뒀다.
3. 재작업이 **파일 2개**(`tailwind.config.js` + 전역 CSS 변수 블록)로 끝나도록 **복사-붙여넣기용 전문**을 [4]에 실었다. design-system을 다시 읽고 옮길 필요 없다.

## 1. 무슨 일이 있었나

`design-system.md` [2] 색 토큰을 게임 자산 **픽셀 실측값**으로 전면 확정했다(v0.2, U-020). U-016의 마지막 미확정("팔레트는 육안 추정")이 닫혔다.

문제는 값이 아니라 **명칭**이다. 게임의 상태 언어가 **명도가 아니라 hue 전환**(기본 파랑 → 눌림 **주황** → 활성 **황금**)이라 웹 관례의 명도 스케일(`primary-500/600/700`)로 표현되지 않는다. `primary-700`에 주황을 넣으면 명칭이 거짓말을 한다.

- `skeleton-plan [4]`는 "색값은 잠정 A안, **확정 시 값만 교체**되도록 토큰명·구조 고정"으로 설계됐다. 좋은 설계였고 지금도 **구조는 유효**하다(테마 무관 정적값 / 테마 의존 CSS 변수 2분할 그대로).
- 다만 **"토큰명 고정" 부분이 내 실측으로 깨졌다.** U-016 집행 표에 "구조 변경 불요"라고 쓴 것도 나다. 실측 전 추정이었고 틀렸다.

## 2. 충돌 판정 (D-083)

**진행 중인 네 작업과 내 결정이 충돌한다.** 침묵은 규약 위반이라 즉시 통지한다. 다만 이건 "총괄 지시 vs 네 진행"이 아니라 **"내 산출물 vs 네 진행"** 이라, 판정 권한은 D-084상 **파트 내 유닛 순서 = 네 자율**이다. 아래는 권고이지 지시가 아니다.

저장소 관측 1건 병기(D-086 — 탐색 방법: 호스트 Glob `docs/**/frontend/**/*` 전건 나열): **`frontend/outbox/007`이 디스크에 없다.** `006` 상태줄이 "SUPERSEDED → 007"을 가리키는데 대상 파일이 없고 `notes/cc-reports/`도 없다. 미발신인지 커밋 전인지는 내가 판단할 수 없다 — 네 소유라 알린다.

## 3. 왜 완주인가 (중단 아님)

D-083은 **완주가 기본값**이고 선점은 근거가 있어야 성립한다고 정했다. 근거를 계산해 봤고, **중단 근거가 서지 않는다**:

- 스켈레톤 범위(`skeleton-plan [2]`)에서 토큰을 **소비하는 곳이 없다.** 라우트는 빈 placeholder, `features/`는 비어 있고, 공통 UI 상태 3종도 "골격만"이다. 토큰은 **정의만 되고 아직 쓰이지 않는다.**
- 따라서 교체 표면 = **`tailwind.config.js` + 전역 CSS 변수 블록 2개 파일.** 컴포넌트 확산이 0이라 지금 멈추나 끝내고 바꾸나 **비용이 같다.**
- 반면 중단 비용은 실재한다 — CC 컨텍스트 폐기·재지시 왕복. **비용이 같은데 중단하면 순손실이다.**

→ **완주 후 config 2개 교체.** 단 하나 조건: **스캐폴드가 토큰을 컴포넌트에 실제로 바르기 시작했다면**(예: Button 시안을 `bg-primary-600`으로 짬) 그때는 확산 전에 알려라 — 그 경우 판단이 뒤집힌다.

## 4. 드롭인 교체 블록 (design-system [2.6] 전문 — 이 파일에서 바로 복사)

```js
// tailwind.config.js — theme.extend.colors 전체 교체
colors: {
  // 조작 계층 — 게임 상태 언어(테마 무관 정적값)
  primary: { DEFAULT:'#0667BD', hover:'#0560AD', pressed:'#E25706', selected:'#E2B206', disabled:'#0A3A63', fg:'#FAF7D5' },
  'on-accent-fg': '#001C33',

  // 정보 계층 — 의미색(-soft 는 12% 알파 합성, 별도 토큰 없음)
  success:'#4ADE80', warning:'#E2B206', danger:'#FF4D4D', info:'#3394DE',

  // 아이템 계층 — 아트 실측(변경 금지)
  element: { water:'#19B2FF', fire:'#FF5500', earth:'#95B259', wind:'#66CCCC' },

  // 표면·텍스트 — CSS 변수 참조(라이트 값은 U-005 확정 시 추가)
  bg:'var(--color-bg)', surface:'var(--color-surface)', 'surface-raised':'var(--color-surface-raised)',
  'surface-slot':'#000000',
  border:'var(--color-border)', 'border-muted':'var(--color-border-muted)',
  text:'var(--color-text)', 'text-muted':'var(--color-text-muted)', 'text-subtle':'var(--color-text-subtle)',
}
```

```css
/* 전역 CSS — 변수 블록 교체 */
:root, [data-theme="dark"] {
  --color-bg: #001C33;             --color-surface: #012A4A;
  --color-surface-raised: #013A63; --color-border: #3394DE;
  --color-border-muted: #14496E;   --color-text: #FAF7D5;
  --color-text-muted: #B8C4D9;     --color-text-subtle: #6B8CA6;
}
```

### 삭제 대상 (남겨두면 죽은 설정이 된다)

- `primary: { 50, 100, 300, 500, 600, 700 }` 6단 스케일 — 게임 UI에 옅은 파랑 층이 없다. 쓸 자리가 없다.
- `accent: { 500, 600 }` — `warning`(정보 계층) / `primary.selected`(조작 계층)로 흡수. **Button `accent` variant도 폐기**했다(즉시구매·입찰 CTA 강조는 색이 아니라 **크기·배치**로).
- 의미색 `-soft` / `-strong` — `-soft`는 12% 알파 합성으로 대체, `-strong`은 4색 모두 `bg` 위에서 본문 AA를 이미 통과해 불요.

**`element` 4색은 종전값과 전부 다르다.** 아트 픽셀 실측 결과 earth는 amber가 아니라 **올리브(80°)**, wind는 green이 아니라 **청록(180°)** 이었다 — 종전값은 관례 추정이었고 반증됐다. 값만 갈아끼우면 된다.

## 5. 토큰으로 표현 안 되는 제약 2건 (feature 단계에서 필요)

스켈레톤에선 안 쓰지만 지금 알아두면 나중에 되돌릴 일이 없다.

1. **element 칩은 `bg`(#001C33) 위에만 놓는다.** `primary`(패널 파랑) 위에서 water 2.4:1 · fire 1.78:1로 무너진다. element-water(200°)와 크롬 파랑(208°)이 **8° 차**라 구조적이다.
2. **hover는 채우기만으론 지각되지 않는다.** `primary.hover`는 기본색과 인접 대비 1.12다 — **`border`를 #3394DE로 밝히는 것과 함께** 써야 한다. 밝히는 방향의 hover(#1E7FD4)는 크림 전경이 3.83:1로 AA를 깨서 기각했다.
