## 1. 색 대비 (WCAG 1.4.3 / 1.4.11)

- 본문 텍스트 4.5:1, 큰 텍스트(18pt/14pt bold 이상) 3:1, UI 컴포넌트·상태 경계 3:1 이상.
- 적용: design-system 2.4 표면/텍스트 토큰은 라이트·다크 각각에서 위 기준을 만족하도록 값 선정. 다크 기본(A안) 채택 시 `text`(#E8EDF7) on `surface`(#141A29), `text-muted`(#9AA7BD) on surface 등 주요 조합을 구현 단계에서 대비 측정·통과 확인(측정은 accessibility-review 스킬 또는 대비 계산기).
- primary 위 텍스트(primary-fg #FFFFFF on primary-500 #6366F1)·accent 위 텍스트도 4.5:1 확인. 미달 시 텍스트를 진하게 하거나 배경 톤 조정.
- 포커스 링(focus-ring)은 인접 배경과 3:1 이상.

## 2. 색만으로 정보 전달 금지 (WCAG 1.4.1)

자금·경쟁 도메인이라 상태 오인은 손실로 직결된다. 색은 보조 신호이고 텍스트/아이콘/형태가 1차 신호다.

- StatusChip(경매·고정가·주문 상태): 의미색 + 상태명 텍스트(+아이콘). 색만으로 SOLD/ACTIVE 구분 금지.
- ElementBadge: 색 + 속성명 텍스트 병기(색약 사용자 대비). 등급(GradeBadge)은 D-073으로 폐기 — 해당 없음.
- 잔액 부족·마감 임박: danger/warning 색 + 명시 문구("잔액 부족", "마감 임박").
- 입력 에러: 색 + 에러 메시지 텍스트(aria-describedby 연결).

## 3. 키보드 접근 (WCAG 2.1.1 / 2.4.3 / 2.4.7)

- 모든 인터랙션(버튼·입력·필터·정렬·페이지네이션·모달·토스트 닫기)은 키보드로 도달·조작 가능.
- 포커스 가시성: 전 포커서블 요소에 명확한 focus-ring(design-system focus-ring 토큰). outline 제거 후 대체 스타일 없음 금지.
- 논리적 포커스 순서: DOM 순서 = 시각 순서. 상세 거래 패널은 금액 입력→입찰→즉시구매 순.
- "더 보기"(cursor 폴백)·무한스크롤 센티넬은 키보드/스크린리더로 다음 페이지 로드 가능.
- 커스텀 셀렉트·드롭다운은 네이티브 시맨틱 우선(또는 ARIA 패턴 + 화살표 키 조작).

## 4. 터치 타깃 (WCAG 2.5.5 지향)

- 최소 44x44px. Button sm(h32)은 터치 맥락에서 md(h40+패딩) 사용 또는 타깃 확장.
- 카드 내 다중 액션·아이콘 버튼 간 간격 확보(오탭 방지). 필터 칩 제거(x) 타깃 44 확보.

## 5. 시맨틱 · 폼 · 대체텍스트 (WCAG 1.1.1 / 1.3.1 / 4.1.2)

- 랜드마크: header/nav/main/footer. 목록은 list 시맨틱, 카드 그리드는 적절한 역할.
- 폼: label for=input(가시 라벨, placeholder 라벨 대용 금지). 힌트·에러는 aria-describedby. 필수는 aria-required.
- 아이템 이미지: 의미 있는 대체텍스트(아이템명·속성·레벨). 장식 아이콘은 aria-hidden.
- 아이콘 전용 버튼(즉시구매·닫기 등): aria-label 필수.
- 금액·시간: 시각은 축약(N:MM)해도 스크린리더용 전체 값 제공(aria-label 또는 sr-only).

## 6. 모달 · 토스트 · 실시간 (WCAG 2.4.3 / 4.1.3)

- 모달: role=dialog·aria-modal=true, 열림 시 포커스 트랩·첫 포커스 이동, 닫힘 시 트리거로 복귀, Esc 닫기, aria-labelledby(제목).
- 토스트: aria-live — 정보/성공 polite, 에러 assertive. 자동 소멸 토스트도 스크린리더가 읽도록. 색+아이콘+텍스트.
- Countdown: 초당 aria-live 갱신 금지(스팸). 임박(warning)·마감(danger)·연장(소프트클로즈) 전환 시점에만 폴라이트 안내. 마감은 정적 "마감" 텍스트로 확정.
- 입찰 피드/상위 입찰 밀림: 폴링 감지 시 폴라이트 안내("상위 입찰 발생"), 시각 토스트와 동기.

## 7. 모션 · 기타 (WCAG 2.3.1 / 1.4.10 / 1.4.4)

- prefers-reduced-motion: 트랜지션·트윈 최소화(design-system 4절). 카운트다운 값은 유지, 애니메이션만 제거.
- 리플로우: 320px 폭까지 가로 스크롤 없이 사용(모바일 우선 그리드 1열).
- 텍스트 200% 확대 시 콘텐츠·기능 유지.
- 자동 갱신(폴링) 콘텐츠가 사용자 조작을 방해하지 않도록(입력 중 포커스·값 보존).

## 8. 검증 방법 (핸드오프·QA 연계)

- 디자인: accessibility-review 스킬로 토큰 대비·컴포넌트 명세 감사(구현 전).
- 프론트: 구현 시 키보드 워크스루 + 스크린리더(1개 이상) 스팟 체크 + 자동 도구(axe 등).
- QA: 접근성 케이스를 시나리오에 포함(키보드 전용 입찰·구매 완주, 색약 시뮬레이션에서 상태 식별).
- 기준 미달은 결함으로 처리(계약 무관 시 디자인/프론트 자율, 계약 영향 시 6절 절차).
