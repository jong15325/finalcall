회원가입 화면의 상태

아래는 같은 폼 컴포넌트의 상태 분기이며 별도 화면이 아니다. 각 캡션의 코드는 docs/spec/api-contract.md §2·§1.6의 실제 에러코드이고, 주황 캡션은 계약에 아직 없는 미래 항목이다.

아이디 중복AUTH_001 · 409

이미 사용 중인 아이디입니다.

409 를 해당 필드로 되돌린다. 폼 단위 배너가 아니라 필드 단위인 이유는 고칠 대상이 명확하기 때문이다 — 로그인 실패(AUTH_003)와 정반대 판단이며, 거기서는 어느 필드가 틀렸는지 알려주지 않는 것이 열거 방지였다.

닉네임 중복AUTH_002 · 409

이미 사용 중인 닉네임입니다.

닉네임은 거래 화면에 노출되는 표시용 값이라 중복을 그대로 알려도 열거 위험이 없다 (계약 §2 가 명시). 아이디와 달리 사용자가 곧바로 다른 값을 고를 수 있어야 한다.

비밀번호 불일치P-009 · 클라이언트

비밀번호가 일치하지 않습니다.

서버 400 이 아니라 제출 전에 클라이언트가 막는다. 요청 자체가 나가지 않으므로 불필요한 rate limit 소모도 없다. 시각 표현은 서버 에러와 동일하게 두었다 — 사용자에게는 "고쳐야 할 필드"라는 점에서 차이가 없기 때문이다.

제출 중loading

가입은 되돌리기 어려운 조작이라 중복 제출 차단이 특히 중요하다 (disabled + aria-busy, §5.1). 필드도 함께 잠근다.

요청 제한 · 카운트다운GATEWAY_429
요청 제한 30초 후 다시 시도할 수 있습니다.

입력한 값은 그대로 남아 있습니다. 카운트다운이 끝나면 버튼이 다시 열립니다.

Retry-After 초를 카운트다운으로 노출하고 트리거 버튼을 잠근다(§5.6). 입력값을 지우지 않는다는 문장을 덧붙였다 — 4필드를 다시 채워야 한다는 불안이 제한 자체보다 이탈을 크게 만든다. 카운트다운은 실제로 돌고 있다.
