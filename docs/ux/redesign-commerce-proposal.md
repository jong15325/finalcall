## 0. 개정의 성격 (왜 뒤집는가)

`design-system.md` v0.2.x는 **원게임 "아이템 정보창 UI"의 남색#001C33 단일 다크 스킨**을 브랜드 전체 팔레트로 채택했다. 사용자가 이를 **오류로 정정**했다 — 게임 아이템 정보창 색을 자금 거래 커머스 전체에 입힌 것이 문제다. 개정 방향:

- **메인/서브 색상 = 무신사(Musinsa) + 마켓컬리(Market Kurly) 커머스 참조.** 깨끗한 **라이트 베이스**로 전환한다.
- **게임 색은 부분 차용만** — element 4색과 아이템 아트 슬롯(검정)은 **아이템 표시 영역에만** 살아남고, 브랜드/조작/크롬 색으로 쓰지 않는다.
- **유지되는 것**: 토큰 구조·이름(Tailwind 1:1), 컴포넌트 스펙([5]), 접근성 원칙([1.2] "색만으로 정보 전달 금지" 등), element 아트 실측값(hex 불변). **바뀌는 것**: 색값, 그리고 라이트/다크 기본의 역전.

이 개정은 `design-system.md`의 "단일 다크·라이트값 0개" 전제를 **라이트 기본으로 역전**한다(4절). 구조는 그대로라 CSS 변수 구조 변경은 없다.

## 1. frontend-design 4선언 (착수 규율)

1. **목적(purpose)**: 신뢰감 있는 **게임 아이템 커머스**(자금 거래 플랫폼). 사용자는 실제 돈에 준하는 캐시·게임머니를 다룬다 — UI는 "게임"이 아니라 "믿을 수 있는 거래처"로 읽혀야 한다. **게임 감성은 아이템에만** 국한해 드러낸다.
2. **톤(tone)**: 무신사식 **미니멀 에디토리얼**(고대비 흑백 기조, 얇은 선, 각진 낮은 반경, 강한 타입 위계, 넉넉한 여백) + 마켓컬리식 **프리미엄 퍼플 포인트**. 깨끗한 라이트 베이스.
3. **제약(constraints)**: WCAG 2.1 AA(모든 텍스트/컨트롤 대비를 라이트 베이스에서 재계산·명시). Tailwind 토큰 **구조 유지, 값만 교체**(신설은 최소, 근거 병기). **element 아트값 불변**.
4. **차별점(differentiation)**: 제네릭 SaaS/부트스트랩(둥근 카드·그림자 남발·파랑 일색)을 회피 — **무신사식 얇은선·각진·타입중심 + 컬리 퍼플 포인트**. 아이템 카드에서만 게임 아트(검정 슬롯 + element색)가 드러나는 **이원 구조**: 깨끗한 커머스 셸 안에 게임을 들여다보는 "창" 하나.

### 2.3 primary — 컬리계 딥 퍼플 (우리 고유값)

컬리 시그니처는 마젠타 계열 딥 퍼플이다. **베끼지 않는다** — 우리 값은 **hue를 살짝 바이올렛(더 파랑)쪽으로 돌리고 명도를 미세 조정**해 컬리 자산과 구분되는 고유 톤 `#6E2A9F`로 정한다(상표·저작권 회피).

| 토큰 | 값 | 대비 | 상태·용도 |
|---|---|---|---|
| primary | `#6E2A9F` | 흰 글자 **8.42** / 배경 위 텍스트 8.42 | 기본 액션·브랜드 포인트·링크·포커스 |
| primary-hover | `#5C2185` | 흰 글자 10.44 | hover(**명도 하강** — 커머스 관례. 게임식 hue 전환 폐기) |
| primary-pressed | `#491A6C` | 흰 글자 12.75 | active/pressed |
| primary-selected | `#F1EAF5` | primary 텍스트 7.15 | **선택된 탭·활성 내비 배경(soft 틴트)**. 텍스트는 `primary` |
| primary-disabled | `#E4E4E7` | 텍스트 `#A1A1AA` | 비활성 버튼(라이트에선 중립 그레이가 자연 — 탈색 퍼플 대신) |
| primary-fg | `#FFFFFF` | — | `primary`/hover/pressed 위 텍스트. **정적값, 테마 무관** |
| primary-soft | `#F1EAF5` | — | (신설) 퍼플 8~10% 틴트 배경 — ghost hover·선택 배경·강조 존 |

> **조작 상태 모델이 근본적으로 바뀐다.** 구 팔레트는 게임의 "상태=hue 전환"(파랑→눌림 주황→활성 황금)을 차용해 `pressed`/`selected`에 전경 반전(`on-accent-fg`)이 필요했다. 라이트 커머스에서는 **명도 램프**(퍼플→더 진한 퍼플)로 돌아가고 전경은 흰색으로 통일된다 — 훨씬 단순하다. 구 `on-accent-fg`(밝은 채움 위 남색 전경)의 역할은 버튼에서 거의 사라지고 **element 칩 라벨**에서만 살아남는다([2.6]).

### 2.4 뉴트럴 스케일 · 테두리 (무신사 그레이 — 얇은 선)

| 토큰 | 값 | 대비 | 용도 |
|---|---|---|---|
| border | `#E4E4E7` | 1.27 (장식) | 카드 외곽선·구분선(무신사식 얇은 선). **장식 경계라 3:1 면제** |
| border-muted | `#F1F1F3` | 1.13 (장식) | 가장 옅은 내부 구분선(표 행 등) |
| border-strong | `#8A8A8F` | **3.44** | **(신설) 인풋·셀렉트·체크박스 등 조작 컨트롤 외곽선** — WCAG 1.4.11(3:1) 충족 |

> **`border-strong` 신설 근거.** 라이트 베이스에서 단일 border 값으로는 "무신사식 whisper-thin 카드 선(≈1.3:1)"과 "인풋 컨트롤 경계 3:1"을 **동시에 만족할 수 없다**(순백 위 3:1 = `#949494` 이상으로, 카드 선으로 쓰면 무겁다). 구 시스템은 남색 위 밝은 파랑(#3394DE, 5.3:1)이 우연히 둘 다 충족했으나 라이트에선 갈린다. 컨트롤 경계는 1.4.11상 "요소 식별에 필수"라 3:1을 지켜야 하므로 별도 토큰으로 분리한다(구 시스템이 `on-accent-fg` 등을 신설한 것과 같은 정당한 구조 추가).

### 2.6 의미색 (라이트 베이스에서 재검증)

구 의미색은 남색 위 기준이라 라이트에선 대부분 너무 밝다 → **라이트 위 4.5:1을 만족하도록 진하게 재정의**했다.

| 토큰 | 값 | on 흰 | 용도 |
|---|---|---|---|
| success | `#14742F` | 5.88 | 낙찰·구매 완료·잔액 충분 |
| warning | `#A0510A` | 5.71 | 마감 임박·주의(잔액 근접) — 딥 앰버(게임 황금 재사용 폐기, 라이트에서 무너짐) |
| danger | `#C81E1E` | 5.74 | 실패·유찰/종료·잔액 부족·취소 |
| info | `#1D4ED8` | 6.70 | 안내·중립 알림(딥 블루 — element-water 시안과 hue 분리) |

- **`-soft`(칩·토스트 배경)** = 해당 색 **8% 알파를 흰색 위에 합성**. 이 위 칩 텍스트는 해당 의미색 base로 두며 전건 **≥ 4.5:1**(darker base가 여유 확보: danger 5.04, info 4.65, warning 4.50, success 4.57 — 계산값). 라이트 베이스라 다크 스킨의 `-strong` 불필요.
- **색만으로 정보 전달 금지** 계승 — 아이콘/텍스트 병기(`accessibility.md` [2]).

### 2.7 element 4색 — 아트값 불변 + **라이트 배경 대비 재검증**

**hex는 아트 픽셀 실측값 그대로 불변**(카드 아트가 정본). 그러나 **역할은 라이트에서 바뀐다** — 아래가 재검증 결과다.

| element | 값(불변) | **텍스트 on 흰(구 남색값)** | near-black 라벨 on 채움 | white on 채움 | on 슬롯(#000) |
|---|---|---|---|---|---|
| water | `#19B2FF` | **2.37** ❌ (남색 위 7.29였음) | 7.47 ✅ | 2.37 ❌ | 8.85 ✅ |
| fire | `#FF5500` | **3.21** ❌ (5.40였음) | 5.53 ✅ | 3.21 ❌ | 6.55 ✅ |
| earth | `#95B259` | **2.39** ❌ (7.24였음) | 7.42 ✅ | 2.39 ❌ | 8.79 ✅ |
| wind | `#66CCCC` | **1.90** ❌ (9.12였음) | 9.34 ✅ | 1.90 ❌ | 11.07 ✅ |

**결론 — 남색 위에서 빛나던 4색이 흰 배경에서 전건 무너진다**(텍스트 대비 1.9~3.2:1, 모두 4.5 미달이고 water/earth/wind는 3:1도 미달). 정확히 다크→라이트의 역전 현상이다. 따라서 라이트에서 element색의 **역할을 반전**한다:

- **다크 스킨**: element = 남색 위 **밝은 텍스트**(칩 글자색).
- **라이트 스킨(개정)**: element = **채움/틴트 배경 + near-black(#18181B) 라벨**. 아트 hex는 그대로 쓰되 전경만 뒤집는다.
  - **권장 패턴(미니멀 정합)**: element **15% 소프트 틴트** 배경(water `#DDF3FF`·fire `#FFE6D9`·earth `#EFF3E6`·wind `#E8F7F7`) + near-black 라벨(15~16:1) + **solid element색 아이콘/도트**로 속성 hue를 소면적에 노출. 라벨이 항상 병기되므로 도트가 3:1 미달이어도 1.4.1(색 단독 금지)·1.4.11(필수 식별) 위반 아님.
  - **강조 패턴(아트 위 오버레이 배지)**: solid element 채움 + near-black 라벨(5.5~9.3:1). 아이템 카드 아트 영역 위에서 더 강한 속성 정체성이 필요할 때.
- 아이템 아트 슬롯 `#000000`은 아트 표시 전용(6.5~11:1, 아트 맥락).

### 2.8 focus-ring

| 토큰 | 값 | 대비 | 비고 |
|---|---|---|---|
| focus-ring | `#6E2A9F` | 8.42(흰) / 8.06(페이지) | `outline: 2px solid` + **`outline-offset: 2px`**. offset이 퍼플 버튼 채움과 링을 흰 간격으로 떼어 링을 살린다(구 시스템의 offset AA 논리를 라이트에서도 계승). `:focus-visible` 사용 |

## 3. 게임 부분차용 경계 규칙 (허용/금지)

이 시스템의 핵심 이원 구조다. **게임색·아트는 "아이템"이라는 좁은 창에만 존재하고, 나머지 커머스 셸은 전부 화이트/그레이/퍼플이다.**

| | 허용 (게임 차용 OK) | 금지 |
|---|---|---|
| **element 4색** | 아이템 속성 배지(ElementBadge)·아이템 카드의 속성 마커·아이템 목록 필터의 element 칩 | 브랜드/조작(버튼·탭·인풋) 색 · 페이지 크롬 · 배경 · 본문 텍스트 · 링크 · 내비 |
| **아트 슬롯 검정(#000000)** | 아이템 카드/상세의 게임 아트 썸네일 배경(아트가 검정 전제) | 페이지·패널·모달 배경 · 히어로 · 그 외 어떤 표면도 검정 금지 |

- **세 계층 불혼합 계승**([1.2]): 조작(퍼플)·정보(의미색)·아이템(element)은 같은 컴포넌트 안에서 색으로 섞이지 않는다. 버튼에 element색 금지, element 칩에 hover 퍼플 금지.
- **element 칩은 라이트 표면(`bg`/`surface`) 위에 2.7의 틴트/채움 패턴으로만** — 구 시스템의 "패널 파랑 위 배치 금지"는 이제 "퍼플 위 배치 금지 + 흰 배경 위 텍스트 직접 사용 금지"로 대체된다.
- 결과: 목록·상세에서 **아이템 카드 한 장이 유일하게 게임이 드러나는 지점**이다. 로그인·가입·마이페이지·탈퇴 등 계정/거래 크롬에는 element색·검정 슬롯이 **전무**하다.

## 4. 라이트 베이스 전환의 함의 (CSS 변수 구조)

`design-system.md` [2.5]는 "**단일 다크·라이트값 0개**"였고 `:root, [data-theme="dark"]` 한 규칙에 다크값을 넣었다. 개정은 이를 **정확히 역전**한다 — 구조는 그대로 두고 값만 뒤집는다.

- **`:root`(기본값 자리)에 이제 라이트값이 들어간다.** 라이트 커머스가 기본이다.
```css
:root {                          /* 기본 = 라이트 커머스 (역전) */
  --color-bg:#FAFAFA;            --color-surface:#FFFFFF;
  --color-surface-raised:#FFFFFF; --color-surface-sunken:#F4F4F5;
  --color-border:#E4E4E7;        --color-border-muted:#F1F1F3;
  --color-border-strong:#8A8A8F;
  --color-text:#18181B;          --color-text-muted:#52525B;
  --color-text-subtle:#71717A;   --color-focus-ring:#6E2A9F;
}
/* [data-theme="dark"] 는 U-005 확정 시 얹는 미래 오버레이. 지금 다크값을 지어내지 않는다
   — 구 문서가 라이트를 미룬 것과 같은 규율을, 방향만 반대로 적용한다. */
```
- **정적 토큰(테마 무관)**: `primary.*`·`primary-fg`·`on-accent-fg`·의미색·`element.*`·`surface-slot`은 그대로 Tailwind config에 정적값으로 둔다 — **2분할(정적/변수) 구조 불변, 값만 교체**.
- **역전의 대칭성**: 구 시스템은 "다크 기본, 라이트 미룸"이었고 개정은 "라이트 기본, 다크 미룸"이다. `focus-ring`을 변수로 둔 이유(테마 오면 덮기 위해)도 그대로 유효 — 방향만 반대다.
- 그림자: 라이트에선 `shadow-sm/md/lg`(구 tailwind.config 라이트 기준값)가 **실제로 부양에 쓰인다**(다크 스킨은 표면 밝기차로 대체했었음). surface-raised(모달)는 shadow-md/lg로 뜬다.

## 6. 검증 요약

- 텍스트·컨트롤·의미색·primary·focus 전 토큰을 라이트 베이스(#FAFAFA/#FFFFFF)에서 sRGB 상대휘도로 계산 → **AA 전건 통과**(본문 4.5:1 / UI 3:1).
- element 4색 라이트 재검증 완료 — 텍스트 사용 불가(1.9~3.2:1) 확인, 채움+near-black 라벨 패턴으로 우회(5.5~16:1).
- 미제출 범위: 다크 테마값(U-005 대기), 아이콘 세트, 실제 게임 아트 자산 연결.

## 7. 사용자에게 물을 열린 질문

1. **CTA 색 — 블랙 vs 퍼플.** 무신사는 주 CTA가 **블랙**(#18181B), 컬리는 **퍼플**이다. 본 제안은 **퍼플을 주 CTA**로 두고 블랙(`ink`)을 보조/고강조 대안으로 마련했다. (a) 퍼플 CTA 유지 · (b) 블랙 CTA + 퍼플은 링크·포인트만 · (c) 혼용(예: 파괴적/최종 확정만 블랙) 중 선호는?
2. **퍼플 톤.** `#6E2A9F`는 컬리보다 살짝 바이올렛(파랑쪽)이다. 더 마젠타(핑크쪽·컬리 근접)로 갈지, 더 인디고(파랑쪽·차분)로 갈지 방향 선호?
3. **페이지 베이스.** `#FAFAFA`(살짝 오프화이트) vs `#FFFFFF`(순백, 더 무신사적). 카드 대비를 위해 오프화이트를 택했으나 순백 선호 시 카드 구획을 border로만 처리.
4. **element 배지 강도.** 아이템 카드에서 (a) 소프트 틴트 칩(미니멀·차분) vs (b) solid 채움 칩(속성 강조·게임감) 중 기본값 선호?
