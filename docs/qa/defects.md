# QA 결함 트래킹 (QA-NNN, D-038·templates §10)

결함 티켓 누적(전 역할 열람). 심각도 Critical|Major|Minor, 상태 OPEN|FIXED|WONTFIX.
결함 티켓은 삭제하지 않는다(qa-guide §5). Critical(돈·정합성 훼손)은 발견 즉시 총괄 push.

기준: api-contract v1.2 · domain-spec v0.4 · ACCEPTED 결정만(qa-guide §1, 추측 금지).
검증 대상 범위: backend/outbox/019(auth 완결) · 021(게이트웨이 완결).
검증 방법: Q-001(계약 기준 정적 정합 검증 + 재실행 가능한 시나리오 스위트).

## 계약 질의(비결함 — 스펙 공백, 격상 처리)

결함이 아니라 계약 근거 부재(qa-guide §4)로, 계약 질의로 격상한다. 상세 판단은 Q-002.

- CQ-1 게이트웨이 rate limit **429 응답 본문 포맷** 미명세: 현행 v1.2에 엣지 오류 응답 스키마 없음.
  구현은 SCG 기본(본문 없음) 추정. 관련: 057(v1.3 진행), 시나리오 QA-S-GW-02. 재실행 대기.
- CQ-2 게이트웨이 **직접접근 차단 403 오류 코드** 미명세: 구현 관측 `COMMON_006`(GatewayAccessFilter →
  ErrorResponse). §5 에러코드 표에 COMMON_006 부재(§5는 COMMON_004만 등재). 관련: 057(v1.3에서
  직접접근 403 명세 여부 판단 예정), 시나리오 QA-S-GW-04. 재실행 대기.

두 건 모두 v1.3 확정 후 해당 시나리오 기대 결과를 확정하고 재검증한다. v1.2 기준으로는 결함 아님.

## 관찰(비결함 — 참고, 근거 인용 아님)

- OBS-1 password 최소 길이 미검증(@Size max=72만, min 없음): 계약 §2에 최소 길이 규정 없어 v1.2
  기준 정합. 보안 게이트2 이월분(B-016)과 동일 사안 — QA 결함 아님, 중복 등재 안 함.
- OBS-2 로그인 타이밍 사이드채널(B-017): 공격자 관점 → 보안 파트 소관(qa-guide §1 역할 경계). QA 비대상.
