# member·계정 생애주기 시나리오 (QA-S-MBR, qa-guide §4)

도메인: 회원 리소스(§2.5 GET/PATCH/DELETE `/me`) + 계정 생애주기(가입→탈퇴→재가입→재탈퇴).
기준: api-contract **v1.4** §2.5·§5 · domain-spec **v0.5** §6.1 · **erd v0.5 §1**(soft delete 자연키
UK) · D-080(잔액 소멸 동의) · D-081(활성 유일성 패턴).
지시: 072(member 시나리오 설계) + 075 §3(재가입 시나리오) — 탈퇴가 재가입의 트리거라 분리 불가하므로
통합 설계한다(075 "통합 설계해도 무방" 자율분).

실행: 백엔드 member 3유닛(프로필·수정·탈퇴) + V4 선행 단위 완료 후. 고위험 아님 → dev 테스트 그린
대체 가능(D-078).

**QA-S-MBR-06 실행 경로 — 확정(082·083)**: 경로 (a) 백엔드 Claude Code가 명시적 테스트로 구현.
전용 QA Claude Code(경로 b) 미지정(DB 제약 검증 1건이라 독립 세션 이득 없음, 기대치 정본이 본
시나리오라 오염 경로 닫힘). **D-078의 "dev 테스트 그린 대체"를 이 케이스에 한해 배제** —
`./gradlew clean build` 그린으로 갈음 불가. V4 완료 보고에 테스트 실재 경로 + 통과 여부를 개별
증거로 명시해야 하며, 총괄 검수(개별 확인) 후 QA에 재검증 통지 → QA-001 FIXED 판정.

### QA-S-MBR-01. 내 프로필 조회 — 노출 필드 한정
사전 조건: 로그인 상태(유효 access).
절차:
1. GET /api/v1/me.
기대 결과: 200 `{ userPublicId, nickname, isAdmin, createdAt }`(§2.5). **`loginId`·`passwordHash`가
  응답에 없어야 한다**(§2.5 노출 범위 — 열거 리스크 SEC-007). 미인증 401.
유형: 기능

### QA-S-MBR-02. isAdmin — 표시 제어일 뿐 인가 근거 아님
사전 조건: 일반 사용자 1명.
절차:
1. GET /me → isAdmin=false 확인.
2. 클라이언트가 isAdmin=true로 위조해도 관리자 엔드포인트(§4.5) 접근 시 서버가 거부하는지 확인.
기대 결과: 관리자 API 접근은 **서버 권위**로 판정되어 `AUTH_005`(403)(§1.2·§2.5 — 클라 플래그는
  표시 제어일 뿐). 응답 isAdmin 값이 인가에 영향 없음.
유형: 기능
비고: 관리자 API(§4.5)는 미구현 구간 → 해당 도메인 착수 시 실행. 현 단계는 GET /me 필드 확인까지.

### QA-S-MBR-03. 프로필 수정 — nickname 한정·중복
사전 조건: 사용자 A(닉 "가"), 사용자 B(닉 "나") 활성.
절차:
1. A가 PATCH /api/v1/me body `{ nickname:"다" }` → 성공.
2. A가 `{ nickname:"나" }`(B 사용 중) → 실패.
3. body에 다른 필드(예: loginId·password) 포함 → 무시되거나 거부(수정 대상 아님).
기대 결과: 1은 200 + 조회와 동일 스키마 `{ userPublicId, nickname, isAdmin, createdAt }`(§2.5).
  2는 `MEMBER_001`(409, §5). 3은 nickname 외 변경 없음(§2.5 — 비밀번호 변경 범위 밖). 검증 실패 400,
  미인증 401. 변경 빈도 제한 없음(domain-spec §6.1).
유형: 기능

### QA-S-MBR-04. 탈퇴 — 동의 필수·세션 폐기·차단 조건
사전 조건: 사용자 A 활성, refresh 세션 2개 이상 보유. 잔액 케이스 2종(0 / 잔존).
절차:
1. DELETE /api/v1/me, body 없음 또는 `{ balanceForfeitAcknowledged:false }` → 실패.
2. 잔액 0인 계정도 body `{ balanceForfeitAcknowledged:true }` 필수인지 확인.
3. 잔액 잔존 상태로 `{ balanceForfeitAcknowledged:true }` → 성공(잔액은 차단 사유 아님).
4. 탈퇴 후 보유했던 refresh 전부로 재발급 시도.
5. (차단) 진행 중 경매·홀드 입찰·미완료 주문 보유 상태로 탈퇴 시도.
기대 결과:
- 1: 400(미동의·누락, §2.5).
- 2: 잔액 0이어도 필드 필수 — 누락 시 400(§2.5 "잔액이 0이어도 필드는 필수").
- 3: 204. 잔존 잔액 소멸·복구 불가, **잔액 잔존은 차단 사유 아님**(D-080).
- 4: refresh **전부 폐기** → 모두 `AUTH_004`(401)(§2.5·SEC-006 — 탈퇴 후 잔여 세션 접근 불가).
- 5: `MEMBER_002`(409, §5).
유형: 기능
비고: 5의 차단 조건(경매·홀드·주문)은 해당 도메인 미구현 구간 → 072 B 항에 따라 구조만 두고 채우는
  방식 허용. 백엔드 완료 보고의 방식 명시를 확인해 **검사 대상이 빈 상태인지** 판별하고, 빈 상태면
  이 케이스는 도메인 완성 후로 이월(미실행 표기).

### QA-S-MBR-05. 재가입·재탈퇴 반복 — QA-001 FIX 검증
사전 조건: V4 선행 단위(D-081 패턴) 적용 후.
절차:
1. 가입(login_id="hong", nickname="홍") → 탈퇴 → **동일 login_id로 재가입**.
2. 재가입 계정으로 로그인.
3. 탈퇴자의 nickname "홍"을 다른 활성 사용자가 `PATCH /me`로 사용 시도.
4. 가입→탈퇴→재가입→재탈퇴→재가입… **반복 무제한**(3회 이상).
기대 결과:
- 1: 재가입 **성공**(201) — `AUTH_001` 오거부 없음(§2.5 "재가입: login_id·nickname 재사용 허용",
  erd §1 soft delete UK 규약).
- 2: 로그인 200 — `findByLoginId` 다건 예외(`IncorrectResultSizeDataAccessException`) **미발생**.
- 3: 성공 — 탈퇴자 nickname 중복 오판정(`MEMBER_001`) 없음.
- 4: 재탈퇴 반복이 UK 충돌 없이 무제한(D-081 — 탈퇴행 NULL·다중 NULL 허용). D-081이 기각한
  `UNIQUE(자연키, is_deleted)`면 여기서 재탈퇴가 충돌해 드러난다.
유형: 기능 (QA-001 회귀)

### QA-S-MBR-06. 활성 유일성 회귀 — 기각 패턴 (a) 함정 탐지 (최우선)
사전 조건: V4 적용 후. **DB 레벨 검증**(API 경유로는 서비스 선검사에 가려 드러나지 않을 수 있음).
절차:
1. 동일 login_id로 **활성 행 2개** 생성 시도(동시 가입 경쟁 + 직접 INSERT 양쪽).
2. 동일 nickname으로 활성 행 2개 생성 시도.
3. 탈퇴행이 존재하는 상태에서 동일 자연키 활성 행 2개 시도.
기대 결과: 전 케이스 **DB 제약이 차단**(활성 유일성 보존, erd §1 규약 의도 + D-081). 정확히 1건만
  성립. 애플리케이션 선검사가 아니라 **DB 제약이** 막아야 한다(domain-spec §8 "정합성은 DB").
유형: 동시성 · 경계값 (회귀)
중요도 근거(리스크 9 — 최우선): D-081이 기각한 `UNIQUE(자연키, deleted_at)` 패턴은 MySQL이 UNIQUE
  에서 NULL을 서로 다른 값으로 취급해 `deleted_at=NULL` 활성 행이 **동일 자연키로 N개 허용**된다.
  QA-S-MBR-05(재가입·재탈퇴)는 이 잘못된 패턴에서도 **전부 통과**한다 — 함정이 조용히 뚫리는 지점이
  오직 이 시나리오다. 074가 "erd 1절 문자적 해석이 규약 의도를 정면으로 깨는 함정"이라 지목한 바로 그
  케이스. 이 시나리오가 없으면 FIX가 틀려도 초록불이 뜬다. **실행 증거 필수**(dev 테스트 그린 대체 불가).

## 설계 종합

- 근거 커버리지: §2.5 4항목(조회 노출·수정 중복·탈퇴 동의/세션/차단·재가입) + §5(MEMBER_001·002)
  + D-080(잔액 소멸 동의) + erd §1·D-081(활성 유일성·재탈퇴) 전건 매핑.
- QA-001 연계: MBR-05가 FIX 회귀, **MBR-06이 FIX 정확성**(패턴 오구현 탐지). FIXED 전환은 두 시나리오
  통과가 조건이다.
- 미실행 이월: MBR-02 인가 부분(관리자 API 미구현), MBR-04 케이스5 차단 조건(경매·홀드·주문 미구현)
  — 해당 도메인 완성 시 실행. 백엔드 완료 보고의 "구조만 두는 방식" 명시 여부로 판별.
- 실행 경로(D-078): MBR-01·03·04·05는 dev 테스트 그린 대체 가능(고위험 아님). **MBR-06은 실행 증거
  필수 — 경로 (a) 백엔드 Claude Code 명시적 테스트, dev 그린 대체 배제**(082 확정, 083 백엔드 통지).
