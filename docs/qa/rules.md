# QA 파트 지침 (D-040, 지침 유형)

QA 역할의 산출물·형식·우선순위 규약. 협업 규약은 common/rules.md,
메시지·티켓 형식은 common/templates.md를 따른다.

## 1. 역할과 투입 시점

- 책임: 확정 스펙 기반 테스트 계획·시나리오 작성, 도메인 구현 완료 시 시나리오 실행,
  결함 리포트(defects.md). 기능 검증 관점 — 보안(공격자 관점)은 보안 파트 소관.
- 투입: G3(api-contract 확정)에 기동, 구현과 병렬로 계획·시나리오 작성.
  G4-n(도메인 구현 완료)마다 시나리오 실행.
- 기준 문서는 확정 스펙과 계약뿐(D-016). 구현 코드나 타 역할 노트를 기대 결과의
  근거로 삼지 않는다. 계약 결함 발견 시 테스트를 멈추지 말고 결함 기록 + 계약 변경
  요청(절차: `common/rules.md [6]`)으로 격상한다.

## 2. 산출물과 위치 (docs/qa/)

| 파일 | 내용 | 형식 |
|---|---|---|
| test-plan.md | 전체 전략 1~2페이지: 범위, 리스크 표, 레벨(수동/자동), 환경, 완료 기준 | 리스크 기반(3절) |
| scenarios/NNN-도메인.md | 도메인별 시나리오 묶음 | 4절 형식 |
| defects.md | 결함 티켓 누적(전 역할 열람) | QA-NNN, templates 10 |
| decision-log.md | QA 결정(Q-xxx): 전략·케이스 설계 결정 | 티켓 규약(4절) |

- 번호 체계 구분(D-025 조건 회답): Q-xxx는 결정 로그(불변, 상태 라벨), QA-NNN은
  결함 티켓(OPEN → FIXED/WONTFIX 상태 갱신). 결정과 결함은 수명이 달라 시퀀스 분리.

## 3. 리스크 기반 우선순위

기능마다 리스크 점수(영향 × 발생 가능성, 각 1~3)를 test-plan의 표에 기록하고
높은 것부터 시나리오를 만든다. 이 프로젝트의 고정 고위험(총괄 지정 동시성 4건, D-008):

1. 마감 직전 입찰 폭주(소프트 클로즈 연장 포함 — 입찰 성공·연장 누락 틈)
2. buyNow vs 입찰 경합(단일 승자)
3. 취소 vs 첫 입찰 경합
4. SOLD 확정-Order 생성 원자성

이 4건은 리스크 점수와 무관하게 시나리오 필수 + 동시 실행 조건 명시.

## 4. 시나리오 형식

```
### QA-S-<도메인>-NN. <제목>
사전 조건: <상태·데이터>
절차: <번호 단계>
기대 결과: <계약 조항·에러 코드 인용>
유형: 기능 | 동시성 | 경계값
```

- 기대 결과에는 반드시 근거(계약 조항, 에러 코드 {DOMAIN}_{3자리})를 인용한다.
  근거를 인용할 수 없으면 스펙 공백이므로 결함이 아니라 계약 질의로 처리.

## 5. 결함 처리 흐름

1. 발견 → defects.md에 QA-NNN 기록(templates 10: 심각도·재현·기대vs실제·관련).
2. 해당 역할로 정보 공유 또는 결정 요청 발신(계약 영향 시 후자 필수).
3. 수정 완료 보고 수신 → 재실행 → FIXED 갱신. 결함 티켓은 삭제하지 않는다.
- Critical(돈·정합성 훼손: 중복 판매, 잔액 오류)은 발견 즉시 총괄 통지(push).

## 6. 실행 분업 — 두뇌/손 (D-078)

QA 대화(두뇌)와 테스트 실행(손)을 분리한다. 정본은 **D-078**(결정 로그)이고,
Claude Code 운용은 `common/rules.md [9]` Claude Code 절을 따른다.

- QA 대화 = 두뇌: 테스트 전략·시나리오 설계·계약 정합 검증·결함 분류·게이트 판정 권고·파일 버스
  조율. 이 대화가 담당한다.
- 테스트 실행(코드 작성·`./gradlew test`·Testcontainers 동적 검증) = 손 = Claude Code.
- 스켈레톤/단순 도메인(auth·게이트웨이 등): 백엔드 dev 테스트 그린으로 실행 대체 — QA는 정적 정합
  검증 + 재실행 가능 시나리오 인계로 충분(001 방식 유지).
- 동시성 고위험 도메인(bid 등, §3 고정 고위험 4건): 실행 증거 필수 → QA 설계 시나리오를 (a) 백엔드
  Claude Code가 테스트로 구현(기본, 테스트=백엔드 repo) 또는 (b) 전용 QA Claude Code로 실행.
  경로·시점은 총괄 지정(D-074). 고위험 시나리오는 '실행 위임용' 작업 프롬프트 형태(templates §18)로도 설계한다.
