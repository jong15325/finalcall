# 아이템 레퍼런스 조사: 서바이벌 프로젝트 (주제 5 재개용)

성격: 총괄 조사 노트(유형 4) — 기획 주제 5 논의의 입력 자료. 결정 아님.
출처: 나무위키 "서바이벌 프로젝트/아이템" (2026-05 수정판)
사용자 방향: 메이플식 복잡 구조 대신 서프형 단순 구조 채택 검토 중.

## 1. 서프 아이템 구조 요약

카드 대분류: 장비카드 / 마법 / 아바타카드(7부위) / 펫카드 / 화이트카드(정령, 소모재) /
실버카드(프리미엄).

장비카드의 정체성은 4개 축으로 거의 결정된다:
- 종류(9): 검, 도끼, 지팡이, 활, 방패, 갑옷, 펜던트, 부츠, 마법
- 속성(4): 불, 물, 바람, 흙
- 등급(2): 블랙, 골드 (골드가 상위 — 발동률·강화 성공률 우위)
- 레벨(1~9): 기본 옵션 수치가 레벨에 비례해 정적으로 결정

인스턴스 변이(같은 카드끼리 달라지는 부분)는 딱 2슬롯:
- 특수스킬 1: 능력치 옵션 (옵션 종류 + 레벨 비례 수치, 예: 공격시간감소 "공시g")
- 특수스킬 2: 부가효과 (효과 종류 + 발동확률/지속시간, 예: 트리플샷, 인비저블)

## 2. FinalCall 모델링 함의

1. item_template 규모가 유한하고 작다: 장비 9종 x 속성 4 x 등급 2 = 72 조합 + 마법·펫·
   아바타 합쳐도 수백 개 미만. → 마스터 데이터를 시드(Flyway 마이그레이션 또는 운영 등록)로
   채우는 방식이 성립. "판매자 제안+승인" 플로우 불필요 (기획 오픈 이슈 1 회답).
2. 인스턴스 속성이 정형 컬럼으로 끝난다: 레벨(1~9) + 특수스킬1(종류, 수치) +
   특수스킬2(종류, 확률/지속) — 3~5개 고정 컬럼. 메이플식 JSON 옵션 + 인덱스 승격
   문제가 소멸. 검색·필터(종류/속성/등급/레벨/특수스킬)도 전부 정형 인덱스로 처리 가능.
3. 카테고리 계층이 얕다: 대분류(장비/마법/펫/아바타/기타) → 종류. 2단이면 충분.
4. 단, 완전 고정 스펙 거래는 아니다: 경매 가치가 특수스킬 조합(예: 물검+공시g 같은
   만렙 옵션)에 크게 좌우된다 → 특수스킬 필터가 검색의 핵심 요구사항. 시세 집계도
   (템플릿, 레벨, 스킬 조합) 단위가 자연스럽다.
5. 강화(레벨업)·합성(화이트카드 소모) 시스템 존재 — 거래 플랫폼 범위에서는 "레벨은
   인스턴스의 현재 상태"로만 취급하면 되고 강화 행위 자체는 범위 밖.

## 3. 메이플식 대비 판단

- 장점: 중앙 마스터(item_template) 성립이 자명, 스키마 정형화, 검색·시세·정합성 문제
  전부 단순화. 기획 로그의 하이브리드 제안(template + JSON 옵션 + 인덱스 승격)에서
  JSON 계층을 제거해도 된다.
- 유지되는 학습 가치: 인스턴스 변이(특수스킬 2슬롯)가 있어 "동일 템플릿, 다른 가치"
  문제(검색 필터, 시세 편차)는 남는다 — 완전 단순화로 잃는 것은 적다.
- 리스크: 실존 종료 게임이라 IP 표기 주의(임의 명칭·가상 데이터로 시드 구성 권장).
