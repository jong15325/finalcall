# FinalCall 표준 템플릿 패키지 (D-025, 지침 유형·총괄 소유)

목적: 메시지·문서가 형식 고민 없이 일정한 모양을 갖게 하여 내용 혼입과 장황화를 방지.
원칙: 템플릿은 최소 골격만 — 섹션을 채우지 못하면 그 섹션을 지운다(빈 섹션 금지).

---

## 1. outbox 메시지 공통 골격 (D-020, D-023)

모든 outbox 파일의 처음 3줄은 고정이다.

```
상태: SENT | ANSWERED → <결정 ID 또는 회신 파일 경로>
회신대상: <원본 파일 경로>          # 회신일 때만. 신규 발신이면 이 줄 삭제
# [<발신> → <수신>] <유형>: <제목>
```

유형은 4종만: 결정 요청 / 작업 지시 / 완료 보고 / 정보 공유.
파일명: `outbox/NNN-주제.md` (역할별 NNN 독립 증가).

```
# [<발신> → <수신>] 결정 요청: <제목>

배경: <상대가 맥락을 모른다고 가정, 1~3줄>

- 추천: <안> — <이유 1~2줄>

(안건 2, 3... 독립 안건은 묶되 번호로 부분 회신 가능하게)

회신: 필요 — 안건별 채택/기각/조건
신규 발번 ID: <없으면 "없음">
```

## 3. 작업 지시

```
# [<발신> → <수신>] 작업 지시: <제목>

목표: <1~2줄>
완료 기준: <검증 가능한 조건, 항목당 1줄>
근거(인용): <문서 §절> — "<1줄 직접 인용>"   (D-082)
의존: <확정돼야 착수 가능한 문서·산출물. 없으면 "없음"> (D-028)
하지 말 것: <범위 제한>
관련 문서: <경로만>

회신: 필요 — 완료 보고 / 불요
```

`근거(인용)` 규칙 (D-082 / D-086):
- 산출물 착수 지시는 **지시 범위의 근거를 확정 스펙에서 직접 인용**한다. 경로만 적지 않는다.
- **인용할 문장이 없으면 지시하지 않는다** — 스펙 공백이므로 계약 질의·결정 요청으로 격상(6절).
- **대칭 조항 (D-086) — 근거는 있으면 인용, 없으면 방법.** 부재("없음")·수량("N건")을 근거로 삼을 때는
  **탐색 방법을 1구 명시**한다(예: "import 기준 grep으로 5건", "호스트 Grep 기준 부재"). 방법을 명시할
  수 없으면 근거로 쓸 수 없다. 긍정 결과는 자기 증명적이지만 부재·수량은 전적으로 도구 커버리지에
  의존하며, 사각지대는 거짓 음성으로만 나타나기 때문이다.
- 규약·프로세스 지시(기동·핸드오버·전파 등)는 확정 스펙 인용 대상이 아니며 결정 로그·사례 경로를 적는다.
- 진행 중 작업과 충돌하는 지시는 완주가 기본값이고, 중단·선점은 총괄이 근거를 제시해야 한다(D-083).
  파생 선행 범위는 발견자 판정이 기본값이며, 총괄 시퀀싱 경계는 파트 간까지다(D-084).

## 4. 완료 보고

```
# [<발신> → <수신>] 완료 보고: <제목>

결과: <1~2줄>
산출물: <경로 목록>
완료 기준 대비: <충족/미충족 + 미충족 사유>
뿌리 점검: <공백·결함 처리 시 필수 — 같은 원인이 다른 층에도 공백을 만들었는가. 해당 없으면 생략> (D-085)
다음 단계 제안: <있으면 1줄>

회신: 불요 (이견 시에만)
신규 발번 ID: <없으면 "없음">
```

`뿌리 점검` 규칙 (D-085): 스펙 공백·결함을 처리·회신할 때 **"같은 원인이 다른 층(스펙/계약/erd/구현/테스트)에도
공백을 만들었는가"** 를 1줄로 답한다. 계보 표는 두지 않는다 — 계보는 `관련`(depends-on/relates-to)·`회신대상`
필드가 유지하고, 레버리지는 표가 아니라 이 질문에 있다.

## 6. 결정 로그 항목 (가이드 4절 준수)

```
## <ID>. <제목 — 결정 내용이 드러나게>

상태: PROPOSED | ACCEPTED | ON-HOLD | SUPERSEDED(→ 대체 ID) · 소유: <역할> · 관련: <참조 키워드> · <날짜>

결정
- <무엇을 하기로 했는지. 원자적 1건>

이유
- <왜. 실물 근거가 있으면 명시>

기각된 대안
- <대안>: <기각 사유>

집행
- <이 결정을 실행하는 문서 경로 + 반영 여부. 없으면 "없음(결정 자체가 정본)". 공란 금지> (D-089)
```

레퍼런스 줄은 외부 근거가 있을 때만. 에스컬레이션 후엔 상태 줄에 escalated-as만 추가, 본문 불변.

`집행` 필드 규칙 (D-089): **"이 결정을 실행하는 문서가 무엇이고 거기 반영됐는가"** 를 적는다. 발번 시점에
반영이 안 끝났으면 반영 지시 경로(outbox 번호)를 적는다. **규약은 옳은데 실행 문서에 번역되지 않아 현장이
어기거나 즉석 판단하는 비동기화**가 실제로 두 번 발생했다(erd [1] 규약 → [4.1] 표 미반영 → V3 위반 /
D-069 → templates [18] 미반영 → Claude Code 반환 경로 부재). 필드는 비워둘 수 없으므로 적으려면 확인하게 된다.
소급 기재는 하지 않는다. **한계: 실행 문서를 지목하게 할 뿐 반영 품질을 보증하지 않는다.**

```
# [총괄 → 전 역할] 정보 공유: G<N> 통과 — <게이트명>

확정된 것: <문서·결정, 1~3줄>

역할별 다음 작업:
- <역할>: <할 일 + 의존>
전 역할 공통(확정 스펙 상향 시 필수, D-092):
  ① 델타가 자기 문서에 영향 있는지 검토 → ② 있으면 반영 → ③ **근거 줄을 새 버전으로 갱신**.
  영향 없으면 근거 줄만 갱신 + 완료 보고에 "델타 영향 없음" 1줄. **검토 없이 근거 줄만 올리지 마라 —
  "v1.4 근거"가 거짓말이 된다.**

회신: 불요
```

`전 역할 공통` 규칙 (D-092): 확정 스펙(domain-spec·erd·api-contract)이 상향되면 **그것을 참조하는 모든 문서의
근거 줄이 즉시 낡는데 낡았다는 신호가 어디에도 가지 않는다.** 각 파트의 2단 마무리 grep은 **자기 문서를
상향할 때만** 돌고, 남이 상향하면 안 돈다. D-089 `집행` 필드도 전사본의 낡음은 감지하지 않는다.
**전파가 유일한 신호 지점**이라 여기에 건다. 실측 8건+(skeleton-plan·screen-spec·erd·api-contract·
design-system·ux-flows·ux/decision-log — 그리고 총괄 지시문 자신도 stale했다).

```
---
**브리핑**

- 수신: <경로 — 요지 1줄> / 발신: <경로 — 요지 1줄>   # 없으면 "없음"
- 발번·상태: <신규 ID, 게이트·추적 표 변경>            # 없으면 "없음"
- 할 일: <사용자가 할 일, 번호 목록 1~3개>             # 없으면 "없음"
- 초안 요지: <초안·제안 생성 응답만 — 핵심 결정·선택지·추천 2~5줄>  # 초안 없으면 생략 (D-063)
```

- 4개 항목·순서 고정. 항목 내용이 없어도 항목 줄은 유지("없음" 표기) — 스캔 위치 일관성.
- "초안 요지"(D-063)는 조건부 5번째 항목: 초안·제안을 생성한 응답에만 추가하고(핵심 결정·
  선택지·추천 2~5줄), 단순 응답에는 생략한다(D-049 간결성 유지). 목적은 사용자가 파일을
  열지 않고 초안 실질을 보고 채택/기각 판단.
- 파일에 쓴 내용도 요지는 여기 노출 필수. 상세 설명은 브리핑 위 본문에서.

## 18. Claude Code 작업 프롬프트 (백엔드/프론트 → Claude Code, D-069)

```
# [<역할> → Claude Code] 작업 지시: <도메인> - <작업>

대상: <도메인·기능 — 예: auth 회원가입>
참조: api-contract [X], erd <테이블>, domain-spec [Y], 관련 <D/B ID>   (절 참조는 대괄호 — D-087)
범위: <이번 작업 포함> / 하지 말 것: <제외·후속>
구현 지침: CLAUDE.md [5] 컨벤션(Entity/Repository/Service/Controller/DTO/ErrorCode) 준수.
  <도메인 특이사항 — 예: 입찰 @DistributedLock, 종료 전이 CAS 단일 승자>
DoD: 계약 준수 + CLAUDE.md 컨벤션 + 테스트(단위·슬라이스) 통과 + 빌드 성공.

커밋 제안: <type>(<scope>): <제목>  (코드 커밋 형식 CLAUDE.md [6], 실행은 사용자)
```

- 부모 대화가 자기 outbox에 저장(`NNN-<도메인>-<작업>.md`). Claude Code는 경로 지정으로 읽는다
  (수신함 스캔 아님). 산출물 = 코드 + 커밋 메시지 제안.

### 완료 보고 반환 경로 (D-088 — 파트 무관 공통)
- Claude Code는 완료 보고를 **`docs/<파트>/notes/cc-reports/<프롬프트번호>-<도메인>-<작업>.md`** 에
  **파일로** 남긴다. 번호는 작업 프롬프트와 일치. 채팅 요약은 선택이고 **정본은 파일**이다.
- **사용자 중계 불요.** 부모 대화가 "수신 확인" 시 인계함을 스캔해 흡수하고, 자기 outbox 보고로 버스에
  재진입시킨다(부모가 버스에서 Claude Code를 대표하는 구조는 불변).
- **금지 경로**: `<파트>/outbox/`(파트 발신 이력 전용 — Claude Code가 쓰면 발신 주체 오염),
  `decision-log.md`·`inbox-log.md`(파트 소유), 타 역할 폴더 전부.
- `cc-reports/`는 Claude Code의 outbox가 **아니라** 부모 파트에 넘기는 **인계함**이다. Claude Code는
  여전히 파일 버스 노드가 아니다(D-069 유지).
- 이 조항이 없어 Claude Code가 매번 사용자에게 저장 위치를 물었고 사용자가 손으로 복붙 중계했다
  (D-069가 "사용자가 전달"로 사용자 중계를 전제했기 때문). D-088이 그 조항을 supersede한다.
