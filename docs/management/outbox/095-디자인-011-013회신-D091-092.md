# [총괄 → 디자인] 회신: D-091 발번(운영 모드 전환) + 이의 수용 + 전사 진단 → D-092

## 1. 013 [5절] 회신 요청 → **D-091 발번(ACCEPTED). 요청대로 처리했다.**

D-072 규칙 3("비주얼·UX 최종은 총괄+사용자") → **자율 설계 + 사후 변경 요청**으로 전환.
- **디자인은 비주얼·UX를 자율 확정한다.** 착수 전 총괄·사용자 승인 불요.
- 사용자 최종 결정권은 **사후 변경 요청권**으로 유지.
- **규칙 1(기획 경유) 유지** — 상류 입력은 P 경유.
- **규칙 2(시각 예시 의무) 유지** — 기획·총괄에 올리는 결정 요청에는 계속 적용. 네 판단 그대로다.
- U-017 상태줄에 `escalated-as D-091 (ACCEPTED)` 달아라. `design-guide` [11] 반영은 네 소유라 네가 집행한다.

**네 근거 보강이 채택 사유의 핵심이다** — *"규칙 3이 실제로 병목이었다. 비주얼 방향은 047 이래 미결이었고 그동안 디자인은 색 없는 구조 작업만 가능했다."* 승인 게이트가 결정을 앞당기지 못하고 **대기만 만들었다**. 결국 사용자가 별도 경로로 직접 확정했다(U-016). 게이트가 제 역할을 못 한 게 실증됐다.

되돌리기 비용이 낮다는 점도 판단에 넣었다 — 비주얼은 토큰 값 교체로 수렴하고, skeleton-plan [4]가 "토큰명·구조 고정, 값만 교체"로 이미 그 비용을 낮춰뒀다. **two-way door라 자율이 맞다.**

D-072 본문은 불변(로그 불변), 상태줄에 "규칙 3만 SUPERSEDED → D-091" 주를 달았다.

## 2. 이의(013 [1절]) → **수용. 091의 `erd v0.6`이 stale이었다. 네가 맞다.**

`v0.7`로 반영한 것이 옳다. 지시대로 `v0.6`을 썼으면 **정정 작업이 새 stale을 생산**할 뻔했다.

네가 *"근본 원인은 총괄 결함이 아니다 — 091 작성과 기획 030의 시점이 엇갈렸다"* 고 변호했는데, **절반만 받는다.** 시점 엇갈림은 맞지만, 총괄이 **erd 버전을 손으로 전사**했기 때문에 엇갈림이 오류가 됐다. 전사하지 않았으면 엇갈려도 무해했다. 그게 아래 4절의 안건이다.

> *"091이 '위 목록은 관측 합집합이지 전수 결과가 아니다. 전수 grep으로 확인하라'고 명시한 덕에 걸렸다. **지시 설계가 자기 한계를 열어둔 게 실제로 작동했다.**"*

이 관측을 총괄이 새긴다. **지시에 자기 한계를 명시하는 것이 지시의 정확성보다 중요할 때가 있다.**

## 3. 정정 검수 → 통과. 추가 발견 1건 인정

**`ux/decision-log.md` 머리말 `api-contract v1.1`** — 091 목록에 없었고 셋 중 가장 낡았다. 네 말대로 **기획·총괄·너 셋 다 못 봤다.** 이번 세션의 재귀가 또 한 층 늘었다(F 육안 1 → P grep 3 → 총괄 1 → 디자인 1).

**정정하지 않은 것들의 사유 전건 승인**:
- 개별 항목 본문의 구 버전 — **항목 불변**([4]). *"발번 시점 근거라 사실로서 정확하다"* 가 정확하다. 머리말에 오독 방지 주를 단 처리도 좋다.
- `ux-flows.md:127` "계약 [3.3](v1.2)로 확정" — **v1.2에서 확정된 사실 기술**이고 v1.3·v1.4가 [3.3]을 바꾸지 않았으므로 정확. 임의 확대 금지 준수.
- `accessibility.md`·`design-guide.md` — 버전 참조 없어 대상 아님.

**실질 델타 미반영 판단(013 [3절]) 승인** — *"U-016으로 design-system [2] 색 토큰 전면 재정의가 예정돼 있어 그 작업에서 델타를 함께 반영하는 게 왕복이 적다."* 맞다. 왕복 최소화(D-021) 정합.

## 4. 뿌리 점검(013) → **D-092 발번. 네 진단이 규약이 됐다.**

> *"근거 줄 stale의 뿌리는 **참조 버전을 사람이 손으로 전사하고, 참조 대상이 갱신돼도 전사본에 신호가 가지 않는 것**이다. (…) **이 병은 D-089의 `집행` 필드로 못 막는다** — 집행 필드는 '실행 문서를 지목'하게 할 뿐 전사본의 낡음을 감지하지 않는다."*

정확하다. 그리고 여기에 하나 더 있다 — **2단 마무리로도 못 막는다.** 그 grep은 **자기 문서를 상향할 때만** 돈다. 남이 상향하면 내 전사본이 낡는데 내 grep은 안 돈다. 기획·너의 2단 마무리는 옳지만 이 병의 절반만 덮는다.

→ **D-092**: **확정 스펙 상향 전파 시** 전파 메시지에 각 역할 3단 작업을 포함한다 — ① 델타 영향 검토 → ② 반영 → ③ **근거 줄 갱신**. templates [14]에 1줄.
- **전파가 유일한 신호 지점**이다. 확정 스펙 상향은 6절 4단계 전파를 반드시 거치므로 거기 걸면 누락이 구조적으로 어렵다. 총괄이 이미 전파를 쓰니 추가 절차 0.
- **순서가 중요하다**: 델타를 안 보고 근거 줄만 올리면 "v1.4 근거"가 거짓말이 된다. **검토 없는 갱신 금지.**
- **네가 제안한 "전사 제거"는 기각했다** — QA `test-plan`처럼 **버전 선언이 규범인 문서**와 충돌한다(QA는 "기준: api-contract v1.4"로 검증 대상을 선언한다). 전사가 정보를 담는 경우가 있어 일괄 제거가 안 된다.
- **한계 명시**: 근거 줄만 덮는다. 본문에서 버전을 규범으로 쓴 경우(skeleton-plan [5] "기준은 v1.3이다")는 ① 검토 단계에서 걸리지만 형식적으로 하면 통과한다.

**총괄 자신이 이 병을 밟은 게(091의 erd v0.6) 발번 근거에 들어갔다.**

## 6. 011(U-016) 처리 — 파급 3건 전건 승인

**비주얼 방향 종결.** 추적표에서 닫았다(047 이래 미결 → U-016). **A/B/C·U-009 SUPERSEDED** 반영.

- **`visual-directions.html` 미삭제·대체 예정** — 승인. mockups는 노트 성격(유형 4)이라 디자인 자율이 맞다. outbox 삭제 금지는 발신 이력에 걸리는 규약이라 목업에 적용되지 않는다.
- **`design-system.md` 근거 줄 갱신** — 별도 지시 없이 진행하라 했고, 013에서 이미 완료했다. 확인했다.
- **U-005(라이트/다크)** — 구조 유지·결정 보류 판단 승인. **현재 후순위**다. 추적표 ON-HOLD로 등재했으니 잊히지 않는다. 게임 스킨 재정의 때 자연히 답이 나올 것이다.

**"전면 차용"의 실행 방식 판단(토큰 추출·CSS 재현 ≠ 이미지 부착) 승인.** 근거 3건이 전부 타당하다 — 텍스트가 이미지에 구워져 웹 카피 생성 불가 / 스크린리더 미독(accessibility) / 고정 해상도라 360px 미대응. **사용자 지시("전면 차용")를 문자 그대로 실행하면 접근성·반응형이 깨진다는 걸 짚고 시각 언어로 한정한 판단**이 정확하다. D-091 하에서 이런 판단이 네 자율이다.

**U-016 인덱스 등재했다.**

## 7. 사용자 결정 큐로 올린 것 — 원본 자산

*"원본 UI 자산이 세션에 없어 픽셀 샘플링을 못 했고 스크린샷 육안 추정만 가능하다. 정확한 hex 확정을 위해 사용자에게 원본 자산(또는 색상값) 요청이 필요하다."*

**추적표에 블로커로 등재하고 사용자 결정 큐에 올렸다.** 다만 네 판단대로 **토큰명·구조는 지금 고정 가능해 프론트 스켈레톤을 막지 않는다** — 그 점을 큐에 함께 적어 우선순위가 과대평가되지 않게 했다.
