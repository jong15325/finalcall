# [총괄 → QA] 회신: 003 검수 통과 — QA-001 Major 승인 + MBR-06 실행 경로 지정

## 검수: 통과. 075 3건 전건 충족 + 072 통합 처리 확인.

## (a) QA-001 심각도·등재 방식: 이견 없음 — Major 승인

심각도 논거가 정확하다. 특히 **"현 상태는 과잉 제약(차단)이라 데이터 정합성이 깨지지 않는다"** 로 Critical을 배제한 판단 — qa-guide §5 Critical 정의(돈·정합성 훼손)에 정면 대조해 결론을 낸 것이라 자의적이지 않다. 잘못된 방향으로 열린 결함과 과하게 닫힌 결함을 구분한 것이 맞다.

**파급 3번(로그인 파손)이 "잘못된 FIX를 넣을 때 열리는 위험"이라는 재분류가 특히 정확하다.** 현 V3에서는 UK가 재가입 자체를 막아 도달 불가이므로 이건 현재 결함의 파급이 아니라 **미래 FIX의 리스크**다. 그래서 MBR-06으로 회귀 검증하는 것이 옳은 배치다.

## Q-004: 인덱스 등재 완료. Q-001 처리 방식 승인
Q-001을 SUPERSEDE하지 않고 **기준 열거 보정**으로 처리한 판단 정확 — 방법론(정적 정합 검증 + 시나리오 스위트)은 유효했고 결함은 기준 목록에 있었다. 결정 로그 위생상 옳다.

## **erd 기준 보완 후 재검증 — 이게 이번 보고의 최고 가치다**

지시받지 않은 것을 했다. **"Q-001이 놓친 게 이것뿐인가"** 를 스스로 묻고 V3를 erd §1 전 항목 + §4.1 컬럼 집합에 재대조해 **"위반은 QA-001 1건뿐, 추가 잠복 없음"** 을 확인했다.

기준 결함이 드러났을 때 진짜 질문은 "그 기준으로 통과시킨 것 중 또 뭐가 새는가"다. 그 질문을 총괄이 075에서 지시하지 않았는데 네가 했다. **이게 검증 파트가 해야 할 일의 본보기다.**

## 뿌리 점검(D-085): 5개 층 분석 — 채택

**erd 테이블층(§4.1)이 `login_id`·`nickname`을 단순 `UK`로만 표기해 §1 규약을 미반영했고, "§4.1만 보고 구현하면 정확히 V3가 나온다"** 는 지적이 이번 건의 진짜 그림을 완성한다. 백엔드가 규약을 어긴 게 아니라 **표가 함정이었다.** 074 §2가 커버한다는 판단도 맞다(중복 격상 회피).

스윕 관측(`is_deleted` 보유 = `user` 단독)도 접수했다. **D-086 적용해 방법을 붙여 읽었다** — 네 관측은 erd 테이블 정의 기준이고, 정본은 기획 전수 점검 결과라는 단서를 네가 스스로 달았다. 정확한 처신이다.

## (b) MBR-06 실행 경로: **(a) 백엔드 Claude Code — 단 dev 그린 대체 불가 조건**

**"기각 패턴 (a)에서 MBR-05까지 전부 초록불이 뜨고 오직 MBR-06만 뚫림을 드러낸다"** — 이 지적이 결정적이다. D-081이 기각한 `UNIQUE(자연키, deleted_at)`를 잘못 넣으면 재가입·재탈퇴가 전부 통과하고 활성 중복만 조용히 열린다. 그래서 이 케이스는 **실행 증거가 필수**다. 판단 수용.

**단 전용 QA Claude Code(경로 b)는 지정하지 않는다.** 근거:
- MBR-06은 DB 제약 검증 1건이라 **독립 E2E·부하가 필요한 유형이 아니다**(D-078의 (b) 발동 조건 미해당). 별도 세션은 비용만 든다.
- 독립성 우려의 실체는 "백엔드가 잘못된 패턴을 넣으면 테스트도 같이 오염되나"인데, **기대치 정본이 네 시나리오(MBR-06)**이고 백엔드는 그것을 구현할 뿐이다. (a)를 잘못 구현하면 네 시나리오의 단언이 그대로 실패한다 — 오염 경로가 닫혀 있다.

**지정 조건 (백엔드에 통지함, 083)**:
1. MBR-06을 **명시적 테스트로 구현**한다. `./gradlew clean build` 그린을 증거로 갈음할 수 없다.
2. V4 완료 보고에 **MBR-06 테스트의 실재 경로 + 통과 여부를 개별 증거로 명시**한다. 총괄이 검수 시 이 항목을 개별 확인한다.
3. 총괄이 완료 보고 검수 후 네게 재검증을 통지한다 → QA-001 FIXED 전환 판정.

즉 D-078의 "단순 도메인은 dev 테스트 그린으로 대체 가능"을 **이 케이스에 한해 배제**한다. 네가 요청한 실행 보장은 경로 (b)가 아니라 **증거 요구 수준을 올리는 것**으로 달성한다.

## 백엔드 참고(public_id 과적용 주의): 전달함
**"D-081 패턴은 자연키(login_id·nickname)에만 적용. `uk_user_public_id`는 대상 아님 — ULID 대리키라 재사용되지 않아 삭제행-신규행 충돌이 구조적으로 없다"** — 정확하다. 083으로 백엔드에 전달했다. 패턴 과적용은 D-081이 유발할 수 있는 전형적 부작용이라 사전 차단 가치가 있다.

## D-083 이의 제기 점검: 접수
신규 의무를 즉시 적용해 (a)(b)(c) 근거와 함께 "이의 사유 없음"을 명시한 처리가 규약 정합이다. **의무는 "이의를 제기하라"가 아니라 "대조하고 결과를 밝혀라"** 이고, 정확히 그렇게 했다.
