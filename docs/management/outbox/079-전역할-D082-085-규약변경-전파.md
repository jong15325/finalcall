# [총괄 → 전 역할] 정보 공유(규약 변경): D-082~085 — 파생 작업 순서 체계 (D-054 전파)

요지 3줄:
1. 파생 작업으로 순서가 붕괴하는 문제를 컨설턴트에 회부(077)해 D-082~085를 발번했다. 원인은 **총괄이 문서 수준 추론으로 현장 실측을 덮어쓴 것**이고, 처방은 절차 추가가 아니라 **총괄 재량을 근거 제시 의무로 치환**하는 것이다.
2. **파트가 새로 익힐 것은 1건뿐이다 — "이의 제기는 권한이 아니라 의무"(D-083).** 나머지 3건은 총괄 측 의무다.
3. 신규 문서·표·역할·절차 0. 기존 템플릿·가이드 보완이다.

정본: management/decision-log.md D-082~085 · templates.md 3·4 · collaboration-guide.md §7

## 파트가 알아야 할 것 (1건)

**진행 중 작업이 총괄 지시와 충돌하면 이의를 제기할 의무가 있다(D-083). 침묵은 규약 위반이다.**
- 종전엔 권한이었고, 그래서 쓰이지 않았다 — 실제 사례에서 백엔드는 이의 권한이 있었으나 침묵했고 사용자가 잡았다. 의무로 바꾼다.
- 총괄 지시가 네 진행 중 작업과 부딪히면 **따르기 전에 말하라.** 현장 실측이 총괄의 문서 추론보다 정확한 경우가 구조적으로 존재한다.

## 총괄이 새로 지는 의무 (3건 — 참고)

- **D-082 근거 인용**: 총괄이 산출물 착수를 지시할 때 범위의 근거를 확정 스펙에서 **직접 인용**한다. 인용할 문장이 없으면 지시하지 않고 격상한다. → 근거 인용 없는 착수 지시를 받으면 이의를 제기해도 된다.
- **D-083 완주 기본값**: 파생으로 순서를 재편해도 **이미 착수된 작업은 완주가 기본값**이다. 중단·선점은 총괄이 근거를 제시해야 성립한다.
- **D-084 판정 권한·시퀀싱 경계**: 파생의 선행 범위는 **발견자 판정이 기본값**(총괄 확대 시 근거 의무). **총괄 시퀀싱은 파트 간까지이고, 파트 내 유닛 순서는 파트 자율**이다. → 총괄이 유닛 단위 순서를 지정하면 이의 대상이다.
- **D-085 뿌리 점검**: 공백·결함 처리 회신에 "같은 원인이 다른 층에도 공백을 만들었나" 1줄. 계보 표는 두지 않는다.

## 템플릿 변경 (전 역할 사용)
- **templates 3(작업 지시)**: `관련 문서` 옆에 **`근거(인용): <문서 §절> — "<1줄 직접 인용>"`** 신설.
- **templates 4(완료 보고)**: **`뿌리 점검`** 필드 신설 — 공백·결함 처리 시 필수, 해당 없으면 생략.

## 배경 사례 (요약)
- 총괄이 계약 확인 없이 member 착수를 지시(066) → 지정한 조항이 실재하지 않음(022) → 파생 4단.
- 백엔드가 V4 선행 범위를 "탈퇴·수정 두 유닛"으로 정확히 좁혔으나 총괄이 전체 선행으로 확대(073) → 진행 중 023 무효화 위기 → 사용자가 발견·정정(076).
- 022(계약층)·028(구현층)이 같은 뿌리인데 뿌리를 묻지 않아 재발.
