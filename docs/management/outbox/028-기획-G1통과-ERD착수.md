# [총괄 → 기획/설계] 작업 지시: G1 통과 — ERD(G2) 착수 + spec 관찰 후속

G1 판정: 통과. domain-spec DRAFT v0.1 총괄 검수 + 사용자 승인 완료(인덱스 게이트 표 기록
2026-07-13). 크리티컬 패스 다음 단계 = ERD(G2).

목표: domain-spec 기준 erd.md 작성(D-036 골격).
완료 기준:
1. D-036 골격 준수: 네이밍 규칙·Mermaid ERD·테이블 표·인덱스 표(이유 열)·Flyway 매핑.
2. domain-spec 정합: 2 애그리거트(Auction/FixedSale), Bid, Order, User, 2단 화폐(캐시/게임머니
   홀드), item_template/item_instance.
3. 아이템 테이블은 D-048 안건화 — 컬럼·특수스킬 슬롯·taxonomy 멤버·가상 시드는 총괄 안건
   (사용자 참여), P 발번 금지.
4. 검색·인덱스 필수 케이스: 특수스킬 조합 필터 + 시세 집계 단위 (템플릿,레벨,스킬조합)
   반영(D-044 조건, spec §7.7).
5. 기술 규칙(테이블·컬럼 네이밍, URL, 페이징)은 백엔드 조기 협의 확정분 기준 —
   그 전 임의 확정 금지(D-035). 백엔드 기동 통보 별도 발신(outbox/029).

관찰 후속(G1 검수, 비차단):
- spec 문구 정정 2건(자기 산출물 직접 정정): 상태 줄 "DRAFT v0"→"v0.1"(3행),
  고정가 판매자 취소 조건 1줄 명시(§5).
- 인스턴스 중복 출품 잠금(동일 item_instance 동시 다중 출품 방지)을 ERD/구현 규칙으로
  반영 검토(§7.8 연계).
- 플랫폼 수수료·정산 정책은 추적표 ON-HOLD 등재됨(총괄·사용자) — ERD 정산 테이블 설계 시
  이 미확정을 전제로.
