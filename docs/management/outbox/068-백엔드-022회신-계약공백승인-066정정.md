# [총괄 → 백엔드] 회신: 회원 리소스 계약 공백 — 보완 승인 + 066 지시 정정

## 결론: 승인 (6절 2단계 통과)

022 지적이 정확하다. 총괄이 계약 전수 검증했다:
- `api-contract.md:96` §2 말미 "user 리소스 엔드포인트는 3절(후속)에서 기술" → §3은 경매·고정가·입찰. **전방 참조 미이행 확인**.
- 잔액은 §4.4 `/me/balance`로 충족. **프로필 조회·수정·탈퇴는 계약 부재**, `MEMBER_` 에러코드 0건.
- 추가 발견(022 범위 밖): **domain-spec에도 프로필·탈퇴·닉네임 언급 0건**(§12 범위 밖에도 미등재). 계약 누락이 아니라 스펙 단계부터의 공백. 반면 erd `user`는 nickname UK·is_deleted·deleted_at 모델링 + V3 구현 완료 → **erd·구현은 탈퇴를 전제하는데 스펙·계약은 침묵**하는 어긋남.

## 066 지시 정정 (총괄 결함)
066의 착수 범위 "계약 §2 이후 회원 관련 조항"은 **실재하지 않는 근거였다**. 계약 확인 없이 순서를 지정한 총괄 결함이다. 임의 설계하지 않고 6절로 올린 판단이 규약 정합이다(D-028 선착순 기준 금지). 해당 문구는 무효, 아래 확정 범위로 대체한다.

## 확정 범위 (총괄+사용자 결정, 범위 안건)
회원 리소스 = **조회 + 수정 + 탈퇴** 전체 채택.
- `GET /api/v1/me` 프로필 조회
- `PATCH /api/v1/me` 프로필 수정 — **nickname 한정**
- `DELETE /api/v1/me` 탈퇴(soft delete)
- `MEMBER_NNN` 에러코드 신설

총괄 지정: **비밀번호 변경은 이번 범위 제외**. 현재 비밀번호 검증·전 세션 폐기·rate limit 등 auth·보안 설계가 붙어 성격이 다르고, 보안게이트2 이월분(B-016)과 묶는 게 맞다. 별도 안건으로 추적표 등재했다.

명세 작성은 기획(P)에 지시했다(069). 확정·전파 후 착수하라.
