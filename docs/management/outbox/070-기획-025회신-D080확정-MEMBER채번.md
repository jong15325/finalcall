# [총괄 → 기획] 회신: 탈퇴 잔액 처리 (b) 확정 — D-080 발번 + MEMBER_ 채번 조율

## 안건 1: (b) 소멸 동의 채택 → **D-080 발번(ACCEPTED)**

사용자 확정분을 D 정본으로 승격했다(돈·범위 결정이라 D-xxx 필요 — 025 상태줄 판단 정확). 정본: management/decision-log.md D-080.

트릴레마 프레이밍이 정확했다. 특히 두 가지를 그대로 D에 채택했다:
- **(a) 기각 논거** — "게임머니는 매물 구매로만 소진되므로 살 매물이 없으면 탈퇴가 영구히 막힌다"는 지적. (a)의 실질이 lock-in이라는 판단에 동의한다.
- **정직한 유보** — "실서비스라면 (c)가 정답, 캐시는 선불전자지급수단 성격상 환불 의무" 를 D-080 기각된 대안에 **명문으로 남겼다**. 덧붙여 **본 결정은 토스 테스트 결제 전제에 종속하며 실결제 도입 시 D-080은 재검토(SUPERSEDE 후보)** 임을 D에 박아뒀다. 유보를 삼키지 않고 올린 판단이 옳다.

### 확정 조건
1. 잔액 잔존 여부와 무관하게 탈퇴 허용. 잔액을 이유로 차단하지 않는다.
2. 탈퇴 확인 단계에서 **잔존 잔액 소멸·복구 불가 명시 동의** 필수(약관·경고 문구).
3. domain-spec v0.5 탈퇴 정책 + api-contract v1.4 `DELETE /me` 반영.
4. **동의 UI는 화면 기획 대상이다** — D-079로 화면 기획도 네 소관이니, 탈퇴 확인 화면의 경고·동의 요소를 screen-spec에 반영하고 디자인(U)에 전달하라. 별도 총괄 지시 없이 069 범위에 포함해 진행.

069 본작업(domain-spec v0.5 탈퇴 정책) 선결 조건이 해소됐다. 진행하라.
참고 자율분 3건(진행 중 거래 시 탈퇴 차단·이력 마스킹·재가입 UK)은 025 정리대로 네 자율이 맞다. 격상 불요.

## 추가 지시: MEMBER_ 에러코드 채번 조율 (충돌 방지)

백엔드가 069 확정 전에 착수 가능분(잔액 조회)을 진행 중이고, 거기서 **`MEMBER_001`을 "잔액 행 부재"로 잠정 사용**했다(backend/outbox/026 사전 통지 — 방어적 내부 코드). 네가 069에서 `MEMBER_NNN`을 채번할 때 같은 번호를 다른 의미로 배정하면 충돌한다.

- **채번 권한은 너(계약 §5 정본)에게 있다.** 백엔드 잠정 코드에 맞출 의무는 없다(D-028 — 먼저 구현한 쪽이 기준이 되지 않는다).
- 다만 **`MEMBER_001` 잠정 사용 사실을 인지하고 채번하라.** 의도적으로 다르게 배정하든 수용하든 네 판단이되, 결과를 완료 보고에 1줄 명시하면 총괄이 백엔드에 정합 지시를 붙인다.
- 판단 기준: 클라이언트 응답에 실리는 코드는 **전부 §5 표에 등재**돼야 한다. 백엔드가 "내부 방어 코드"라 분류했더라도 응답으로 나가면 계약 대상이다 — 이 관점에서 필요 코드를 빠짐없이 도출하라.
