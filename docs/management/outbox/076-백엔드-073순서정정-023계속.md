# [총괄 → 백엔드] 정정: 073 실행 순서 오류 — 023 계속 진행, V4는 탈퇴·수정의 선행으로 환원

## 정정 사유 (총괄 오류)

073 말미 "실행 순서"에 **V4 UK 재구성을 1번으로 올린 것은 총괄 오류다.** 즉시 정정한다.

네가 028에서 V4를 **"탈퇴·프로필 수정 두 유닛의 공통 선행"** 이라고 범위를 좁혀 올린 것이 정확했다. 그런데 총괄이 이를 전체 선행으로 확대해 **진행 중이던 023을 무효화할 뻔했다.** 실제 의존을 다시 따지면:

- **023 member 도메인 재배치** — 순수 파일 이동(기능 무변경). UK·자연키와 무관. **V4에 막히지 않는다.**
- **024 잔액 조회** — `user_balance` 대상. 자연키 UK 이슈 없음(balance는 `user_id` FK/UK). **V4에 막히지 않는다.**
- **025 게이트웨이 핸들러** — 완전 독립. 언제든 병행.
- **프로필 수정·탈퇴** — `PATCH /me` 중복 오판정(`existsByNickname`이 탈퇴행을 셈), `DELETE /me` 후 재가입. **여기만 V4 선행.**

즉 V4는 **3유닛의 선행이지 전체의 선행이 아니다.** 네 원 판단대로 환원한다.

## 확정 순서

1. **023 재배치 — 진행 중인 것 그대로 완주.** 중단하지 마라.
2. **V4 UK 재구성 + 리포지토리 정정 + auth 회귀** (단일 단위, D-081) — 023 직후 권장. 사유: 023이 `UserRepository`를 `domain/member`로 옮기므로, V4가 **최종 위치에서 한 번만** 수정하면 된다. 순서를 뒤집으면 수정 후 이동이라 diff가 두 번 갈린다.
3. **024 잔액 조회** — 2와 순서 무관(독립). 네 판단으로 2·3 순서 조정 가능.
4. **프로필·수정·탈퇴 3유닛** — V4(2번) 완료 후.
5. **025 게이트웨이 핸들러** — 아무 때나 병행(WebFlux 별도 세션). 완료 시 QA RETEST-1·2 트리거 통지(067 의무).

유지되는 제약은 둘뿐이다:
- **V4는 UK + 리포지토리 + 회귀 테스트를 단일 단위로** (분리 시 로그인 파손 — D-081 동반 필수, 네 경고 그대로).
- **V4 → 프로필 수정·탈퇴** 선행.

나머지 순서는 **네 자율**이다. 총괄이 유닛 단위 순서까지 지정하지 않는다 — 그게 이번 꼬임의 원인이었다.

## 재발 방지

착수 지시 전 "이 작업의 근거가 확정 스펙에 실재하는가" 검증을 빠뜨린 것(066), 파생 작업의 선행 범위를 발견자보다 넓게 잡은 것(073) 둘 다 총괄 결함이다. 순서 체계 자체를 컨설턴트에 회부했다(077). 결과는 규약으로 전파한다.

**진행 중 작업이 총괄 지시와 충돌하면 즉시 알려라.** 이번엔 사용자가 잡았다 — 네가 먼저 이의를 제기했어야 할 사안이고, 그럴 권한이 있다.
