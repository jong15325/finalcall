# [총괄 → 컨설턴트] 작업 지시: 프로젝트 컨텍스트 공통 등록 규칙 규약화

목표: 각 파트 대화가 프로젝트 지식(스냅샷)에 공통 필수로 등록해야 할 파일 집합과
등록/비등록 경계, 최신성 처리 방침을 규약(C-xxx 초안 → 총괄 승인 → D 발번)으로 확정한다.

배경: 프로젝트 컨텍스트 등록 대상은 현재 명문화된 규칙이 없다. 역할·세션이 늘면
등록 누락으로 근거 문서를 못 보는 사고 위험이 있어 D-016 확장(또는 신규 D)으로 못 박는다.

총괄 사전 정리(입력, 미확정 참고):
- 공통 필수 5종(근거 D-016 기준 위계 + 인스트럭션 필독 지정):
  1. docs/management/collaboration-guide.md (규약 전체)
  2. docs/management/templates.md (모든 형식 정본)
  3. 확정 스펙 3종 docs/domain-spec.md · erd.md · api-contract.md
     — 현재 domain-spec 초안만 존재. 확정 시점에 교체 등록.
  4. docs/management/decision-log.md (총괄 D 로그, ACCEPTED만 근거)
  5. docs/management/decision-index.md (마스터 인덱스·게이트·추적)
- 비등록(공통 아님): 파트별 decision-log·notes·outbox(자기 폴더 상시열람 + 필요시 pull),
  루트 CLAUDE.md·frontend/CLAUDE.md(해당 파트 전용 지침).
- 최신성 trade-off(핵심): D-007상 단일 진실은 저장소, 프로젝트 지식은 스냅샷.
  1·2·확정 스펙은 안정적이나 4·5(로그·인덱스)·초안 스펙은 매 결정마다 낡음.
  방침 (A) 5종 전부 등록 + "정본은 저장소, 어긋나면 저장소 우선" 헤더 명시 /
       (B) 안정 파일만 등록, volatile은 재개 시 pull 규약화.
  총괄 권고: (A) — 재개 시 어차피 필독으로 읽으니 스냅샷은 출발점이면 충분,
  등록 누락 사고가 더 위험.

완료 기준:
1. 공통 필수 등록 목록 확정(위 5종 가감 여부 + 확정 스펙 교체 트리거 명시)
2. 등록/비등록 경계 규칙화(파트 전용·volatile 처리 포함)
3. 최신성 방침 A/B 중 택1 근거와 함께 제안 — 채택 시 등록 파일 헤더 문구도 제시
4. D-016 확장 vs 신규 D 여부 판단 → C-xxx 발번, 총괄 승인 대상 형태로 회신
의존: 없음 (D-016·D-007 ACCEPTED 기반)
하지 말 것: 확정 스펙 내용·아이템 안건 논의(범위 밖), 저장소 파일 직접 등록·수정
(등록은 사용자 실행), 파트별 필독 목록 재설계(D-016 본문 개정은 별건)
관련 문서: docs/management/collaboration-guide.md(D-016 읽기 규칙),
docs/management/decision-log.md(D-007), docs/management/decision-index.md
