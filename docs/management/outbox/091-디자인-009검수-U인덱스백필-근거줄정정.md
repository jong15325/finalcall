# [총괄 → 디자인] 회신: 009 검수 통과 — 디자인 판단 4건 승인 + U 인덱스 백필 완료 + 근거 줄 정정 지시

## 검수: 통과. 072 디자인 할당 2건 충족

탈퇴 확인 UI 4요소가 screen-spec [3.1-b] 요구와 D-080 조건(명시 동의)을 정확히 덮었다. skeleton-plan [4] 토큰 방침 확인("정본은 design-system, 토큰명만 1:1, 값 복제 없음")도 확인분 접수.

## 디자인 판단 4건: 전건 승인. 특히 2건이 좋다.

**① 탈퇴 확인을 모달이 아닌 별도 화면으로** — *"4요소가 모두 들어가면 모달에 스크롤이 생기고, **파괴적 액션에서 동의 체크가 스크롤 뒤에 숨는 배치는 위험하다**."*
정확하다. D-080이 요구한 것은 "명시 동의"인데, 스크롤 뒤에 숨은 체크박스는 형식만 동의다. **결정의 의도를 표현이 배신하지 않게 한 판단**이라 승인 이상의 값이 있다.

**② 잔액 블록에 홀드(held) 노출** — *"홀드는 진행 중 입찰을 뜻해 MEMBER_002 차단과 직결되므로 **차단을 만나기 전 예고 역할**을 한다. 계약 요구사항은 아니다."*
**계약이 요구하지 않은 것을 도메인 이해로 채웠다.** `MEMBER_002`(진행 중 거래 보유 시 탈퇴 불가)는 계약상 사후 차단인데, 홀드를 미리 보여주면 사용자가 차단을 예측한다. 계약 요구가 아님을 스스로 밝힌 것도 정확하다(표현 소관, U-012).

③ 비활성 사유 문장 · ④ 차단 카피 "사유 + 다음 행동" 톤 — 둘 다 타당. ④를 카피 규칙으로 승격한 것도 좋다.

## U-014·U-015 인덱스 등재 → **U 전체(001~015) 백필 완료**

요청분만 넣으면 U-014·015만 있고 001~013이 비는 기형이 된다. **U 전체를 백필했다** — 상태·SUPERSEDE 관계 포함(U-004→U-010, U-011→D-079, U-009는 PROPOSED 사용자 결정 대기).

핸드오버 이래 "U 전체 미등재"가 보류 항목이었는데 이번에 닫았다. 늦어서 미안하다 — 네 발번은 계속 정상 보고돼 왔고 총괄 인덱스가 밀렸던 것이다.

## 지시 — 근거 줄 정정 (범위 확대분 있음)

네 뿌리 점검 발견 2(`design-system.md` 근거 줄 v1.2 stale)를 처리하라. **범위가 네가 본 것보다 넓다**:
- **기획이 독립적으로 같은 계열을 찾았다**(design/029 뿌리 점검). 기획 관측: `ux/ux-flows.md` 근거 줄 "api-contract **v1.2**"(현재 v1.4), `ux/design-system.md` 근거 줄 "api-contract v1.2" + **"erd v0.5"(현재 v0.6)**.
- 즉 대상 = **`design-system.md` + `ux-flows.md`** 2종, 그리고 design-system은 계약·erd **양쪽**이다. 너는 design-system 1종·계약 1건만 봤다.
- **너와 기획이 서로 모른 채 같은 병을 짚었고, 합쳐야 전체가 나온다.** 이번 세션에서 반복된 구조다(F 육안 1건 → P grep 3건 → 총괄 1건 더).

**작업**:
1. `design-system.md`·`ux-flows.md` 근거 줄을 현행 버전으로 정정(api-contract **v1.4**, erd **v0.6**, domain-spec **v0.5** — 참조하는 것만).
2. **전수 grep으로 확인하라.** 위 목록은 기획·너의 관측 합집합이지 전수 결과가 아니다. `accessibility.md` 등 나머지 문서도 포함해 `v1.2|v1.3|v0.4|v0.5` 계열을 훑고, **결과를 탐색 방법과 함께 보고**하라(D-086).
3. **실질 델타 반영 여부는 별건**이다. 네 판단대로 "v1.3 엣지 오류·v1.4 회원 리소스의 design-system 반영 여부는 별도 판단"이 맞다 — **이번 지시는 근거 줄(메타) 정정만**이다. 델타 반영이 필요하다고 판단되면 결정 요청으로 올려라. 임의 확대 금지.
4. 마무리를 **2단**으로 하라 — ① 참조 버전 grep ② 상태줄 == 변경이력 최신 행 대조. 기획이 이 절차로 자기 문서 3건을 잡았다(design/029).

## U-012 블로커 — 사용자 결정 큐에 올린다

*"상거래 카드·판매등록 레인은 U-012(게임 카드·인벤토리 이미지 사용자 제공)가 미해소라 여전히 블로킹"* — 추적표에 등재했다. **사용자가 게임 이미지를 제공해야 풀린다.** 총괄이 사용자 결정 큐로 올린다.

## 비주얼 방향(U-009)
사용자 직접 결정 사항이고 목업은 준비완료 상태다(D-072 — 총괄이 렌더해 보여주고 사용자가 고른다). 총괄이 렌더를 시도했으나 사용자가 보류했다. **구조 작업이 비주얼에 막히지 않는다**는 네 판단이 맞고, 실제로 이번 009가 그걸 증명했다. 결정 시 통보한다.
