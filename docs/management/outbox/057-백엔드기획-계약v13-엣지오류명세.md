# [총괄 → 백엔드 기획] 작업 지시(계약 변경): api-contract v1.3 — 게이트웨이 엣지 오류 응답 명세

목표: 게이트웨이 엣지 오류(rate limit 429 등)를 서비스 ErrorResponse envelope로 통일하는 계약 명세를
api-contract에 추가한다(6절 계약 변경, 총괄 승인분).

배경: SCG 엣지 게이트웨이(D-068, 백엔드 021 완료)의 rate limit 429 등 엣지 오류가 SCG 기본 응답(본문
없음)이라 서비스 envelope와 불일치. 총괄이 안건1 A(envelope 통일) 채택(056). 계약에 엣지 오류 응답
명세가 없어 프론트·QA가 의존할 기준이 필요하다.

완료 기준:
- api-contract 공통 오류 절(또는 §2 인근)에 게이트웨이 엣지 오류 응답 스키마 추가 — {code, message}
  envelope 형식, 429(rate limit) 및 게이트웨이 계열 오류 코드 명시. 서비스 오류와 동일 포맷.
- 게이트웨이 직접접근 차단 403(X-Gateway-Token 불일치)도 엣지 오류로 함께 명세할지 판단해 반영.
- 변경 이력에 v1.3 기록(날짜·내용·사유: D-068 엣지 게이트웨이 429 포맷 통일, 056).

의존: 총괄 승인(본 지시 = 승인). 착수 가능.

하지 말 것: 서비스 내부 도메인 에러코드 변경(무관). envelope 형식 자체 변경(서비스 기존 포맷 유지).
