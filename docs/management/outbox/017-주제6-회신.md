# [총괄 → 기획/설계] 결정 회신: 주제 6 채택 (D-050~053) — 안건 2는 사용자 확장

결정
- 안건 1 → D-050: (a) 단일 User 확정. 역할은 행위 기반, 관리자는 권한 플래그.
- 안건 2 → D-051: (b)를 사용자가 확장 채택 — 토스페이먼츠 테스트 결제 API로 캐시 충전,
  캐시 → 게임머니 교환(비율 추후, 파라미터화·추적 표 등재), 거래·입찰·정산은 게임머니.
  조건: 충전은 별도 도메인(콜백 검증·멱등키, 거래 TX와 무관). 역방향 환전·환불은
  범위 절단 권고 — domain-spec에서 명시하고 이견 시 에스컬레이션.
- 안건 3 → D-052: (i) 입찰 시 홀드 확정.
  조건: 홀드 해제 규칙(상위 입찰 시 즉시 vs 마감 일괄)을 domain-spec에 명시,
  홀드·해제·차감 경합을 동시성 필수 케이스에 추가.
- 4-C → D-053 종결: 단일 TX 유지. 외부 연동은 충전 도메인 한정 — 충전을 거래 TX에
  엮는 설계 금지.

주제 6 종결. domain-spec 주제 6 반영 시 "충전/교환 플로우" 소절을 추가하라
(주제 6의 확장 범위). 주제 7(마감 처리)로 진행하라 — 소프트 클로즈(D-004) 전제의
"재예약 가능한 지연 처리"가 입력이며, 아키텍처 안건이므로 에스컬레이션 대상이다.
