# [기획/설계 → 총괄] 결정 요청: 주제 7 마감 처리 방식 (정책 수준)

배경: 주제 1~6 종결. 마지막으로 경매 마감·예약시작·고정가 만료의 시각 기반 상태 전이를
어떤 방식으로 처리할지 정함. 소프트 클로즈(D-004)로 마감 시각이 반복 갱신되므로
"재예약이 싼" 구조가 핵심 제약. 구체 기술은 백엔드 자율, 여기선 정책 방향만 확정.

안건 1. 마감 트리거 메커니즘
- 선택지: (a) 주기 폴링 스케줄러(DB 스캔)  (b) 지연 큐(정시 트리거)
          (c) 하이브리드 — 재예약 가능한 지연 인덱스(score=마감시각) + 짧은 주기 워커 + DB 재구축 안전망
- 추천: (c). 소프트 클로즈로 마감 시각이 반복 갱신되므로 재예약 비용이 관건.
  지연 인덱스 score 갱신만으로 재예약되고, DB가 진실이라 인덱스 유실 시 재구축 가능(4-A 정합).
  순수 폴링은 정확도/부하 트레이드오프, 순수 지연 큐는 매 연장마다 취소+재삽입 churn.
  구체 기술(Redis ZSET / DelayedQueue / 스케줄러 라이브러리)은 백엔드 자율.

안건 2. 트리거 대상 통합 여부
- 대상: SCHEDULED 시작(activation), 경매 마감, FixedSale endAt 만료 — 모두 "시각 도달 시 상태 전이" 동일 패턴.
- 추천: 단일 지연 인덱스로 통합(트리거 종류만 구분). 별도 스케줄러 다중 운용 지양.

안건 3. 중복·유실 처리
- 추천: 마감 처리는 4-B CAS로 멱등(이미 종료면 no-op) → 워커 다중화·중복 실행 안전.
  유실은 DB 재구축 스캔(WHERE status=ACTIVE AND 마감<=now)으로 복구.

파급: 마감 처리 지점에서 최고입찰 게임머니 차감 + 나머지 홀드 해제(D-052)가 4-B 종료 전이와
한 트랜잭션/직렬화 단위에 묶여야 함(D-008 4-D "동일 직렬화 단위" 원칙 연장) — 동시성 필수 케이스.
