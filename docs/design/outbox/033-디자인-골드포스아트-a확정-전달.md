# [기획 → 디자인, 총괄] 정보 공유: 골드포스 아트 **(a) 확정** — 상거래 카드 완전 언블록

**디자인 앞**: 031에서 총괄 격상 중이라 남겨둔 마지막 1건이 확정됐다. **이제 상거래 카드에 대기 항목이 없다.**
**총괄 앞**: 097 회신 요청분 — (a) 확정과 D-066 해석을 디자인에 전달 완료. screen-spec [3.5-b]에 집행했다.

## 확정: (a) — `gold_black` 유지 + 골드포스 별도 표시

- 골드포스 활성 매물도 카드 아트는 **`gold_black`**. `gold_force` 세트로 교체하지 않는다.
- 골드포스는 **별도 표시**(배지·테두리 등)로 얹는다 — **표현 방식은 네 자율**(U-012, D-091).
- 근거: 레벨·속성은 거래 판단의 1급 축(시세 집계 D-044·erd 인덱스·목록 필터)인데 `gold_force`는 레벨·속성 분기가 없어(18 = 2크기 × 9종류) 교체 시 그 축이 소실된다. 골드포스는 D-066상 시세 키에서 제외된 부차 속성 — **부차 속성 때문에 1급 축이 가려질 수 없다.**

총괄이 덧붙인 판정이 이 결정의 핵심이라 그대로 전한다: **"원게임은 게임이고 이건 거래소다."** 게임에서 아트 교체는 "내 아이템에 골드포스가 켜졌다"는 신호로 충분하다 — 플레이어는 자기 아이템을 이미 안다. 거래소는 **처음 보는 매물을 목록에서 비교하는 곳**이라 레벨·속성이 안 보이면 거래가 성립하지 않는다. 맥락이 다르니 같은 자산을 다르게 쓴다.

## U-016 충돌 없음 — 네 프레임이 이미 답이었다

내가 032에서 "(a)는 원게임 충실도(U-016)와 충돌한다"고 유보했는데, **그 유보는 불필요했다.** 네가 U-016을 보고하며 이미 정리해 둔 프레임 안에 답이 있었다 — **"전면 차용의 실행 방식은 이미지 부착이 아니라 토큰 추출·CSS 재현"**, 근거는 *텍스트가 이미지에 구워져 웹 카피 불가 / 스크린리더 미독 / 고정 해상도 360px 미대응*.

즉 **"원게임을 문자 그대로 재현하면 웹으로서 기능하지 않는 지점에서는 웹이 이긴다"** 가 U-016의 해석으로 이미 확정돼 있었다. 골드포스 아트 교체는 정확히 같은 유형이다. U-016은 **시각 언어의 차용**이지 게임 화면의 복제가 아니므로 (a)는 U-016을 위반하지 않는다.

## D-066 해석 — 총괄 승인. 031에서 보낸 대로 유효하다

D-066은 **검색·집계 축**에서의 배제이지 **표시 금지가 아니다.** 계약 [3.3]이 `goldforceExpireAt`을 노출하는 것이 근거다 — 표시를 금지할 거면 계약이 필드를 안 줬을 것이다. 총괄이 "계약이 필드를 노출한다는 것을 근거로 든 게 정확하다"고 승인했다. **골드포스 표시는 자유롭게 설계하라.**

## 원게임 동작 확인 — **대기하지 마라. 선결이 아니다.**

032에서 내가 "교체가 아니라면 안건 1이 소멸한다"며 사용자 확인을 선결처럼 뒀는데 **틀렸다. 총괄이 정확히 반박했다:**

| 원게임 실제 동작 | (a) 하의 결과 |
|---|---|
| 골드포스 시 아트 교체됨 | `gold_black` 유지 + 배지 → 레벨·속성 보존 |
| `gold_force`는 다른 UI 요소용 | `gold_black` 그대로 → 레벨·속성 보존 |

**두 경우 모두 카드 아트는 `gold_black`이다.** 확인 결과가 (a)의 실행을 바꾸지 않으므로 선결이 아니다. 내가 (b)를 살아있는 선택지로 둔 탓에 없는 의존을 만들었고, 그대로 뒀으면 **너를 불필요하게 대기시킬 뻔했다.** 내 오류다.

`gold_force` 18개 자산의 실제 용도는 별건으로 사용자 결정 큐에 낮은 우선순위로 올라갔다 — **그 자산을 쓸지 말지는 네 자율(D-091)이고 상거래 카드를 막지 않는다.**

## 반영

`screen-spec [3.5-b]`에 골드포스 아트 처리·D-066 표시 해석을 명시했다(P-012·P-013과 같은 절). 화면 층 기준선이니 이후 같은 질문이 반복되지 않는다.
