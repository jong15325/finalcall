# [기획/설계 → 총괄] 결정 요청: 아이템 ERD 모델 확정 (D-048 안건, ①~⑤ 묶음)

배경: ERD(G2) 아이템 도메인 설계. D-048(아이템 세부는 자율 예외 → 총괄·사용자 확정)에 따라
아래 방향을 안건으로 올린다. 각 안건의 추천은 이미 사용자와 직접 논의해 도출한 방향이며(참조:
업로드 SurvivalProject SQL `user_item` 구조 + ItemFusionSkill.cpp 인코딩 분석, notes/erd-item-modeling.md),
총괄 검토 + 사용자 최종 확정을 요청한다. 근거: D-044~047, D-062, B-001~009(네이밍/식별자). P 발번 없음(D-048).

안건 1. 아이템 타입 → item_template 마스터 정규화
- 선택지: (a) 타입코드(4자리)를 대분류·중분류(슬롯군)·속성·종류 정형 컬럼으로 분해해 item_template에
  저장, 인스턴스는 template_id FK. (b) 타입코드 원형 보존, 디코딩은 앱/뷰.
- 추천: (a). D-044(마스터+정형 컬럼)와 정합. "속성·종류 부분 필터"·시세 집계가 정형 컬럼 인덱스를
  타야 §7.7 요구 충족. 타입코드는 파생값. (타입코드 자리 규칙: 대분류=천, 중분류=백, 속성=십, 종류=일 —
  ItemFusionSkill.cpp `main_type=(type/100)%10` 등으로 확인.)

안건 2. 특수스킬 → 정규화(2슬롯 + 발동확률)
- 선택지: (a) itm_skill 단일 int를 skill1_id·skill2_id·skill_percent 3컬럼으로 분해.
  (b) 단일 int 보존.
- 추천: (a). 인코딩 `itm_skill = 발동확률×1,000,000 + 스킬1×1,000 + 스킬2`(검증 완료). §7.3의
  "특수스킬 2슬롯"을 실물로 검증. skill_percent=스킬 발동확률(합성 결과, 골드포스와 무관).
  스킬 조합 필터·시세(§7.7)가 slot 컬럼 인덱스로 처리됨. 스킬 ID는 스킬 정의 마스터 FK(가상 시드).

안건 3. 골드포스 → 인스턴스 시간 속성
- 선택지: (a) 인스턴스에 gf_expire_at(골드포스 만료시각) 컬럼, 활성/잔여는 파생. (b) 미반영.
- 추천: (a). 골드포스=아이템 자체 발동확률의 시간제 상태(스킬 발동확률과 별개). 거래 가치·검색·시세
  요인. 착용·세트 발동확률 계산(같은 속성 3피스 등)은 게임플레이라 범위 밖(§7.6). §7 신규 속성이라
  spec §7.3/§7.7 보강 필요 여부 함께 판단 요청.

안건 4. 소유·이전
- 선택지: (a) 현재 소유자 owner_id FK + 외부식별자 public_id(ULID)/내부 id(B-004) + 소유 이력을
  item_ownership_history 신설(instance_id·from/to_owner_id·transferred_at·유형)로 전 체인 추적,
  first_owner 캐시 컬럼 없음. (b) 이력을 Order에서만 파생 + first_owner 인스턴스 캐시.
- 추천: (a). 최초·직전·전체 이전 체인을 이력 테이블에서 조회(비거래 이전=관리자 지급·시드도 통합).
  거래 이전은 Order와 연계해 이력 행 추가. §7.8 소유·이전 근거.

안건 5. 인벤토리 + 출품 에스크로 + 임시보관
- 5-1 인벤토리: 인스턴스에 owner_id + slot_no 인라인, 사용자당 96칸은 비즈니스 제약(별도 인벤토리
  테이블 없음).
- 5-2 출품=에스크로: 출품 시 아이템을 정규 인벤토리에서 제외하고 경매/고정가(Auction/FixedSale)가
  보유. 중복 출품 방지 = "인벤토리→출품중" CAS 단일 승자(D-008 패턴, 부분 유니크 인덱스 불요).
  게임머니 홀드와 에스크로 대칭.
- 5-3 임시보관(오버플로우): 별도 임시보관 테이블 신설, 상한 없음(거래 성립·복귀 항상 성공). 낙찰
  이전·유찰/취소 복귀 시 정규 슬롯 여유 없으면 임시보관 배정. 보관 기한(expire_at)은 선택 속성(회수
  규칙 미확정, 파라미터화).
- 위치 불변식: 아이템은 한 시점 정확히 한 위치(정규 인벤토리/임시보관/출품 에스크로). '위치 단일 진실'
  표현(디스크리미네이터 vs 테이블 존재)과 XOR 제약은 ERD 인덱스·제약 설계에서 확정.
- 추천: 위 5-1~5-3 방식. 낙찰 이전·정산은 Order 단일 트랜잭션(§5, §7.8, D-053).

범위·후속(참고, 결정 아님)
- ERD/시드 단계로 이월: 스킬 정의 마스터·taxonomy 멤버·가상 명칭·수치(D-047), 위치 단일진실 구체 표현,
  §7.7 골드포스 축 추가 여부.
- 착용·세트 발동확률 계산, 강화·합성 행위는 범위 밖(§7.6, D-046).
