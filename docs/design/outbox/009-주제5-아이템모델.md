# [기획/설계 → 총괄] 결정 요청: 주제 5 아이템 도메인 모델

배경: 사용자 레퍼런스 검토로 방향이 서바이벌 프로젝트형 단순 구조로 정해짐(013 지시,
총괄 조사노트 입력). 메이플식 하이브리드 대비 대폭 단순화 가능. ERD(G2)의 기반이 되는
아키텍처·범위 결정 4건을 요청. 세부(enum 멤버·컬럼명·검색축)는 확정 후 P 발번/ERD로 미룸.

안건 1. 아이템 도메인 모델 형태 (아키텍처·one-way door)
- 선택지: (a) 메이플식 하이브리드 유지(item_template + JSON 옵션 + 인덱스 승격)
          (b) 서프형 단순화 — 중앙 시드 item_template 마스터 + 정형 컬럼 인스턴스 속성(JSON 제거)
              + 얕은 2단 카테고리(대분류→종류) + 축(속성/등급)
- 추천: (b). 템플릿 공간 유한(수백 미만)→마스터 자명, 인스턴스 변이 정형(레벨+특수스킬 2슬롯)
        →JSON·인덱스 승격 문제 소멸. 검색·시세·정합성 단순화. "동일 템플릿 다른 가치"는 남아 학습가치 유지.

안건 2. 아이템-판매 관계
- 추천: 매물이 item_template FK 참조 + 인스턴스 속성 정형 컬럼 보유 + 등록시점 표시필드 스냅샷(이력).
        (기존 P-007 "스냅샷 단독" 초안은 void, 마스터 참조로 대체)

안건 3. 강화·합성 범위 (범위 절단)
- 추천: 강화·합성 "행위"는 범위 밖. 레벨은 인스턴스의 현재 상태 값으로만 취급.

안건 4. item_template 채우기 방식 (오픈이슈 1 회답)
- 추천: 고정 시드 세트(운영/마이그레이션 관리). 판매자 제안+승인 플로우 불필요(템플릿 공간 유한).
        실존 게임 명칭·데이터 미사용 — 가상 명칭·수치로 시드(IP 주의).

참고(오픈이슈 2 taxonomy): 안건 1=(b) 채택 시 서프형 2단 계층으로 확정됨.
