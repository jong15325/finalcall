# [기획 → 총괄] 결정 요청: 탈퇴 시 잔액(캐시·게임머니) 잔존분 처리 (069 지정 격상)

## 배경

069가 격상 지정한 항목이다. 069 본작업(domain-spec v0.5 탈퇴 정책)의 **선결 조건**이라 먼저 올린다 — 이 결정 없이는 탈퇴 정책을 쓸 수 없다.

- domain-spec §12는 역방향 환전(게임머니→캐시)·환불을 범위 밖으로 절단했다(D-051).
- 캐시는 단방향으로만 흐른다: 외부 결제 → 캐시 → (교환) → 게임머니 → 거래. 되돌아오는 경로가 없다.
- erd `user`는 `is_deleted`·`deleted_at` 탈퇴를 전제하고 V3 구현이 끝났다.
- 따라서 잔액을 보유한 채 탈퇴하면 **그 돈은 소멸한다**. 돈 문제라 기획 자율 대상이 아니다.

## 안건 1. 탈퇴 시 잔존 잔액 처리

핵심은 트릴레마다. 환불·역환전이 없는 상태에서 아래 셋은 **동시에 만족할 수 없다**. 하나를 반드시 포기해야 한다.

1. 탈퇴 자유 허용
2. 잔액 소멸 방지
3. §12 범위 유지(환불·역환전 없음)

- **선택지 (a) 잔액 0 조건부 차단** — [2+3 유지, 1 포기]. 캐시·게임머니 잔액이 있으면 탈퇴 불가(`MEMBER_NNN` 422). 소진 후 탈퇴.
- **선택지 (b) 소멸 동의** — [1+3 유지, 2 포기]. 탈퇴 확인 단계에서 잔존 잔액 소멸에 명시 동의를 받고 소멸 처리. 약관·경고 문구 명시.
- **선택지 (c) 환불·역환전 도입** — [1+2 유지, 3 포기]. §12 범위 해제 + PG 환불 연동.

### 추천: (b) 소멸 동의

이유:
- **(a)는 사용자 적대적이다.** 게임머니는 매물 구매로만 소진되므로 살 매물이 없으면 탈퇴가 영구히 막힌다. 캐시는 게임머니 교환만 가능(단방향)해 캐시 소진도 결국 게임머니 소비로 귀결된다. 즉 (a)의 실질은 "탈퇴하려면 돈을 다 써라"이며, 잔액을 이유로 탈퇴를 막는 건 실무·법적으로도 방어하기 어렵다.
- **(b)는 업계 표준에 가깝다.** 게임머니·포인트류는 "탈퇴 시 잔여분 소멸, 복구 불가"를 약관에 명시하고 소멸시키는 것이 통상적이다. 명시 동의 + 탈퇴 확인 경고로 처리한다.
- **본 프로젝트의 캐시는 토스페이먼츠 테스트 결제 기반(D-051)이라 실화폐 손실이 아니다.** (b)의 최대 약점인 "실결제금 소멸"이 이 전제에서 성립하지 않는다.
- (a)와 달리 탈퇴 FSM이 단순해진다(잔액 조건 분기 없음).

정직한 유보: **실서비스라면 (c)가 정답이다.** 캐시는 선불전자지급수단 성격이라 현금성 충전금에 환불 의무가 따르는 것이 실제 규제 환경이다. 다만 069가 범위 확대를 금지했고 §12가 이미 환불을 절단했으므로 이번 범위에선 제외한다. (c)를 택하려면 범위 결정이 선행돼야 한다.

### 보수적 대안이 필요하면 (a)

"돈 소멸은 어떤 경우에도 안 된다"를 우선하면 (a)다. 이 경우 lock-in을 완화할 운영 창구(수동 처리)가 별도로 필요하며, 그 자체가 범위 밖 항목이 된다.
