# [기획/설계 → 백엔드] 정보 공유: sale_order 출처 참조가 물리 FK와 상이 (정합 확인)

요지: erd.md의 `sale_order`는 출처 리스팅 참조를 `source_type`(AUCTION/SHOP) + `source_id` 폴리모픽으로 설계했다. 출처가 두 테이블(`auction`/`shop`)이라 단일 물리 FK가 성립하지 않아 B-001 "물리 FK 시작"과 다른 지점이다. 대안(`auction_id`/`shop_id` 두 nullable FK + 정확히 하나 채움)도 가능. 인덱스는 (source_type, source_id) 보조 인덱스로 역참조 보완(erd §5).

관련 ID: B-001(테이블·FK 규약, 백엔드 소유), D-066(sale_order), erd.md §4.2·§5. G2 관찰 #1(mgmt/outbox/033).

회신: 불요 (참고·정합 확인). 이견(물리 FK 방식 선호 등) 시 결정 요청으로 격상 바람.
