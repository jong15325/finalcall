# [기획/설계 → 총괄] 결정 요청: 주제 6 사용자·거래 범위

배경: 주제 5 종결(D-044~047). 주제 6은 사용자/역할 모델과 결제·정산 범위를 정함.
이 결정이 4-C 재확정(단일 TX vs outbox 승격, D-008 조건)의 입력이다. 대부분 범위·아키텍처라 안건화.

안건 1. 사용자·역할 모델
- 선택지: (a) 단일 User(판매자·구매자 겸용) + 관리자 플래그  (b) 판매자/구매자 역할 엔티티 분리
- 추천: (a). 한 사용자가 등록·입찰·구매를 모두 하는 C2C 거래소라 역할은 행위 기반이면 충분.
  분리는 과설계. 인증은 JWT 스켈레톤이 식별 보장(D-002).

안건 2. 결제·정산 범위 (money model, 핵심)
- 선택지: (a) 결제 미포함 — 거래 성립(SOLD/Order)까지만, 실제 결제·정산 범위 밖
          (b) 내부 포인트 지갑 — 모의 충전 → 입찰·구매에 사용 → 판매자 지갑으로 정산
          (c) 외부 PG 연동
- 추천: (b). 프로젝트 핵심 도전이 동시성인데, 내부 지갑은 잔액 차감·홀드라는 동시성 표면을
  추가해 학습가치가 크고, 정산까지 내부 DB라 원자적 처리 가능. (c) PG는 외부연동 부담+범위 과다,
  (a)는 동시성 시나리오(지불능력·중복차감)가 빈약.

안건 3. 입찰·구매 시 자금 처리 (안건 2=(b) 채택 시)
- 선택지: (i) 입찰 시 잔액 홀드(에스크로)  (ii) 낙찰/구매 시에만 차감
- 추천: (i) 홀드. 지불능력 보장 + 마감·낙찰 시 차감 경합이 동시성 필수 케이스로 이어짐.
  단 홀드 관리(입찰 갱신 시 이전 홀드 해제) 복잡도 수용.

파급 통지(4-C): 안건 2=(b)면 SOLD→Order→포인트 정산이 전부 내부 DB → 4-C는 단일 TX 유지가
자연스러움. 안건 2=(c)면 외부 결제로 outbox 승격 필요. 4-C 재확정은 안건 2 결과에 직접 종속.
