# 기획/설계 결정 로그 (P-xxx)

협업 가이드(docs/management/collaboration-guide.md) 4절 티켓 규약(D-009~D-011)을 따른다.
- ID: P-<3자리>, 접두어별 독립 증가, 불변, 재사용·재번호 금지. 1결정=1번호.
- P-003~P-007: void(규약 이전 임시 사용, 인덱스 미등록·재사용 금지). 정식 신규 발번은 P-008부터. 상세: outbox/006, notes/topic-5.md.
- 상태 라벨: PROPOSED / ACCEPTED / ON-HOLD / SUPERSEDED(대체 ID 명시).
- 필드: ID · 제목 · 상태 · 소유역할 · 결정 · 이유 · 기각된 대안 · 관련(참조 ID) · 날짜.
- 참조 키워드: depends-on / relates-to / supersedes / escalated-as.
- 에스컬레이션 4기준에 걸린 사안은 총괄 로그(D-xxx)가 정본. 여기서는 "escalated-as D-xxx (ACCEPTED)" 참조만 남긴다(내용 중복 기록 금지).
- 총괄로 보내는 모든 프롬프트 끝에 "신규 발번 ID: ..." 1줄 첨부 → 마스터 인덱스(management/decision-index.md) 동기화.
- 이 로그 + 총괄 D-로그가 domain-spec.md 초안의 근거가 된다.
- 기존 P-001~002는 규약 이전 발번분. D-011 지시에 따라 상태 라벨·참조만 추가하고 내용은 소급 재작성하지 않음.

논의 순서: 판매 방식 모델링 → 입찰 규칙 → 생명주기/상태 전이 → 즉시구매·낙찰 동시성 → 아이템 도메인 → 사용자·거래 범위 → 마감 처리 방식

## P-001. 판매 방식 모델링 구조 (C안)

상태: ACCEPTED · 소유: 기획 · 관련: relates-to D-004, D-005, D-008 · 2026-07-12

결정
- 경매(영국식 + 즉시구매)와 고정가를 별도 애그리거트로 분리.
  - `Auction`: 영국식 경매. 즉시구매는 `buyNowPrice` 선택 속성.
  - `FixedSale`: 고정가. 입찰 개념 없음.
  - `Bid`는 경매에만 존재.
- 통합 피드용 공통 부모 `Listing` 도입 여부는 ERD 단계에서 재판단(보류).

이유
- 타입 1·2는 입찰·마감·낙찰 메커니즘 동일, 차이는 `buyNowPrice` 존재 여부뿐 → 분리 시 입찰 서브시스템 중복.
- 고정가는 Bid·시간 기반 낙찰이 없는 "재고 1개 원자적 선점" → 경매 통합 시 무의미한 nullable·조건 분기로 FSM 오염.
- 동시성 이점: buyNow 종료 = 고정가 구매와 동일한 원자적 선점 패턴 → 공통 정책 재사용.

기각된 대안
- A안(단일 Listing + saleType enum): nullable 대량, FSM 조건 분기 폭증.
- B안(3개 독립): 타입 1·2 입찰 로직 전면 중복.

## P-002. 즉시구매가/시작가 제약

상태: ACCEPTED · 소유: 기획 · 관련: relates-to D-004 · 2026-07-12

결정: 등록 시점 `buyNowPrice > startPrice`.
이유: 같거나 낮으면 입찰할 이유가 없어 경매가 무의미.
기각: 제약 없음(경매 성립성 훼손).

## P-008. 입찰 홀드 해제 규칙

상태: ACCEPTED · 소유: 기획 · 관련: relates-to D-052 · 2026-07-13

결정: 상위 입찰 발생 시 직전 최고입찰자의 게임머니 홀드를 즉시 해제한다(마감 일괄 해제 아님).
이유: 즉시 해제는 자금 회전이 빠르고 직관적. 마감 일괄은 밀린 입찰의 홀드가 누적돼 사용자 잔액이 장시간 묶임(여러 경매 병행 시 악화). D-052가 domain-spec 명시를 요구한 입찰 도메인 세부(two-way door)로 자율 결정.
기각: 마감 일괄 해제(잔액 장기 잠금, UX 저하).
주: 홀드·해제·차감 경합은 동시성 필수 케이스로 등재(D-052).

## 주제 5. 아이템 도메인 — escalated-as D-044~047 (ACCEPTED), 종결

- 안건 1 → D-044: (b) 서프형 단순화(중앙 시드 item_template + 정형 컬럼 인스턴스, JSON 제거, 2단 카테고리).
- 안건 2 → D-045: 매물 = template FK + 인스턴스 정형 컬럼 + 등록시점 표시필드 스냅샷. P-007 void 확정.
- 안건 3 → D-046: 강화·합성 행위 범위 밖, 레벨=상태값.
- 안건 4 → D-047: 고정 시드(가상 명칭·수치, IP 회피).
- D-048: 아이템 도메인은 자율 결정 예외 — 세부(컬럼·특수스킬 목록 등 two-way door 포함)도 총괄 안건화. 따라서 P-008 세부 발번하지 않음(ERD/spec 착수 시 안건으로 올림).
- 파급(D-044 조건): 특수스킬 조합 필터·시세 집계 단위(템플릿·레벨·스킬조합)는 ERD(G2) 검색·인덱스 필수 케이스. notes/spec-format-checklist 반영.
- 재분석 상세: notes/topic-5.md.

## 주제 6. 사용자·거래 범위 — escalated-as D-050~053 (ACCEPTED), 종결

- 안건 1 → D-050: 단일 User(행위 기반 역할), 관리자=권한 플래그.
- 안건 2 → D-051: 2단 머니 모델 — 토스페이먼츠 테스트 API 캐시 충전 → 캐시↔게임머니 교환(비율 파라미터화, 추적표 등재) → 거래·입찰·정산은 게임머니. 충전은 별도 도메인(콜백 검증·멱등키, 거래 TX 무관). 역방향 환전·환불 범위 절단(domain-spec 명시).
- 안건 3 → D-052: 입찰 시 게임머니 홀드(에스크로). 홀드 해제 규칙(상위 입찰 즉시 vs 마감 일괄) domain-spec 명시. 홀드·해제·차감 경합 = 동시성 필수 케이스.
- 4-C → D-053: 단일 TX 유지 확정(외부 연동은 충전 도메인 한정). 4-C 재확정 종결.
- domain-spec 주제 6에 "충전/교환 플로우" 소절 추가. 상세: notes/topic-6.md.
