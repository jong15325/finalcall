성격: 미확정 분석/초안 — 타 역할 근거 인용 금지 (D-014 유형 4). 확정은 총괄 안건(D-048) 경유.
관련: D-044~047, D-048, D-062, ERD(G2), 업로드 SQL `user_item` 구조(미확정 참고, 구조만 — 실데이터·명칭 미사용 D-047)

## 참고: 실게임 user_item 구조 (구조만 참고)

정형 컬럼 인스턴스(JSON 없음) — D-044 실물 검증. 컬럼: 타입·골드포스(만료시각)·레벨·스킬·uuid·소유자(현재/최초/이전)·슬롯·생성일.

## 타입코드 4자리 자리값 해독 (구조)

| 자리 | 의미 | 값 |
|---|---|---|
| 1 | 대분류 | 1=무기(장비). 그 외(펫/아바타/마법 등)는 데이터로 확인 |
| 2 | 중분류(슬롯군) | 1=무기(도·지·검·활) / 2=방어구·장신구(방·펜·갑·신) / 3=필드(필·ss필) |
| 3 | 속성 | 1=물 2=불 3=흙 4=바람 (무속성 등 여부 데이터 확인) |
| 4 | 종류 | 슬롯군1:1도2지3검4활 / 슬롯군2:1방2펜3갑4신 / 슬롯군3:1필2ss필 |

검증: 1123=무기·무기군·불·검 / 1213=무기·방어군·물·갑. 표 전체 일관.

## 논의점 상태 (①~⑤)

- ① 아이템 타입 표현 — 확정 방향(사용자 직접, 2026-07-13): (a) item_template 마스터로 정규화. 대분류·중분류(슬롯군)·속성·종류를 정형 컬럼으로 분해, 인스턴스는 template_id FK. 타입코드는 파생/역산값. 검색·필터·시세(§7.7)가 정형 컬럼 인덱스로 직결. → 총괄 안건화 대기(P 발번 없음).
- ② 특수스킬 — 확정 방향(사용자 직접, 2026-07-13): itm_skill 정규화. 인코딩 `itm_skill = 발동확률×1,000,000 + 스킬1×1,000 + 스킬2`(ItemFusionSkill.cpp ItemGenerateSkillCombine). → 인스턴스 컬럼 skill1_id·skill2_id·skill_percent 3개. skill_percent = 스킬 발동확률(합성 결과, 골드포스와 무관). 스킬 ID(100~435, 3자리)는 스킬 정의 마스터 FK(가상 시드, D-047), 슬롯1/2 유효 풀은 장비 종류별 상이(검증·시드). §7.3 2슬롯 실물 검증 + 발동확률 추가. → 총괄 안건화 대기.
- ③ 골드포스 — 확정 방향(사용자 직접, 2026-07-13): 인스턴스에 gf_expire_at(골드포스 만료시각) 컬럼. 이는 "아이템 자체 발동확률"의 시간제 상태로 스킬 발동확률(②)과 별개. 활성/잔여는 현재시각 대비 파생(저장 안 함). 거래 가치·검색·시세 요인 → §7.7에 골드포스 활성/잔여 축 추가 검토. 착용·세트 발동확률 계산(같은 속성 3피스 등)은 게임플레이라 범위 밖(§7.6). → 총괄 안건화 대기.
- ④ 소유·이전 — 확정 방향(사용자 직접, 2026-07-13): 현재 소유자 = item_instance.owner_id FK(→ User). 외부 식별자 public_id(ULID)/내부 id BIGINT(B-004, itm_uuid 대응). 소유 이력 = item_ownership_history 신설(instance_id, from_owner_id, to_owner_id, transferred_at, 유형/사유) — 최초·직전·전체 체인 여기서 조회, first_owner 캐시 컬럼 두지 않음. 낙찰·구매(Order) 연계 행 추가 + 비거래 이전(관리자 지급·시드)도 통합. → 총괄 안건화 대기.
- ⑤ 인벤토리 — 확정 방향(사용자 직접, 2026-07-13): (a) 인라인. 인스턴스가 owner_id + slot_no 직접 보유(실 SQL itm_usr_id+itm_slot). 별도 인벤토리 테이블 없음 — §7.8 "별도 인벤토리 애그리거트 여부"를 '불필요'로 닫음. 96칸 상한은 비즈니스 제약(등록·이전 시 빈 슬롯 검사). 장착 슬롯(user_equipments)은 게임플레이라 범위 밖(§7.6). → 총괄 안건화 대기.
  - ⑤-1 출품=에스크로 — 확정 방향(사용자 직접, 2026-07-13): 출품 시 아이템을 정규 인벤토리에서 제외하고 경매/고정가가 보유(에스크로). 별도 출품 테이블 신설 없음(Auction/FixedSale이 instance_id 보유). 중복 출품 방지 = 인벤토리→출품중 CAS 단일 승자(D-008 패턴 재사용, 부분 유니크 인덱스 불요). 게임머니 홀드와 에스크로 대칭. 슬롯 해제 이점. 유찰·취소 복귀: 판매자 정규 슬롯 여유 있으면 슬롯, 만실이면 임시보관(⑤-2)으로 — 복귀 항상 성공. 낙찰 이전도 동일(여유 슬롯 or 임시보관), Order 단일 TX(§5, §7.8, D-053).
  - ⑤ 위치 모델(ERD 확정 대상): 아이템은 한 시점 정확히 한 위치 — 정규 인벤토리(slot_no) / 임시보관(별도 테이블) / 출품 에스크로(리스팅 보유). '위치 단일 진실' 표현(디스크리미네이터 vs 테이블 존재)과 XOR 불변식은 ERD 작성 시 제약으로 확정.
  - ⑤-2 임시 인벤토리(오버플로우) — 확정 방향(사용자 직접, 2026-07-13): (b) 별도 임시보관 테이블. 낙찰 시 구매자 정규 슬롯 여유 없으면 임시보관 배정 → 거래 성립을 인벤토리 여유에 종속시키지 않음. 임시보관은 상한 없음(무기한 성공 보장). 보관 기한(expire_at)은 선택 속성(nullable), 회수 규칙 미확정. 불변식: 정규 슬롯(slot_no 보유) XOR 임시보관(임시 테이블 행 존재) — ERD 제약으로 강제.
