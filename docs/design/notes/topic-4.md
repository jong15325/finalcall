# 작업 노트 — 주제 4 동시성 파생 메모

유형 4 작업 노트. 근거로 인용 금지(참고용). 정본은 총괄 D-008.
domain-spec 작성 시 반영할 파생 사항 정리.

## D-008 파생 (domain-spec 반영용)
- 명문화 요구(4-A): "정합성은 DB, 처리량은 락" 원칙 문장을 domain-spec에 명시. 백엔드가 구현 시 인용.
- 4-B: 종료성 전이(SOLD/CANCELLED)는 조건부 CAS UPDATE 단일 승자 패턴.
- 4-C 조건 1: 단일 TX 유지 vs outbox 승격 최종 결정은 주제 6 종료 직후 총괄 재확정 안건으로 자동 회부 → 주제 6 끝나면 즉시 outbox 프롬프트 작성.
- 4-D 조건 2: 소프트 클로즈 마감 연장 판단을 입찰 수용과 "동일 직렬화 단위"에 포함(입찰 성공했는데 연장 누락되는 틈 방지).
- 총괄 지정 필수 케이스 4건(buyNow 경합 / 취소 vs 첫 입찰 / SOLD-Order 원자성 / 마감 폭주)은 D-008에서 커버 확인 완료.

## D-005 파생 (domain-spec 반영용)
- FixedSale의 SOLD도 경매 SOLD와 동일하게 Order 애그리거트로 핸드오프(구매 경로 단일화).
- 유찰(UNSOLD) 후 재등록은 별도 플로우 없음 — 신규 등록으로 처리(범위 절단).
- SCHEDULED는 경매만. FixedSale은 미지원(비대칭 허용).
