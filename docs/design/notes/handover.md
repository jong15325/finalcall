**재설계가 오면 내 것이 정면으로 대상이다 — 그런데 뒤가 이미 굳어 있다.**
- 내 소유 = `docs/spec/` 3종(domain-spec v0.5 / erd v0.7 / api-contract v1.4) + `docs/frontend-planning/`(screen-spec v0.4 / skeleton-plan v0.3) + `docs/design/`.
- **비대칭이 핵심이다**: 스펙은 종이라 고치면 되지만 **구현·DB는 이미 나가 있다** — auth·member·게이트웨이 구현분, Flyway **V4까지 소비**(V1 init · V2 notice_auditor · V3 user_and_balance · V4 자연키 UK). Flyway는 append-only라 **되돌리는 게 아니라 V5+로 덮는 것**뿐이다. 스펙만 재설계하면 그 순간 스펙과 DB가 갈라진다.
- 재설계 결과가 `spec/`에 닿으면 **`[6]` 절차가 발동한다**(변경 요청 → 총괄 승인 → **기획만** 수정 → 총괄 전파). **재설계라고 이 절차가 면제되지 않는다.** 그리고 `[6.3]`·D-092가 근거 줄 3단 갱신(①델타 검토 →②반영 →③근거 줄)을 요구한다 — 오늘 그 3단을 안 돌아서 낡은 게 두 건 나왔다(아래).
- 재설계가 **체계 축(규칙)과 프로젝트 축(설계)에 동시에** 걸린다. `[1.5]` — 각 축 종결자가 자기 축만 정한다. **컨설턴트=규칙, 총괄=설계·시퀀싱, 나=spec 문서.** 한 사람이 다 정하는 그림이면 그게 틀린 것이다.
