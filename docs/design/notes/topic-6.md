# 주제 6 사용자·거래 범위 작업 노트

성격: 미확정 분석/초안 — 타 역할 근거 인용 금지 (유형 4)
관련: D-050~053, outbox/010, mgmt/outbox/017

## 확정 요지 (정본 D-050~053)
- 사용자: 단일 User, 역할은 행위 기반(등록=판매자, 입찰/구매=구매자). 관리자=권한 플래그.
- 머니 모델(2단):
  - 캐시: 토스페이먼츠 테스트 결제 API로 충전. 별도 "충전 도메인"(콜백 검증·멱등키). 거래 TX와 분리.
  - 게임머니: 캐시↔게임머니 교환(비율 파라미터화, 추적표 등재). 거래·입찰·정산은 전부 게임머니.
  - 역방향(게임머니→캐시 환전)·환불: 범위 절단(domain-spec 명시, 이견 시 에스컬레이션).
- 입찰 자금: 입찰 시 게임머니 홀드(에스크로). 낙찰 시 차감, 패자 홀드 해제.
- 4-C: 단일 TX 유지(D-053). 충전(외부)만 분리, 거래 TX에 외부 연동 엮기 금지.

## domain-spec 반영 항목 (주제 6 작성 시)
- "충전/교환 플로우" 소절 추가: 캐시 충전(외부 콜백·멱등) → 게임머니 교환 → 거래.
- 홀드 해제 규칙 명시 — 미정 세부(P 후보, 입찰 도메인 two-way door):
  - 후보 (i) 상위 입찰 발생 시 이전 최고입찰자 홀드 즉시 해제 (자금 회전 빠름, 직관적)
  - 후보 (ii) 마감 시 일괄 해제 (홀드 누적으로 잔액 묶임)
  - 잠정 leaning: (i). domain-spec 작성 시 확정.
- 환전·환불 범위 절단 명시.

## 동시성 필수 케이스 (누적, notes/topic-4와 동기)
- 홀드·해제·차감 경합(D-052).
- 마감 처리 시 최고입찰 차감 + 나머지 홀드 해제(주제 7 연계).
