# [프론트 → 총괄] 결정 요청: 스켈레톤 레인 분담·순서 (PF 기획 → F 구성 → 생성 → repo)

배경: 사용자가 프론트 스켈레톤 진행 방식을 지시했다. 요지 — (1) 프론트 저장소는 스켈레톤 완성 후 생성(선생성 아님), (2) 스켈레톤 기획은 프론트 기획(PF)이 담당, 스켈레톤 구성은 프론트 구현(F)이 담당, (3) 프론트 Claude Code가 스켈레톤 생성 후 레포에 업로드. 파트 간 순서·분담(경계·시퀀싱)이라 D-074에 따라 총괄 확정을 요청한다. 현재 F는 구성 초안(F-002)을 병렬 진행 중, Claude Code 생성 프롬프트(outbox/003)는 보류로 내렸다.

안건 1. 스켈레톤 레인 순서·분담 확정
- 선택지: (a) PF 스켈레톤 기획(무엇을·범위·IA 셸·토큰 통합 방침) → F 구성(어떻게·툴링·배선·Claude Code 프롬프트) → 프론트 Claude Code 생성 → 사용자 repo 생성·push (b) 기존안(F가 구성까지 단독 진행)
- 추천: (a) — 사용자 지시와 D-077(PF=프론트 기획 소유)·D-074(선행 게이팅)에 정합. PF 기획이 상류 기준선(screen-spec 연장선)이 되고 F 구성이 이를 구현 레벨로 배선하면 재작업이 적다.
- 요청: 승인 시 총괄이 PF에 "스켈레톤 기획" 작업 지시 발신(F는 PF에 직접 지시 불가). F 구성은 병렬 착수하되 PF 기획과 어긋나면 F가 정합(진행측 부담).

안건 2. repo 생성 시점 재확인(059 대비 변경)
- 059는 "셋업 시 계약 복사본 생성"이었으나, 사용자 지시로 repo는 스켈레톤 완성 후 생성한다. 스켈레톤은 로컬 작업 디렉터리에서 생성→검증(DoD)→그 후 repo 생성·계약 v1.2 복사본 헤더 기입(D-030)·초기 push(사용자).
- 요청: 이 시점 변경 확인(계약·타 역할 무영향, 프론트 내부 로지스틱스).

회신: 필요 — 안건별 채택/기각 + (승인 시) PF 스켈레톤 기획 지시
신규 발번 ID: 없음 (레인 재편 = 사용자 지시·총괄 시퀀싱 사안. F-002는 구성으로 재배치 주석 처리)
