# [디자인 → 총괄] 정보 공유: D-090 관측 — 마운트 뷰는 stale이 아니라 "바이트 절단"이며, sandbox git 경유 시 저장소 파손 경로가 있다

요지 3줄:
1. 마운트 뷰는 낡은 내용을 서빙하는 게 아니라 **파일을 줄 중간에서 잘라서** 서빙한다(절단량 8B ~ 11KB, 파일마다 제각각).
2. `git`이 그 절단된 워크트리를 읽으므로, **sandbox에서 `git add`/`commit`을 실행하면 절단된 내용이 커밋된다** — 조회 오류가 아니라 저장소 파손이다.
3. 지금 이걸 막고 있는 것은 D-090이 아니라 **D-061(커밋은 사용자가 호스트에서 단일 실행)** 이다. 우연히 막고 있다.

상세는 아래. 회신 불요.

## 1. 관측 경위

`docs/ux/` 커밋 메시지를 작성하며 변경 파일을 확인하려고 sandbox `git status`를 돌렸다. **이번 세션에 손대지 않은 파일 6개**가 `M`(수정됨)으로 나왔다 — `design-system.md` · `ux-flows.md` · `mockups/wireframe-auth.html` · `outbox/004` · `006` · `008`. 전부 직전 커밋(149cd7e)에 포함된 파일이라 변경이 있을 수 없다.

`git diff --stat`은 `14 files changed, 28 insertions(+), 218 deletions(-)` 를 보고했다. **삭제 218줄이 허구다.**

## 3. 새 사실 — 종전 관측과 무엇이 다른가

D-090 발번 당시의 관측 7건(총괄 5 + 디자인 2)은 전부 **"조회 결과가 틀리게 나온다"** 였다. 그래서 대응도 "판단 근거로 쓰지 마라"였고, 그건 옳다.

이번 건은 **한 층 아래**다:
- `git`은 마운트 뷰를 **워크트리로 읽는다.** 사람이 판단에 쓰든 안 쓰든 도구가 읽는다.
- 즉 sandbox에서 `git add .` → `git commit` 을 실행하면 **절단된 파일이 저장소에 들어간다.** 되돌리기는 되지만(git), 그 사이 다른 역할이 그 커밋을 정본으로 읽으면 오염이 번진다.
- **실패 신호가 없다.** git은 정상 종료하고 "N files changed"를 보고한다. 절단을 "사용자가 지운 것"으로 해석하기 때문이다.

## 4. `§` 문자(D-087)와의 관계 — **원인이 아니다**

절단 지점이 우연히 `§` 근처인 파일이 있어(`design-system.md:249` "계약 §5 ErrorCode"가 "계약 §"에서 끊김) D-087과 같은 병으로 보일 수 있으나 **아니다.** 절단량이 파일마다 8B·114B·3,899B·11,396B로 제각각이고 `§`가 없는 파일도 절단된다. `§` 금지(D-087)는 여전히 유효하지만 이 건의 대책이 아니다.

이 구분을 적어두는 이유: 원인을 `§`로 오귀속하면 "`§`를 지웠으니 안전하다"는 잘못된 안심이 생긴다.

## 5. 함의 — 규약 변경을 제안하지 않는 이유

**D-061이 이미 이 경로를 막고 있다.** 커밋은 사용자가 호스트에서 단일 실행하므로 sandbox git이 커밋을 만들 일이 없다. 그래서 신규 규약을 제안하지 않는다.

다만 **D-061의 근거가 하나 늘었다**는 점은 기록될 값어치가 있다고 본다. D-061은 원래 "커밋 주체 일원화"(감사 추적·사용자 통제) 사유로 채택된 규약인데, 이제 **저장소 무결성 방어**라는 두 번째 사유가 붙었다. 나중에 누군가 "CC가 커밋까지 하면 왕복이 줄지 않나"라고 D-061 완화를 제안할 때, 이 관측이 없으면 그 제안이 합리적으로 보인다. **완화 비용이 실제로는 저장소 파손이다.**

판단은 총괄 몫이다. 내가 제안하는 범위는 여기까지다.

## 6. 디자인 측 대응

U-018(호스트 도구 전용)에 이미 덮여 있어 추가 발번하지 않는다. 실무상 이번 세션에 지킨 것:
- 수신 스캔·파일 판단 전건 호스트 Grep/Read.
- bash 사용처는 `git log`·`wc -c`·md5 등 **실행·계측 한정**. 단 이번 관측으로 `git status`·`git diff`의 **내용 판단**도 신뢰할 수 없음이 드러났으므로, 앞으로 변경 파일 목록은 호스트에서 확인한 것을 정본으로 삼는다(사용자에게도 그렇게 안내했다).

## 7. 사용자에게 안내한 것

커밋은 Windows 호스트에서 실행하고, **호스트 `git status` 목록이 정본**이며 sandbox가 보고한 유령 6건이 뜨면 무시하라고 안내했다.
