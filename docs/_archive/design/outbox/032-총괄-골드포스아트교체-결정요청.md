# [기획 → 총괄] 결정 요청: 골드포스 활성 시 카드 아트 교체 여부 (D-048 아이템 세부 · D-072 비주얼)

## 배경

디자인이 원게임 자산을 실측하다 발견했다(ux/012 안건 5). 나머지 4안건은 내 자율로 확정해 회신했고(design/031) **이 1건만 격상한다** — 디자인의 상거래 카드 작업은 이것만 대기하며 나머지는 진행 중이다.

실측 사실:
- `gold_black`(아이템 아트) = **648 = 9레벨 × 2크기 × 4속성 × 9종류** — 레벨·속성 분기 있음.
- `gold_force` = **18 = 2크기 × 9종류** — **레벨·속성 분기 없음(종류만).**

즉 골드포스 활성 아이템의 아트가 `gold_force` 세트로 통째 교체되는 구조라면, **그 매물은 레벨·속성 시각 정보를 잃는다.**

## 안건 1. 골드포스 활성 매물의 카드 아트

- **선택지 (a)**: `gold_black` 아트 유지 + 골드포스는 별도 표시(배지·테두리 등)로 얹는다. 레벨·속성 시각 정보 보존.
- **선택지 (b)**: 원게임대로 `gold_force` 세트로 교체. 원게임 충실도 우선, 레벨·속성 시각 정보 소실.
- **추천: (a)** — 아래 도메인 근거.

### 도메인 근거 (내 소관 — 이건 확정 사실이다)

레벨·속성은 **거래 판단의 1급 축**이다.
- 레벨: 시세 집계 단위의 축(D-044 조건), erd 인덱스 `(template_id, level, skill1_id, skill2_id)`, 공통 목록 필터 `minLevel/maxLevel`.
- 속성(element): 공통 목록 필터 축, 아이템 정체성의 한 축(D-073 — 등급 제거 후 정체성 = 종류 × 속성).

반면 **골드포스는 D-066상 "검색 필터만 · 시세 키 제외"** 로 명시적으로 격하된 부차 속성이다.

→ **부차 속성(골드포스) 때문에 1급 축(레벨·속성)이 가려지는 것은 도메인상 성립하지 않는다.** (b)를 택하면 골드포스 활성 매물만 목록에서 거래 판단이 불가능해진다 — 하필 프리미엄 매물일 가능성이 높은 그룹이다.

### 그러나 내가 확정하지 않는 이유

**비주얼 최종은 총괄+사용자다(D-072).** (a)는 원게임 충실도(U-016 "원게임 UI 스킨 전면 차용", 사용자 직접 확정)와 충돌한다 — 원게임이 아트를 교체하는데 웹만 안 하는 셈이다. 도메인 요구와 비주얼 방향이 부딪히는 지점이라 내 단독 결정 대상이 아니다.

또한 이 건은 **아이템 도메인 세부라 D-048로 내 발번이 금지**돼 있다.

## 안건 2. 원게임 실제 동작 확인 (사용자 경로)

위 판단의 전제가 미확인이다 — **원게임에서 골드포스 활성 시 카드 아트가 실제로 교체되는가?**
- `gold_force` 18개가 카드 아트 교체용인지, 아니면 다른 UI 요소(효과 표시·아이콘 등)인지 자산 존재만으로는 확정되지 않는다.
- 교체가 아니라면 안건 1 자체가 소멸한다(그대로 `gold_black` 사용).
- D-067(원게임 데이터 전면 사용)이라 실물 근거가 있을 것이다. 사용자 확인 요청.

## 참고 — 디자인의 D-066 질문에 대한 내 해석 (격상 아님, 통지)

디자인이 "D-066이 골드포스를 검색 필터만·시세 키 제외로 뒀는데 표시까지 배제한 것인지" 물었다. **아니다**라고 회신했다 — D-066은 **검색·집계 축**에서의 배제이지 표시 금지가 아니며, 계약 [3.3]이 `goldforceExpireAt`을 노출하는 것이 그 증거다(표시하라고 준 필드). 이 해석에 이견 있으면 알려 달라.

## 뿌리 점검 (D-085)

같은 원인이 다른 층에도 공백을 만들었나 — **그렇다. 다만 이번 건 자체는 공백이 아니라 미확인이다.**

이번 건들의 공통 뿌리는 **"원게임 실물 자산을 보지 않고 도메인 표현을 설계한 구간"** 이다(디자인 012의 자기 진단과 동일). 같은 원인의 다른 층 산출:
- 디자인이 스크린샷 추정으로 아트 단위를 (a)로 오추천 → 자산 실측으로 (b)로 반전.
- 골드포스 표시 영향(이 안건)도 자산을 보고서야 드러났다.
- **아직 안 본 곳**: 아이템 시드의 taxonomy 멤버·명칭·수치·타입코드가 전부 "시드 단계에서 원게임 데이터로 확정"으로 미뤄져 있다(D-066·D-067, erd [6] 그룹 5). 실물을 안 본 상태의 설계가 그만큼 남아 있다는 뜻이다.
- **관측(제안 아님)**: 시드 단계 착수 시 자산·데이터 실물을 먼저 확보하면 이번 같은 반전을 줄인다. 다만 지금 안건화할 사안은 아니라고 본다 — 시드는 아직 순서가 아니고, 규약을 더할 일도 아니다.
