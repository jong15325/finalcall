```
[기획/설계 → 총괄] 동시성 정책 4건 결정 요청 (정책 수준, 구현 기법은 백엔드 자율)

배경: 판매 성립 시 중복 판매/중복 낙찰 방지가 핵심. 구현(락 종류 등)은 백엔드 자율이고,
여기서는 "정합성을 어느 계층이 최종 보증하는가"만 정책으로 고정하려 함.
스켈레톤에 MySQL / Redis(Redisson 분산락) 존재.

4-A) 정합성 최종 보증 계층
   - 선택지: (a) 분산락이 보증  (b) DB(조건부 원자 갱신+유니크 제약)가 최종 보증, 락은 최적화
   - 추천: (b). 원칙 "정합성은 DB, 처리량은 락".
4-B) 종료성 전이 — 추천: 조건부 CAS UPDATE(WHERE status='ACTIVE', affected=0이면 종료). 단일 승자.
4-C) SOLD ↔ Order 원자성 — 추천: 기본 단일 트랜잭션, 결제 도입 시 outbox 승격. 주제 6 의존.
4-D) 입찰 폭주 — 추천: 경매 단위 직렬화 + DB 최종 정합성. Redis 완충·기법은 백엔드 자율.

필수 케이스 4건(buyNow 경합/취소 vs 첫 입찰/SOLD-Order 원자성/마감 폭주) 모두 커버.
추천안 요약: 4-A)DB 보증+락 최적화 4-B)조건부 CAS 4-C)단일TX·outbox 승격 4-D)경매단위 직렬화
```
