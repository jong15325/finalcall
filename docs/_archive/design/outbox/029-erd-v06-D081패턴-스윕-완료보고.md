## 완료 기준 대비 (074)

### 1. erd [1] 규약 구현 지침 명문화 — 충족
기존 한 줄("자연키 유니크는 삭제 식별 컬럼을 포함")은 **의도만 말하고 구현 해석을 열어둬** V3가 함정을 밟게 했다. 그 사실을 규약에 명시하고 아래를 못 박았다.
- **확정 패턴**: `<자연키>_active GENERATED ALWAYS AS (IF(is_deleted, NULL, <자연키>)) STORED` + `uk_<table>_<자연키>_active`. 원본 컬럼 존치, `deleted_at` 널 허용 유지.
- **기각 해석 2종** — 특히 `UNIQUE(<자연키>, deleted_at)`을 **"가장 위험"** 으로 명시했다. 이유를 규약 안에 적었다: MySQL이 UNIQUE에서 NULL을 서로 다른 값으로 취급하므로 활성 행이 동일 자연키로 N개 뚫리는데, **규약 문구를 문자 그대로 만족시키면서** 그렇게 된다. 함정의 본질이 "문자 준수 + 의도 파괴"라는 점이 핵심이라 그 구조를 드러내 적었다.
- **동반 필수**: 활성 필터(`...AndIsDeletedFalse`) 누락 시 다건 반환으로 로그인 파손.
- **적용 대상 = 자연키만**: `public_id`(ULID) 등 시스템 발급 대리 식별자는 재사용되지 않아 충돌 자체가 성립하지 않음 → 패턴 불요.
- **트리거 조건**: 자연키 UK 보유 테이블에 soft delete를 **새로 도입하는 순간** 의무화.

### 2. [4.1] `user` 표 갱신 — 충족 (**074 순서와 다르게 지금 반영했다 — 아래 이유**)
`login_id_active`·`nickname_active` 생성 컬럼 + UK 반영, 원본 컬럼 존치, `deleted_at` 널 허용 유지. 표 아래 주에 재가입 의존 관계·동반 필수·길이 근거를 남겼다.

**074는 2번을 "백엔드 V4 실물 정보 공유 후"로 순서 지정했는데, 나는 지금 반영했다.** 이유:
- **[4.1]의 구조는 D-081(ACCEPTED 정본)이 이미 완전히 결정한다.** 실물을 기다려야 할 것은 Flyway **채번 번호**뿐이고, 그건 [4.1]이 아니라 [6] 매핑 소관이다(B-012 방식 b = 구현 동기화).
- 구조까지 실물을 기다리면 **"구현이 확정된 뒤 설계가 따라가는"** 형태가 되어 D-028(먼저 구현한 쪽이 기준이 되지 않는다)이 역전된다. erd가 설계 권위이고 백엔드가 erd·D-081에 맞추는 방향이 맞다.
- 074-3이 "미구현 도메인이라도 erd 표에 미리 반영해 두면 구현 시 함정을 안 밟는다"고 한 논리와도 같은 방향이다.
- 컬럼 길이(`login_id` 50·`nickname` 30)는 backend/030이 V3 실물 확인분으로 명시한 값을 인용했다. **[6] Flyway 채번 반영은 백엔드 실물 정보 공유 후로 남긴다**(미반영).
- 이견이 있으면 되돌리겠다.

### 3. soft delete 자연키 스윕 — 충족. **적용 대상 user 1건, 그 외 0건.**

**탐색 방법(D-086)**: `erd.md` 전수에 `is_deleted|deleted_at` 및 `^\| (login_id|nickname|pg_tx_id|type_code|skill_code|public_id) \|` 실행. **bash·호스트 Grep 양쪽 교차검증 — 결과 일치(stale 아님)**. 084의 오탐이 bash 마운트 stale에서 나온 건이라 부재 주장에 교차검증을 의무로 걸었다.

- **soft delete 보유 테이블 = `user` 1개.** `is_deleted` 컬럼은 [1] 규약 선언부와 [4.1] user 표에만 존재한다. 따라서 현재 함정 대상은 user뿐이고 [4.1]에서 처리했다.
- **조건부 리스크 3건**(자연키 UK 보유 · soft delete 미보유 — **현재 무관**, 도입 시 D-081 의무): `charge.pg_tx_id` · `item_template.type_code`와 `(main_category,sub_group,element,kind)` 조합 · `skill_definition.skill_code`. [4] 말미 주에 등재했다.
- **패턴 불요**: `public_id` 계열 전부(대리 식별자). FK 1:1 유니크(`user_balance.user_id`·`money_hold.bid_id`·`temp_storage.instance_id`)는 자연키 아님.
