# [기획 → 총괄] 완료 보고: 확정 스펙 3종을 `docs/spec/`으로 이동

결과
- 3종을 `docs/spec/`으로 옮겼다. 내용·버전·상태줄 무변경, 루트 잔존 0. `[6]` 절차 미발동.
- **이동 도중 D-090의 실물 재현을 관측했다** — bash 마운트 뷰가 **바로 이 3파일을 절단본으로 서빙하고 있었다.** 아래 [관측] 참조. 지시대로 `mv`를 썼다면 erd 68줄·계약 34줄·spec 41줄이 소실된 채 이동됐다.

완료 기준 대비
- **`docs/spec/` 생성 후 3종 실재**: 충족 — 호스트 Glob `docs` 하위 `**/spec/*.md` → 3건 정확일치.
- **루트에 3종 잔존 없음(복사 아닌 이동)**: 충족 — 호스트 Read `docs/domain-spec.md`·`docs/erd.md` → `File does not exist`. bash `ls *.md` → `No such file or directory`(보조).
- **3종 상호 경로 참조가 새 위치 기준으로 맞다**: 충족 — **대상 0건.** 3종은 서로를 **경로로 참조하지 않는다**(버전명으로만: "근거: domain-spec v0.5, erd v0.7"). 탐색 방법: 3파일 각각에 호스트 Grep `docs/|\.md` 전수 → 총 3건이며 전부 비대상(`CLAUDE.md` 2건 = 루트 파일·이동 무관 / `erd.md` 자기 파일명 1건 = 경로 아님·이동 후에도 참).
- **내용·버전·상태줄·근거 줄이 이동 전과 동일**: 충족 — 줄 수 3파일 전건 일치(227/409/374, 이동 전 호스트 Read 기준). 상태·소유·근거·형식·버전규칙 줄 호스트 Grep 전수 대조 → 12건 전건 문자열 일치. 경로 참조 정정분이 0건이라 **diff는 완전 공집합이다**(지시가 허용한 "경로 참조 외" 변경조차 없다).
- **`design/` 살아있는 참조 정정**: 충족 — 실측 결과 2건, 아래 [범위 실측].
- **탐색 방법 명시**: 이 보고 전체가 호스트 도구 기준이다(`[9.1]`). bash는 삭제 실행·보조 확인에만 썼고 판단 근거로 쓰지 않았다(`[9.2]`·`[9.3]`).

범위 실측 (`[5.29]` — 총괄이 세지 않은 부분)

탐색 방법: 호스트 Grep 패턴 `domain-spec\.md|erd\.md|api-contract\.md`를 `docs/design` 전수 실행 → 17건 / 8파일. 분류:

1. **정정함 — 2건.** `notes/handover.md` :22(내 소유 목록)·:55(재개 필독 순서). 둘 다 `docs/<파일>.md` → `docs/spec/<파일>.md`.
2. **비대상 — 12건.** `outbox/**` 11건 + `decision-log.md` 1건. 유형 5·3 불변, 지시 "하지 말 것" 그대로 뒀다. **총괄 실측(전체 77건/58파일 중 대다수가 이 둘)이 `design/` 안에서도 그대로 성립한다** — 17건 중 12건이 불변 문서다.
3. **정정하지 않음 — 3건, 판단 1건.** `notes/handover-kickoff-prompt.md`. 경로 참조를 갖고 있으나 **문서 전체가 이미 죽었다**: 필독이 구 정본(`management/collaboration-guide.md`)을 가리키고, 상태 요약이 "G1 대기"(현재 G4-n)이며, 상태줄·4줄 브리핑을 지시하는데 둘 다 폐지됐고(C-041·C-056), 킥오프 정본은 이제 `templates.md [14]`다(`[5.52]`). **경로만 고치면 나머지가 낡은 채로 살아 있는 것처럼 보이므로** 고치지 않고 머리에 폐기 주를 달았다. 유형 4 자유 범위 안이다(`[3]`).
   - 이 파일의 존재 자체가 `templates.md [14]` 주석("킥오프가 규약을 복사하면 사본이 늘어난다")의 실례다. 삭제 여부는 체계 축이라 내가 정하지 않는다 — 필요하면 컨설턴트 안건이다.
4. **`docs/frontend-planning/` — 대상 0건, 확인함.** D-079로 이 폴더도 내 소유라 지시의 "`design/` 자기 폴더" 표현보다 내 실제 범위가 넓다. 실측했더니 **경로 참조가 0건이었다**(호스트 Grep `domain-spec\.md|erd\.md|api-contract\.md|docs/spec` → `No matches found`). `screen-spec`·`skeleton-plan`은 스펙을 **버전명으로만** 인용한다("근거: api-contract **v1.4**"). 그래서 총괄이 그은 범위와 결과가 같다 — **범위 지정은 옳았고, 그 이유는 총괄이 든 근거(`[3.4]` 소유)가 아니라 실측상 대상이 없었기 때문이다.**

관측 — D-090이 오늘 실물로 재현됐다 (`[9.1]`·`[9.2]`의 근거 사례)

지시는 파일 이동이라 bash `mv`가 자연스러운 실행이고, `[9.3]`도 "bash는 실행에만"이라 문면상 허용된다. **그런데 이 3파일이 정확히 마운트 절단 대상이었다.**

| 파일 | bash 뷰 | 호스트 실물 | 소실 |
|---|---|---|---|
| `domain-spec.md` | 186줄 / 20,765B | **227줄** | 41줄 |
| `erd.md` | 341줄 / 21,636B | **409줄** | 68줄 (§5 인덱스 표 전체 + §6 Flyway 전체) |
| `api-contract.md` | 310줄 / 21,166B | **374줄** | 34줄 |

- 절단은 **에러 없이** 일어난다. bash `tail` 상 `erd.md`는 `| instance_id | BIGINT | N |`에서 행 중간에 끊기고, `domain-spec.md`는 UTF-8 시퀀스 중간에서 끊긴다(`cat -A` 확인). 열면 그냥 "짧은 파일"이라 의심 트리거가 없다.
- **마운트가 통째로 낡은 게 아니다.** 같은 호출에서 내가 방금 호스트로 편집한 `handover.md`, 오늘 생성된 `management/outbox/REFORM/`, `common/rules.md`(400줄, 호스트와 일치)는 전부 정상이었다. **이 3파일만 Jul 14 캐시본으로 고정돼 있었다** — 즉 "bash 뷰는 낡았다"가 아니라 **"어느 파일이 낡았는지 bash 안에서는 알 수 없다"**가 정확한 진술이고, 그래서 `[9.2]`가 조회 결과 전체를 판단에서 배제하는 형태여야 한다.
- 그래서 호스트 Read → 호스트 Write → 삭제로 옮겼다. 삭제만 bash `rm`을 썼다(내용 무관 메타 연산이고, 대체본이 호스트에 이미 실재함을 Glob으로 확인한 뒤).
- **erd v0.7 이력이 기록한 v0.6 구조 오류와 같은 뿌리다**(원인: "bash 마운트 뷰가 [5]·[6]을 서빙하지 않아 문서 말미로 오판"). 그때 서빙되지 않은 [5]·[6]이 오늘도 정확히 그 위치에서 잘려 있었다. **같은 파일이 같은 지점에서 두 번 물렸다** — 일회성 사고가 아니라 지속 상태다.

뿌리 점검 (`[5.30]`)
- 이 작업이 필요했던 이유는 `rules.md [3]`이 2026-07-15 개편(C-056)에서 `spec/`을 선언했는데 실물이 따라오지 않아서다. **규약 개정과 실물 이행이 다른 축·다른 역할에 걸쳐 있어(체계=컨설턴트 선언 / 프로젝트=총괄 시퀀싱 / 실행=소유 역할) 그 사이에 "정본이 거짓인 구간"이 생긴다.** 이번엔 총괄이 REFORM/002로 닫았다. 구조적 처방은 체계 축이라 내가 내지 않는다.

다음 단계 제안
- 타 역할 참조 정정 전파(`_broadcast/`)는 이제 순서가 열렸다 — 실물이 `docs/spec/`에 있다.
- **전파에 위 [관측]을 실어 달라.** 각 역할이 자기 폴더 참조를 고치려고 파일을 열 텐데, bash로 열면 절단본을 보고 "참조가 없다"고 오판할 수 있다. 부재 판정이 `[5.29]`에 걸리는 작업이라 탐색 방법 지정이 필요하다.
