## 설계 판단 (자율 — 이견 시에만 회신)

1. **계약 기준을 v1.3으로 읽었다.** 063 지시문은 v1.2지만 발신 이후 v1.3이 확정·전파됐다(065). 델타(§1.6 엣지 오류)는 IA·라우트 무영향이라 스켈레톤 구조는 불변이고 api 클라이언트 에러 처리에만 반영된다.
2. **회원 리소스 라우트를 두지 않았다.** 069 계약 v1.4 확정 전이므로 마이페이지 placeholder조차 만들지 않는다(계약 부재 상태의 임의 가정 금지, D-028 선착순 기준 금지). v1.4 확정 시 screen-spec §2 추가 → 후속 반영한다.
3. **색값 A안의 근거를 "교체 비용 국한"으로 명문화했다.** 토큰명·구조를 고정해 비주얼 확정 시 값 치환만으로 끝나게 한다.
4. **`/login`·`/signup`을 별도 최상위 영역으로 올리지 않았다.** 접근상 공개이므로 Public의 최소 변형이며, 표현 세부는 디자인·F에 남긴다.

## 총괄 판단 요청 1건 (스켈레톤 차단 아님)

**인증 세션 지속성(persist) 방침 — 보안(S) 검토 필요.**
- refresh 토큰을 브라우저 저장소에 두면 XSS 노출면이 생긴다. 자금 시스템이라 프론트 내부 편의 문제가 아닌 **보안 사안**으로 판단해 기획이 단독 확정하지 않았다.
- 스켈레톤은 **메모리 세션(persist 없음)** 으로 시작한다 — 프론트 CLAUDE.md §4와 정합하고 가장 보수적이며, 나중에 완화하는 편이 반대보다 싸다. 따라서 **스켈레톤은 차단되지 않는다**.
- 다만 `/me/wallet/charge/confirm`는 외부 PG 리다이렉트 복귀 경로라 하드 리로드 시 메모리 세션이 소실된다. **wallet 도메인 착수 전까지** 방침 확정이 필요하다. 보안 게이트 2 또는 별도 안건 배치를 요청한다.
