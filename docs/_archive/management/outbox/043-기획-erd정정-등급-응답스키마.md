# [총괄 → 기획/설계] 작업 지시: erd §6 Flyway 정정(6절) + 등급 확정 + 응답 스키마 공백 (3건 묶음)

1. erd §6 Flyway 매핑표 정정 (6절 승인, B-012):
- 배경: 스켈레톤이 V1(init_schema)·V2(notice_auditor) 기소비 → append-only상 도메인
  마이그레이션은 V3부터. 백엔드가 user/balance를 V3__user_and_balance로 작성(B-012).
  erd §6은 V1__user_and_money를 지시해 실제 채번과 어긋남(스키마 변경 아님, 버전 라벨).
- 승인: erd §6 매핑표를 실제 채번 기준으로 정정. 방식 = 구현 진행 동기화(백엔드가 실제 채번을
  정보 공유 → 기획이 §6 갱신). V3=user_and_balance 시작, 화폐(charge/exchange/hold)는 후속
  버전 분리. 변경 이력에 B-012·6절 기록. 계약 무영향.

2. 등급(grade) 단계 수·명칭 확정 (디자인 U-004 연계):
- erd grade는 INT 축이나 값 목록이 스펙에 없음. 디자인이 색 5티어(gray→green→blue→purple→gold)로
  잠정 매핑(U-004 PROPOSED). 등급 단계 수·명칭을 확정해 디자인에 전달(표시 매핑, 계약 무영향).
  원게임 데이터 전면 사용(D-067)이라 원게임 등급 체계 채택 가능.

3. 목록/상세 응답 필드 스키마 계약 공백 (디자인 ux-flows §6-1):
- 디자인·프론트가 경매 목록/상세 응답의 구체 필드 스키마를 필요로 함. api-contract §3이
  "요약+스냅샷" 수준이라 필드 열거 공백. 계약에 응답 스키마를 구체화(초안 보강)할지 또는 백엔드
  구현 응답 기준으로 정합할지 판단·반영. 계약 문안 변경이면 6절.
