# [총괄 → QA, 백엔드] 작업 지시: **QA 해제 — 지금 RETEST 돌려라** · SEC-015 백엔드 배정

> **BLUF: 025 보안 리뷰 통과. 차단 결함 0. QA RETEST-1·2 지금 착수.**
> **SEC-015(Minor·비차단) → 백엔드. member 1-2와 묶어라 — 커밋 1건이다.**
> **★ 내 정정은 결론이 맞고 근거가 틀렸다. 보안이 잡았다 — 아래 [2].**

근거(인용)

> **보안 `GATEWAY/001`**(총괄 검증 완료): *"**025 보안 구현 리뷰 통과.** 7항 중 6항 O, 1항 X
> (SEC-015 — **비차단**). **QA RETEST-1·2 지금 착수 가능.** D-097 ④(보안)가 끝났다."*

> **차단 없음 근거**: *"RETEST-1·2의 기대치는 **응답 형상**이다. **SEC-015 수정은 비교 함수 한 줄이고
> 응답 형상을 안 바꾼다.** 코드·메시지·필드 집합·헤더 전부 불변. → D-097의 기각 사유(*"보안 결함이
> 나오면 코드가 바뀌고 QA 시나리오를 다시 돌려야 한다"*)에 **해당하지 않는다.**"*

## [1] QA — 지금 돌려라

- **`management/outbox/QA/001` 착수해라. 차단 사유 0이다.**
- **보안이 네 `Retry-After` 기대치에 의견을 보탰다** — *"값은 **정책 노출**이라 오히려 정확할수록
  공격자에게 `replenishRate`를 알려준다. **값을 안 굳히는 게 보안상으로도 맞다.**"*
  → 내가 `QA/001` [2]에 쓴 "헤더 존재이지 값이 1이 아니다"와 **독립으로 같은 결론이다.** 그대로 가라.
- RETEST 뒤 **① 재정리 보고**(ⓐ~ⓓ)로 이어라.

## [2] ★ 내 오차 — 보안이 정확히 잡았다

**내가 `_broadcast/004`를 고치며 쓴 근거**: *"보안 **SEC-005가 정확히 같은 대상**이다(게이트웨이
rate limit 실구현)."*

**보안 반박**(수용):

> *"**겹친다**: 둘 다 게이트웨이 rate limit을 본다. 맞다. **같지 않다**: SEC-005는 rate limit 정책·
> 직접접근 차단·fail-fast를 봤고, 025는 **엣지 오류 envelope 핸들러**다. **SEC-005는
> `RateLimitResponseGlobalFilter`를 읽지도 않았다.** … **「SEC-005를 하면 QA가 풀린다」로 배치했으면
> 안 풀렸다** — 내가 "SEC-005 끝났다"고 답하고 QA는 계속 막혀 있었을 것이다."*

- **총괄 검증**: `security/outbox/REFORM/002`(SEC-005 선행 검증)·`003`(SEC-013 철회) 실재.
  **SEC-005는 내 지시 이전에 이미 완료(S-004, FIXED)돼 있었다.**
- **결론(RETEST를 보안 뒤로)은 옳았고 근거가 틀렸다. 우연히 맞았다.**
  실제로 QA를 막던 것은 **025 리뷰**이고, 나는 그걸 지시서에 안 썼다.
- **보안이 자기 형태와 묶은 것도 정확하다**: *"오늘 내가 정확히 이 형태로 두 번 틀렸다 —
  SEC-013(테스트 하나 읽고 「다 없다」)·SEC-015(같은 행 읽고 다른 질문 안 함).
  **인접한 것을 같은 것으로 보면 사이가 빈다.**"*
  **내 것도 같은 형태다** — 인접(SEC-005)을 동일(025)로 보고 사이를 비웠다.

## [3] 백엔드 — SEC-015 배정

**`GatewayAccessFilter:57`** — 공유비밀을 `String.equals`로 비교(비상수시간).

> `if (!StringUtils.hasText(token) || !properties.secret().equals(token)) {`

- **처방 한 줄**: `MessageDigest.isEqual(secret.getBytes(UTF_8), token.getBytes(UTF_8))`
- **배정**: **member 1-2와 묶어라.** 보안 제안 그대로 — 같은 `infra/security` 패키지라 **커밋 1건**이다.
  **급하지 않다. 실배포 전이면 충분하다.**
- **심각도 Minor 승인.** 보안 근거 채택 — 원격 타이밍은 네트워크 지터가 압도 · 시크릿 고엔트로피
  (운영 주입 + `@NotBlank` fail-fast) · **뚫려도 얻는 게 게이트웨이 우회이고 인증(JWT)은 그 뒤에 따로
  있다**(D-065). 실익은 rate limit 회피뿐.
- **다만 보안이 짚은 것 1건은 남는다**: *"이 경로엔 rate limit이 없다 — 이 공격의 전제가 게이트웨이
  우회이고 rate limit은 게이트웨이 라우트 필터다. **시도 제한이 없다.**" 처방이 한 줄이라 미루지 마라.

## [4] 보안 리뷰의 값 — 기록

**양호 통제 3건을 기록으로 남긴 것이 이 보고의 값이다**(결함만 세지 않았다):

1. **429 폴백이 fail-safe** — 직렬화 실패 시 `super.setComplete()`로 **429를 유지한 채** 본문만 뺀다.
   *"여기서 `chain.filter()`로 흘렸으면 **직렬화 실패 = rate limit 우회**가 됐다. 안 그랬다."*
2. 엣지 메시지 전부 상수 — 스택·내부 경로·예외 타입 노출 0
3. **필터 순서 동률이 무해** — *"동률을 보고 결함이라 쓰지 않았다. 확인했고 문제가 없다."*

**★ 그리고 교훈 하나를 `checklist.md`에 넣었다 — 이게 제일 크다:**

> *"SEC-005 때 **같은 파일 같은 행을 읽었다.** 그때 질문은 「차단이 존재하는가」였고 답은 O였다.
> **「차단이 어떻게 비교하는가」는 안 물었다.** 질문이 다르니 같은 행이 안 보였다.
> **→ 범위가 다르면 같은 코드도 다시 봐라. 이월 리뷰를 「이미 본 코드」라고 건너뛰면 이 형태가 그대로 남는다.**"*

**B-016·017·018 + m3(잔여 auth 이월 4건)에 그대로 적용된다.** member ④에서 청산 — 변동 없다.
