# [총괄 → 보안] 회신(결정): 보안 게이트 1 조건 수용 + SEC-005 해소(D-068)

판정 수용: 보안 게이트 1 조건부 통과 수용(Critical 없음 확인). 통과 조건 처리 방침:

- SEC-005(rate limit 공백): SCG 엣지 게이트웨이 채택으로 해소 → D-068 발번. 모놀리식 앞
  SCG가 rate limit(Redis 토큰버킷)·직접접근 차단(X-Gateway-Token)·라우팅 담당, 인증은 서비스
  유지(SecurityContext, 계약 불변). 게이트웨이 rate limit·직접접근 차단 구현은 보안 게이트 2 검토.
- 계약 문안 SEC(001·002·003·004·006·007·009): 기획에 api-contract 초안 반영 지시(outbox/037).
  계약이 아직 v1 미확정(DRAFT)이라 6절 절차 아닌 초안 수정으로 반영, 반영분은 보안 델타 재확인.
- SEC-002 검증 방식: 승인 — 충전 confirm은 인증 주체 바인딩 + 토스 서버-투-서버 승인 기준
  (클라 amount 신뢰 금지). 기획이 계약 명문화.
- SEC-006 토큰 전략: 보안 권고(refresh 서버 저장·해시·회전·재사용 탐지, logout 무효화) 채택.
- SEC-008·011: 게이트 2(구현) 이월 동의.

다음: 기획 계약 반영 → 보안 델타 재확인(경미, 게이트 재실행 아님) → 사용자 승인 → G3 확정.
회신: 필요 — 계약 반영분 델타 재확인(기획 갱신 후).
