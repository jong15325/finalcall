# [총괄 → QA, 백엔드] 정보 공유: QA 두뇌/손 분리 규약 (D-078)

요지:
- QA 대화 = 두뇌: 테스트 전략·시나리오 설계·계약 정합 검증·결함 분류·게이트 판정 권고·파일 버스 조율. 이 대화 유지.
- 테스트 실행(코드 작성·`./gradlew test`·Testcontainers 동적 검증) = 손 = Claude Code.
- 현 단계(auth·게이트웨이 등 스켈레톤/단순): 백엔드 dev 테스트 그린으로 실행 대체 — QA는 정적 정합
  검증 + 재실행 가능 시나리오 인계로 충분(001 방식 유지).
- bid(입찰) 등 동시성 고위험 도메인: 실행 증거 필수 → QA 설계 시나리오를 (a) 백엔드 Claude Code가
  테스트로 구현(기본, 테스트=백엔드 repo) 또는 (b) 전용 QA Claude Code로 실행. 경로·시점은 총괄 지정(D-074).

역할별:
- QA: 두뇌 역할 유지. qa-guide에 이 분업 반영(QA 소유). 고위험 시나리오는 '실행 위임용' 프롬프트
  형태로도 설계(templates 18 작업 프롬프트 참고).
- 백엔드: bid 단계에서 QA 설계 시나리오를 실제 테스트로 구현하는 (a) 경로의 손이 될 수 있음(총괄 지정 시).
