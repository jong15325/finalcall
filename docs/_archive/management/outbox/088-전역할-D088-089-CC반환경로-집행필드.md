## D-088 — Claude Code 완료 보고 반환 경로 (백엔드·프론트)

**문제**: Claude Code가 작업을 마치고 **완료 보고를 어디 저장할지 사용자에게 매번 물었다.** 위치가 규약에 없어 사용자가 즉석 판단했고 결국 채팅 출력을 **손으로 복붙 중계**했다. D-069가 "사용자가 부모 대화에 전달"로 **사용자 중계를 전제**했는데, Claude Code는 다른 대화에 텍스트를 넘길 수단이 없고 가진 건 파일 도구뿐이다. 규약 위반이 아니라 **규약이 실행 문서로 번역되지 않은 것**이다.

**규칙**:
- 반환 경로 = **`docs/<파트>/notes/cc-reports/<프롬프트번호>-<도메인>-<작업>.md`**. 번호는 작업 프롬프트와 일치. 채팅 요약은 선택, **정본은 파일**.
- **부모 대화가 "수신 확인" 시 인계함을 스캔해 흡수** → 자기 outbox 보고로 버스 재진입. 사용자 중계 불요.
- **금지 경로**: `<파트>/outbox/`(발신 이력 전용 — CC가 쓰면 발신 주체 오염), `decision-log.md`·`inbox-log.md`, 타 역할 폴더 전부.
- `cc-reports/`는 CC의 outbox가 **아니라 인계함**이다. **Claude Code는 여전히 파일 버스 노드가 아니다**(D-069 유지 — 이 조항은 불변).
- D-069의 **리포트 루프 조항만** SUPERSEDED. 나머지 D-069 조항은 전부 유효.

**프론트(F)**: 스켈레톤 scaffold를 Claude Code로 돌릴 때 이 경로를 쓴다. `frontend/outbox/003` 재발신 시 반영하라. 백엔드는 `notes/claude-code-kickoff.md`에 자율 선반영 완료(030부터 발효).

## D-089 — 결정 로그 `집행` 필드 (전 역할)

**문제(실측 2건)**: **"상위 규약은 옳은데 하위 실행 문서에 번역되지 않아 현장이 어기거나 즉석 판단한다."**
1. `erd [1]` soft delete 규약 → `erd [4.1]` user 표에 미반영 → **"표만 보고 구현하면 정확히 V3가 나온다"** → QA-001 Major.
2. `D-069` 리포트 루프 → templates [18]·킥오프에 미반영 → CC 반환 경로 부재 → 복붙 마찰.

둘 다 규약 자체는 옳았고 **실행 문서와의 비동기화**가 피해를 냈다.

**규칙**: 결정 로그 항목에 `집행:` 필드를 둔다.
- 내용 = "이 결정을 실행하는 문서 경로 + 반영 여부".
- 실행 문서가 없으면 **"없음(결정 자체가 정본)"** 이라 명시. **공란 금지.**
- 발번 시점에 반영이 안 끝났으면 반영 지시 경로(outbox 번호)를 적는다.
- 소급 기재 불요.

**한계(과장하지 않는다)**: 이 필드는 실행 문서를 **지목하게 할 뿐 반영 품질을 보증하지 않는다.** 발견 확률을 올리는 장치이지 방지 장치가 아니다.
