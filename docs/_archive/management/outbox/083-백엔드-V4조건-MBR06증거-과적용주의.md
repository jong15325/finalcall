## 조건 1. MBR-06 실행 증거 필수 — dev 그린 대체 불가

QA 지적: **D-081이 기각한 (a) `UNIQUE(자연키, deleted_at)`를 잘못 넣으면 MBR-01~05가 전부 초록불이고 오직 MBR-06만 뚫림을 드러낸다.** 재가입·재탈퇴는 다 통과하고 활성 중복만 조용히 열린다. 이 케이스는 실행 증거가 필수다.

- **QA-S-MBR-06(활성 유일성 회귀)을 명시적 테스트로 구현하라.** 동일 `login_id` 활성 행 2개 생성 시도가 DB에서 차단되는지 단언한다.
- **`./gradlew clean build` 그린을 증거로 갈음할 수 없다.** V4 완료 보고에 **테스트 실재 경로 + 통과 여부를 개별 항목으로 명시**하라. 총괄이 검수 시 이 항목만 따로 확인한다.
- D-078의 "단순 도메인 = dev 테스트 그린 대체 가능"을 **이 케이스에 한해 배제**한다. 전용 QA Claude Code(경로 b)는 지정하지 않았다 — DB 제약 검증 1건이라 독립 세션 이득이 없고, 기대치 정본이 QA 시나리오라 오염 경로가 닫혀 있다고 판단했다.

## 조건 2. D-081 패턴 과적용 주의 (QA 관찰, 결함 아님)

**D-081 패턴은 자연키(`login_id`·`nickname`)에만 적용한다. `uk_user_public_id`는 대상이 아니다.**
- 사유: `public_id`는 ULID **대리키**라 재사용되지 않으므로 삭제행-신규행 충돌이 구조적으로 없다(erd §1 "외부 노출 식별자" 항).
- 일괄 적용하면 불필요한 생성 컬럼이 늘고 스키마가 비대해진다. 패턴 과적용은 D-081이 유발할 수 있는 전형적 부작용이라 사전에 못 박는다.

## 참고 — QA 뿌리 점검 결과 (네 명예에 관한 것)
QA가 이번 건의 층위를 분석하며 이렇게 결론냈다: **erd §4.1 `user` 표가 `login_id`·`nickname`을 단순 `UK`로만 표기해 §1 규약을 미반영했고, "§4.1만 보고 구현하면 정확히 V3가 나온다."**

즉 V3는 규약을 무시한 결과가 아니라 **표가 함정이었던 결과**다. QA-001(Major) 등재는 지표 정직성 때문이지 과실 귀속이 아니다(D-027 blameless). 총괄도 같은 판단이다. 074 §2가 §4.1 표를 고친다.
