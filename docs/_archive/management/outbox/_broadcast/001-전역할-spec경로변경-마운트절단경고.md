# [총괄 → 전 역할] 정보 공유: 확정 스펙 3종이 `docs/spec/`으로 이동했다 + **bash로 스펙을 읽지 마라**

요지
- **경로 변경**: `docs/domain-spec.md`·`erd.md`·`api-contract.md` → **`docs/spec/`** 아래. 내용·버전 무변경(v0.5 / v0.7 / v1.4). 근거 = `common/rules.md [3]`.
- **★ 경고**: bash 마운트 뷰가 **바로 이 3파일을 절단본으로 서빙 중이었고 아직 살아 있다.** `erd.md`는 bash에서 **409줄이 아니라 341줄**이고 **[5] 인덱스 표 전체와 [6] Flyway 매핑 전체가 없다.** 에러 없이, 조용히.
- **자기 폴더의 살아있는 참조만 각자 정정한다.** 불변 문서(`outbox/**`·`decision-log.md`)는 고치지 않는다.

## 1. 경고부터 — 이게 경로 변경보다 중요하다

기획이 이동 중에 관측했다(`design/outbox/REFORM/001` [관측], 실측·재현):

| 파일 | bash 뷰 | 호스트 실물 | 소실 |
|---|---|---|---|
| `domain-spec.md` | 186줄 | **227줄** | 41줄 |
| `erd.md` | 341줄 | **409줄** | **68줄 — [5] 인덱스 표 전체 + [6] Flyway 전체** |
| `api-contract.md` | 310줄 | **374줄** | 34줄 |

**세 가지를 알아야 한다.**

**(1) 실패 신호가 없다.** 절단은 에러를 내지 않는다. 행 중간에서 끊기고(`erd.md`는 `| instance_id | BIGINT | N |`에서), 열면 그냥 "짧은 파일"이다. **의심 트리거가 없다.**

**(2) 마운트가 통째로 낡은 게 아니다 — 이게 핵심이다.** 같은 시점에 `common/rules.md`(400줄)·오늘 생성된 파일들은 bash에서도 **정상**이었다. **이 3파일만 캐시본으로 고정돼 있었다.** 그러니 "bash가 낡았나 확인해보자"가 성립하지 않는다 — **어느 파일이 낡았는지 bash 안에서는 알 수 없다.** 정상 파일이 섞여 있어서 오히려 안심하게 된다.

**(3) 지속 상태다. 일회성 사고가 아니다.** `erd` [5]·[6]은 **2026-07-15 erd v0.6 구조 오류를 만든 바로 그 미서빙 구간**이고, 오늘 같은 지점에서 또 잘려 있었다. **같은 파일이 같은 자리에서 두 번 물렸다.**

### 그래서 너희에게 뭘 요구하나

- **확정 스펙을 bash로 읽지 마라.** `cat`·`head`·`tail`·`grep` 전부. 호스트 Read/Grep만 쓴다(`rules [9.1]`·`[9.2]`).
- **특히 "없다"고 판정할 때 조심해라.** `[5.29]`(부재·수량은 탐색 방법 명시)가 정확히 여기서 문다. bash로 `erd.md`에 grep을 돌리면 **[5]·[6]에 있는 것은 전부 "없음"으로 나온다.** 없는 게 아니라 안 서빙된 것이다.
- **백엔드에게 특히**: Flyway 채번을 `erd [6]`에서 확인하는 순간이 오면, bash로는 **[6]이 존재하지 않는다.** V5 이후를 그 위에서 판단하면 v0.6 구조 오류가 세 번째로 재현된다.
- **파일을 옮기거나 복사할 때도 그렇다.** 기획이 지시대로 `mv`를 썼다면 **143줄이 소실된 채 이동됐고 아무도 몰랐을 것이다.** 기획은 호스트 Read → 호스트 Write → 삭제로 우회했다. `mv`가 "실행"이라 문면상 허용돼 보인 것이 함정이었다 — **총괄 지시문의 결함이다. 내가 `mv`를 자연스럽게 만들었다.**

## 2. 경로 변경 — 각자 할 일

**대상**: 자기 폴더의 **살아있는 참조**만.

```
docs/domain-spec.md   → docs/spec/domain-spec.md
docs/erd.md           → docs/spec/erd.md
docs/api-contract.md  → docs/spec/api-contract.md
```

**탐색**(호스트 Grep, bash 금지 — 위 [1] 참조):

```
domain-spec\.md|erd\.md|api-contract\.md
```

**분류 규칙** — 3종으로 갈린다:

| 분류 | 처리 |
|---|---|
| `outbox/**`(유형 5) · `decision-log.md`(유형 3) | **고치지 않는다.** 발신·결정 시점의 사실이다. 소급 정정 금지 방향(D-087·D-089)과 같다 |
| `notes/**`(유형 4) · 지침 · 킥오프 · `findings.md` 등 **살아있는 참조** | **고친다** |
| 문서 전체가 이미 죽었으면 | 경로만 고치지 말고 **폐기 주를 달아라.** 경로를 고치면 나머지 낡은 내용이 살아 있는 것처럼 보인다(기획 판단, 승인) |

**보정용 실측** — 기획 폴더 결과다. 네 폴더도 비슷한 비율일 것이다:

> `docs/design` 전수 17건 / 8파일 → **정정 2건 · 불변이라 제외 12건 · 죽은 문서라 폐기 주 3건.**

**세지 말고 실측해라.** 총괄 전체 실측은 77건/58파일이나 **대다수가 불변 문서다.** 숫자에 놀라지 마라 — 실제로 고칠 건 폴더당 한 줌이다.

**하지 말 것**
- **타 역할 폴더를 고치지 마라**(`[3.2]`). 자기 폴더만.
- **`spec/` 3종을 고치지 마라**(`[3.4]` — 소유는 기획). 내용·버전 무변경으로 이동됐고 그대로 두면 된다.
- **`common/rules.md`를 고치지 마라**(체계 축·컨설턴트 소유).
- **커밋하지 마라**(사용자 단일 실행 · sandbox git 금지 C-040).
