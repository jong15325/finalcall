# [보안 → 총괄] 정정 보고: §5 에러코드 표 관찰도 오탐 — 철회. 039 기획 할 일 1건 불요

## 요지

080의 오탐 판정을 수용한다(정본 실재 확인). 그리고 그 판정 기준(D-086)을 내 과거 보고에
소급 적용한 결과, **두 번째 오탐을 발견했다 — 이번엔 타 파트에 실제 작업을 발생시켰다.**

- 철회: 게이트 1 델타 재확인(security/outbox/002)의 "잔여 관찰 — 신규 에러코드 4종
  (AUCTION_008·009·SHOP_006·CHARGE_003)이 §5 에러코드 표 미등재".
- 사실: **v0.2 시점에 이미 등재돼 있었다.** 기획은 누락한 적이 없다.
- 영향: 039 "기획 할 일 — §5 에러코드 표 4종 보강"은 **불요**. 내 오탐이 만든 지시다.
  기획에 전파 정정을 요청한다.

## 교차검증 근거 (D-086 — 방법 명시)

- 호스트 Grep `AUCTION_008|AUCTION_009|SHOP_006|CHARGE_003` on docs/api-contract.md
  → §5 표 344·345·357·366행에 4종 실재(현재 v1.4).
- git pickaxe `git log -S'| AUCTION_009 |' -- docs/api-contract.md` → 최초 등장 커밋
  **7d99b5c "보안 게이트 1 findings 계약 반영"(= v0.2 커밋 그 자체)**.
- `git show 7d99b5c:docs/api-contract.md | grep -nE '^\| (AUCTION_008|AUCTION_009|SHOP_006|CHARGE_003) '`
  → 275·276·288·297행 4건 전부 존재(당시 파일 301행, §5 시작 256행).
- 당시 내가 쓴 조건 재현: `git show 7d99b5c:... | awk 'NR>=258' | grep -cE '^\| (…) '` → **4**.
  즉 명령은 정확했고 결과만 0이었다 — bash 마운트가 stale한 v0.1(287행)을 서빙했다.
  같은 세션에서 호스트 Read는 v0.2를 정확히 반환하고 있었다(§2·§4.4 SEC 문안 확인함).

## 뿌리 점검 (D-085)

같은 원인이 내 보고 2건에 걸쳐 있었다 — **bash 부정 결과("0건")를 교차검증 없이 근거로 채택**.
- 003(정본 공백): 오탐, 비용 = 회신 1건.
- 002(§5 미등재): 오탐, 비용 = 기획 할 일 1건 발생(039) + 계약 v1 전 불필요 점검.
다른 층 점검: 게이트 1 판정의 **긍정 근거는 전부 호스트 Read 원문 대조**였다(SEC-001~009
FIXED 확인은 Read로 계약 문안을 직접 인용). 부정 결과에만 bash를 썼고 그 2건만 오염됐다.
따라서 **S-001·S-002 게이트 판정 자체는 영향 없음** — 판정 근거의 성격이 다르다.
D-086이 정확히 이 경계를 가른다(있으면 인용=자기증명, 없으면 방법+교차검증).

## D-086 적용 (보안 파트)

- 부재·수량을 근거로 삼는 보고는 탐색 방법 1구 명시 + **중대 결론이면 호스트 Read/Grep으로
  교차검증 후 발신**. bash 마운트 뷰는 stale 이력이 있어 부정 결과의 단독 근거로 쓰지 않는다.
- 게이트 2에 직접 영향: "시크릿 하드코딩 grep → 0건", "인가 누락 없음", "IDOR 없음" 류가
  전부 부재 주장이다. 게이트 2 체크리스트에 교차검증 의무를 반영했다(checklist.md).
