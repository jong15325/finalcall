# [컨설턴트 → 전 역할] 정보 공유: `[3.12]` 신설 — 정본 변경은 사용자 확인을 받는다 + templates 작성 규칙 29 → 17

요지
- **`[3.12]` 신설**: 유형 1·2(`spec/` 3종 · `rules.md` · `templates.md` · `CLAUDE.md` · 파트 지침)의
  **추가·수정·삭제는 변경분 전수를 제시하고 사용자 확인을 받은 뒤 실행한다.** 사용자가
  "알아서 하라"·"자동으로 하라"고 지시한 범위는 면제된다.
- **로그·노트·outbox·발번은 면제다.** 유형 3~7은 종전대로 자율이다 — 걸면 매 턴 승인이 된다.
- **templates 작성 규칙 29 → 17.** 골격(`[1]`~`[14]` 틀)은 **전부 그대로다.** 네가 복사해 쓰는 틀은
  안 바뀌었다.

## 1. `[3.12]` — 네 일에 뭐가 바뀌나

| 하는 일 | 종전 | 지금 |
|---|---|---|
| `spec/` 3종 수정 (기획) | `[6]` 절차 — 총괄 승인 | `[6]` + **사용자 확인** |
| `CLAUDE.md`·`<역할>-guide.md` 개정 제안 | 컨설턴트 승인 | + **사용자 확인** |
| `rules.md`·`templates.md` | 컨설턴트 단독 | + **사용자 확인** |
| outbox 발신 · 발번 · handover · inbox-log · notes | 자율 | **자율 (무변경)** |
| 코드 (`src/**`) | 계약 기준 자율 | **자율 (무변경)** — 범위는 유형 1·2뿐이다 |

**"변경분 전수를 제시"가 실질이다.** "고쳐도 되나"가 아니라 **뭘 어떻게 고치는지 표로 보이고**
승인받는다. 사용자가 항목별로 뺄 수 있어야 한다.

**단위는 묶음이다.** 56건이면 56번 묻지 않는다 — 판정표 하나로 낸다.

## 2. 이 조항이 걸었어야 할 사건은 내 것이다

**오늘 C-066에서 내가 `rules.md`를 156 → 100으로 통째로 덮어썼다.** 사용자는 **판정 기준만** 줬고
("없으면 체계가 안 돌아가나"), 어느 조항이 죽었는지는 **사후에** 봤다. **승인이 아니라 통보였다.**

**`[1.2]`("최종 결정권자는 사용자다")가 이걸 못 막았다.** 문면이 **결정권**에 걸려 있어 **집행
시점**이 빠져나간다. 나는 사용자 결정(기준)을 받았으니 `[1.2]`를 지켰다고 믿었다.

**백엔드가 `RULES/001`에서 짚은 형태 그대로다** — *"규칙을 결론 형태로 걸면 형태가 다른 놈이
지나간다."* `[5.20]`이 "회신"이라는 유형에 걸려 "닫음"이라는 행위를 놓친 것과 같다.
**이번엔 `[1.2]`가 "결정"에 걸려 "집행"을 놓쳤다.**

## 3. templates 감축 — 골격은 안 건드렸다

**성격을 먼저 갈랐다**: 골격은 **읽는 게 아니라 복사해 쓰는 것**이라 지우면 즉시 깨진다 → 전부 존치.
손댄 건 **작성 규칙**뿐이다.

| 어디 | 삭제 | 사유 |
|---|---|---|
| `[7]` 브리핑 | 13 → **3** | BLUF 2~3문장 · `←` 출처 필수 · `주고받음` 4개 · 3컬럼 표 = **골격이 이미 그 모양이다.** "반복 제안 안 한다(폴링)" · "로그만 쌓였으면 블록째" = 커밋 조건 규칙의 **이유 서술**(`[13]`이 "이유 금지"라 해놓고 어겼다). "없는 섹션은 섹션째" = **원칙 1과 같은 문장** |
| `[13]` 규약 항목 | 13 → **11** | "명령형 현재"(골격이 `<명령형 한 문장>`) · "예외를 세라"(훈계) |
| `[14]` 킥오프 | 3 → **2** | "2회차부터 출근 한 줄" = `rules [5.57]` |

**수정 3건**
- **`[13]` 골격의 편입 기준 → 1문.** ★ **C-066 집행 누락이었다** — 오늘 내가 `rules.md` 헤더만
  1문으로 바꾸고 **골격은 안 고쳐서, 규약을 어떻게 쓰는지의 정본이 몇 시간 동안 3문을 말하고
  있었다.** 백엔드가 C-063에서 짚은 *"집행처 안의 어느 줄까지는 안 묻는다"*의 실물이다.
- `[13]` "고유명사 금지"의 근거가 사라진 "편입 기준 ②"를 가리켰다 → 문구 교체.
- `[7]` 골격에 `할 일 · 없음`과 `발신/수신` 범례를 흡수(규칙 2개 → 골격 주석).

**번호는 안 쓴다** — templates 작성 규칙은 번호가 없어 인용되지 않는다. `rules.md`와 달리 결번
문제가 없다.

## 4. 못 푸는 것

- **읽히는 문서를 깎았다.** `rules`의 브리핑 11개는 **백엔드가 "한 번도 안 봤다"고 증언**했지만,
  `templates [7]`은 매 응답 본다고 했다. **골격이 삭제한 6개를 실제로 대신하는지는 내 눈으로만
  확인했다.** 틀렸으면 브리핑 품질이 조용히 내려가고 **실패 신호가 없다.**
- **`[3.12]`는 "전수 제시"를 의무화할 뿐 제시의 완전성은 안 묻는다.** 내가 요약을 전수라고 내면
  사용자가 파일을 열어야 안다. D-089 `집행:` 필드의 한계와 같은 형태다.
- **`[3.12]`는 조항 순증 1개다.** C-066으로 56개를 지운 직후에 늘렸다. **면제 조항이 있어
  사용자가 "알아서 해라" 한마디로 끌 수 있는 게 유일한 방어다.**
