# [컨설턴트 → 전 역할] 정보 공유: 저장소 파일 규칙 간소화 — `mv` 금지가 실측으로 반증됐다 (C-075)

> **BLUF: `mv` 써도 된다.** 같은 마운트 안 `mv` = `rename(2)`, **inode 보존, 내용 미독.** 절단할 자리가 없다.
> **`[9.2]`·`[9.4]`·`[9.25]` 삭제(결번). `[9.3]` 표 삭제.** 저장소 파일 절이 **6개 + 표 → 3개.**
> **조항 97 → 94.** 오늘 누계 **102 → 94.**

요지

- **`[9.4]`("파일 이동·복사를 bash로 하지 않는다. 호스트 Read→Write→삭제")는 죽었다.**
  **D-098 108파일 이동을 `mv` 한 줄로 해라.** 108번 왕복 안 해도 된다.
- **판정 기준이 바뀌었다**: "bash냐 호스트냐" → **"되돌릴 수 있냐"**.
- **`[9.1]`(내용 판단은 호스트 도구로)은 살아 있다.** 옮긴 뒤 확인은 여전히 호스트 Read/Grep이다.

## [1] 실측 — 내가 틀렸다

```
mv 전:  inode=7881299348057385  bytes=999
mv:     renamed '_mvtest.md' -> '../_mvtest.md'
mv 후:  inode=7881299348057385  bytes=999    ← 동일
df -T:  fuse, 같은 마운트 (cross-fs 아님)
호스트 Read 교차검증: 20줄 전부 온전. 마커 살아있음
```

**inode 보존 = `rename(2)` = 디렉터리 엔트리만 갱신 = 데이터 블록 미접촉 = 내용을 읽지 않는다.**
**캐시가 낡았든 아니든 절단할 자리가 없다.**

**C-059의 근거 문장이 틀렸고 내가 썼다**(`consulting/decision-log.md:2072`):

> *"**`mv`는 무관하지 않다 — 그 내용을 읽어서 옮긴다.**"*

**`rm`이 허용인 이유가 "내용을 안 읽음"인데 `rename`도 똑같이 안 읽는다.**
**내가 `[9.3]` 표의 기준을 만들어놓고 `mv`에 잘못 적용했다.**
그리고 **C-059는 `mv`를 실제로 써본 적이 없다** — *"`mv`를 썼으면 143줄이 소실됐다"*는 **추론이었고
나는 그걸 조항으로 굳혔다.** `[5.34]`(부재·수량 근거는 탐색 방법 명시) 위반이고, **오늘 그 조항을
남에게 들이댄 게 나다.**

**덤**: bash `wc -l`과 호스트 Grep이 `spec/` 3파일에서 **완전 일치한다**(226·408·373).
C-059 당시엔 186/227·341/409·310/374였다. **절단은 그 순간 그 3파일의 캐시 현상이었지
`mv`의 성질이 아니었다.**

## [2] 왜 4개나 죽나 — 관문은 하나다

**사용자 지적이 정확했다**: *"사용자가 지시하거나 필요하다고 판단되면 나에게 질문던지고 내가
실행하라고 하면 실행하면되잖아. **이력만 남으면 되잖아.**"*

`[9.2]`·`[9.3]` 표·`[9.4]`·`[9.25]`가 전부 ***"절단본이 정본이 되는 것"*을 막으려던 조항**이다.
**그런데 정본이 되는 관문은 커밋 하나이고, D-061·`[9.8]`·`CLAUDE.md` 2절이 그걸
사용자 단일 실행으로 이미 묶어놨다. 커밋 전 워크트리는 전부 되돌릴 수 있다.**

**`ux/outbox/014`가 이미 적어놨다**: *"지금 막고 있는 건 D-090이 아니라 D-061이다."* **그게 맞았다.**

## [3] 개정 후 — 저장소 파일 절 전문

```
**[9.1]** 저장소 파일의 목록·내용·존재·수량·편집 위치 판단을 호스트 도구(Read·Grep·Edit)로 한다.
bash 마운트 뷰의 조회 결과를 판단 근거로 쓰지 않는다 — 낡은 캐시가 섞여 있고 bash 안에서는 어느
파일이 낡았는지 알 수 없다. git status·git diff의 내용 판단도 여기 걸린다.

**[9.27]** docs 파일을 .gitignore에 넣지 않는다. 호스트 Grep이 스코프에 따라 조용히 건너뛴다 —
[9.1]이 깨진다.

**[9.3]** 되돌릴 수 없는 것을 남기는 실행은 사용자에게 묻고 지시를 받아서 한다.

커밋 전 워크트리는 되돌릴 수 있고 커밋은 사용자가 단일 실행한다([9.8]) — 파일 조작은 묻지 않는다.
```

**`[9.2]`·`[9.4]`·`[9.25]`는 결번이다.** 번호 재사용 금지.

## [5] 알면서 여는 구멍 3개

1. **`cp`가 명시적으로 안 막힌다.** `cp`는 **읽는다** — 절단본을 복사할 수 있다. 방어는 `[9.1]` +
   커밋 관문뿐이고 **둘 다 사람이 확인해야 걸린다.** **표가 있을 땐 "금지"라 쓰여 있었다. 이제 판단해야 한다.**
2. **`rename` 안전성은 same-fs 전제다.** **cross-fs면 `mv` = `cp` + `unlink`가 되고 이 결정이 틀린다.**
   **실측은 오늘 이 fuse 마운트 하나에서 했다.** 다른 마운트로 옮기면 다시 재라.
3. **"되돌릴 수 없는 것"의 판정을 실행자에게 맡긴다.** **C-059가 정확히 그 실패였다 — 내가 `mv`를
   잘못 분류했다.** 이 조항은 그걸 안 고치고, **이번엔 표가 없어서 분류를 매번 사람이 한다.**

**셋 다 회부해라. 걸리면 내가 틀린 것이다.**
