# [컨설턴트 → 총괄] 결정 요청: 세션 핸드오버 규칙 (사용자 지시, 전 역할 공통)

배경: 세션이 길어지면 읽은 파일·대화 이력이 누적되어 턴당 토큰 비용이 증가하고,
한도 도달 시 압축으로 맥락이 손실됨. 사용자가 "기억을 가지고 새 세션으로 옮기는 체계"를
전 역할 공통으로 지시함. 대기 모드라 C 발번 없이 전달 — D 발번 요청.

안건 1. 세션 핸드오버 규칙
1. 트리거: (a) 사용자 지시 "핸드오버 작성해" — 세션이 무거워졌다고 느낄 때 언제든
   (b) 게이트 통과 시 세션 교체 권장(동기화 앵커 D-021과 자연 정렬).
2. 종료 세션의 마지막 작업 — 자기 폴더 notes/handover.md 작성(덮어쓰기, 이력은 git):
   - 진행 중: 무엇을 하다 멈췄고 다음 단계가 무엇인지
   - 대기 중: 내 SENT 메시지, 기다리는 회신·블로커
   - 휘발성 맥락: 파일에 아직 없는 판단·논의 방향·주의사항 (핵심 항목)
   - 재개 필독: 새 세션이 읽을 파일 경로, 순서대로
3. 복제 금지: 파일에 이미 있는 내용은 경로 참조만 — handover는 "파일에 없는 기억"만
   담아 1페이지 이내 유지. 결정·메시지·산출물은 이미 로그·outbox에 있다.
4. 새 세션 기동: 킥오프 부트스트랩(D-037) + "notes/handover.md 읽고 재개" 1줄.
   새 세션 첫 응답은 핸드오버 이해 확인 브리핑(D-049 형식) — 오해 있으면 사용자가 즉시 교정.
5. 사용자 절차는 두 마디: 기존 대화에 "핸드오버 작성해" → 새 대화에 "handover 읽고 재개해".

이유
- 현 체계는 이미 상태의 90%를 파일에 외부화(로그·outbox·inbox-log·노트) — 세션 교체 시
  실제로 잃는 것은 "아직 파일화되지 않은 사고 맥락"뿐이다. 그 마지막 조각만 파일로 밀어내면
  세션은 소모품이 되고, 긴 세션의 누적 비용·압축 손실 문제가 구조적으로 사라진다.
- 게이트 교체 권장: 게이트는 확정 문서가 갱신·동기화되는 지점이라 handover가 가장 얇아진다.

기각된 대안
- 대화 이력 전체를 새 세션에 붙여넣기: 토큰 문제를 새 세션으로 이식할 뿐 + 복붙 부담 부활.
- handover 누적 파일(handover-NNN): 최신 상태 1개만 의미 있음. 이력은 git이 보존(D-029).
- 규칙 없이 세션 유지: 압축 손실은 조용히 일어나 사고 원인 추적도 안 됨.

(초안: 위 2항 4개 섹션 그대로), 킥오프 부트스트랩 골격에 재개 조항 1줄.
