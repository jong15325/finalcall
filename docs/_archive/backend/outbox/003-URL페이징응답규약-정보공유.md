# [백엔드 → 기획, 총괄] 정보 공유: URL·페이징·응답 규약 확정 (B-004~007)

요지(3줄):
- D-035 조기 기동 안건2·3 확정(아키텍처 무관 범위). 계약(G3) api-contract "공통 규약" 섹션에 인용 가능.
- URL/식별자/페이징/정렬·필터/응답 envelope 규약 확정. 상세는 backend/decision-log.md B-004~007.
- 단, "사용자 식별 헤더" 규약(`X-User-Id` vs SecurityContext)은 아키텍처 결정 B-008(outbox/002)에 종속 → 보류. 그 부분만 제외하고 반영 바람.

## 확정 규약
- 노출 식별자(B-004): 외부 노출 리소스(auction, item)는 `public_id`(ULID) URL 노출, 내부 조인·FK는 `id`(BIGINT). 인증 뒤 내부 전용은 `id` 허용.
- URL(B-004): URI 경로 버저닝 `/api/v1/...`, 리소스 복수형, 종속은 1단 중첩(`/auctions/{id}/bids`), 상태전이 동사 URL 최소화.
- 페이징(B-005, B-007): cursor 기본(실시간 목록)/offset 예외(관리·소규모).
  - cursor 응답: `data: { content: [...], nextCursor: "...|null", hasNext: bool }` (fetchSize+1로 hasNext 판정).
  - offset 응답: `data: { content: [...], page, size, totalElements, totalPages }`.
- 정렬·필터(B-006): 정렬 `sort=field,{asc|desc}` 다중 허용·화이트리스트. 필터 명명 파라미터+화이트리스트(범위 `minXxx`/`maxXxx`, enum 대문자). 정렬·필터 필드는 ERD 인덱스와 1:1.
- 응답/에러 envelope(안건3 재확인): 스켈레톤 유지. 성공/에러 독립 타입.
  - 성공 `ApiResponse`: `{ success:true, data, timestamp }` (data null이어도 포함).
  - 에러 `ErrorResponse`: `{ success:false, code:"DOMAIN_NNN", message, errors?, timestamp }` (errors는 검증 실패 시만).
  - 코드는 도메인 enum(`ErrorCode` 구현, `{DOMAIN}_{3자리}`), status 별도 보유. 공통 `CommonErrorCode`(예: `COMMON_004 LOCK_ACQUISITION_FAILED`→409, 분산락 실패).

## 반영 요청(참고)
- ERD: 정렬·필터 화이트리스트 필드 = 인덱스 설계 근거(D-044 검색·시세 축 정합).
- 계약(G3): 위 공통 규약을 "공통 규약" 섹션에 인용. 개별 엔드포인트·상태전이 액션 명세는 기획 확정 사안.

회신: 불요 (참고·반영용, 계약 내용 변경 아님). 이견 시 결정 요청으로 격상 바람.
단, 사용자 식별 헤더는 B-008 회신 후 별도 공유 예정.

신규 발번 ID: 없음(기존 B-004~007 공유). B-008은 outbox/002로 별도 에스컬레이션 진행 중.
