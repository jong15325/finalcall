# FinalCall 표준 템플릿

모든 산출물의 **모양**을 정한다. 여기엔 규칙이 없다 — 무엇을 할지는 `rules.md`, 왜 그런지는 `<역할>/decision-log.md`.

- **부팅 필독**: `rules.md` + 이 문서 + `spec/` 3종.
- **소유·개정**: 컨설턴트.
- **원칙 3개**
  1. **최소 골격만.** 채울 것이 없는 섹션은 **지운다.** 빈 섹션·"해당 없음"을 남기지 않는다.
  2. **필수 필드는 비우지 않는다.** 비울 것 같으면 보내지 말고 격상한다.
  3. **템플릿은 상한이 아니라 하한이다.** 더 쓸 수 있으나 골격은 지킨다.

최종 갱신: 2026-07-16 · 반영: C-064 · C-065 · C-069 (작성 규칙 29 → 17)

## [6] 결정 로그 항목

**`결과`는 긍정·부정·중립을 한 섹션에 나란히 쓴다.** 좋은 것과 나쁜 것을 갈라 놓으면 나쁜 것이
각주가 되고, 비용이 없는 척하는 문서가 된다.

```
## <ID>. <제목 — 결정 내용이 드러나게>

상태: PROPOSED | ACCEPTED | ON-HOLD | SUPERSEDED (→ 대체 ID) · 소유: <역할> · 관련: <참조 키워드> · <날짜>

맥락
- <어떤 힘들이 충돌하나. 중립적으로. 실물 근거는 경로·수치로>

결정
- <"~한다". 원자적 1건. 능동태, 애매어 금지>

결과
- 좋아짐: <이 결정이 개선하는 것>
- 나빠짐: <이 결정이 치르는 비용·추가 부담·새로 생기는 위험>
- 못 푸는 것: <처방이 닿지 않는 범위. 효과를 과장하지 않는다>

기각된 대안
- <대안>: <기각 사유>

집행: <반영처 + 반영됐는지 확인하는 방법>

레퍼런스: <외부 근거. 없으면 이 줄 삭제>
```

- SUPERSEDED 시 본문을 지우지 않고 상태 줄 아래에 **대체 사유 주**를 단다
- 에스컬레이션 후엔 상태 줄에 `escalated-as <ID>`만 추가한다

## [13] 규약 항목 (`rules.md` · 파트 지침)

### 문서 골격

```
# <제목>

<이 문서가 답하는 질문 1줄>

- **부팅 필독**: <해당하면>
- **소유·개정**: <역할>. 개정하면 **덮어쓴다**(불변 아님, 이력은 git).
- **편입 기준 — 1문이다**: **"이 조항을 지우면 뭐가 실제로 깨지나?"**
  답이 *"언젠가 누가 실수할 수도"* 면 이 문서에 없다. 답이 *"지금 A가 B를 못 찾는다"* 면 있다.
- **읽는 법**: 모든 규칙은 `[N.M]` 번호 + 명령형 한 문장이다. 표는 참조 데이터일 뿐 규칙이 아니다.
  **결번은 정상이다** — 삭제된 조항의 번호를 재사용하지 않는다.

최종 갱신: <날짜> · 반영: <최신 결정 ID>

---

## [N] <절 제목>

<표가 필요하면 여기. 표는 참조 데이터다>

**[N.1]** <명령형 한 문장>
**[N.2]** <명령형 한 문장>
근거: <결정 ID 목록>
```

### 작성 규칙

- **이유 금지.** "왜냐하면"이 나오면 그건 결정 로그로 간다. `근거:` 줄의 ID가 이유를 대신한다
- **고유명사 금지.** 도메인명·특정 ID·버전·날짜가 규칙 문장에 들어가면 **다음 사례에서 조항이
  거짓이 된다** (문서 경로는 예외)
- **한 항목 = 한 규칙.** 묶지 않는다
- **번호 없는 규칙을 두지 않는다.** 굵게 쓴 문장도 규칙이면 번호를 준다
- **절차는 예외다.** 순서가 본질인 규칙은 한 번호 아래 번호 목록으로 쓴다.
  쪼개면 `[N.M.1]`이 되어 과설계다
- **절 번호는 고정한다.** 항목이 늘어도 절을 새로 만들지 않는다
- **항목 번호는 append-only다.** 신설은 **그 절의 최대 번호 + 1**을 쓴다.
  **중간에 삽입해 뒤를 밀지 않는다** — 밀면 불변 문서(`outbox/`·`decision-log`)의 인용이 영구히 어긋난다
- **번호는 발번 순서, 배치는 논리 순서다.** 둘이 어긋나는 건 정상이다(`[9.25]`가 `[9.3]` 옆에 있어도 된다).
  **결번도 정상이다** — 조항이 빠지면 번호를 재사용하지 않는다
- **개정 후 `^\*\*\[N\.\d+\]` grep으로 중복·결번을 확인한다.** 조항이 아니라 작업 습관이다
- **개정 후 `git show <직전 해시>:<파일>`로 기존 조항의 번호가 이동했는지 대조한다.**
  **밀림은 grep으로 안 잡힌다** — 밀린 번호는 중복도 결번도 아니고, 전부 연속이고 전부 실재하는
  다른 조항을 가리켜서 **실패 신호가 없다**
- 마지막 절은 **"이 문서가 하지 않는 것"** — 내용별 정본 경로 표

## [14] 킥오프 프롬프트 (새 세션 첫 기동)

브리핑 `할 일`의 `프롬프트` 칸에 그대로 넣는다. **사용자가 복붙만 한다.**

```
너는 FinalCall 프로젝트의 <역할>이다.

필독: docs/common/rules.md · docs/common/templates.md · docs/spec/ 3종
자기 폴더: docs/<역할>/
저장소: D:\Java\finalcall

출근해라.
```

- **역할 설명을 여기 쓰지 않는다.** `rules.md [1]`에 있다. 킥오프가 규약을 복사하면 사본이 늘어난다
- 특정 안건 한정 기동이면 마지막 줄을 `출근하고 <안건>만 처리해라`로 바꾼다
