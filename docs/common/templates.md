# FinalCall 표준 템플릿

모든 산출물의 **모양**을 정한다. 여기엔 규칙이 없다 — 무엇을 할지는 `rules.md`, 왜 그런지는 `<역할>/decision-log.md`.

- **부팅 필독**: `rules.md` + 이 문서 + `spec/` 3종.
- **소유·개정**: 컨설턴트.
- **원칙 3개**
  1. **최소 골격만.** 채울 것이 없는 섹션은 **지운다.** 빈 섹션·"해당 없음"을 남기지 않는다.
  2. **필수 필드는 비우지 않는다.** 비울 것 같으면 보내지 말고 격상한다.
  3. **템플릿은 상한이 아니라 하한이다.** 더 쓸 수 있으나 골격은 지킨다.

최종 갱신: 2026-07-15 · 반영: C-054

## [6] 결정 로그 항목

**`결과`는 긍정·부정·중립을 한 섹션에 나란히 쓴다.** 좋은 것과 나쁜 것을 갈라 놓으면 나쁜 것이
각주가 되고, 비용이 없는 척하는 문서가 된다.

```
## <ID>. <제목 — 결정 내용이 드러나게>

상태: PROPOSED | ACCEPTED | ON-HOLD | SUPERSEDED (→ 대체 ID) · 소유: <역할> · 관련: <참조 키워드> · <날짜>

맥락
- <어떤 힘들이 충돌하나. 중립적으로. 실물 근거는 경로·수치로>

결정
- <"~한다". 원자적 1건. 능동태, 애매어 금지>

결과
- 좋아짐: <이 결정이 개선하는 것>
- 나빠짐: <이 결정이 치르는 비용·추가 부담·새로 생기는 위험>
- 못 푸는 것: <처방이 닿지 않는 범위. 효과를 과장하지 않는다>

기각된 대안
- <대안>: <기각 사유>

집행: <반영처 + 반영됐는지 확인하는 방법>

레퍼런스: <외부 근거. 없으면 이 줄 삭제>
```

- SUPERSEDED 시 본문을 지우지 않고 상태 줄 아래에 **대체 사유 주**를 단다
- 에스컬레이션 후엔 상태 줄에 `escalated-as <ID>`만 추가한다

## [7] 사용자 브리핑 (매 응답 끝, 채팅)

사용자가 **작업 전체를 한 번에 보는 수단**이다. 결론이 맨 앞, 근거가 뒤.

```
---
**브리핑**

> **<결론 1~2문장. 이번 응답에서 무엇이 결정·완료·발견됐나>**

**한 일**
- **<작업명>** ← <출처: 어느 지시·결정·스레드에서 나왔나 · 경로 또는 ID>
  <구체적으로 무엇을 했나 1줄> → `<산출물 경로>`
- **<작업명>** ← <출처>
  <1줄> → `<경로>`

**주고받음**
- **→ <파트>** `<경로>` — <요지 1줄> · 회신 필요 | 불요
- **← <파트>** `<경로>` — <요지 1줄>

**발번·상태** · <ID> <상태> · <ID> → <상태 변경>

**할 일**

| # | 무엇 | 발신/수신 |
|---|---|---|
| 1 | **<동사로 시작>** — <왜 / 안 하면 뭐가 막히나> | **→ <파트>** |
| 2 | **<동사로 시작>** — <이유> | **← <파트>** |
| 3 | **<동사로 시작>** — <이유> | — |

**프롬프트** · #<번호> → <파트>
```
<복붙할 문구>
```

**커밋**
```
git add <경로> && git commit -m "<제목>

<본문>"
```
---
```

**작성 규칙**

- **맨 위 인용줄이 BLUF다.** 사용자가 그 줄만 읽어도 상황을 알아야 한다. **2~3문장을 넘기지 않는다** —
  넘으면 그냥 문단이지 BLUF가 아니다
- **`한 일`의 각 항목에 `←` 출처를 반드시 단다.** 출처가 파생 사슬을 보여준다. 출처를 못 쓰겠으면
  근거 없이 한 일이므로 그 사실을 적는다
- **`주고받음`은 방향·파트·경로·요지 4개를 모두 쓴다.** `→`는 발신, `←`는 수신
- **`할 일`은 동사로 시작하고 이유를 붙인다.** "검토"가 아니라 "templates.md `[6]` 결과 필드를 검토 —
  다음 결정부터 이 형식으로 쓴다". 없으면 `**할 일** · 없음`
- **`발신/수신`은 사용자가 어느 대화를 열어야 하는지를 준다.** `→`는 사용자가 그 파트에 전달,
  `←`는 그 파트에서 받아와야 할 것, `—`는 사용자가 여기서 판단할 것
- **표에는 컬럼 3개만 둔다.** 프롬프트·커밋은 **표 아래 블록**으로 뺀다 — 여러 줄이라 칸에 안 들어가고,
  커밋은 대화당 1회라 컬럼으로 두면 나머지 행이 전부 `—`가 된다
- **`프롬프트` 블록은 복붙만 하면 되게 완성형으로 쓴다.** 사용자가 문구를 짓게 하지 않는다.
  어느 할 일의 것인지 `#<번호> → <파트>`로 잇는다. 없으면 블록째 지운다
- **`커밋` 블록은 그 응답에서 산출물을 냈을 때만 낸다.** `git add` 부터 전체 명령을 완성형으로 쓴다
- **반복 제안하지 않는다.** 이전 응답의 산출물은 이미 제안했다. 사용자가 커밋했는지 알 수 없다고
  해서 "혹시 몰라" 다시 내는 것은 폴링이다 — 사용자가 `커밋`을 지시하면 그때 낸다
- 대화 로그만 쌓였거나 산출물이 없으면 **블록째 지운다**
- 없는 섹션은 **섹션째 지운다**
- 파일에 쓴 내용도 요지는 여기 노출한다

## [13] 규약 항목 (`rules.md` · 파트 지침)

### 문서 골격

```
# <제목>

<이 문서가 답하는 질문 1줄>

- **부팅 필독**: <해당하면>
- **소유·개정**: <역할>. 개정하면 **덮어쓴다**(불변 아님, 이력은 git).
- **편입 기준**: 3문 전부 "예"인 것만 있다.
  ① 앞으로 새로 시작할 작업에도 적용되나 ② 도메인명·파일명·ID·날짜를 지워도 규칙이 성립하나
  ③ 읽고 다르게 행동하나
- **읽는 법**: 모든 규칙은 `[N.M]` 번호 + 명령형 한 문장이다. 표는 참조 데이터일 뿐 규칙이 아니다.

최종 갱신: <날짜> · 반영: <최신 결정 ID>

---

## [N] <절 제목>

<표가 필요하면 여기. 표는 참조 데이터다>

**[N.1]** <명령형 한 문장>
**[N.2]** <명령형 한 문장>
근거: <결정 ID 목록>
```

### 작성 규칙

- **명령형 현재.** "~한다 / ~하지 않는다". 과거·경위 서술 금지
- **이유 금지.** "왜냐하면"이 나오면 그건 결정 로그로 간다. `근거:` 줄의 ID가 이유를 대신한다
- **고유명사 금지.** 도메인명·특정 ID·버전·날짜가 규칙 문장에 들어가면 편입 기준 ②에 걸린다
  (문서 경로는 예외)
- **한 항목 = 한 규칙.** 묶지 않는다
- **번호 없는 규칙을 두지 않는다.** 굵게 쓴 문장도 규칙이면 번호를 준다
- **절차는 예외다.** 순서가 본질인 규칙은 한 번호 아래 번호 목록으로 쓴다.
  쪼개면 `[N.M.1]`이 되어 과설계다
- **절 번호는 고정한다.** 항목이 늘어도 절을 새로 만들지 않고 해당 절 안에 붙인다
- **예외를 세라.** 예외가 2개를 넘으면 규칙 자체가 틀린 것이다. 다시 설계한다
- 마지막 절은 **"이 문서가 하지 않는 것"** — 내용별 정본 경로 표

## [14] 킥오프 프롬프트 (새 세션 첫 기동)

브리핑 `할 일`의 `프롬프트` 칸에 그대로 넣는다. **사용자가 복붙만 한다.**

```
너는 FinalCall 프로젝트의 <역할>이다.

필독: docs/common/rules.md · docs/common/templates.md · docs/spec/ 3종
자기 폴더: docs/<역할>/
저장소: D:\Java\finalcall

출근해라.
```

- **역할 설명을 여기 쓰지 않는다.** `rules.md [1]`에 있다. 킥오프가 규약을 복사하면 사본이 늘어난다
- 2회차부터는 `출근` 한 줄이면 된다. 킥오프는 첫 기동에만 쓴다
- 특정 안건 한정 기동이면 마지막 줄을 `출근하고 <안건>만 처리해라`로 바꾼다
