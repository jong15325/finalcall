# FinalCall 공통 규약

이 문서 하나로 "지금 뭘 해야 하나"가 끝난다. **"왜 그런가"는 여기 없다** — `근거:`의 결정 ID를
해당 역할 `decision-log.md`에서 찾는다.

- **부팅 필독**: 이 문서 + `common/templates.md` + `spec/` 3종. 그 외는 필요할 때만 연다.
- **소유·개정**: 컨설턴트. 소유 역할이 제안하고 **컨설턴트가 승인·결정**한다(총괄 승인 없음, [1.4]).
  개정하면 **이 문서를 덮어쓴다**(불변 아님, 이력은 git).
- **편입 기준**: 3문 전부 "예"인 것만 이 문서에 있다. 하나라도 "아니오"면 결정 로그로 간다.
  ① 앞으로 새로 시작할 작업에도 적용되나 ② 도메인명·파일명·ID·날짜를 지워도 규칙이 성립하나
  ③ 읽고 다르게 행동하나
- **읽는 법**: 모든 규칙은 `[N.M]` 번호 + 명령형 한 문장이다. 표는 참조 데이터일 뿐 규칙이 아니다.

**[1.6]** **총괄은 라우터가 아니다.** 파트의 말을 다른 파트에게 옮기지 않는다.

## [2] 결정 권한

|---|---|
| 규약·규칙·보고 형식·문서 체계·절차 | **컨설턴트** |

**[2.1]** 결정은 해당 역할이 스스로 내리고 자기 결정 로그에 기록한다.
**[2.2]** 아래 4기준 중 **하나라도** 해당하면 에스컬레이션한다. 애매하면 올린다.
1. **범위 변경** — 기능의 추가·삭제·연기
2. **경계 침범** — 확정 스펙 또는 다른 역할의 작업에 영향을 주는 결정
3. **아키텍처·기술 선택** — 구조나 기술 스택의 방향을 정하는 결정
4. **One-way door** — 되돌리기 비용이 큰 결정

**[2.3]** 올릴 곳은 위 표가 정한다.
**[2.4]** 수신처를 헷갈리면 안건을 쪼갠다.
**[2.5]** 자기 문서·자기 코드 안에서 닫히고 나중에 바꿔도 싼 결정은 올리지 않는다.

## [4] 결정 로그

**[4.1]** ID는 `<접두어>-<3자리>`. 접두어별 독립 증가.
**[4.2]** 항목은 **불변이다. 재사용·재번호하지 않는다.**
**[4.3]** 1항목 = 1 원자적 결정. 묶지 않는다.
**[4.4]** 상태 라벨은 4종만 쓴다: `PROPOSED` / `ACCEPTED` / `ON-HOLD` / `SUPERSEDED(→ 대체 ID)`.
**[4.5]** 항목 형식은 `templates.md [6]`을 따른다.
**[4.6]** 참조 키워드는 4종만 쓴다: `depends-on` / `relates-to` / `supersedes` / `escalated-as`.
**[4.7]** 에스컬레이션은 다음 순서로 한다.
1. 역할이 자기 로그에 `PROPOSED` 발번
2. 종결자가 자기 접두어로 발번 — **체계는 `C-xxx`, 프로젝트는 `D-xxx`**
3. 원 역할이 자기 항목을 `escalated-as <ID> (ACCEPTED)`로 갱신

**[4.8]** 에스컬레이션 시 **내용을 중복 기록하지 않는다.**
**[4.9]** 컨설턴트가 스스로 설계·결정한 체계 항목은 `C-xxx`에서 종결한다. **D 재발번을 하지 않는다.**
**[4.10]** 종결자로 보내는 모든 메시지 끝에 `신규 발번 ID:` 1줄을 붙인다. 없으면 "없음"이라 쓴다.
**[4.11]** 결정 ID와 티켓 번호를 섞지 않는다. 결함·발견은 `QA-NNN` / `SEC-NNN`.
**[4.12]** 결정이 규약·실행 문서를 바꾸면 `집행:` 필드에 반영처를 적는다.
**[4.13]** `집행:`의 반영을 **같은 커밋에서 한다.**
**[4.14]** `management/decision-index.md`는 목차다. **근거로 인용하지 않는다** — 단일 진실은 각 역할 로그다.
**[4.15]** `결과` 필드에 **긍정·부정·중립을 한 섹션에 나란히 쓴다.** 좋은 것과 나쁜 것을 갈라 놓지 않는다.
**[4.16]** 처방이 못 푸는 범위를 **자진 명시한다.** 효과를 과장하지 않는다.
**[4.17]** 결함·발견이 오탐으로 판명되면 **철회 사유를 남기고 상태를 `WONTFIX`로 바꾼다.** 지우지 않는다.
근거: D-009, D-010, D-011, D-038, D-089, C-036, C-047

## [5] 메시지·보고

### 전달 경로

**[5.1]** **파트끼리 직접 보낸다.** 정합·질의·핸드오프·통지는 직통이 기본값이다.
**[5.2]** 총괄로는 4종만 보낸다: **에스컬레이션 4기준([2.2]) · 게이트 판정 요청 · 계약 변경 요청([6]) · 파트 간 충돌.**
**[5.3]** 체계 안건은 컨설턴트로 보낸다([2] 표).
**[5.4]** **총괄 검수는 위험 기반이다.** 확정 스펙 변경·게이트 판정·파트 간 충돌만 검수한다.
**[5.5]** 파트 내부에서 닫히는 산출물은 검수하지 않는다.
**[5.6]** 파트 직통 합의가 계약·범위에 닿는다고 판단되면 **발견 즉시** [6] 또는 [2.2]로 격상한다.

### 지시 충돌 (종결자가 둘일 때)

**[5.7]** 한 안건의 **실행 지시는 한 발신자만 낸다.** 발신자는 **실행이 속한 축**의 종결자다.
**[5.8]** 다른 축의 결정은 그 발신자의 `근거(인용)`에 싣는다. **별도 메시지로 보내지 않는다.**
**[5.9]** 겹치는 지시를 받으면 **두 발신자 모두에게** 이의를 제기한다([5.43]). 혼자 짜맞추지 않는다.
**[5.10]** 충돌이 **축 경계** 문제면 두 종결자가 경계를 정한다. 아니면 [3.9] 기준 위계로 판정한다.

### 파일 버스

**[5.11]** 역할 간 모든 전달을 **발신자 outbox에 파일로 남긴다.**
**[5.12]** outbox 파일을 **삭제하지 않는다.**
**[5.13]** 경로는 `<역할>/outbox/<스레드>/NNN-주제.md`로 쓴다. 번호는 스레드 안에서만 증가한다.
**앞으로만 적용한다.** 기존 flat `NNN-주제.md`는 소급 이관하지 않는다 — **flat 구간과 스레드 구간의
영구 공존은 결함이 아니라 설계 결과다.**
**[5.14]** 스레드명은 **사용자가 읽고 바로 아는 대문자 한 단어**로 한다(`MEMBER`·`AUCTION`·`BID`·`GATEWAY`).
**[5.15]** 스레드는 **최초 발신자가 붙인다.** 사용자에게 붙이게 하지 않는다.
**[5.16]** 전 역할 전파·공지는 `_broadcast/` 스레드에 둔다.
**[5.17]** 한 산출물이 여러 스레드에 걸치면 **주 스레드에 두고** 헤더 `관련 스레드:`에 나머지를 병기한다.
**[5.18]** **outbox 파일을 발신 후 고치지 않는다.**
**[5.19]** **상태 줄을 두지 않는다.**
**[5.20]** 회신도 발신이다. 자기 outbox에 쓰고 헤더에 `회신대상: <경로>`를 명기한다.

### 수신함

**[5.21]** **수신함을 두 시점에만 스캔한다: ① 출근 시 ② 사용자가 `수신함 확인` 지시할 때.**
매 응답마다 스캔하지 않는다.
**[5.22]** 스캔은 전 역할 `outbox/`에서 **`[X → 자기역할]` 헤더**를 찾는 것이다.
**[5.23]** 자기 `inbox-log.md`에 **없는 파일만** 신규로 처리한다.
**[5.24]** 처리 후 `inbox-log.md`에 1줄 추가한다.
**[5.25]** 수신함 스캔(`[X → 나]`)과 접두어 스캔(`<접두어>-` 언급)은 **다른 것이다.** 둘 다 한다.

### 대기 큐

**[5.26]** 대기 여부를 **손으로 관리하지 않는다.** 아래로 파생시킨다.
- 대기 중 = `회신: 필요`인 파일 중, 어떤 파일도 `회신대상:`으로 지목하지 않은 것
- 탐색: `회신: 필요` grep − `회신대상:` grep

**[5.27]** `회신: 필요 | 불요`를 **발신 시점에 한 번 쓴다.** 이후 갱신하지 않는다.

### 유형 4종

**[5.28]** 모든 메시지를 4유형 중 하나로 쓴다: **결정 요청 / 작업 지시 / 완료 보고 / 정보 공유.**
**[5.29]** 형식은 `templates.md [1]~[5]`를 따른다.
**[5.30]** **템플릿의 필수 필드를 비우고 보내지 않는다.**
**[5.31]** 계약·스펙에 영향을 주는 내용을 **정보 공유로 보내지 않는다.** 결정 요청으로 격상한다.

### 발신 의무

**[5.32]** 산출물 착수를 지시할 때 `근거(인용)` 필드에 확정 스펙·ACCEPTED 결정의 **원문을 인용한다.**
**[5.33]** 인용할 수 없으면 **지시하지 않고 격상한다.**
**[5.34]** **부재·수량을 근거로 삼을 때 탐색 방법을 명시한다.**
**[5.35]** 공백·결함을 처리할 때 **"이게 어디서 비롯됐나"를 1줄 점검**하고 결과를 적는다.
**[5.36]** 같은 수신자로 가는 독립 안건은 1메시지에 번호 매겨 묶는다(부분 회신 허용).
**[5.37]** 발신 전 "이 회신만 오면 진행 가능한가"를 자문한다.
**[5.38]** 후속 질문을 유발하는 문구를 쓰지 않는다.
**[5.39]** 타 역할 소유 ID·산출물을 논의·변경·재해석하면 소유 역할 앞 정보 공유를 남긴다(1~3줄).
**[5.40]** **추천 없는 선택지를 내지 않는다.** 판단을 떠넘기지 않는다.
**[5.41]** **추천이 자기 정본과 어긋나지 않는지 확인한다.** 정본이 이미 닫은 선택지를 내지 않는다.
**[5.42]** 완료 보고는 완료 기준을 **항목별로 대응시킨다.** 뭉뚱그리지 않는다.

### 수신 의무

**[5.43]** **이의를 제기한다.** 받은 지시가 진행 중 작업과 충돌하거나 근거가 틀렸다고 판단하면 침묵하지 않는다.
**[5.44]** 이의에 판단 근거를 함께 낸다.
**[5.45]** 진행 중 작업은 **완주가 기본값이다.** 중단은 지시가 아니라 합의로 한다.

### 사용자 브리핑

**[5.46]** 매 응답 끝에 채팅으로 브리핑을 낸다. 형식은 `templates.md [7]`을 따른다.
**[5.47]** 파일에 쓴 내용도 요지를 채팅에 노출한다.
**[5.48]** 브리핑 맨 앞에 **결론을 먼저 쓴다.** 근거는 뒤에 둔다.
**[5.49]** 브리핑의 `한 일`은 항목마다 **출처를 명시한다** — 어느 지시·결정·스레드에서 나왔는지.
**[5.50]** 브리핑의 `주고받음`은 **방향·파트·경로·요지 4개를 모두 쓴다.**
**[5.51]** 브리핑의 `할 일`은 **동사로 시작하고 이유를 붙인다.**
**[5.52]** 브리핑의 `할 일`에 **발신/수신을 표기한다** — 사용자가 어느 대화를 열어야 하는지 준다.
**[5.53]** 브리핑에 **붙여넣을 프롬프트를 완성형으로 준다.** 사용자가 문구를 짓게 하지 않는다.
**[5.54]** 브리핑에 **산출물 커밋 명령을 완성형으로 준다**([9.10]). 로그만 쌓였으면 내지 않는다.
**[5.55]** 프롬프트·커밋은 **`할 일` 표 아래 블록**에 둔다. 표 컬럼으로 만들지 않는다.
**[5.56]** 새 세션 첫 기동은 `templates.md [14]` 킥오프 프롬프트로 한다. 2회차부터는 `출근` 한 줄로 한다.
근거: D-017, D-020, D-021, D-023, D-024, D-049, D-063, D-082, D-083, D-085, D-086, C-041, C-042, C-056, C-057

## [6] 확정 스펙 변경 절차

**[6.1]** 변경 절차는 다음 순서로 한다.
1. 변경 필요를 발견한 역할이 **변경 요청**을 총괄로 보낸다
2. 총괄이 영향 범위를 판단해 승인·기각한다
3. 승인 시 **기획만** `spec/`을 수정하고 변경 이력(버전·날짜·내용·사유)을 문서에 남긴다
4. 총괄이 영향받는 모든 역할에 전파한다(`_broadcast/`)

**[6.2]** **기획을 포함해 누구도 총괄 승인 없이 확정 스펙을 수정하지 않는다.**
**[6.3]** 확정 스펙이 바뀌면 그것을 근거로 인용한 문서의 **근거 줄을 갱신한다**(델타 검토 → 반영 → 갱신).
근거: D-001, D-092

## [7] 게이트와 진행

| 게이트 | 통과 기준 | 통과 시 |
|---|---|---|
| G1 domain-spec | 기획 초안 + 총괄 검수 + 사용자 승인. 미해결 ON-HOLD는 인덱스 등재 | ERD 착수 |
| G2 erd | G1 기준 + domain-spec 정합 확인 | api-contract 착수 |
| G3 api-contract | 총괄 검수 + 보안 게이트 1 + 사용자 승인 | 백/프론트/QA/보안 동시 기동 |
| G4-n 도메인 구현 | 계약 준수 + 컨벤션 + 테스트 통과 + QA 시나리오 실행 + defects 처리 | 다음 도메인 착수 |

**[7.1]** 게이트 판정은 총괄이 한다.
**[7.2]** 게이트 통과를 `decision-index.md` 게이트 표에 1줄 기록한다. **D 발번하지 않는다.**
**[7.3]** 게이트 **기준 자체의 개정**은 컨설턴트가 결정한다.
**[7.4]** 보안은 G3 직전 계약을 검토하고, 도메인 전체 완료 후 구현을 리뷰한다. 결과는 `security/findings.md`.
**[7.5]** **시간 기반 리추얼을 두지 않는다.** 이벤트 기반 2종만 둔다.
1. **게이트 통과** → 총괄이 `_broadcast/`로 전파(변경점 + 역할별 할 일 + 지식 동기화 목록)
2. **역할 작업 블록 종료** → 자기 outbox에 완료 보고를 남긴다. 수신처는 [5.2]가 정한다

**[7.6]** 완료 보고를 **총괄에게 따로 보내지 않는다** — 총괄은 스캔으로 읽는다([8.9]).
**[7.7]** 총괄은 착수를 지시하기 전에 **선행 완료를 확인한다.**
**[7.8]** 선행이 확정 전이면 착수를 지시하지 않는다.
**[7.9]** 파생 범위의 판정은 **발견자가 기본값이다.** 파트 간에 걸치면 총괄이 시퀀싱한다.

### 병행 판정

**[7.10]** 두 작업의 병행 여부를 **2문으로 판정한다. 둘 다 "아니오"여야 병행한다.**
1. **의존** — A의 산출물이 B의 입력인가?
2. **쓰기 충돌** — 두 작업이 **같은 파일**을 쓰나?

**[7.11]** **쓰기 집합이 겹치지 않으면 병행한다.** 겹치지 않는데 직렬화하지 않는다.
**[7.12]** 쓰기 충돌은 **파일 경로로 센다.** "같은 도메인"이 아니라 "같은 파일"이다.
**[7.13]** **파생 여부는 판정 기준이 아니다.** 한 뿌리에서 나온 작업들도 [7.10] 2문을 통과하면 병행한다.
**[7.14]** 병행 판정은 **발견자가 기본값이다.** 파트 간에 걸치면 총괄이 판정한다.
근거: D-019, D-022, D-028, D-074, D-084, C-042, C-055

## [8] 세션

| 시점 | handover 행동 |
|---|---|
| 착수 | 무엇을 시작하는지 **먼저** 적는다 |
| 국면 전환 | 갱신한다 |
| 완료 | 해당 항목을 지운다 |
| 퇴근 | 정리만 한다 |

**[8.1]** `notes/handover.md`를 **일을 하기 전에 먼저 쓴다.**
**[8.2]** **일을 끝내고 나서 handover를 쓰지 않는다.**
**[8.3]** 완료한 항목을 handover에서 **지운다.** 쌓지 않는다.
**[8.4]** handover에 **휘발성 맥락만** 담는다. 파일에 있는 내용은 경로 참조만 한다.
**[8.5]** handover에 **진행 중 작업을 반드시 적는다.**
**[8.6]** handover를 **덮어쓴다. 이력을 남기지 않는다.** 형식은 `templates.md [8]`.

**[8.7]** **출근**은 사용자의 `출근` 지시로 시작한다. 순서는 고정이다.
1. `common/rules.md` · `common/templates.md` · `spec/` 3종을 읽는다
2. 자기 `notes/handover.md`를 읽는다
3. **수신함을 스캔한다** — 전 역할 outbox에서 `[X → 자기역할]` ([5.21]~[5.25])
4. 자기 접두어를 전 역할 outbox에서 grep해 `inbox-log.md`에 없는 언급을 점검한다
5. 자기 앞 대기 큐를 산출한다([5.26])
6. 브리핑으로 보고한다(`templates.md [7]`)

**[8.8]** **퇴근**은 사용자의 `퇴근` 지시로 시작한다. 순서는 고정이다. **2단계뿐이다.**
1. `notes/handover.md`를 정리한다
2. 브리핑으로 보고한다

### 총괄 출근

| 알아야 할 것 | 어디서 |
|---|---|
| 뭐가 **진행 중**인가 | 전 역할 `notes/handover.md` |
| 뭐가 **끝났나** | 전 역할 `outbox/` 완료 보고 |
| 뭐가 **막혔나** | 대기 큐([5.17]) |

**[8.9]** **총괄은 현황을 보고받지 않는다.** 출근 시 [8.7]에 더해 위 3종을 스캔한다.
**[8.10]** 총괄은 스캔 결과로 시퀀싱을 판단하고, 필요하면 작업 지시를 낸다([7.7]).
**[8.11]** 총괄은 스캔 결과를 `common/status.md`에 **덮어쓴다.**
**[8.12]** 파트는 총괄의 스캔을 기다리지 않는다. **막히거나 충돌하면 즉시 올린다**([5.2]).

### 현황 파일

**[8.13]** `common/status.md`는 **뷰다. 정본이 아니다.** 형식은 `templates.md [10]`.
**[8.14]** `status.md`와 `outbox/`·`handover.md`가 어긋나면 **후자를 따른다.**
**[8.15]** `status.md`가 낡거나 틀리면 **고치지 않고 지우고 재생성한다.**
**[8.16]** `status.md`를 근거로 인용하지 않는다.
**[8.17]** `status.md`의 `시작 전`만 손으로 적는다. 나머지 3열은 파생한다.
**[8.18]** 출근·퇴근 없이 세션을 시작·종료하지 않는다.

## [9] 도구·환경

### 저장소 파일

**[9.1]** 저장소 파일의 **목록·내용·존재·수량·편집 위치 판단을 호스트 도구**(Read·Grep·Glob·Edit)로 한다.
**[9.2]** **bash 마운트 뷰(`/sessions/.../mnt/...`)의 조회 결과를 판단 근거로 쓰지 않는다.**
**[9.3]** bash는 빌드·테스트 등 마운트 뷰와 무관한 실행에만 쓴다.
**[9.4]** 부득이 bash 조회를 인용하면 호스트 교차검증 결과를 병기한다.
**[9.5]** **sandbox에서 `git add`·`git commit`을 실행하지 않는다.**
**[9.6]** `git status`·`git diff`의 내용 판단을 근거로 쓰지 않는다.

### git

| 성격 | 어디 | 커밋 |
|---|---|---|
| **산출물** | `spec/` · `<역할>/` 루트 파일 · 코드 | 완성될 때 |
| **대화 로그** | `<역할>/outbox/` · `<역할>/notes/` · `inbox-log.md` · `decision-log.md` | **독립 커밋 없음** |

**[9.7]** docs 커밋의 git 실행은 **사용자가 단일 실행자로 전담한다.** 역할 대화는 대행하지 않는다.
**[9.8]** 커밋 대상의 성격은 **위치가 정한다**(위 표).
**[9.9]** **대화 로그는 스스로 커밋을 유발하지 않는다.** 산출물 커밋에 묻어서 실린다.
**[9.10]** **산출물을 낸 파트가 그 산출물의 커밋 메시지를 제안한다.** 브리핑 `할 일`의 `커밋` 칸에 낸다.
**[9.11]** **파트는 로그 커밋 메시지를 제안하지 않는다.** 로그 배치는 총괄이 조립한다.
**[9.12]** 로그 배치 커밋의 트리거는 2개다.
1. **게이트 통과** → 총괄이 전파와 함께 제안한다(스캔 결과로 조립, [8.9])
2. **사용자 `커밋` 지시** → 언제든

**[9.13]** 스테이징을 `git add docs/`로 한정한다. **`git add -A`를 쓰지 않는다.**
**[9.14]** **코드는 atomic 커밋을 유지한다**(`CLAUDE.md`). docs와 한 커밋에 섞지 않는다.

### 프로젝트 지식

**[9.15]** 각 역할 대화의 프로젝트 지식에 **공통 필수 3종**을 등록한다:
`common/rules.md` · `common/templates.md` · `spec/` 3종.
**[9.16]** 게이트 통과 시 교체 등록한다.
**[9.17]** 등록 파일 헤더에 표기한다: `스냅샷 사본 — 정본: 저장소 <경로> · 기준 <게이트/해시7> · 어긋나면 저장소 우선`.
**[9.18]** 타 파트 로그·노트·outbox·자기 inbox-log는 등록하지 않는다. 필요 시 pull한다.
**[9.19]** 등록·갱신 실행은 사용자가 한다.

### Claude Code

**[9.20]** Claude Code는 부모 대화의 '손'이다. **버스 노드가 아니다** — 별도 outbox·수신함 스캔이 없다.
**[9.21]** 부모 대화가 작업 지시를 자기 outbox에 남기고, Claude Code는 경로 지정으로 읽는다.
형식은 `templates.md [12]`.
**[9.22]** Claude Code는 완료 보고를 **파일로 반환한다**(`<역할>/notes/cc-reports/NNN-<주제>.md`).
**[9.23]** 사용자가 Claude Code 보고를 중계하지 않는다.
**[9.24]** 부모 대화가 그 보고를 읽고 완료 보고·에스컬레이션을 자기 outbox로 재진입시킨다.
