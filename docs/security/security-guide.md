# 보안 파트 지침 (D-041, 지침 유형)

보안 역할(D-013)의 검토 절차·산출물 규약. 협업 규약은 common/rules.md,
형식은 common/templates.md를 따른다.

## 1. 역할과 게이트 (D-013)

- 책임: 설계·계약·구현의 보안 검토, 위협 모델링, 취약점 리포트. 공격자 관점 —
  기능 검증(QA)과 구분.
- 게이트 1 (G3 직전, 계약 확정 차단 권한): domain-spec·erd·api-contract 초안에 대한
  설계 검토. 통과 없이는 G3를 닫지 않는다.
- 게이트 2 (도메인 전체 구현 완료 시): 구현 코드 리뷰(인증·인가 적용 실태, 검증 우회 경로).
- 게이트 외 수시: 계약 변경(6절) 발생 시 보안 영향 1줄 의견을 총괄 회신에 첨부.

## 2. 산출물과 위치 (docs/security/)

| 파일 | 내용 |
|---|---|
| threat-model.md | 도메인별 위협 모델(3절 형식). 게이트 1에서 작성, 이후 갱신 |
| checklist.md | 게이트별 검토 체크리스트(4절 기반, 프로젝트 맞춤 진화) |
| findings.md | 발견 티켓 누적(SEC-NNN, 전 역할 열람 — templates 10) |
| decision-log.md | 보안 결정(S-xxx): 기준·정책 결정 |

- 번호 체계: S-xxx는 결정 로그, SEC-NNN은 발견 티켓(별도 시퀀스, QA와 동일 논리).
- Critical 발견(자금 탈취·인증 우회 가능)은 즉시 총괄 통지 + 해당 구현 중단 요청 권한.

## 3. 위협 모델링: STRIDE-lite

전면 STRIDE 워크숍 대신, 도메인(자금 흐름 중심)별로 표 1개:

```
### <도메인> (예: bid)
| 위협(STRIDE 분류) | 시나리오 | 기존 통제 | 잔여 리스크 → 조치(SEC-NNN) |
```

이 프로젝트의 고정 검토 축(도메인 리스크, D-013·D-004~008 파생):
1. 인증·인가: 소유자 검증(자기 경매 조작), 관리자 권한 경계, JWT 만료·재발급
2. 입찰 부정: shill 우회(다계정), 자기 입찰·연속 입찰 검증 우회, 입찰 상한(buyNow) 우회
3. 자금 정합성: 중복 결제·이중 지불, 잔액 검증 우회, 정산(에스크로) 경합
4. 시간 조작: 마감·소프트 클로즈 연장 로직에 대한 클라이언트 시간 신뢰 여부
5. 입력·주입: OWASP Top 10 기본(주입, 과다 노출, IDOR — 특히 순번 ID 리소스 접근)
6. 시크릿·설정: 환경변수 관리, fail-fast 준수(CLAUDE.md 4절)

## 4. 게이트 체크리스트 (초기본 — 운영하며 진화)

게이트 1(설계·계약): 모든 엔드포인트에 인증 요구 명시 여부 / 리소스 접근의 소유자 검증
규정 여부 / 에러 응답의 정보 과다 노출 / 금액·상태 전이의 서버 단독 결정 여부(클라이언트
값 신뢰 금지) / 위 3절 축 1~4의 계약 반영 확인.
게이트 2(구현): @PreAuthorize 등 인가 적용 실태 표본 검사 / 검증 로직의 우회 경로
(API 직접 호출) / 시크릿 하드코딩 grep / IDOR 표본 테스트.

## 5. 발견 처리 흐름

1. 발견 → findings.md에 SEC-NNN(심각도: Critical/Major/Minor, 공격 시나리오 필수).
2. 계약·설계 영향 시 계약 변경 요청(templates 15) 격상, 구현 문제면 해당 역할로 결정 요청.
3. 수정 확인 후 상태 갱신. 티켓 삭제 금지. Critical은 미해결 상태로 게이트 통과 불가.

## 6. 레퍼런스

OWASP Threat Modeling Cheat Sheet(경량 반복 모델링, 긴 워크숍 회피), OWASP Security
Culture(STRIDE 체크리스트 수준 채택), ASVS(통제 선정 참조용 — 전면 준수 인증은 과잉이라
미채택), Google SRE(Critical 차단 권한의 근거 — 게이트는 통과 기준이 전부).
