## 왜 (사용자 지적 2026-07-19)
EPIC-FE-REDESIGN 결과물을 브라우저로 확인한 사용자 판정:
1. **전체적인 디자인이 너무 별로다** — 대폭 전면 진행
2. **영역별로 디자인이 틀어진다. 통일성 없음**
3. 카드 골드 아웃라인 ↔ 속성·골드포스 **태그 겹침** → **태그 아예 삭제**
4. 매물 영역 **카드 하단 레이아웃이 제각각**
5. 경매 목록에서 마감 상품 블랙 처리 시 **아웃라인이 튄다**
6. 경매 목록 **필터 디자인**이 별로

**진단**: 3·5번은 총괄이 `§5.12` 골드포스 아웃라인을 정본으로 확정하면서 **실물에서 다른 요소와

1·2·4·6은 **손으로 쌓은 디자인 시스템의 한계**다 — 통일성은 컴포넌트가 한 몸일 때 나온다.

## ★ 에픽 조정 (2026-07-19)
### FC-062 폐기 — FC-058에 흡수
원안은 아트를 마지막(FC-062)에 뒀으나 **§5.12 골드포스 아웃라인·Game-Color Containment가
전부 폐기**되면서 그 티켓에 **남은 것이 아트 경로 로직 이식뿐**이 됐다.
게다가 **아트가 마지막이면 홈·경매·인벤토리가 전부 "Lv.N" 텍스트**로 나온다 — 매 티켓마다
"볼 게 없다"가 반복된다. → **FC-058이 아트 기반을 함께 만든다.**

### FC-057 완료 시점의 실제 상태 (사용자 지적으로 드러남)
총괄이 *"셸을 확인해달라"*고 했으나 **전 라우트가 placeholder라 볼 것이 사실상 없었다.**
셸 = 헤더·내비·푸터 껍데기이고 본문은 비어 있다. **"화면이 나온다"를 티켓 진행 상황만 보고
넘겨짚은 총괄 오류**다. → 사용자 판단으로 **FC-058(홈)까지 만든 뒤 함께 판정**하기로 했다.

**교훈**: "확인해주세요"라고 할 때 **무엇이 보이는 상태인지 먼저 확인하고 말할 것.**
라우트를 열어보면 5초에 알 수 있었다.

### FC-064 신설 — 경매 상세 + 입찰 (2026-07-19)
원안 `FC-059 = 경매 목록·상세`를 **쪼갰다.** 근거: **홈 한 화면이 3번 재작업**됐다
(피드백 12건 → 아웃라인 §5.12 정정 → 모바일 파손 3건). **한 티켓에 화면 둘을 묶으면
한쪽 반려가 다른 쪽까지 되돌린다.**
→ **FC-059 = 목록**, **FC-064 = 상세 + 입찰**(미개설).

FC-064가 다룰 것: 안2 배치(상단 가로 2열 + 마감·입찰 전폭 + 이력 전폭) · 스티키 입찰 바 ·
아트 확대 라이트박스 · 입찰 뮤테이션(`POST /auctions/{id}/bids`, 백엔드 구현됨) ·
입찰 이력(`GET /auctions/{id}/bids`) · **`BID_003`(자기 경매) 화면 분기는 계약 한계**

### FC-065 신설 — 템플릿 결함 2건 (2026-07-19)
FC-058·FC-059가 각각 **템플릿 전역 결함**을 발견하고 둘 다 우회 후 미처리로 넘겼다:
`Button`이 **`disabled`를 DOM에 전달하지 않고**(눈에만 비활성, 보조기술엔 멀쩡 — WCAG 4.1.2),
`ui/Checkbox` **배럴이 lodash를 끌고 온다**(청크마다 약 33 kB 순수 증가).

**화면 티켓이 아니라 기반 티켓**이라 순서상 어디든 들어갈 수 있으나, **결함 2는 화면이 늘수록
비용이 반복**되므로(청크마다 33 kB) 화면을 더 만들기 전에 처리하는 편이 이득이 크다.
**착수 전 선행 판단 1건** — 템플릿 원본 수정 / 래퍼 신설 / 우회 유지 중 택일(FC-065 본문).
(상세 응답에 판매자 식별자가 없다 — `isSeller: boolean` 추가가 게이트2 대상).
