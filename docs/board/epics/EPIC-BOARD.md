## 목표

게시판을 하드코딩 enum(현행 `NoticeType`)이 아니라 **DB 레코드(Board 레지스트리)**로 정의해, 코드 수정 없이 게시판을 추가·삭제·변경할 수 있는 커스텀 게시판 시스템을 만든다. 이번 에픽은 관리자 UI 대신 **시드로 커뮤니티·공지·이벤트 3개 게시판을 심되**, 데이터 구조는 향후 관리자 CRUD가 얹힐 수 있도록 옵션화한다. 게시글(Post)·댓글(Comment)·이미지 첨부를 지원하고, 기존 `notice` 도메인은 이 시스템의 '공지' 게시판으로 흡수한다.

## 제품 결정 (게이트1 확정)
- **게시판 관리**: 우선 시드(Flyway)로 커뮤니티·공지·이벤트 정의. 관리자 생성/삭제 UI는 **다음 에픽**(범위 밖). 단 데이터 모델은 런타임 CRUD를 견디게 설계.
- **댓글**: 포함. 게시판별 댓글 허용/차단을 옵션으로.
- **이미지**: 포함. 본문 이미지·이벤트 배너 업로드. 스토리지 방식은 게이트2.
- **공지 흡수**: notice 데이터 이관 + 도메인 제거 + 프론트 공지 페이지 새 API 전환.

## T1에서 상신될 게이트2 후보
1. **이미지 저장 위치** — 로컬 디스크 vs 오브젝트 스토리지(S3/MinIO). 배포 방식 영향.
2. **공지 흡수 방식** — 데이터 이관 + notice 도메인 제거(되돌리기 큰 변경, CLAUDE.md가 notice를 "참조 구현"으로 명시).
3. **게시판 옵션 모델** — 쓰기 권한(관리자전용/로그인유저)·댓글허용·게시판 유형 등 옵션화 범위.
