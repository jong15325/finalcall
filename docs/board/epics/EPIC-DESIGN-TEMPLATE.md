## 목표
- **정적 HTML 목업으로 시각 디자인을 먼저 확정한다.** 그다음 프론트 구현이 이를 집행한다.
- 방침(사용자 지시 2026-07-18): 백엔드 동결 → **디자인 템플릿 HTML 완성** → 이후 기능 에픽은 프론트+백엔드 동반.

## 왜 이 에픽이 생겼나 (반복 금지 기록)
사용자가 처음으로 브라우저에서 화면을 열고 **"디자인이 거의 안 되어 있다"**고 지적했고, 사실이었다.
- 라우트 16개 중 **12개가 `PagePlaceholder`**("스켈레톤 placeholder — feature 단계에서 구현됩니다"). **홈(첫 화면)부터 placeholder.**
- `PublicLayout`은 얇은 헤더 + 텍스트 링크 3개. 푸터·브랜드 표현 없음. 주석이 스스로 *"도메인 콘텐츠는 없다(스켈레톤)"*.
- 로그인은 흰 배경에 `h1` + 필드 2개 + 버튼. **접근성·토큰은 정확한데 시각 디자인이 없다.**

**근본 원인**: `design-system.md`는 **토큰 값 + 컴포넌트 계약**(무슨 prop·무슨 상태·무슨 a11y) 명세지 **"어떻게 보여야 하는가"가 아니다.** 그런데 아무도 시각 디자인을 맡지 않았고, 리뷰는 "규칙 위반 여부"만 물어서 통과했다. **문서 준수 ≠ 디자인 완성.**

## 이 에픽이 만드는 것
`docs/ux/mockups/` 아래 **자체완결 정적 HTML**. 선례: `redesign-commerce.html`.
- 브라우저로 바로 열어 보고 판단할 수 있어야 한다(빌드·서버 불요).
- React 구현이 아니라 **디자인 결정의 기록**이다. 확정 후 frontend-impl이 이를 집행한다.

## 계승할 원칙 (design-system.md)
- **§1.2 색 3계층**: 조작=블랙 CTA·퍼플은 액센트(링크·포커스·선택)만. **퍼플을 CTA 채움으로 쓰지 않는다.**
- **Game-Color Containment**: element 4색·검정 아트 슬롯은 **아이템 카드·속성 배지·아이템 필터 칩에만**. 버튼·탭·인풋·크롬·배경·내비에 쓰지 않는다 — 게임색이 조작/크롬으로 새면 커머스 신뢰감이 무너진다.
- 라이트 커머스(무신사·컬리 감각 참조, 값 미복제) · 등급 배지 폐기(D-073) · WCAG 2.1 AA.
