## 확정 UI 계약

### 1. 페이지와 판매 방식

- `/sell?item=<itemInstancePublicId>` 선점 모델과 선택 아이템 유효성 검사는 유지한다. 아이템 영역은 경매·고정가가 공유하고 판매 방식 탭보다 먼저 인지되게 배치한다.
- 판매 방식은 native tab 또는 동등한 접근성의 단일선택 조작으로 `경매`와 `고정가`를 전환한다. 키보드 조작, 명시적 선택 상태와 연결 패널 이름을 제공한다.
- 아이템, 경매 폼, 고정가 폼 상태는 서로 독립적으로 보존한다. 탭 전환은 반대 탭 입력을 초기화하거나 제출 요청에 섞지 않는다. 확인 다이얼로그와 제출은 현재 활성 탭만 대상으로 한다.
- 공통 영역: 선택 아이템 상세, 판매 방식, 예상 수수료/정산 안내, 최종 등록 CTA. 분기 영역: 경매의 시작가·선택적 즉시구매가·시간 설정 / 고정가의 판매가·서버 자동 기한 안내.

### 2. 경매 기본 시간 설정

- 시작 방식은 `즉시 시작`으로 고정한다. 기본 경로에서는 `startAt`을 요청에서 생략한다. 예약 시작 UI는 제공하지 않는다.
- 기본 기간은 `1일`, `3일`, `7일` 세 프리셋이며 한 항목만 선택한다. 프리셋의 하루는 달력 날짜가 아니라 24시간의 경과시간이다(각각 24·72·168시간).
- `now`는 프리셋을 선택한 사용자 이벤트 시점에 `Date.now()`로 한 번 캡처한다. `endAt = capturedNow + duration`으로 계산하며, 같은 프리셋을 다시 선택하면 새 `now`로 다시 계산한다. 렌더마다 또는 매초 `endAt`을 밀지 않는다. 제출 시점에는 기존 검증처럼 실제 현재 시각으로 `endAt > now`를 재검증한다.
- 계산된 종료 시각은 `YYYY. MM. DD. HH:mm:ss KST`처럼 날짜·시각·`KST`를 생략 없이 표시하고, 보조 문구로 선택 기간을 함께 표시한다. API에는 해당 Instant의 UTC ISO-8601 값을 전송한다.
- 대한민국 표준시 `Asia/Seoul`을 표시·직접입력 기준으로 고정한다. 서울은 DST를 사용하지 않으므로 항상 UTC+09:00이며, 브라우저/OS 시간대가 달라도 계산·표시·전송 결과가 달라지지 않아야 한다. 프리셋은 절대 경과시간을 더하고 KST로 포맷한다.
- 소프트클로즈가 꺼진 기본값은 `maxEndAt = endAt`으로 자동 파생한다. 필수 API 필드는 충족하되 연장은 발생하지 않는다. 프리셋 변경 시 두 값을 함께 갱신한다.

### 3. 고급 시간 설정과 소프트클로즈

- `고급 시간 설정`은 기본적으로 접혀 있고, 펼쳐도 즉시 시작 원칙은 바뀌지 않는다. 직접 변경 대상은 `endAt`과 소프트클로즈 설정뿐이다.
- 직접 종료 시각 입력은 KST의 민간시(civil time)로 해석한다. 라벨과 입력 주변에 `KST`를 항상 표시하고, 이를 UTC ISO-8601 Instant로 변환한다. 브라우저 로컬 시간대로 해석하는 기존 `datetime-local -> Date` 변환은 이 화면 계약에 맞게 KST 고정 변환으로 교체한다.
- 직접 시각을 유효하게 입력하면 기간 선택은 `직접 설정` 상태가 된다. 이후 1/3/7일 프리셋을 누르면 직접값을 버리고 해당 이벤트 시점 기준으로 다시 계산한다.
- 소프트클로즈는 하나의 on/off 조작으로 제공한다. off이면 두 선택 필드를 요청에서 모두 생략하고 `maxEndAt=endAt`이다. on이면 `감지 구간`과 `1회 연장 시간`을 모두 선택해야 하며 둘 중 하나만 요청하는 상태를 허용하지 않는다. 현재 허용 옵션(60/120초 감지, 120/300초 연장)을 재사용한다.
- 소프트클로즈 on에서는 `최대 연장 종료 시각`을 명시적으로 입력해야 하고 `maxEndAt > endAt`으로 UI에서 엄격히 검증한다. 이는 서버의 `≥` 계약보다 안전한 UI 제약이며, 실제 연장 가능한 폭이 0인 모순 상태를 막는다. 서버 설정 상한 초과는 기존 `AUCTION_008` 오류로 인라인 안내한다.
- `maxEndAt`은 기본 화면에서 독립 필드로 노출하지 않는다. 소프트클로즈 off에서는 자동 파생하고, on일 때만 고급 영역에 노출한다. 종료 시각을 바꿔 기존 최대 연장 시각이 새 종료보다 이르면 오류를 표시하며 몰래 보정하지 않는다.
- 요약에는 기본 종료 시각과 최대 연장 종료 시각을 구분해 표시하고, 소프트클로즈가 입찰에 따라 연장될 수 있다는 조건을 텍스트로 설명한다. 색만으로 상태를 전달하지 않는다.

### 4. 고정가 시간 안내

- 고정가 탭에는 기간 프리셋, 종료 시각 입력, 소프트클로즈를 노출하지 않는다. 등록 요청은 기존대로 아이템과 가격만 보낸다.
- `판매 기한은 서버가 등록 시점에 자동 결정합니다(현재 기본 7일)`라고 안내하되, 이는 예상 안내이며 정확한 `endAt`은 등록 응답/상세에서 확정됨을 명시한다. 클라이언트가 예상 종료 Instant를 요청에 추가하지 않는다.

### 5. 선택 아이템 상세 정보

- 축약 카드나 추가 모달 없이 페이지 안에서 항상 펼쳐 보인다. `CardInfoDialog`의 시각·정보 어휘를 재사용하되 dialog role, 닫기, focus trap, overlay는 사용하지 않는 inline 상세 컴포넌트로 구성한다.
- 필수 표시: 아이템 이미지/프레임, 골드/블랙 프레임 타입과 세부 종류, 명칭, 레벨 기반 채널 제한, 속성(색+텍스트), 골드포스 잔여일 또는 없음, 특수 스킬 1·2의 이름/코드 fallback과 적용 확률, 인벤토리 슬롯/판매 가능 상태. 값이 없으면 행을 숨겨 의미를 잃게 하지 말고 `없음`으로 표시한다.
- `ItemFrame`, `itemArt`, `decodeTypeCode`, `channelLimitOf`, `resolveSkillSlots`, `goldforceRemainingDays` 등 기존 정본 계산을 재사용한다. API 응답 필드를 추가하거나 별도의 `GET /items/{id}` 호출을 요구하지 않는다.
- “인벤토리에서 다시 선택” 링크는 유지한다. 로딩·무효 item·빈 인벤토리 상태에서는 판매 폼을 활성화하지 않고 현재 빈 상태와 복구 행동을 제공한다.

### 6. 반응형 정보 구조

- 1280px: 선택 아이템 상세와 활성 판매 폼을 나란히 비교할 수 있다. 최종 요약/CTA는 폼 흐름에서 떨어지지 않으며 sticky 사용 시 AppShell header와 겹치지 않는다.
- 390px: 단일 열 순서 `페이지 제목 → 아이템 상세 → 판매 방식 탭 → 활성 폼 → 비용/시간 요약 → CTA`로 고정한다. 아이템 상세는 기본 접힘 없이 전부 노출한다.
- 모바일에서 스킬명·일시·큰 금액은 줄바꿈 가능해야 하며 가로 스크롤을 만들지 않는다. 터치 대상 44px 이상, 숫자는 tabular, 오류는 해당 입력 바로 아래 텍스트와 오류 요약/첫 오류 focus를 유지한다.

## 게이트2 판정

- **게이트2 불필요.** 이번 결정은 기존 API 필드를 UI에서 계산·표시하는 방식과 정보 구조만 정밀화한다. API 요청/응답, DB 스키마, 서버 시간 정책, 성능 특성을 변경하지 않는다.
- `startAt`은 기존 optional 필드를 생략하고, 고정가 `endAt`은 기존 서버 자동 계산을 그대로 따른다. 소프트클로즈 on의 `maxEndAt > endAt`은 서버 계약(`≥`)을 깨지 않는 클라이언트 측 강화 검증이다.
- 후속 구현에서 기간 옵션을 서버 계약으로 승격하거나, 고정가 기한을 판매자가 지정하게 하거나, soft-close 상한을 새 값으로 고정하거나, 인벤토리 API 필드를 추가해야 한다면 별도 게이트2와 영향 티켓 산출이 선행되어야 한다.
