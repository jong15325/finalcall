## 목표
**홈이 첫 화면인데 아직 `PagePlaceholder`다.** FC-041 목업을 실코드로 집행해 그것을 없앤다.
공통 셸(헤더·푸터·브랜드)은 전 화면에 걸리므로 함께 한다.

## 현재 상태 (방침 전환의 발단)
- **홈 = `PagePlaceholder`** ("스켈레톤 placeholder — feature 단계에서 구현됩니다")
- `PublicLayout` = 얇은 헤더 + 텍스트 링크 3개. **푸터·브랜드 표현 없음.** 주석이 스스로
  *"도메인 콘텐츠는 없다(스켈레톤)"*라고 적어뒀다.

## 집행할 목업
`docs/ux/mockups/template-home-logged-out.html` · `template-home-logged-in.html`

### FC-041이 확정한 디자인 결정 (그대로 집행)
- **홈은 "마케팅 랜딩"이 아니라 거래소 첫 화면**이다. **스크롤 0px에 실제 카운트다운** —
  카피로 주장하지 않고 **데이터로 증명**한다.
- **브랜드는 색분할이 아니라 활자 덩어리 + `CALL` 퍼플 2px 마감선**(경매 카드 잔여시간
  게이지와 같은 형태).
- **헤더 2행.**
- **활성 내비는 퍼플이 아니라 near-black 2px 밑줄.**
- 섹션마다 **구조 변주**(피처드·격자·카드·행목록·표) — 같은 리듬 반복 금지.
- 여백 3단 **48·64·80**.
- 표면 층 분리를 **섹션 밴딩**으로 쓴다(`bg`/`surface`/`surface-band`/`surface-sunken`).

## ★ 반응형 — 별도 설계 (지속 원칙)
> **반응형은 배치 변경이 아니다. 웹은 웹, 모바일은 모바일에 맞게 짜여야 한다.**

"좁아지면 1열로 접는다"는 설계로 인정하지 않는다. **데스크톱·모바일 구조를 각각 도식으로
제시**한다. 셸은 전 화면에 걸리므로 특히 중요하다 — 모바일 내비를 어떻게 할지(드로어·하단탭·
축약 등)가 이 티켓의 결정 사항이다.

## 함께 처리할 드리프트
**`features/item/lib/element.ts`의 `ELEMENT_CODES`가 1·2만 등재**돼 있고 주석도
"정본은 1·2 뿐"(계약 v1.9 기준)이다. **계약 v1.10 §3.3.1이 1~4를 확정**했다(원본 게임 DB
4경로 확증). **1=물·2=불·3=흙·4=바람 전량 등재**하고 주석을 v1.10 기준으로 갱신한다.
- **폴백 의무는 존치**한다 — 축 확장 가능성 + 배포 시차. 계약이 규정한 클라이언트 의무
  ("미등록 코드는 중립 표기 폴백 + 코드 집합 크기 하드코딩 금지")는 그대로다.
- FC-051 테스트는 등록 목록을 순회하는 방식이라 **등재 후에도 통과**한다.

## DoD
- 홈이 `PagePlaceholder`가 아니다. 로그인 전/후 두 상태가 모두 동작한다.
- 공통 셸(헤더 2행·푸터·브랜드)이 **전 화면에 적용**된다.
- **홈의 카운트다운이 실데이터**다 — 계약 §3 경매 목록 API를 쓴다. 하드코딩 금지.
- `ELEMENT_CODES` 1~4 등재 + 주석 갱신.
- **테스트 동반**(FC-051이 깔아뒀다) — 최소: 홈이 로그인 전/후 렌더된다 · 셸이 렌더된다 ·
  빈 목록/로딩/에러 상태에서 크래시하지 않는다.
- `npm run test`·`typecheck`·`lint`·`build` 전건 통과.
