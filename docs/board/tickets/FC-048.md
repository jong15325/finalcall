## 목표
**홈이 첫 화면인데 아직 `PagePlaceholder`다.** FC-041 목업을 실코드로 집행해 그것을 없앤다.
공통 셸(헤더·푸터·브랜드)은 전 화면에 걸리므로 함께 한다.

## 현재 상태 (방침 전환의 발단)
- **홈 = `PagePlaceholder`** ("스켈레톤 placeholder — feature 단계에서 구현됩니다")
- `PublicLayout` = 얇은 헤더 + 텍스트 링크 3개. **푸터·브랜드 표현 없음.** 주석이 스스로
  *"도메인 콘텐츠는 없다(스켈레톤)"*라고 적어뒀다.

## 집행할 목업
`docs/ux/mockups/template-home-logged-out.html` · `template-home-logged-in.html`

### FC-041이 확정한 디자인 결정 (그대로 집행)
- **홈은 "마케팅 랜딩"이 아니라 거래소 첫 화면**이다. **스크롤 0px에 실제 카운트다운** —
  카피로 주장하지 않고 **데이터로 증명**한다.
- **브랜드는 색분할이 아니라 활자 덩어리 + `CALL` 퍼플 2px 마감선**(경매 카드 잔여시간
  게이지와 같은 형태).
- **헤더 2행.**
- **활성 내비는 퍼플이 아니라 near-black 2px 밑줄.**
- 섹션마다 **구조 변주**(피처드·격자·카드·행목록·표) — 같은 리듬 반복 금지.
- 여백 3단 **48·64·80**.
- 표면 층 분리를 **섹션 밴딩**으로 쓴다(`bg`/`surface`/`surface-band`/`surface-sunken`).

## ★ 반응형 — 별도 설계 (지속 원칙)
> **반응형은 배치 변경이 아니다. 웹은 웹, 모바일은 모바일에 맞게 짜여야 한다.**

"좁아지면 1열로 접는다"는 설계로 인정하지 않는다. **데스크톱·모바일 구조를 각각 도식으로
제시**한다. 셸은 전 화면에 걸리므로 특히 중요하다 — 모바일 내비를 어떻게 할지(드로어·하단탭·
축약 등)가 이 티켓의 결정 사항이다.

## 결과 (2026-07-19)
커밋 `467f53e`, **프론트 17파일만**. 테스트 신규 8건 / 전체 **24건 통과**. **홈이 더 이상
`PagePlaceholder`가 아니다** — 방침 전환(2026-07-18)의 발단이 닫혔다.

### 모바일 내비 = 하단 탭바 (근거 4가지)
1. 목적지가 4개뿐이다. 햄버거 뒤에 숨기면 **모든 이동이 2탭**이 되는 순손실. 드로어는 목적지가
   화면에 다 안 들어갈 때의 해법이다.
2. **카운트다운 제품은 "반복 확인" 패턴** — 경매↔고정가↔홈을 계속 오간다. 반복 이동은 1탭이어야 한다.
3. 엄지 도달 — 세로로 긴 화면에서 상단 우측이 가장 멀다. 주 내비를 상단에 두는 건 마우스 전제의 관성.
4. 상단을 1행(56px)으로 비워야 **스크롤 0px에 실데이터가 들어온다.** 데스크톱 2행(114px)을
   그대로 올리면 히어로가 접혀 **이 화면의 정체성이 죽는다.**

활성 표시는 데스크톱 밑줄 모티프를 **위아래만 뒤집었다**(하단 고정이라 밑줄이 화면 밖으로 밀림).
색이 아니라 형태로 표시하는 규칙은 동일하고 퍼플·게임색이 새지 않는다.

### 정직하게 뺀 것 2건 (판단이 좋다)
- **마감선 게이지 미구현** — 남은 시간 비율을 그리려면 시작 기준점이 필요한데 `startAt`은
  nullable이고 `createdAt`은 상세에만 있다(§3.3). 임의 기준(24h 등)으로 채우면 **눈금 없는
  막대가 사실이 아닌 비율을 주장**한다.
- **"10초마다 갱신" 문구 제거** — 홈은 폴링하지 않으므로 **거짓말이 된다.** `dataUpdatedAt`
  기반 "목록 기준 HH:MM:SS · 남은 시간은 매초 계산됩니다"로 교체(남은 시간은 `endAt` 파생이라
  실제로 매초 정확하다).

### 상태 설계 — 첫 화면이 백지가 되지 않는다
- **로딩**: 좌측 안내 열·CTA·속성 퀵필터는 데이터 무관이라 **즉시 렌더**. 우측만 스켈레톤이고
  높이를 맞춰 도착 시 무점프.
- **빈 목록**: 히어로는 **패널을 지우지 않고** 그 자리에서 다음 행동을 준다("이 자리에서
  카운트다운이 시작됩니다" + CTA 2개). **고정가 밴드는 비면 섹션을 걷어낸다** — 빈 밴드는
  면이 아니라 얼룩이 되기 때문([2.1]).
- **에러**: 섹션별 **격리**. 히어로가 죽어도 제목·CTA·퀵필터·격자·푸터는 산다.
  고정가는 **에러를 숨기지 않는다**(빈 목록만 숨긴다 — 조용한 실패 방지).

### 캐시 키 분리 (실질적 버그 예방)
`auctionKeys.preview`를 `list`와 분리했다. 같은 키를 `useInfiniteQuery`(pages 구조)와
`useQuery`(단일 페이지)가 공유하면 **한 캐시 엔트리를 두고 서로 덮어써 화면이 깨진다.**

## ★ 후속 — 게이트2 상신 3건 (계약 부재로 구현 불가)
1. **자유문 검색이 계약에 없다.** §3 공통 필터·§4.1 어디에도 `q`/keyword가 없다. 목업은
   "검색이 마켓플레이스의 1차 IA"라며 헤더 중앙에 뒀는데, 지금 만들면 **동작하지 않는 컨트롤**이
   된다([5.2] "사유 없는 비활성 금지"). **만들지 않았고 레이아웃은 그 자리를 수용**한다 —
   계약이 규정되면 재설계 없이 들어간다.
2. **카테고리 개수 집계 API 없음.** 목업의 "블랙카드 1,284개" 타일을 채울 엔드포인트가 없다.
   게다가 목업의 카테고리 축은 `mainCategory`인데 **§3.3.1이 `mainCategory=1`만 거래 대상**으로
   스코프를 잘랐다. → 섹션 제외, 진입 경로는 **속성 퀵필터**로 대체.
3. **시세 랭킹 목록 API 없음.** §4.1 `GET /market-prices`는 `typeCode`+`level` **단건 집계**다.
   목업의 "최근 낙찰 시세 표"(상위 N종 + 전주 대비)는 이걸로 못 만든다. → 섹션 제외.
   **홈이 6섹션 → 4섹션이 됐다.**
