## 목표
**화면 시각 검증을 가능하게 만든다.** 현재 `item_instance`가 전부 `INVENTORY`이고 경매 시드가
없어 **홈·경매 목록·상세 세 화면이 전부 빈 상태**로 나온다. FC-048·FC-049가 만든 것을
**아무도 눈으로 못 봤다** — 실아트가 뜨는지조차 확인되지 않았다.

## ★ 백엔드 한시 동결 해제 (사용자 승인 2026-07-19, 2회차)
**범위는 시드 마이그레이션 1건.** 도메인 로직·엔티티·API·스키마를 건드리지 않는다.
작업 후 **동결 복귀**. EPIC-CLOSING·EPIC-SHOP·FC-035 minor는 여전히 동결이다.
(1회차는 FC-052 아이템 시드였다.)

## ★★ 이 시드가 아이템 시드보다 어려운 이유

### 1. 시간 기준 — 마이그레이션은 한 번만 실행된다
고정 timestamp를 박으면 **며칠 뒤 전부 종료 상태**가 되어 시드가 죽는다.
`NOW()` 기준 상대시간(`DATE_ADD(NOW(6), INTERVAL ...)`)이 적용 시점을 기준으로 삼지만,
그래도 **임박(T-5분)·초임박(T-30초)은 적용 직후 몇 분만 유효**하다.

→ **판단하고 근거를 대라.** 선택지 예: 임박 구간을 긴 시간으로 잡되 화면이 임박으로 인식하는
값을 쓴다 / 재실행 가능한 별도 스크립트를 함께 제공한다 / 만료를 수용하고 재적용 방법을 문서화한다.
**"며칠 뒤 못 쓰게 되는 시드"를 아무 말 없이 남기지 마라.**

### 2. 금액 불변식 — 입찰을 넣으면 홀드가 따라온다
입찰 없이 `ACTIVE`만 넣으면 화면에 **"입찰 없음 · 시작가"만** 보인다. 그러면 FC-049 부채 9
(**"입찰 없음·시작가" vs "현재가·입찰 N회"가 나란히 있을 때 혼동되지 않아야 한다**)의
판정 대상이 반쪽이 된다. → **입찰이 붙은 경매가 있어야 한다.**

그런데 입찰은 `money_hold`·`user_balance`와 정합해야 한다. EPIC-BID가 세운 **불변식 I1~I10**을
깨면 안 된다(근거 `docs/spec/bid-domain-spec.md`).
→ **입찰자 계정의 잔액·홀드가 시드 입찰과 정합해야 한다.** 필요하면 입찰자 계정을 추가하고
잔액을 충분히 넣어라. **불변식을 어떻게 지켰는지 반환에 적어라.**

### 3. 에스크로 — `item_instance.location`
경매 등록은 `INVENTORY → LISTED` CAS 전이를 동반한다(`markListedIfInInventory`).
시드도 **같은 상태로 맞춰야** 한다. 안 맞으면 화면은 뜨지만 도메인 상태가 거짓이 된다.

## 필요한 상태 다양성 (FC-042 목업이 검증 대상으로 삼은 것)
한 목록에 섞여 있어야 판정이 된다:
- **입찰 있음 / 없음** — 부채 9의 판정 대상
- **마감 여유 / 임박 / 초임박** — 카운트다운 3구간(§5.9 임계값 5분·30초)
- **종료 — 낙찰(SOLD) / 유찰(UNSOLD)** — "마감 · 낙찰" / "마감 · 유찰" 사유 병기 확인
- **`SCHEDULED`** — 미개시 분기(`BID_007`) 확인
- **즉시구매가 있음 / 없음** — `buyNowPrice` null일 때 "설정 없음" 자리 유지 확인
- **골드포스 활성 / 없음** — §5.12 아웃라인 확인

**분량**: 경매 목록이 **20장 규모**로 차야 리듬이 보인다(FC-042 DoD). 아이템은 FC-052가
40종 42인스턴스를 만들어 뒀다.

### ★ 설계 원칙 — "손으로 적지 않고 파생시킨다"
불변식을 데이터 배치가 아니라 **규칙**으로 보장했다. 이게 이 시드의 핵심이다.
- **I1**: `highest_bid_amount`/`highest_bidder_id`를 INSERT에 하드코딩하지 않고 **입찰 원장에서
  UPDATE로 파생**. 어긋날 여지 자체를 제거했다.
- **I3**: 홀드 상태를 `bid.status`에서 **기계적으로 파생**(ACTIVE→HELD·OUTBID→RELEASED·
  WON→CAPTURED). "경매당 HELD ≤ 1"이 배치가 아니라 규칙으로 보장된다.
- **I4**: `game_money_held`를 HELD 원장 `SUM`으로 반영. **역방향(잔액을 적고 홀드를 맞추기)을 금지.**
- **에스크로**: 대상을 아이템 목록으로 적지 않고 **`status IN ('SCHEDULED','ACTIVE')` 조건으로
  선택**. 결과가 `markListedIfInInventory` CAS와 동일해진다.
- **I10**: 입찰자가 1명이면 연속 재입찰이 되어 위반 → **`seed_bidder` 추가**로 교대하게 했다.
롤백 트랜잭션 dry-run으로 **위반 0** 확인.

### ★ BUYNOW 결제를 의도적으로 생략 (판단이 좋다)
`sale_order`·정산이 **EPIC-CLOSING 미구현이라 원장 행이 없다.** **없는 원장을 시드가 발명하지
않았다.** SOLD(BID)는 `money_hold` CAPTURED가 명세된 원장이라 차감했다 — 비대칭이 이 근거로
정당화된다. 판매자 입금도 같은 이유로 생략.

### 시간 기준 — 만료를 숨기지 않고 재적용 경로를 제공
전 시각을 `NOW(6)` 상대 오프셋으로 계산. **다만 임박은 약 4분 30초, 초임박은 약 28초만 유효**하다
— "지금부터 N초 뒤"는 정적 데이터로 오래 유지할 방법이 **원리적으로 없다**(길게 잡으면 그건 이미
임박이 아니다). 만료를 수용하고 **재적용 경로를 설계에 넣었다.**

**재적용**: V13 주석 `[B]`에 **실행 가능한 SQL 4문장**. `SEEDAUCT...0001`의 `created_at`을 시간
앵커로 심고 `@seed_shift` 델타로 auction·bid·money_hold를 함께 이동한다. **앵커도 같이 이동하므로
몇 번이든 반복 실행 가능**하다. → **시각 검증 직전에 이 4문장을 실행하는 것이 지원되는 워크플로다.**

## ★★ 구조 문제 — 데모 시드가 운영에 적용된다 (규모가 커졌다)
`spring.flyway.locations`가 `classpath:db/migration` **단일**이고 프로파일 분리가 없다.
V9부터의 문제이나 **V12·V13이 그 위에 쌓여 이제 심각하다**:
> 운영 DB에 **더미 계정 3개**(BCrypt 평문 `"password"` 해시) + **게임머니 500만 × 3** +
> **경매 20건** + **입찰 27건**이 부팅과 동시에 들어간다.

티켓 지시대로 이 티켓에서 해결하지 않았다. **프로파일별 시드 분리**(`db/migration` + `db/seed`
분리, `locations`를 프로파일로 스위치)는 **별도 결정 사안 → 백로그 등재.**

## 발견 — 미처리
1. **기본 목록에 종료 경매가 안 섞인다.** `statusScope()`가 status 미지정 시 `SCHEDULED·ACTIVE`만
   노출(계약대로). SOLD/UNSOLD 5건은 **`?status=SOLD` 명시 필터로만** 보인다 — "마감·낙찰/유찰"
   문구 판정은 그 경로로. 데이터는 다 있다.
2. **마감 지난 ACTIVE가 방치된다.** 영속 전이 워커가 EPIC-CLOSING 소유·미구현이라 임박·초임박
   4건이 몇 분 뒤 "`end_at`이 과거인 ACTIVE"로 남는다. 재적용[B]이 되돌리는 유일한 수단.
3. **V12 골드포스가 절대일자**(`gf_expire_at` 2026-08-25~12-01 고정) → **2026-12-01 이후 활성 0**
   이 되어 §5.12 아웃라인 검증이 불가해진다. V12 소유 문제.
4. **`BidConcurrencyTestBase`가 시드를 지운다** — 비-트랜잭션 `deleteAllInBatch()`로 공유
   Testcontainers DB의 시드 경매·입찰을 실행 도중 날리고 `game_money_held`를 되돌리지 않아
   **I4 드리프트**가 남는다. 이번엔 아무것도 깨지 않았으나 **테스트 격리 냄새**.
5. **판매자가 20건 전부 `seed_seller` 한 명** — 카드에 판매자명이 노출되면 전부 같다.
   두 번째 판매자는 아이템 소유 이전이 필요해 제외.
