### 반응형 — 접기가 아닌 지점 4개
| 항목 | 데스크톱 | 모바일 |
|---|---|---|
| CTA 도달 | 폼 아래 정위치 | **카드 내부 sticky bottom** |
| 보조 설명 | 병렬 열 | **접힌 아코디언** |
| 첫 필드 포커스 | 자동 | **안 함** |
| 에러 전달 | `role=alert` 배너 | + **포커스 이동·스크롤** |

**sticky 근거**: 가입 4필드는 360×640에서 **키보드 뒤 잔여가 ~300px**이라 CTA가 절대 안 들어온다.
`fixed`가 아닌 이유 — fixed는 흐름 밖이라 하단 패딩을 따로 확보해야 하고 OAuth·푸터 위까지 떠다닌다.

**모바일 다단계 분할은 명시적 기각** — 계약에 없는 중간 상태(부분 제출)를 만들거나 비밀번호를
클라이언트에 오래 들고 있게 된다.

## ★ 판단 대기 4건 — 확정하지 마라
사용자 결정 사항이다. **목업의 현재 상태를 유지**하고, 개편이 영향을 주면 **보고**하라.
1. **약관 동의** — 문장 vs 체크박스. **체크박스면 계약 §2에 동의 필드 추가 = 게이트2.**
   더불어 체크박스는 CTA 위에 와야 하는데(미체크 시 disabled) **모바일 sticky 바가 가릴 수 있어
   sticky 영역에 함께 넣는 설계가 추가로 필요**하다.
2. **네이버 버튼 대비** — 흰 라벨 on `#03C75A` = **2.25:1**, opacity .78 합성 후 **1.94:1**.
   브랜드 규격 자체가 AA 미달이다.
3. **가입 CTA 문구** — "회원가입" vs "가입하기". 18px/800 슬롯은 어느 쪽이든 한 줄에 들어간다.
4. **폼 좌측 배치** — DOM 순서 규칙을 관례보다 우선한 결과. 좌/우 어느 쪽이든 반응형 설계는 성립.

## 브라우저로 확인 못 한 것
- **★ 모바일 키보드 + sticky 실동작** — `interactive-widget=resizes-content`는 **Chromium 108+
  안드로이드 전용이고 iOS Safari는 미지원**이다. iOS에서는 레이아웃 뷰포트가 안 줄어 **sticky가
  키보드 뒤에 남을 수 있다.** 실기 검증 필요(폴백은 `visualViewport` 리스너).
- **`matchMedia` 분기 전부 미검증** — jsdom에 없어 `AuthAside`(아코디언)·`useDesktopAutoFocus`가
  **가드에 걸려 no-op**으로 테스트된다. "데스크톱에서 열려 있다"만 검증됐고 **모바일 접힘·폭 변경
  재동기화·오토포커스 발동은 미검증**이다.
- `scrollIntoView` 실제 스크롤(jsdom 미구현) · `env(safe-area-inset-bottom)` 노치 실측 ·
  960/720 두 경계 리플로우 · OAuth 브랜드색 실물 인상.
