## 목표
FC-043 목업(재점검본)을 실코드로 집행한다. 로그인·회원가입은 **이미 구현돼 있으나**
시각 디자인이 목업과 다르다.

## 집행할 목업
`docs/ux/mockups/template-auth-login.html` · `template-auth-signup.html`

### FC-043이 확정한 것
- **최소 셸**(워드마크 헤더 + 축약 푸터) — *"돈을 다루는 제품에서 브랜드 없는 로그인 화면은
  피싱 화면과 구별되지 않는다"*
- **OAuth 자리 지금 확보** (나중에 넣으면 카드 높이 40% 증가 = 재설계)
- **에러 처리를 두 화면에서 반대로** — 로그인 실패는 **폼 단위 배너만**(필드 강조 시 회원 열거
  힌트, SEC-007) / 가입 중복은 **필드 단위**
- **주인공 = 폼 그 자체**(입력값 17 + 주 CTA 18). 인증에는 큰 수치가 없어 경매 상세의 44px을
  복사하지 않는다. 화면의 무게 중심이 흰 카드 안에 있다

### 반응형 — 접기가 아닌 지점 4개
| 항목 | 데스크톱 | 모바일 |
|---|---|---|
| CTA 도달 | 폼 아래 정위치 | **카드 내부 sticky bottom** |
| 보조 설명 | 병렬 열 | **접힌 아코디언** |
| 첫 필드 포커스 | 자동 | **안 함** |
| 에러 전달 | `role=alert` 배너 | + **포커스 이동·스크롤** |

**sticky 근거**: 가입 4필드는 360×640에서 **키보드 뒤 잔여가 ~300px**이라 CTA가 절대 안 들어온다.
`fixed`가 아닌 이유 — fixed는 흐름 밖이라 하단 패딩을 따로 확보해야 하고 OAuth·푸터 위까지 떠다닌다.

**모바일 다단계 분할은 명시적 기각** — 계약에 없는 중간 상태(부분 제출)를 만들거나 비밀번호를
클라이언트에 오래 들고 있게 된다.

## ★ 판단 대기 4건 — 확정하지 마라
사용자 결정 사항이다. **목업의 현재 상태를 유지**하고, 개편이 영향을 주면 **보고**하라.
1. **약관 동의** — 문장 vs 체크박스. **체크박스면 계약 §2에 동의 필드 추가 = 게이트2.**
   더불어 체크박스는 CTA 위에 와야 하는데(미체크 시 disabled) **모바일 sticky 바가 가릴 수 있어
   sticky 영역에 함께 넣는 설계가 추가로 필요**하다.
2. **네이버 버튼 대비** — 흰 라벨 on `#03C75A` = **2.25:1**, opacity .78 합성 후 **1.94:1**.
   브랜드 규격 자체가 AA 미달이다.
3. **가입 CTA 문구** — "회원가입" vs "가입하기". 18px/800 슬롯은 어느 쪽이든 한 줄에 들어간다.
4. **폼 좌측 배치** — DOM 순서 규칙을 관례보다 우선한 결과. 좌/우 어느 쪽이든 반응형 설계는 성립.

## 창작하지 않은 것 — 유지하라
- **약관 동의 체크박스** (계약 §2에 동의 필드 **없음**)
- **비밀번호 규칙 힌트** (계약이 정책 미명세 — 지어내면 "안내는 통과인데 400")
- **이메일 필드** (계약 §2 `signup` body = `{loginId, password, nickname}`. 자리만 잡혀 있다)
