## 목표
경매 목록 화면을 만든다. 지금 `PagePlaceholder`다.

## ★ 범위를 쪼갰다 — 상세는 FC-064
에픽 원안은 "경매 목록·상세"였으나 **한 티켓에 화면 둘은 위험**하다. 근거: **홈 한 화면이
3번 재작업**됐다(피드백 12건 → 아웃라인 정정 → 모바일 파손). 목록·상세를 묶으면 한쪽 반려가
다른 쪽까지 되돌린다.
→ **FC-059 = 목록**, **FC-064 = 상세 + 입찰**(신규).

## 재사용 — 이미 있는 것
FC-058이 만든 것을 **그대로 쓴다**(공유 위치라 재사용이 전제다):
- `features/auction/components/` — `AuctionGridCard`·`AuctionFeatureCard`·`AuctionRowItem`·
  `CountdownText`·`UrgencyBadge`·`SnapCarousel`·`interactionClass`
- `features/item/components/ItemArtSlot` + `itemOutline.css`(§5.12 2겹 링·크로마키 처리)
- `features/item/lib/` — `itemArt`·`itemCode`·`element`·`goldforce`
- `lib/api/auctions.ts`·`lib/queries/auctions.ts`

**카드를 새로 만들지 마라.** 이 에픽의 목적이 *"컴포넌트가 한 몸이라 통일성이 나온다"*이고,
지난번 지적("영역별로 디자인이 틀어진다")의 원인이 화면마다 카드를 따로 만든 것이었다.
**부족하면 공유 컴포넌트를 확장**하고, 그 변경이 **홈에도 반영된다는 것을 의식**하라.

## 화면 구조 (레이아웃 B — 사용자 확정)

- **모바일**: 필터를 **바텀시트로 교체**(레일을 접는 게 아니다) + 적용된 필터 칩 줄

  (`max-w-full overflow-x-hidden` 루트 가드 · `grid-cols-1`에서 시작 · 고정 폭은 큰 BP에서만)

### 설계 판단 — 기록해둘 것
- **레일↔시트는 교체다.** `hidden lg:block`으로 레일을 **좁은 폭에선 렌더하지 않고**, 같은
  `AuctionFilterPanel`을 시트에 넣는다. 폼이 한 벌이라 **폭에 따라 거를 수 있는 조건이 달라지지 않는다.**
- **`kind` 종속은 비활성이 아니라 미출현.** 대분류 미선택 시 종류 묶음이 **없고** 이유를 한 줄로 안내.
  선택 시 `legend`가 **"무기 종류"** — 라벨 자체가 다의성을 없앤다. 칩도 **"무기 · 검"**.
  ★ 방어는 UI가 아니라 **`normalizeFilters` 한 곳**에 있다 — URL·칩·초기화가 전부 통과하므로
  손으로 고친 `?kind=1`도 서버에 안 나간다. 컴포넌트에 뒀다면 링크 공유·뒤로가기로 샌다.
- **카드를 한 장도 새로 만들지 않았다.** 열 수만 다르다(홈 `xl:4` / 목록 `xl:3` — 레일이 240px).
- **`auctionKeys.list` → `preview` 개명 + `browse` 신설.** 홈 캐시가 목록 필터에 딸려 무효화되지
  않는다(분리 목적 달성). 홈 51건 전건 통과로 확인.
- **`hasNext=false`면 "24개"로 정확히 적는다** — 다 받고도 "이상"이라 적는 건 거짓이다.
  구 프론트 규칙("항상 N개 이상")에서 **의도적으로 벗어난 유일 지점**.

### ★ 번들 실측이 잡은 문제

메인 청크에 lodash가 없어 **중복이 아닌 순수 증가**였다. 직접 임포트로 **44.13 → 19.48 kB**.
