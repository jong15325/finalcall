## 목표
새 프론트에 **API·인증 계층을 세운다.** 화면은 만들지 않는다 — 화면이 딛고 설 바닥이다.

## 배경 (FC-055 결과)
- **서버 상태 = react-query 유지** 확정. 근거: 커서 페이징 대응물 부재 · 캐시 키 분리가 곧 무효화
  전략 · 입찰 후 무효화가 도메인 핵심 · 템플릿 37종은 props 기반이라 비용 0.
- **그러나 HTTP 클라이언트가 둘이다.** 우리 `apiClient`(fetch)와 **템플릿 axios 서비스가 공존**한다.
  → **이 티켓에서 하나로 만든다.**

## 복원할 규칙 (FC-055 이관 대장, 원본 `origin/master` `05b5e1b`)
| 규칙 | 원위치 | 왜 |
|---|---|---|
| **refresh single-flight** | `lib/api/client.ts` | 동시 401 다발을 **1회로 합류**. 없으면 refresh가 병렬 폭주 |
| **429 재시도 정책** | `lib/queryClient.ts` | **4xx 무재시도**, `GATEWAY_429`만 `Retry-After` 존중 |
| **에러 envelope 언랩** | `lib/api/client.ts` | 서버 공통 응답 포맷(§5) |
| **에러 코드 표** | `types/errorCodes.ts` | `BID_007`·`ITEM_003` 등 계약 등재분 누락 전력 있음 |
| **테스트 setup 스토어 초기화** | `test/setup.ts` | 없으면 **"혼자 통과, 전체 실패"** 순서 의존이 생긴다 |

## ★ 게이트2 후보 — 토큰 저장소
`accessTokenPersistStrategy`가 템플릿 기본은 **쿠키**인데 FC-055가 일단 `localStorage`로 뒀다.
**refresh 토큰 회전(계약 §2)과 얽힌 보안 결정**이다.
→ **확정하지 말고 분석·권고만 하라.** 최소한 아래를 판단해 반환하라:
- 우리 계약의 refresh 흐름(§2 `POST /auth/refresh`)에서 **XSS·CSRF 노출면이 각각 어떻게 달라지는지**
- 템플릿 기본(쿠키)을 따를 때 **`X-Gateway-Token` 프록시·백엔드 CORS/SameSite와 충돌하는지**
- 현행 백엔드가 **토큰을 어떻게 내려주는지**(바디인지 Set-Cookie인지) — 코드로 확인하라.
  **백엔드는 동결이라 바꿀 수 없다.** 서버가 이미 정한 방식이 선택지를 좁힌다.

## DoD
- **HTTP 전송로가 하나다.** 템플릿 axios 서비스를 걷어내고 `apiClient`로 통일(또는 반대 —
  **판단하고 근거를 대라**. 단 **둘 다 남기지 마라**).
- 위 5개 규칙 복원. 각각 **테스트로 고정**한다(FC-055가 vitest를 살려뒀다).
- 인증 흐름(로그인·로그아웃·refresh·401 처리)이 **계약 §2대로** 동작한다.
- react-query `queryClient` 설정(재시도 정책 포함).
- `npm run test`·`typecheck`·`lint`·`build` 전건 통과.

## 제약
- **화면을 만들지 마라.** 셸은 FC-057, 화면은 FC-058~062.
- **`backend/**` 수정 금지**(동결). **`docs/**` 수정 금지**(발견은 보고만).
- **토큰 저장소를 확정하지 마라** — 권고만. 게이트2다.
- 계약에 없는 엔드포인트·필드를 전제하지 마라.
- 코드 스타일: 템플릿 prettier(`semi: false`·`tabWidth: 4`) + eslint flat config.
