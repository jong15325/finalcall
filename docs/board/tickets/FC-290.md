## 목표 / DoD

실제 AppShell·토큰·공용 컴포넌트를 그대로 사용해 메인색 후보 10안을 비교한다. 의미색은 고정하고 일반 주요 행동·선택·내비게이션·푸터만 후보색을 따르며, 흰 글자와 WCAG AA 대비를 검증한다.

## 파생 경위

워크벤치 구축 후 사용자가 실제 프론트 정본 기반으로 색상 목업을 다시 요청해 FC-288에서 파생했다.

## 디자인 게이트 선택 (2026-08-13)

사용자가 실제 프론트 워크벤치의 `브라이트 스틸`(`fc-palette-steel-blue`) 후보를 최종 선택했다.
후보값 정본은 `frontend/src/workbench/fixtures/colorSystem.ts`이며, 전역 채택 대상은 다음과 같다.

| semantic token | 값 |
|---|---:|
| `--chrome-bg` | `#32475A` |
| `--chrome-bg-strong` | `#273746` |
| `--chrome-bg-raised` | `#273746` |
| `--chrome-bg-selected` | `#32475A` |
| `--control-action` | `#3D5F7C` |
| `--control-action-hover` | `#2E485F` |
| `--control-action-ink` | `#FFFFFF` |
| `--control-focus` | `#C78300` |

`success #16A34A`, `danger #E11D48`, `warning #A0510A`, `info #1D4ED8`와 각 의미색의 ink/soft
토큰은 변경하지 않는다. route element 색은 기존처럼 아이템 표시, `WorldMapBackground`, 명시적
`RouteAccentScope` 안에만 격리하며 commerce chrome·CTA·focus를 재색하지 않는다.

## 계약 영향과 후속 티켓

이 선택은 `docs/spec/frontend-ui-system-contract.md` §1·§2의 navy/gold/orange 공식 팔레트와 토큰 실값,
`DESIGN.md`의 요약값을 바꾸는 **게이트2 대상**이다. 디자인 게이트 선택만으로 기존 DECIDED 계약을 덮지 않는다.
영향 티켓은 다음 순서로 새로 발번한다.

1. **계약 델타(architect)**: `frontend-ui-system-contract.md` §1·§2의 브랜드·chrome·action·focus 값을
   브라이트 스틸로 변경하고 `DESIGN.md`를 파생 동기화한다. API·DB·route element·의미색 계약은 불변이다.
2. **전역 토큰 적용(frontend-impl)**: `frontend/src/styles/tokens.css`의 기존 palette/semantic alias를
   위 8개 값에 1:1 대응시킨다. 병렬 토큰·페이지별 override·raw color를 추가하지 않고 기존 consumer를
   일괄 승계한다. 워크벤치 fixture는 비교·회귀 증거로 유지한다.
3. **통합 리뷰(reviewer)**: navigation·drawer·footer·CompareBar·primary action·AuthLayout을 390×844와
   1280×800에서 확인하고 typecheck·lint·test·build·UI guard를 전부 실행한다. 의미색 고정과 route element
   격리도 함께 판정한다.

기존 FC-270(계약), FC-271(토큰 이관), FC-282(action ink), FC-290(후보 비교)의 완료 산출물은 영향 근거이지만
과거 티켓을 재개하지 않는다. 위 세 후속 티켓으로 변경·검증 이력을 분리한다.

### focus 대비 보완 필요

WCAG 상대휘도 계산 결과 흰 글자는 chrome `9.61:1`, strong `12.20:1`, action `6.72:1`, action hover
`9.51:1`로 AA를 충족한다. focus `#C78300`은 흰 surface `3.15:1`, chrome `3.06:1`, strong `3.88:1`이나
app canvas `#F4F5F8`에서는 `2.89:1`이다. 현 계약의 focus ring 인접 배경 3:1을 만족하려면 게이트2에서
다음 중 하나를 확정해야 한다.

- **추천**: 선택값 `#C78300`은 유지하고 focusable control이 white surface 또는 steel chrome 안에서만 해당
  링을 접하도록 구조·guard를 확정하며, canvas 직결 focus target에는 기존 semantic token으로 3:1 보조 경계를
  제공한다.
- 대안: `--control-focus` 값을 3:1 이상인 근접색으로 조정한다. 이는 사용자가 선택한 fixture 실값을 바꾸므로
  별도 확인 없이는 적용하지 않는다.

게이트2가 끝날 때까지 production token과 `frontend-ui-system-contract.md`는 변경하지 않는다.
