## 목표
- 사용자 간 실시간 채팅의 저장·전송·순서·중복·재접속·오프라인·인가·확장 모델을 결정한다.
- 기존 Redis·Kafka와 최신 Spring 생태계 후보를 비교하고 역할을 명확히 분리한다.

## DoD
- 1:1 채팅 우선 범위와 후속 확장 경계를 명시한다.
- DB 스키마, REST API, 실시간 프로토콜, 이벤트 계약 초안을 작성한다.
- Redis·Kafka·WebSocket 계층의 책임과 장애 시 동작을 정의한다.
- 메시지 순서, 멱등성, 읽음 상태, 재접속, 보존, 차단·신고·rate limit, 관측성을 설계한다.
- 목표 트래픽과 용량 산정, 부하·장애·동시성 테스트 전략을 제시한다.
- 되돌리기 큰 결정과 대안을 게이트2 브리핑 항목으로 분리한다.

## 근거인용
