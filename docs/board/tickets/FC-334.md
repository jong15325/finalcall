## 목표 / DoD / 검증
- DB commit 성공 후 Redis fast-path publish를 요청·JDBC 반환 경계 밖의 전용 bounded executor에서 수행하도록 내부 계약을 확정한다.
- immutable metadata snapshot만 전달하고 메시지 본문·JWT·SecurityContext·MDC 민감정보는 executor에 전파하지 않는다.
- 유한 pool·queue, non-blocking enqueue, 명시적 thread name, rejection·worker failure·bounded shutdown의 metric/drop 정책을 정의한다.
- rejection·실패는 요청 실패나 동기 fallback으로 전파하지 않고 DB outbox→Kafka 경로를 내구 fallback으로 유지한다.
- 외부 REST/STOMP/event schema와 ERD는 변경하지 않는다.
- rollback 0 enqueue, commit당 event별 1 enqueue, Redis 지연 시 HTTP/JDBC 비차단, 포화·종료·중복/역순 수렴과 단계별 부하 검증 기준을 명시한다.
- 2026-08-20 사용자 게이트2 승인에 따라 `chat-domain-spec.md` v1.2/G2-CHAT-7로 확정했다.

## 파생 경위
- FC-329의 150/s 재검증에서 `afterCommit()` 동기 Redis publish가 JDBC resource cleanup 전에 connection을 오래 점유하는 잔여 병목으로 관측되어 2026-08-20 게이트2 권고안 A 승인 후 파생했다.
