## 목표
인벤토리 슬롯을 이미지 중심으로 정리한다(실물 피드백·단순 수정). (1) 슬롯 하단 아이템 이름 텍스트 제거, (2) 아이템 이미지와 아웃라인(프레임)이 슬롯에 여백 없이 꽉 맞게.

## DoD
- `InventorySlotGrid.tsx`(+InventoryPage) 슬롯에서 **하단 아이템 이름 라벨 제거**.
- 아이템 이미지 + 아웃라인(프레임)이 슬롯 셀에 **여백 없이 꽉 맞게**(빈 슬롯 아웃라인도 정합). 아이템 프레임 아트 규칙(캔버스 72×134 정수배·크로마키 모서리 파랑 방지) 유지.
- 반응형(6칸 그리드) 유지·빈 슬롯/확장 버튼 배치 깨지지 않게. hover·비교/선택 오버레이 있으면 이미지 영역 불변 규칙 준수.
- `npm run build`+eslint+vitest 그린(InventorySlotGrid.test 갱신). 경매/마켓 카드엔 영향 없게(인벤 전용).

## 추가 (사용자 피드백 2차)
- 인벤토리 슬롯 hover 효과를 **상단 이동(translateY) → 아이템 이미지 확대(scale/zoom)**로 변경. 인벤 전용 override(경매/마켓 카드 hover 무영향)·hover 개별 카드에만(§3.1 #6)·프레임 내부 비율 불변(transform scale)·overflow-hidden 안에서 클립.

## 추가 (사용자 피드백 3차)
- **hover 확대 오버플로**: overflow-hidden에 클립돼 확대 이미지가 잘림 → hover 시 이미지가 슬롯 밖으로 살짝 튀어나오게(오버플로 노출·z-index 상향). 정지 아웃라인 핏 유지.
- **확장 슬롯 탭 크기 버그**: 확장 탭 페이지 슬롯이 기본 페이지보다 작게 렌더 → 전 페이지 슬롯 크기 동일하게.

## 추가 (사용자 피드백 4차 — 반응형)
- 인벤토리 그리드 **뷰포트 기준 6/3/2 반응형**. 6→3 브레이크포인트가 일찍 발동해 넓은 화면에서 공백인데 3칸 → 임계 낮춰 6칸. 페이지 간(기본/확장 탭) **슬롯 셀 크기 통일**(같은 뷰포트=같은 컬럼수·크기, 페이지 구성 무관).

## 추가 (사용자 피드백 5차 — 근본원인 확정)
- **버그 근본원인(총괄 브라우저 DOM 측정 확정)**: `<section mx-auto max-w-[820px]>`이 flex-column 부모에서 `mx-auto`로 stretch 안 되고 내용 크기 수축 → 빈 슬롯 페이지(25-48·49-72·73-96)는 섹션 336px·컬럼 42px로 붕괴("페이지 2~4 슬롯 작아짐"의 진짜 원인). 앞선 3·4차의 "코드상 동일" 판정이 놓친 지점. **수정 = 섹션에 `w-full` 추가**(width:100%로 부모 채우고 max-w 캡 → 전 페이지 820px 동일, 측정 검증).
- **탭 라벨**: `기본 슬롯 / 25-48 / 49-72 / 73-96` → `기본 슬롯 / 추가 슬롯1 / 추가 슬롯2 / 추가 슬롯3`.

## 추가 (사용자 피드백 6차 — 셀 여백)
- w-full로 셀이 122px(1fr)로 넓어져 72px 카드 주위 다크 여백 발생 → 셀 폭을 **카드 프레임 폭(72px) 고정**으로(1fr 폐기), justify-center 중앙 정렬. 카드 꽉참 + 고정폭이라 페이지 간 일관(붕괴 원천 차단). 반응형 6/3/2 컬럼 수 유지.

## 추가 (사용자 피드백 7차)
- 개별 슬롯 아웃라인 모서리 라운드 제거(FilledSlot/EmptySlot `rounded-xl`→각짐). 섹션 카드 등 다른 라운드 보존. 총괄 브라우저 확인.
