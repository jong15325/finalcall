## 목표
- **에픽의 핵심 티켓.** 마감 직전 입찰 폭주에서 정확성을 잃지 않는 입찰 처리를 구현한다.
- 경매 단위 직렬화(D-008) 안에서 검증 → 홀드 → 직전 홀드 해제 → 최고가 갱신 → 소프트클로즈 연장을 원자적으로 수행한다.

## DoD
- **`POST /api/v1/auctions/{auctionPublicId}/bids`** 구현. 인증 필요, 주체는 **SecurityContext에서만** 도출(요청 바디로 입찰자 식별 금지 — IDOR 차단).
- **직렬화**: FC-030 게이트2 (a) 결정 방식으로 경매 단위 직렬화. `@DistributedLock` 채택 시 AOP self-invocation 주의(CLAUDE.md 섹션 4 — 외부 빈 경유).
- **검증 순서·에러코드**(계약 §5와 1:1): `BID_006` 마감/종료(409) · `BID_003` 자기 경매(403) · `BID_004` 연속 입찰(409) · `BID_001` 최소 증분 미달(422) · `BID_002` buyNowPrice 이상(422) · `BID_005` 잔액 부족(422). 정확한 순서는 bid-domain-spec 확정본을 따른다.
- **홀드 왕복**: 입찰 성공 시 게임머니 홀드 생성, **직전 최고입찰자 홀드 즉시 해제**(P-008). 실패 시 전량 롤백 — 홀드만 남거나 잔액만 묶이는 중간 상태가 없어야 한다.
- **최고가 갱신**: `auction.highest_bid_amount`·`highest_bidder_id` 갱신(직렬화 구간 내).
- **소프트클로즈 연장**: 잔여시간 < `soft_close_window_sec`이면 `end_at += soft_close_extend_sec`, `max_end_at` 상한 클램프, `extension_count` 증가. 동일 직렬화 단위에서 판정(계약 §3.1 "동일 단위").
- **응답 201**: `{ bidPublicId, amount, currentHighestAmount, endAt }`.
- **테스트**: 단위·통합 + **동시성 통합 테스트**(동시 입찰 시 최고가 단조 증가, 홀드 합계 불변식, 연장 중복 없음). 본격 폭주 시나리오는 FC-034.
- 스타일: `./gradlew :backend:spotlessApply` 후 checkstyle 통과.

## 보안 유의 (최고위험 — end-of-turn 리뷰 on 구간)
- 금전 이동 원자성: 홀드 이중 생성·이중 해제·미해제, 잔액 음수화 불가.
- 직렬화 우회: 락 밖에서 읽은 값으로 판정하지 말 것(TOCTOU).
- `BID_003`/`BID_004` 우회: 판정 근거를 직렬화 구간 내에서 재확인.
