## 목표
- 입찰 이력을 조회 가능하게 하고, EPIC-AUCTION이 null/0으로 하드코딩해 둔 경매 응답의 최고가 필드를 **실값으로 대체**한다.

## DoD
- **`GET /api/v1/auctions/{auctionPublicId}/bids`** 구현. **인증 불요**(계약 §3.1), offset 페이지네이션, 입찰자 **마스킹**(계약 §3.3 — 닉네임 마스킹, 원문 노출 금지).
- **★ `minNextBidAmount` 구현(계약 v1.8 F3 미이행분 — 총괄 슬라이싱 누락 보정 2026-07-18)**: `AuctionDetailResponse`에 필드가 **아예 없다**. FC-030 게이트2에서 계약에 추가됐으나 FC-032·FC-033 어느 티켓 DoD에도 명시되지 않아 구현되지 않았다(FC-037 프론트가 발견). 이 필드가 없으면 프론트의 "다음 최소 입찰가"가 영구히 `—`로 남는다. 산출 로직은 `BidService.minNextBidAmount`와 **동일 규칙**이어야 한다(첫 입찰=`startPrice`, 후속=`최고가 + BidIncrementProperties.incrementFor(최고가)`) — 증분표를 두 번 구현하지 말고 공용화하라. 종료 경매는 null(계약 v1.9 §3.3).
- **★ `highestBidAmount` 정렬 keyset 교정(FC-038 리뷰 발견 #6, 2026-07-18)**: `AuctionRepositoryImpl.java:155`가 "본 에픽 전건 NULL" 전제로 `HIGHEST_BID_AMOUNT` keyset을 **id만으로** 잡고 있다(`case HIGHEST_BID_AMOUNT -> idAfter(lastId, asc)`). **실값이 들어오는 순간 페이지 경계가 깨져 중복·누락이 발생한다.** 최고가 실값 대체와 **같은 티켓에서 반드시 함께** 고쳐야 한다 — 실값만 넣고 keyset을 두면 무음 페이징 버그가 된다. NULL 정렬 위치(NULLS FIRST/LAST)도 함께 확정하라(입찰 없는 경매가 섞인다).
- **auction 목록·상세 실값 대체**: `highestBidAmount`(현재 null 고정) · `bidCount`(현재 0 고정) · `highestBidderMasked`(현재 null 고정)를 실제 값으로 바꾼다. **스키마·계약 무변경**이어야 한다 — auction-domain-spec §9-b가 "EPIC-BID 진입 시 실값으로 자연 대체(스키마·계약 무변경)"로 이미 설계해 뒀다.
- **N+1 방지**: 목록에서 경매별 최고가·입찰수를 가져올 때 경매 건수만큼 쿼리가 늘지 않아야 한다(`auction.highest_bid_amount` 비정규화 컬럼 활용 or 집계 조인). QueryDSL.
- **`bidCount` 산출 근거 확정**: 비정규화 컬럼 신설 없이 `bid` 집계로 낼지, 집계 비용이 문제면 FC-030 판정을 따른다.
- **테스트**: 슬라이스(정렬·페이징·마스킹) + 통합(입찰 후 목록·상세에 실값 반영). EPIC-AUCTION의 기존 통합 테스트 중 "최고가 null/0" 단정이 있으면 실값 기준으로 갱신.
- 스타일: `./gradlew :backend:spotlessApply` 후 checkstyle 통과.
