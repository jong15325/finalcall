## 목표 (버그 수정 + UX 강화)
현재 중복확인이 advisory(제출 비차단)라 **확인 없이 회원가입이 뚫린다**(사용자 보고). 아이디·닉네임 중복확인을 **제출 전제(필수)** 로 강제한다.

## DoD (프론트 SignupForm)
- **미확인 차단**: 아이디 또는 닉네임이 "중복확인 완료(available)" 상태가 아니면 회원가입 제출 차단 + 해당 필드에 안내 문구("아이디 중복확인을 진행해 주세요." / "닉네임 중복확인을 진행해 주세요.").
- **둘 다 확인 필요**: 아이디·닉네임 **모두** available 확인돼야 가입 가능.
- **taken/error 차단**: 확인 결과 중복(taken)·오류 상태도 제출 차단(available만 통과).
- **값 변경 시 재확인**: 확인 후 아이디/닉네임 값을 바꾸면 확인 상태 초기화(idle)로 되돌려 재확인 강제(현 동작 유지·확인). 초기화된 상태에서 제출하면 위 안내 문구.
- 백엔드 409(AUTH_001/AUTH_002)는 **최종 방어선으로 유지**(엔드포인트는 여전히 advisory·예약 아님).
- 접근성: 안내 문구 `role`·`aria-live`·포커스 이동 기존 패턴 재사용. `npm run build`·lint·vitest 그린(미확인 제출 차단·변경 후 재확인 테스트 추가). 커밋 금지.
