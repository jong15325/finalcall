## 목표
판매 UX를 인벤토리 주도로 바꾼다. (1) 인벤토리를 **아이템 마켓과 같은 전체폭 페이지 영역**으로 개편(그리드 배치는 인벤토리 유지), (2) 아이템 **클릭 → 상세 다이얼로그의 [판매하기]** → 판매 페이지 이동, (3) 판매 페이지는 **선택한 아이템만** 노출(전체 선택 그리드 제거). **디자인 게이트 승인됨**(목업 사용자 승인 2026-08-04).

## 목업(정본 참조)
`scratchpad/sell-flow-mockup.html`(인터랙티브). 웹/모바일, 3단계 흐름·팔레트(navy/gold/orange=index.css) 반영.

## DoD
1. **인벤토리 개편(InventoryPage/InventorySlotGrid)**: MarketPage 셸과 동형 — 헤더(제목+부제+우측 액션 "임시 보관함") + 툴바(전체 아이템·용량 배지) + **전체폭 그리드**(웹 6열/태블릿 3열/모바일 2열, 마켓과 동일). 좁은 820px 중앙 박스 제거. **인벤토리 성격 유지**(빈 슬롯·용량 5/24·프레임 타일). 슬롯 클릭 가능(스킬 플립은 다이얼로그 상세로 흡수).
2. **아이템 상세 다이얼로그**: 슬롯 클릭 → 아이템 상세(프레임·이름·속성/종류/Lv·스킬) + **[판매하기]** 액션. 웹=중앙 모달·모바일=바텀시트. 마켓 카드→ShopCardInfoDialog 패턴/컴포넌트 재사용 검토(ItemFrame·ItemSkillSummary 재사용).
3. **판매 이동 배선**: [판매하기] → `/sell?item=<itemInstancePublicId>`(URL 쿼리 정본, MarketPage searchParams 관례·리로드 생존). 
4. **판매 페이지 선점 모드(SellPage)**: `?item` 있으면 그 아이템만 **잠금 카드**로 상단 고정(1단계 picker 그리드 제거) + "인벤토리에서 다시 선택" 링크(→인벤토리). `?item` 없거나 무효면 **빈 상태**("인벤토리에서 판매할 아이템을 선택하세요 → 인벤토리로"). 이후 판매 방식·가격·시간·우측 등록확인은 기존 유지.
5. 타입체크·lint·해당 테스트 통과(SellPage 기존 테스트 갱신, 인벤토리 클릭·선점 테스트 추가). 계약/백엔드 **무변경** 확인. coding-discipline·impeccable 스킬 준수.
