### 구성 판단 — `vitest.config.ts` 분리 + `mergeConfig` 상속
합침을 택하지 않은 이유가 좋다: `vite.config.ts`에 `X-Gateway-Token` 주입이 들어 있고 테스트
설정은 앞으로 계속 만지게 된다(setup·include·coverage). test 블록을 그 파일에 넣으면
**테스트 설정을 건드릴 때마다 GATEWAY_403 지뢰 옆을 지나는 구조**가 된다. 분리의 통상 단점인
alias·플러그인 중복은 `mergeConfig`가 없앤다.

### ★ 테스트 설계 주의 (재사용 가치 있음)
**특정 코드를 "미등록"이라 단정하지 않았다.** `ELEMENT_CODES`는 계속 자라므로 등록 목록을
테스트에 복제하면 **축 확장 때마다 거짓 실패**한다. 명백한 범위 밖 값(`99`)과 **등록 목록 자체를
순회**하는 방식을 썼다 → 3·4를 등재해도 테스트가 그대로 통과한다.
스모크 판정 기준도 "h1이 보인다" 수준으로 얕게 잡았다 — 문구를 세밀히 걸면 카피 수정마다 깨져
**스모크가 잔소리로 전락**한다.

핵심 방어: **M-1 회귀**(빈 스킬 슬롯 null·undefined → "없음") · **0~120 전수 라벨 무예외**
(배열 인덱싱·exhaustive switch 하드코딩 차단) · 소비처 3곳 미등록 코드 렌더.
