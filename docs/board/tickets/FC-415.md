## 목표
- 비인증 반복 요청이 추천 DB 집계 비용을 무제한 증폭하지 못하도록 엣지에서 제한한다.

## DoD
- 일반 service route보다 앞선 정확 경로·GET 전용 RequestRateLimiter route를 추가한다.
- 기본값은 replenishRate 1, burstCapacity 10, requestedTokens 1이며 환경변수로 조정 가능하다.
- 기존 `TrustedProxyClientIpKeyResolver`와 Redis 토큰버킷을 재사용한다.
- 제한 초과 429 `GATEWAY_429`·`Retry-After`와 Redis 장애 fail-closed 동작을 검증한다.
- 다른 `/api/v1/**` 및 구매·취소 POST의 라우팅·보안 계약을 바꾸지 않는다.

## 근거(인용)
> 보안 게이트2 승인: 공개 추천 GET에 IP당 초당 1회, burst 10의 전용 제한을 적용하고 Redis 장애 시 fail-closed를 유지한다. (2026-08-31 사용자)

## 검증
- 실제 Redis Testcontainers에서 burst 429 `GATEWAY_429`·`Retry-After: 1` 통과.
- SCG 기본 limiter의 Redis 장애 fail-open을 실측하고 홈 추천 route 전용 래퍼로 429·하류 요청 0건 보장.
- route 우선순위·정확 Path+GET·기본값 바인딩과 gateway 전체 테스트 8건 통과.
- gateway spotless, checkstyleMain/Test, bootJar, `git diff --check` 통과.

## 보안 재작업 요청
- 홈 전용 limiter 빈이 기존 auth/chat 기본 limiter 자동 구성에 영향을 주지 않도록 타입·빈 배선을 완전 격리.
- 환경변수 replenishRate 변경 시 `Retry-After` 연동.

## 보안 재작업 완료
- 홈 limiter를 `RateLimiter<RedisRateLimiter.Config>` composition으로 분리하고 기본 `redisRateLimiter` primary 유지.
- Redis 장애에서 홈 429·하류 0회, 기존 auth route 200·하류 1회로 정책 분리 검증.
- 홈 `Retry-After = ceil(requestedTokens/replenishRate)`로 연동, 비기본 3/2에서 2초 확인.

## 보안 2차 재작업 요청
- rate limit 세 환경값 모두 양수, `burstCapacity >= replenishRate`를 부팅 시 fail-fast 검증.
- 0·음수·관계 역전 설정의 컨텍스트 실패 테스트 추가.

## 보안 2차 재작업 완료
- 검증된 `HomeRecommendationRateLimitProperties`로 세 값 양수와 burst≥replenish를 부팅 시 강제.
- 0·음수·역전 관계 컨텍스트 실패, 정상 비기본값 바인딩 통과.
- overflow 없는 동적 Retry-After 계산과 gateway 전체 테스트 19건 통과.
