## 게이트2 상신 후보 (5건 — 사용자 승인 필요)
- **(a) ★ 직렬화 메커니즘**: 경매 단위 직렬화(D-008)를 `@DistributedLock`(Redis, E1) / DB 비관적 락 / auction row CAS 중 무엇으로 구현할지. **프로젝트 핵심 기술 도전의 본체**이고 되돌리기 비용이 크다. 트레이드오프(정확성·처리량·장애 시 동작·테스트 가능성)를 근거와 함께 제시할 것.
- **(b) 홀드 원자성 경계**: 잔액 차감·홀드 생성·직전 홀드 해제를 한 트랜잭션에 묶을 범위와 락 범위의 관계. 직전 입찰자 해제가 실패했을 때의 정합 회복.
- **(c) 소프트클로즈 연장 규칙**: `max_end_at` 상한 도달 시 동작, `extension_count` 증가 시점, 연장 계산이 직렬화 구간 안에서 일어나는지.
- **(d) SCHEDULED→ACTIVE 영속 전이**: 현재 lazy 파생(표시층, EPIC-AUCTION 게이트2 (a) 결정). 입찰은 실제 ACTIVE 판정이 필요 → 워커 도입을 EPIC-BID로 당길지 EPIC-CLOSING에 둘지, 아니면 입찰 시점 파생 판정으로 충분한지.
- **(e) BID_004(연속 입찰) 판정 근거**: `auction.highest_bidder_id` vs `bid` 테이블 조회. 전자는 스키마 무변경·직렬화 구간 내 판정 가능.
