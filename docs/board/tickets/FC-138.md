## 목표
이메일 인증 화면을 구현한다. 현 `VerificationCard`("준비 중" 자리보류·aria-disabled) **활성화** + 이메일 설정/6자리 코드 입력/재전송 쿨다운/시도초과 흐름. 디자인 게이트 통과(목업 승인 2026-07-27).

## DoD
- **API 클라이언트** `lib/api/email.ts` 신설: `PUT /api/v1/me/email {email}`·`POST /api/v1/me/email/verification-request`(202)·`POST /api/v1/me/email/verify {code}`. 계약 §4.2~4.4.
- **VerificationCard 활성화**: aria-disabled·"준비 중" 자리보류 해제, 이메일 인증 항목을 실동작으로. (휴대폰 인증은 백엔드 없음 → "준비 중" 유지)
- **흐름 구현**(목업 3상태 준수):
  - 미설정 → 이메일 등록 폼(`@Email`, `PUT /me/email`).
  - 설정·미인증 → 마스킹 이메일+"미인증"+"인증 코드 받기"(`verification-request`)·"이메일 변경".
  - 코드 입력 → 6칸 OTP + 남은시간(mm:ss, TTL 10분) + 시도 n/5 + "코드 다시 받기"(쿨다운 60초 카운트다운) → `verify`.
  - 인증완료 → 성공 상태+"인증됨"+"이메일 변경"(재인증 안내).
- **에러 처리**(FC-136 메시지): 불일치(EMAIL_001)·만료(EMAIL_002)·시도초과(EMAIL_003)·쿨다운(EMAIL_004)·이미인증(EMAIL_005)·미설정(EMAIL_006)·이미사용중(EMAIL_007). 재전송 쿨다운은 실 카운트다운.
- **보안/접근성**: 이메일 원문 미노출(마스킹만), OTP 입력 aria·label, 코드 입력값 로깅 금지. 목업 웹/모바일 설계 반영(모바일 OTP 터치 타깃·하단 CTA).
- 성공 시 me 쿼리 무효화로 F4 배너 갱신(F4 연계).
- 컴포넌트 테스트(상태 전이·에러·쿨다운) 추가·통과.
