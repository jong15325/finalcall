## 체크리스트

### A. 데이터 없이도 볼 수 있는 것 (FC-039 없이 선행 가능)
- [ ] **빈 상태** 화면이 초라하지 않은가(빈 상태도 설계 대상이다)
- [ ] 반응형 — 모바일 1열 → sm 2 → lg 3 → xl 4. 브라우저 폭을 줄여가며 깨지는 지점 확인
- [ ] 타이포·여백 리듬이 기존 화면(로그인·가입·프로필)과 **한 시스템으로 보이는가**
- [ ] 필터 바 조작감 — 칩 크기(44px 타깃이 과하게 두툼하지 않은지), 선택 상태 시인성
- [ ] 키보드만으로 목록 → 필터 → "더 보기"까지 도달 가능한가(Tab만 사용)

### B. 데모 시드 후 (FC-039 완료 시)
- [ ] **카드 그리드 전체 인상** — 20장쯤 깔았을 때 리듬이 살아나는가, 아니면 단조로운가
- [ ] **`Countdown` 색전이 3구간** — 여유(muted) / T-5분(warning) / T-30초(danger). 실제로 눈에 띄게 다른가
- [ ] **"입찰 없음 · 시작가" vs "현재가 · 입찰 N회"** 가 나란히 있을 때 혼동되지 않는가
- [ ] 종료 경매 **딤 + "마감" 오버레이**가 충분히 구별되는가
- [ ] **무한스크롤** — 스크롤로 자동 로드되는가, "더 보기" 폴백도 동작하는가, 로딩 스켈레톤이 튀지 않는가
- [ ] 정렬 전환(마감임박/최고가/최신) 시 목록이 **처음부터** 다시 그려지는가(커서 초기화)
- [ ] 상세 화면 — 아이템 스탯 `dl` 가독성, **최고가/입찰수 영역이 값 있을 때/없을 때 레이아웃이 흔들리지 않는가**
- [ ] disabled 입찰 CTA가 "눌러도 되는 것처럼" 보이지 않는가(사유 문장 포함)
- [ ] `ItemArtSlot` 플레이스홀더가 **비어 보이지 않는가** — 게임 아트가 들어갈 자리라는 게 읽히는가

### C. 안티-AI 감각 점검 (디자인 원칙)
- [ ] 무신사·컬리 참조 커머스 톤이 실제로 느껴지는가, 아니면 부트스트랩 기본값 같은가
- [ ] 블랙 CTA가 화면에서 **적절히 무거운가**(§1.2 — 강조를 색이 아니라 크기·배치로)
- [ ] element 배지가 게임 느낌을 주되 **커머스 신뢰감을 해치지 않는가**(Game-Color Containment의 목적)

## 산출
- 발견 사항을 **심각도와 함께** 기록. 디자인 조정이면 디자인 게이트 경유, 구현 결함이면 frontend-impl 회부.
- 이 티켓은 **사용자가 주도**한다. 총괄은 체크리스트 제공 + 발견 사항 티켓화를 맡는다.
