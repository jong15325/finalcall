## 목표 / DoD / 검증
- Kafka consumer는 양 app에서 유지하되 전역 outbox/Kafka lag monitor는 배포당 정확히 한 replica에서만 활성화한다.
- monitor 활성 여부를 consumer 활성 여부와 독립된 설정으로 분리하고 기본값·validation·조건부 빈 생성을 검증한다.
- 2-app Linux 성능 topology가 active monitor 정확히 1개를 강제하고 artifact로 설정·metric 증거를 보존한다.
- active monitor를 유지한 동일 Linux 10/s에서 HTTP 201 101/101, p95 `<200ms`, p99 `<500ms`를 통과하면 50→150→300/s를 진행한다.
- 외부 REST/STOMP/event 계약과 DB schema·ERD는 변경하지 않는다.

## 파생 경위
- FC-329 run `32440472146`에서 양 app의 전역 Kafka lag probe가 동시에 실행된 시각과 10/s latency tail이 겹쳐, replica별 중복 관측 계약을 보정하기 위해 파생했다.
