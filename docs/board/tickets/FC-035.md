## DoD
- **동시성**(최우선): 직렬화 구간 경계가 정확한가 — 락 밖에서 읽은 값으로 판정하는 TOCTOU 없는가. AOP self-invocation으로 `@DistributedLock`이 무력화된 경로 없는가(CLAUDE.md 섹션 4). 락 획득 실패·타임아웃 시 동작이 정의돼 있는가. `concurrency-review` 스킬 체크리스트 적용.
- **홀드 정합**: 금전 총량 보존(잔액 + 활성 홀드). 홀드 이중 생성·이중 해제·미해제 경로. 직전 입찰자 홀드 해제 실패 시 회복. 잔액 음수화 불가.
- **도메인 인가**: 입찰 주체가 **SecurityContext에서만** 도출되는가(요청 바디 신뢰 금지, IDOR). `BID_003`(자기 경매)·`BID_004`(연속 입찰) 우회 경로. 입찰 내역 조회의 마스킹 일관성·permitAll 스코프.
- **계약 정합**: `BID_001~006` ↔ 계약 §5 코드·HTTP 상태 1:1. 응답 필드가 계약 §3.1과 일치. auction 최고가 필드 실값 대체가 스키마·계약 무변경으로 이뤄졌는가.
- **QA**: 소프트클로즈 `max_end_at` 상한 준수, 경계값(최소 증분 정확히 일치·buyNow 정확히 일치·마감 직전 1ms), 테스트가 불변식을 실제로 검증하는가(통과만 하는 껍데기 테스트 아닌지).
- **산출물**: `docs/board/reviews/FC-035-review.md` — critical/major/minor 심각도 랭킹. critical·major 0이어야 통과.
- 읽기 전용 — 코드를 수정하지 않는다. 발견은 FC-032 등으로 재작업 회부.
