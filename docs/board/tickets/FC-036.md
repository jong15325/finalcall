## 목표
- 경매 목록 화면을 만든다. **이 프로젝트의 첫 경매 화면**이며 이후 상세·입찰 UI의 기반이 된다.

## DoD
- **라우트·페이지**: 경매 목록 페이지 신설. 기존 `frontend/src/routes`·`pages` 구조와 `lib/api/client.ts` 패턴을 따른다(새 HTTP 클라이언트를 만들지 말 것).
- **API 연동**: `GET /api/v1/auctions` — **cursor 페이징**(§5.7: 센티넬 무한스크롤 + "더 보기" 폴백 버튼 — 키보드·스크린리더 접근 필수). `hasNext=false` 시 종료 표시.
- **정렬**: 마감임박(`endAt`)·최고가(`highestBidAmount`)·최신(`createdAt`). 계약 화이트리스트 밖 값을 보내지 않는다.
- **필터(핵심 4종만 — 디자인 게이트 승인)**: `status` · `minPrice`/`maxPrice` · `element`. 나머지 §5.4 필터는 **구조만** 잡아두고 구현하지 않는다. 적용된 필터는 제거 가능한 칩으로 가시화(§5.4 접근성).
- **`ItemCard`(§5.3)**: 상단 검정 아트 슬롯(**플레이스홀더** — 자산 매핑은 후속) + 하단 커머스 영역(아이템명·가격·카운트다운·판매유형 칩·판매자 닉네임). 반응형 1→2(sm)→3(lg)→4(xl)열.
- **`Countdown`(§5.9)**: font-num, 임박 단계 색 전이(여유 `text-muted` → T-5분 `warning` → T-30초 `danger`). **`aria-live=off`**(초당 갱신 스팸 방지), 임박/마감 전환 시점에만 폴라이트 안내. 종료 시 "마감" 정적 표시.
- **`StatusChip`(§5.8)**: 경매 status를 의미색 `-soft` 배경 + 텍스트 병기(색 단독 금지).
- **★ 최고가 표시**: `highestBidAmount`가 **현재 전건 null**이다(입찰=EPIC-BID 미구현). `auction-domain-spec §9-b` 확정대로 **"입찰 없음 · 시작가 N"**으로 표시하라. **`startPrice`를 현재가인 것처럼 보여주지 말 것.** null 분기를 유지하면 EPIC-BID 완료 시 실값으로 자동 전환된다(계약·스키마 무변경 설계).
- **상태**: 로딩 스켈레톤 · 빈 상태 · 에러 상태. 종료 경매는 딤 + "마감" 오버레이(§5.3).
- **접근성**: `docs/ux/accessibility.md` 준수. 키보드 내비, 포커스 링(`--color-focus-ring`), 색 단독 정보 전달 금지.

## 금지
- **디자인 시스템을 벗어난 새 색·컴포넌트를 만들지 마라.** §1.2 3계층 규칙(조작=블랙 CTA·퍼플 액센트 / 정보=의미색 / 아이템=element)을 지키고, **Game-Color Containment**(element 색은 아이템 카드·속성 배지·필터 칩 밖 사용 금지)를 위반하지 마라.
- 백엔드(`backend/**`)를 건드리지 마라 — EPIC-BID가 병렬로 돌고 있다. 계약·spec·티켓·보드도 수정 금지.

## 근거(인용)
> 계약 §3.3 `AuctionSummary { auctionPublicId, status, startPrice, buyNowPrice?, highestBidAmount?, bidCount, startAt?, endAt, sellerNickname }`.
