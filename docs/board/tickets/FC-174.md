B=클라가 senderId 미전송(서버 토큰 주체 고정)이므로 `sender_id=demo1`은 송신 시점 store.accessToken이 T1이었다는 물증 — 원인은 로그인 비원자(`updateTokens`만)+refresh single-flight의 **세션 세대 가드 부재**(stale rotate가 새 세션 토큰 덮어씀) → 증상 2. **밴드에이드(메모만 무효화) 금지**, 세션 전환 1곳 원자 리셋(`resetSession`=store clear + `queryClient.clear()` + refresh 무효화)+refresh 세대 가드로 해결. authStore는 QueryClient 미접근(오케스트레이션=핸들러/브릿지 계층). 백엔드·api-contract **무변경 확인**. **게이트2 아님**. 단일 frontend-impl 티켓(파일집합=artifacts). 상세=spec §3~§6.
## 목표
로그아웃→다른 계정 로그인(계정 전환) 시 **이전 계정의 신원·데이터가 잔존**하는 세션 생명주기 결함을 없앤다. 메모 라이브 검증(FC-173 후속)에서 발견됐으나 **auth/세션(FC-056) 도메인** 결함으로, 인증 필요 전 화면에 영향한다.

## 증상 (재현·물증)
- 사용자 제보: demo3에게 보낸 쪽지가 demo1·demo2 받은함에도 보임.
- DB 물증(`user_memo`): demo2 UI에서 보낸 쪽지가 `sender_id=demo1`로 저장됨(신원 뒤바뀜). 즉 요청이 **직전 계정 토큰/신원**으로 나감.
- 백엔드는 정상: 토큰 주체대로 정확히 저장·필터(demo1 fresh 로그인 시 받은함 정상적으로 빔).

## 추정 근본원인 (architect가 확정)
- **A. react-query 캐시 미초기화**: `memoKeys`(및 여타 쿼리)가 **사용자 무관 전역 키**인데 `clearSession`이 QueryClient 캐시를 안 비운다 → 이전 계정 목록/뱃지 잔존.
- **B. 토큰·user 원자성 결여**: 로그인 2단계(토큰 → GET /me) 사이/계정 전환 시 토큰과 user 요약이 desync → 요청이 이전 신원으로 귀속.
