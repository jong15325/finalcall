## 목표
- 실시간 경매 목록의 가로 전용 카드를 아이템마켓과 같은 공용 세로 카드 composition으로 전환한다.
- 아이템 identity·스킬·가격·입찰 수·마감 시간·상태·판매자를 거래 판단 순서로 안정적으로 배치한다.
- FC-313에서 이미 진행한 두 스킬 행 높이·퍼센트 강조 변경은 보존하되 전체 카드 계약 안으로 편입한다.

## DoD
1. **공용 composition**
   - `AuctionCard`는 `AuctionSummary → ItemCardViewModel`과 경매 extension slot 조립만 맡는다.
   - `ItemCardView density="compact"`, `ItemCardArtwork`, `ItemFrame`, `ItemCardActionSurface`,
     `ListFrame`을 재사용하고 카드 chrome·스킬·가격·판매자 DOM을 복제하지 않는다.
   - `ItemCardView`에 경매 타입 import나 도메인 boolean prop을 추가하지 않는다.
   - generic `artwork` slot의 feature geometry wrapper로 아이템마켓 compact stage보다 세로 `44px` 확장한다.
     내부 72×134 frame 비율은 유지하며 공용 view에 auction boolean이나 기준 절대 높이를 복제하지 않는다.
2. **앞면 정보 순서**
   - artwork(좌상단 phase + 우상단 bid badge) → type/element → kind/level → 스킬 1·2 → 가격 →
     countdown → 판매자 순서를 지킨다. 본문 입찰 수 행은 제거한다.
   - 0·1·2개 스킬이 같은 두 행 높이를 가지며 스킬2 퍼센트는 아이템마켓 강조 체계를 재사용한다.
   - `highestBidAmount == null`이면 `시작가`, 값이 있으면 `현재가`; 입찰 수 0은 `입찰 없음`이다.
3. **상호작용**
   - 이미지와 정보 본문은 경매 상세로 이동하고 keyboard 대표 link는 하나뿐이다.
   - 경매 목록에서 compare button·`CardCompareOverlay`·`aria-pressed`·compare-store 구독을 완전히 제거한다.
     아이템마켓·홈 preview·경매 상세의 기존 compare는 변경하지 않는다.
   - phase/bid badge는 비상호작용이며 상세 pointer action 위에 겹쳐도 클릭을 막지 않고 focus order에 들어가지 않는다.
   - bid badge는 4.5:1 대비와 tabular 숫자를 유지한다. 시각값은 0=`입찰 없음`, 1~9,999=`입찰 N건`,
     10,000 이상=ko-KR compact notation(`입찰 1.2만건`·`입찰 9,007조건`)으로 최대 2행 표시한다.
   - 전체값은 `title`과 `aria-label` 또는 동등한 accessible text에 축약 없는
     `입찰 9,007,199,254,740,991건` 형식으로 보존한다.
   - visual/full label을 함께 반환하는 경매 feature 순수 helper를 운영 카드와 workbench Candidate가 직접 공유한다.
     `ItemCardView`에 bid-count formatter·임계값·경매 도메인 prop을 넣지 않는다.
   - 경매 목록에는 flip을 조립하지 않는다. 경매 상세, 홈 preview와 아이템마켓 dialog/flip은 변경하지 않는다.
4. **반응형·상태**
   - `AuctionListPage` ready와 skeleton은 별도 경매 preset을 만들지 않고 아이템마켓과 같은
     `layout="catalog"` (`grid-cols-2 gap-3 xs:grid-cols-3 min-[1200px]:grid-cols-6`)를 직접 사용한다.
   - 320px·390px 2열, 576px 3열, 1200px/1280px 6열이며 gap도 `gap-3`으로 동일하다.
   - 고정 최소 폭을 두지 않고 모든 grid child·본문에 `min-w-0`를 유지한다. 좁은 카드에서 본문은
     가격→countdown→판매자 순서로 적층하고 full 금액은 wrap하며, 판매자·스킬명만 truncate한다.
   - 320·390·1280·200% 확대에서 overflow가 없고 ready와 catalog skeleton의 열 수·geometry가 같다.
   - `AuctionListPage`의 단일 `useNow()`를 모든 카드가 공유한다. 카드별 timer·polling·신규 요청이 없다.
5. **디자인 게이트**
   - 실제 AppShell 기반 dev-only `/__design/auction-card`에서 0/1/2 skill, 긴 문자열·가격,
     시작 전/진행 중/마감, 입찰 0/9,999/10,000/매우 큰 수, compact 기준/+44px artwork fixture를 제공한다.
     입찰 badge의 최대 2행 visual compact label과 full `title`·accessible label을 함께 검증한다.
     compare selected/full fixture는 제거한다.
   - 390×844 2열·200% 확대와 1280×800 6열에서 정보 위계·artwork +44px·badge 대비/최대 2행·전체
     accessible value·세로 facts·금액 wrap·image/detail hit-area·focus·overflow·production residue를 확인한 뒤
     운영 반영한다.
6. **검증**
   - `AuctionCard`, `AuctionListPage`, `ListFrame`/skeleton, `auctionPriceOf`·`Countdown`, 목록 compare 부재와
     다른 화면 compare 비영향 테스트, typecheck·lint·production build·workbench guard가 통과한다.

## API·성능 경계
- 기존 `GET /auctions`의 `AuctionSummary`만 사용한다. API·백엔드·DB·query key·error contract 변경은 없다.
- 신규 dependency·asset·Canvas·RAF·network request가 없고, 단일 초 tick 외 지속 작업을 추가하지 않는다.

## 영향 분석
- 직접 영향: FC-071(가로 경매 카드), FC-273(ListFrame/grid), FC-274(공용 composition),
  FC-278(통합 검증), FC-280~281(카드 시각·clipping 회귀), FC-312~313(경매 카드 복구·확장).
- 경매 목록의 compare 진입만 제거한다. compare session/store, 아이템마켓·홈 preview·경매 상세의 compare 계약과
  API는 영향받지 않는다. artwork stage +44px는 경매 adapter의 generic artwork slot geometry에만 적용한다.
- 입찰 수 compact 표기는 경매 feature helper와 이를 공유하는 운영 `AuctionCard`·workbench Candidate·관련 테스트에만
  영향을 준다. API 원본 정수와 `ItemCardView` 공용 모델은 변경하지 않는다.
- 완료 티켓은 수정하지 않는다. 본 티켓과 `frontend-ui-system-contract.md §6.6`이 후속 델타 정본이다.
- 사용자의 2026-08-16 전체 세로 카드 확장 요구가 기존 §6.5의 가로 카드 보존 결정을 대체한다.

## 근거인용
> 실시간 경매 페이지 목록에서 각 아이템별 예를들어 스킬1만 있을 경우 스킬1, 2 모두 있는 아이템 영역보다 짧아지는 문제가 있음 스킬1, 스킬2 모두 표기 후 스킬이 없을 경우 없음 으로 표기되도록해줘 추가적으로 이전에 아이템 마켓에 적용했던 퍼센트 색상 적용하고

> 실시간 경매 목록 카드 전체를 아이템마켓 형태의 공용 composition으로 재사용하고 경매 시간, 시작가/현재가,
> 입찰 수, 상태, 판매자 등을 잘 배치한다. — 사용자 확장 요구, 2026-08-16
