## DoD
1. **닉네임 가용성 조회 엔드포인트 계약**: 회원가입 라이브 중복확인용. 제안 = `GET /api/v1/auth/nickname/availability?nickname={닉네임}` → `ApiResponse<{available: boolean}>`(형상은 기존 컨벤션 따름). **비로그인 접근 허용**(회원가입 중 호출). 입력 검증(형식·길이=닉네임 규칙 재사용), 정규화 규칙 명시. api-contract에 추가.
2. **소셜 닉네임 정책 명문화**: "provider 표시명 + **항상** 랜덤 꼬리표"(현: 충돌 시에만). 꼬리표 형식·길이·베이스명 정규화(30자 제한 내)·충돌 재시도 정책을 spec(member-domain-spec 또는 관련 spec)에 기술. 응답 형상 불변.
3. **게이트2 판단**: 신규 엔드포인트가 되돌리기 큰 결정(경로·인증·열거 정책)을 포함하면 총괄에 상신 표시. 없으면 계약 확정.
4. **파급 영향**: 변경/추가 spec 파일과 영향 티켓(FC-161·FC-162) 관점 정리.
