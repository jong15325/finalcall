## 목표
마이페이지(`/me`)의 **본인인증 영역(`VerificationCard`)** 이 **모바일에서 다른 카드 영역과 사이즈가 어긋나는** 문제를 확인해 이웃 카드와 동일하게 맞춘다. 사용자 보고: "본인인증 영역 반응형 사이즈가 모바일 버전에서 문제가 있음 — 다른 영역과 동일하게 설정"(2026-07-28).

## 조사 시작점 (총괄이 스코프한 것)
- 렌더 위치: `frontend/src/pages/MePage.tsx` — `ProfileCard`(전폭) 아래 `<div className="grid gap-4 lg:grid-cols-2">` 안에 `VerificationCard` + `WalletSummaryCard`. 모바일(<lg)은 1열 스택.
- 카드 셸 비교: `VerificationCard`(section, `flex h-full flex-col rounded-2xl border border-line bg-surface p-5 sm:p-6`) 와 `WalletSummaryCard`(동일 셸)는 클래스가 같아 보인다 → **차이는 셸이 아니라 내부 콘텐츠/상태(OTP 입력·카운트다운 등)나 모바일 특정 뷰포트에서 드러날 수 있다.** 실제 모바일 뷰포트로 재현해 원인을 특정할 것.

## DoD
- **모바일 뷰포트로 재현**(예: 375~430px 폭, 프론트 `npm run dev` + 브라우저 devtools)해 본인인증 카드가 이웃 카드(`WalletSummaryCard`·`ProfileCard`·거래내역·탈퇴 섹션)와 **어떻게 다른지**(너비·높이·패딩·오버플로·정렬 중 무엇인지) 구체적으로 특정.
- 그 불일치를 **이웃 카드와 동일한 반응형 처리로** 맞춘다. 새 디자인 발명 금지 — 기존 카드들의 패턴(rounded-2xl·border-line·bg-surface·p-5 sm:p-6·h-full 등)에 정렬.
- **웹(lg+) 레이아웃은 회귀 없이 유지**([[responsive-separate-design]] — 배치만 바꾸지 말고 모바일/웹 각각 확인). VerificationCard의 3상태(미설정/미인증/코드입력)와 OTP 입력이 모바일에서 깨지지 않는지 확인.
- 최소 변경(coding-discipline). 접근성/기능 회귀 없음. 프론트 빌드·lint·typecheck·관련 테스트 그린.
