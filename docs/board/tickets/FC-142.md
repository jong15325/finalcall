## 목표
환경종속·시크릿·운영 튜닝값을 **전부 env로 외부화**하고, IntelliJ **EnvFile 플러그인**으로 `.env` 한 파일을 실행 구성에 주입해 관리한다. Spring이 이미 `${ENV:기본값}`로 env를 읽으므로 **빌드 의존성 추가·런타임 라이브러리·코드 변경 없음**(순수 IDE-side 주입). 사용자 범위 결정: "환경종속+시크릿+튜닝값 전부, 단 목록형 구간표는 yml 유지"(2026-07-28).

## DoD

### 1) 하드코딩 스칼라 → `${ENV:기본값}` 외부화 (`application.yml` 공통)
현재 리터럴인 스칼라를 **기존 값을 그대로 기본값으로 둔 채** `${VAR:기본값}`로 바꾼다(로컬·전 프로파일 동작 불변). 최소 대상:
- `server.port: 8080` → `${SERVER_PORT:8080}`
- `jwt.algorithm: HS256` → `${JWT_ALGORITHM:HS256}`, `jwt.access-exp-minutes: 30` → `${JWT_ACCESS_EXP_MINUTES:30}`, `jwt.refresh-exp-days: 14` → `${JWT_REFRESH_EXP_DAYS:14}`
- `spring.mail.host: smtp.naver.com` → `${MAIL_HOST:smtp.naver.com}`, `spring.mail.port: 465` → `${MAIL_PORT:465}`
- `email.verify.{code-length:6, ttl-seconds:600, resend-cooldown-seconds:60, max-attempts:5}` → 각 `${EMAIL_VERIFY_*:기본값}`
- `gateway.internal.enforced: true` → `${GATEWAY_INTERNAL_ENFORCED:true}` (테스트 base가 false로 오버라이드하는 경로 무영향 확인)
- 그 외 스칼라 튜닝값(management 트레이싱 sampling 등)도 판단해 외부화하되, **애매하면 남기고 보고**. `spring.mail.properties.*`(auth/ssl 플래그)는 465 SSL 고정이라 유지 권장(판단해 보고).

### 2) 목록/중첩 구조는 yml 유지 (env 제외)
`bid.increment.tiers`·`fee.policy.tiers`·`resilience4j.*` 등 **목록/중첩 정책 테이블은 env로 빼지 않는다**(env는 목록에 부적합, 이미 properties로 관리됨). `.env.example`·문서에 "왜 제외인지" 한 줄 명시.

### 3) fail-fast 설계 **불변** (★ 최우선 제약)
dev/prod의 시크릿 주입 방식을 **절대 바꾸지 않는다**: `DB_*`·`REDIS_*`(기본값 없는 `${ENV}`), `JWT_SECRET`·`GATEWAY_INTERNAL_SECRET`·`APP_NAME`·`APP_DESCRIPTION`(relaxed binding, placeholder 금지) 그대로. **공통 `application.yml`의 시크릿(`MAIL_USERNAME`/`MAIL_PASSWORD` 등)에 기본값을 넣지 않는다**(넣으면 prod fail-fast 무력화, CLAUDE.md 섹션 4). local yml의 기존 로컬 더미 기본값은 유지.

### 4) `.env.example`(커밋) — 전 env 키 카탈로그
레포 루트에 `.env.example` 생성. **4개 yml(application·-local·-dev·-prod) 전체에서 참조하는 모든 env 키**를 그룹별(DB/Redis/JWT/Gateway/Mail/이메일인증/검색/워커/앱/기타)로 열거. 값은 **로컬 안전 예시**로 채우되, **시크릿은 빈 값/플레이스홀더**(`MAIL_PASSWORD=`, 주석으로 "네이버 앱 비밀번호"). 헤더 주석에: IntelliJ EnvFile 사용법 요약·실 `.env`는 gitignore·시크릿 커밋 금지·목록형 정책은 yml 관리 명시.

### 5) `.gitignore` 보호
`.env`, `.env.*` 추가 + `!.env.example` 예외. (실 `.env` 유출 차단 — FC-141이 지적한 누락 해소.)

### 6) IntelliJ EnvFile 설정 문서
`docs/backend/references/env-file-setup.md`(한국어, 짧게): EnvFile 플러그인 설치 → 백엔드 실행 구성 EnvFile 탭에 `.env` 추가 → Active profiles=local → 실행. `.env`를 `.env.example`에서 복사해 시크릿 채우는 절차. 실발송 시 `MAIL_*` 3종.

### 7) 검증·산출
- **실 `.env`는 생성하지 않는다**(시크릿 포함 — 사용자 몫). `.env.example`만.
- `./gradlew :backend:spotlessApply :backend:checkstyleMain` 통과(JAVA_HOME=JDK21 단독 실행, gradle 동시 실행 금지).
- **회귀 없음 논증**: 외부화한 모든 값이 former 리터럴을 `${VAR:default}`의 default로 보존 → env 미주입 시 바이트 동등. dev/prod fail-fast 경로 무변경 확인.
- 커밋하지 말 것(사용자 승인). 워킹트리 변경만.
