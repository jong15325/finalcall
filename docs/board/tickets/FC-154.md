## 목표
provider `code`를 받아 토큰 교환·userinfo 조회 후 우리 JWT를 발급하는 엔드포인트를 구현한다.

## DoD
- **OAuthService**: provider별(naver·kakao) `code` → access token 교환 → userinfo 조회 → FC-153 find-or-create → **기존 `TokenProvider.generateAccessToken`+`RefreshTokenStore.issue(userId)`로 발급**. provider 추상화(enum + 전략).
- ⚠️ **풀링 HTTP 클라이언트**(Spring `RestClient`, 연결 재사용·타임아웃 설정) — 매 호출 new 금지([[git-push-headless-resolver-fail]] 커넥션 누수 교훈).
- **AuthController**: `POST /api/v1/auth/oauth/{provider}` → `LoginResponse`(기존 형상). try-catch 금지(전역 핸들러).
- **config**: `oauth.{naver,kakao}.{client-id,client-secret,redirect-uri,token-uri,userinfo-uri}` — env 주입(prod fail-fast, 로컬 `${ENV:기본}`). 시크릿 커밋 금지.
- **SecurityConfig**: `/api/v1/auth/oauth/**` permitAll(GatewayAccessFilter 정합).
- **AuthErrorCode 확장**: 잘못된 code·provider 오류·state 불일치 등.
- 테스트(교환 성공→토큰·provider 오류·재사용). `spotlessApply :checkstyleMain :test` 그린. 커밋 금지.
- **키 요청**: 착수 시 총괄이 사용자에게 네이버·카카오 client-id/secret·redirect-uri 발급 요청.

## 근거인용
FC-152 계약. RefreshTokenStore/TokenProvider(userId 기반 재사용). SEC-006(refresh 회전). D-068(게이트).
