## 목표
로컬 경매장(`/api/v1/auctions`, 프론트 경매장 화면)에 **진행 중(ACTIVE) 경매 100건**을 올린다. 현재 시드 경매 39건은 마감시각이 과거(2026-07-25)라 전부 종결(UNSOLD/SOLD)이고 진행 중이 0건이라 경매장이 비어 있다(오늘 2026-07-28).

## 배경 (총괄이 스코프)
- 경매 등록 = `AuctionController.register`(`POST /api/v1/auctions`), `AuctionRegisterRequest(itemInstancePublicId, startPrice, buyNowPrice, startAt, endAt@NotNull, softClose*, maxEndAt@NotNull)`. `startAt` null/과거 → ACTIVE, `endAt` 미래 → 진행 유지.
- 각 경매엔 **판매자 소유 인벤토리 아이템**이 필요. 생성 헬퍼 = `LocalDemoDataService.createInventoryItem(ownerId, typeCode, level, skill1, skill2, skillPercent, gf, slot)`. 참조 로직 = `LocalDemoSeeder.auction(...)`(207행: 아이템 생성 → `auctionService.register`). 슬롯 충돌 회피(`nextSlot`) 주의.
- 기존 `LocalDemoSeeder`는 **멱등**(demo1 존재 시 통째 skip)이라 재부팅으론 안 생김.
- 경매장 노출은 **ES read-model**(listings_search alias) 기준 — 등록분이 ES에 색인돼야 보인다(reindex-on-startup=true 또는 CDC).

## DoD
- **진행 중(ACTIVE) 경매 정확히 100건** 생성. `endAt`은 충분히 미래(예: 1시간~30일 분산 — 일부 곧-마감, 다수 다일짜리)로 두어 시연 중 유지되게. 아이템은 기존 시드처럼 **다양하게**(타입·레벨·스킬·가격 구간 varied), 판매자는 데모 계정 분산.
- **도메인 로직 재사용**: `auctionService.register` + `LocalDemoDataService` 경유. ES 문서·DB row를 손으로 쓰지 말 것(검증/정합 우회 금지).
- **기존 데이터 무손상**: 기존 39 경매·5001 마켓·회원·인벤토리 보존(추가만).
- **ES 색인 확인**: `listings_search`에서 `listingType=AUCTION AND status=ACTIVE` 카운트 ≥ 100, 또는 `GET /api/v1/auctions` 목록에 100건 노출 확인.
- 구현은 **local 프로파일 한정**(운영 유출 금지) — 기존 LocalDemoSeeder 패턴처럼 플래그/조건 게이트. 재실행 시 중복 폭증 방지 가드(횟수 기반 카운트 등) 고려.
- checkstyle/spotless 통과. 커밋하지 말 것(사용자 승인 대기).
