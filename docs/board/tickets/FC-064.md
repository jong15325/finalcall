## 계약 분석 결과 (architect · 2026-07-19 · 총괄 대조 완료)

### ✅ 계약이 이미 충족 — 그냥 쓰면 되는 것
| 항목 | 확인 |
|---|---|
| `GET /auctions/{id}` | 공개. 계약 §3.3 ↔ `AuctionDetailResponse` **17필드 1:1 일치** |
| `minNextBidAmount` | **서버 파생값이 내려온다.** `AuctionService`와 `BidService`가 **같은 `BidIncrementProperties`**를 쓰므로 "안내 금액으로 입찰했는데 거부"가 구조적으로 불가. **증분표를 클라에 복제하지 마라** |
| `POST /auctions/{id}/bids` | 요청 `{amount}`, 201 `{bidPublicId, amount, currentHighestAmount, endAt}`. **`endAt`은 소프트클로즈 연장 반영 후** 값이라 스티키 바 카운트다운을 응답으로 즉시 재동기화할 수 있다 |
| `GET /auctions/{id}/bids` | **존재하고 공개다.** offset 페이징(§1.3), `amount desc` 고정 |
| `BID_001~007` · `AUCTION_004` | 계약 §5 ↔ `BidErrorCode` **7값 전수 일치**. 에러 envelope에 `code`가 실려 화면 분기 가능 |

### ★ 벽 3건 — 전부 우회로가 있어 착수를 막지 않는다

**1. `isSeller` 부재 → 닉네임 비교로 파생한다 (계약 변경 불필요)**
`sellerNickname`이 **마스킹 없이 원문**으로 내려오고, 닉네임은 활성 회원 간 **유일**하다
(`uk_user_nickname_active`). `GET /me`의 `nickname`과 비교하면 된다.
탈퇴 닉네임 재사용이 유일한 오탐 경로인데 **진행 중 경매를 가진 판매자는 탈퇴가 차단**된다(`MEMBER_002`).
→ **★ 표시 제어일 뿐 인가가 아니다.** 입찰 버튼을 숨기되 서버 `BID_003`(403) 처리는 **반드시 구현**한다.

**2. 스킬 이름 → 지금은 코드 중립 표기로 폴백**
HANDOVER는 "사전 부재"로 적었으나 **정정**: `GET /items/{itemInstancePublicId}`가
`ItemSkillResponse{skillCode, name}`으로 **이름을 이미 내린다.** 진짜 벽은
**`AuctionItemView`에 `itemInstancePublicId`가 없어 링크가 끊긴 것**이다.
→ 계약 §3.3이 *"사전에 없는 코드는 중립 표기로 폴백"*을 이미 의무화했으므로
**`스킬 #{code}` + `skillPercent`(정수, 항상 존재)** 표기가 계약 준수다. **게이트2 대기 중 이대로 간다.**

**3. 즉시구매 → 화면에서 제외한다**
계약 §3.1에 `POST /auctions/{id}/purchase`가 **완전 명세돼 있으나 백엔드 미구현**이다
(`AuctionController`에 매핑 없음 · `AUCTION_005/009`가 enum에 부재 — EPIC-CLOSING 소유).
→ **버튼을 만들면 404다.** `buyNowPrice`는 **정보 표기로만** 쓴다.
→ ★ **미구현 경로 목록에 `/auctions/{id}/purchase`를 추가하라** — 계약에 있어서 구현된 줄 알기 쉽다
(FC-048이 `/shops`로 똑같이 당했다).

### ★ 4. 마감 판정은 클라가 시각으로 한다
`resultType`은 **항상 null**이고(EPIC-CLOSING 소유), `Auction.displayStatus()`는
**SCHEDULED→ACTIVE 승격만 하고 마감 강등을 안 한다**(마감 워커 없음).
→ **`endAt`이 지난 경매도 `status: ACTIVE`로 내려온다.** 서버 status를 그대로 믿으면
**종료된 경매에 활성 입찰 바가 뜬다.**
→ **`now >= endAt`이면 자체적으로 "마감"으로 렌더**하고 입찰 바를 비활성화한다.
이는 서버와 정합한다 — `BidService.isBiddable()`도 status가 아니라 **시각**으로 판정하고
이 경우 `BID_006`으로 거부한다.
→ 낙찰자는 `highestBidderMasked`로 표기하되 **"낙찰"이라 단정하지 마라**("최고 입찰"까지만).

### 계약↔구현 불일치 (로그아웃 바디 누락과 동종)
- **판매자 취소 403이 계약에 미기재** — `AuctionService.cancel()`이 주체≠판매자에 `AUCTION_001`(403)을
  던지는데 계약 §3.1 cancel은 `AUCTION_007`·`AUCTION_006`만 열거한다.
  → **상세에 판매자 취소 버튼을 넣는다면 `AUCTION_001` 처리를 명시 구현하라.**
- **입찰 이력 `size` 상한 100** — 서버가 조용히 정규화(`normalizeSize`)한다. 계약엔 없다.
  → **무한스크롤 페이지 크기를 100 이하로.**
