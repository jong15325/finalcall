## 목표
FC-045(design-system v0.6)가 만든 파급을 정리한다. **정본이 스스로 모순된 상태를 먼저 없앤다.**

## ★ 1순위 — 정본 내부 모순 (지금 존재하는 결함)
**§2.2 색 토큰 표(126행)의 `primary-disabled` 전경이 아직 `#A1A1AA`다.** §5.1은 v0.6에서
`#5F5F66`으로 개정됐으므로 **정본 한 문서 안에서 두 값이 충돌한다.** 대비 열도 `—`(미계산)로
비어 있다.

- §2.2 전경을 **`#5F5F66`(4.99)** 로 맞추고 **대비 열을 채운다.**
- **`text-disabled` 토큰 신설(§2.4) 검토** — 현재 raw hex라 "토큰 → Tailwind 1:1" 원칙에
  어긋난다. 신설하면 §5.1이 토큰을 참조하게 되어 같은 모순이 재발하지 않는다.

FC-045에서 범위를 §3·§5.1로 한정해 손대지 않은 것이지 발견을 놓친 것이 아니다.

## 2순위 — 목업 정본 위반 해소
v0.6 개정으로 **4면이 위반 상태**다. 실측 근거는 FC-045 반환에 있다.

| 파일 | 위반 |
|---|---|
| `template-auction-detail.html` | 14/15/16/20px **22회** |
| `template-auction-list.html` | 14/15/16/19px **14회** |
| `template-home-logged-out.html` | 14/15/16/19/24/32px **25회** |
| `template-home-logged-in.html` | 14/15/16/19/24/32px **25회** |
| (인증 2면) | **정합 — 조치 불요** |

disabled 전경 `#A1A1AA` → `#5F5F66` 교체 대상은 **로그인·회원가입·홈 2면**이며,
`template-auction-list.html`은 **`#A1A1AA`와 `#5F5F66`을 동시 사용**해 내부 모순이 있다.
`auction-detail`은 이미 `#5F5F66`이라 조치 불요.
(`redesign-commerce.html`은 탐색용 프로토타입이라 대상 제외.)

## 3순위 — 잔여 이상값
- **`.7rem`(11.2px) 2건** — `auction-detail`의 `.bid-cards .amt .u`·`.mobilebar .price .u`.
  어느 단계에도 속하지 않는 오타성 값(`.6875rem` 의도 추정).
- **`1.1875rem`(19px)** — `auction-list` 1건·홈 2건. 역할 불명 잔여값.
- **§5.1 버튼 높이 `sm h32`인데 목업 전면이 `h36`**을 쓴다. 타이포 축이 아니라 FC-045가 손대지
  않았다. 정본과 실제 중 어느 쪽을 고칠지 판단이 필요하다.

## DoD
- §2.2·§2.4 정합 완료 — **정본 안에서 disabled 값이 하나로 수렴**한다.
- 목업 4면이 v0.6 스케일을 준수한다. 교체는 **역할 기반 매핑**을 따른다(14/15/16 → 13 또는 17,
  20 → 17 또는 28, 24/30/32 → 28 또는 34). FC-045가 21개 역할의 흡수처를 이미 식별했다.
- 잔여 이상값 3종 처리 또는 사유 기록.
- **대비 재검증** — 크기·색이 바뀌면 대비도 바뀐다.

## 제약
- **디자인 게이트 대기 중**임에 유의한다(FC-042·FC-043). 목업 교체는 **스케일 준수 목적의
  기계적 치환**이며, 이 티켓에서 **레이아웃·구조·시각 방향을 바꾸지 않는다.**
  게이트 판정 결과에 따라 목업이 다시 바뀔 수 있으므로 **범위를 넘기지 않는 것이 중요하다.**
- 계약·spec·보드·코드 수정 금지.

## 비고
FC-045가 드러낸 사실 — **홈 2면·목록 1면은 타이포 개편을 전혀 거치지 않았고, `auction-detail`
조차 절반만 개편됐다**(주인공 축만 재설계, FC-041 상속 셸은 그대로). 즉 이 티켓은 "정본을
따라가는 정리"가 아니라 **개편을 나머지 화면에 실제로 적용하는 작업**이다. 분량을 얕게 잡지 말 것.

## ★ 범위 축소 (2026-07-19, 사용자 지시)
> **정본 모순만 먼저 처리. 상세 디자인은 프론트 진행할 때 개선한다. 진도를 먼저 나간다.**

**이 티켓 = 1순위(§2.2 정본 내부 모순)만.** 2·3순위는 **React 구현 단계로 이월**한다.

### 이월된 것 (이 티켓에서 제외)
- **목업 4면 타이포 위반** — `auction-detail` 22회 · `auction-list` 14회 · 홈 2면 각 25회.
  React 구현 시 v0.6 역할 스케일로 맞춘다. FC-045가 21개 역할의 흡수처(13/17)를 이미
  식별해뒀으므로 그때 매핑표로 쓴다.
- **disabled `#A1A1AA` → `#5F5F66` 목업 교체** — 로그인·회원가입·홈 2면.
  `auction-list`의 두 값 동시 사용도 함께.
- **잔여 이상값** — `.7rem`(11.2px) 2건 · `1.1875rem`(19px) 4건 · 버튼 높이 h32 vs h36.

### 이월 판단 근거
목업은 **시각 방향을 확정하는 도구**이지 최종 산출물이 아니다. 방향이 정해진 이상 목업을
픽셀 단위로 정본에 맞추는 것보다 **React 구현에서 한 번에 맞추는 편이 일이 적다** — 목업을
고쳐도 그 값이 다시 손으로 코드에 옮겨져야 하므로 중간 산출물을 두 번 다듬는 셈이 된다.
정본(design-system)이 정확하면 구현이 참조할 곳은 정확하다.

**단 정본 내부 모순은 이월 대상이 아니다** — 정본이 스스로 어긋난 상태로 구현에 들어가면
구현자가 어느 값을 믿을지 알 수 없다. 이월의 전제가 "정본이 정확하다"이므로 이것만 먼저 닫는다.
