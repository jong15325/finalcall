## 목표 (EPIC-BOARD 계약 선행 · contract-first)
커스텀 게시판 시스템의 계약·스키마를 정본화한다. 구현 팬아웃(FC-197~204) 전 계약을 확정해 backend/frontend 실시간 협상을 제거한다. 게시판을 하드코딩 enum이 아니라 **DB 레코드(Board 레지스트리)**로 정의하는 데이터 모델과, 그 위의 게시글·댓글·이미지 첨부·인가 규칙을 확정한다.

## DoD
1. **board-domain-spec.md 신규** — 게시판 도메인 정본화:
   - **Board 레지스트리 모델**: slug(URL 키)·이름·설명·정렬순서·활성여부 + **옵션 필드**(쓰기 권한 정책·댓글 허용 여부·게시판 유형). 향후 관리자 CRUD를 견디는 형상(이번 에픽은 시드로만 채우되 모델은 런타임 변경 가능하게).
   - **Post/Comment 도메인**: BaseEntity 상속·soft delete·작성자 귀속·인가 불변식(쓰기정책 위반 차단·본인/admin만 수정삭제·IDOR 방지).
   - **인가 규칙**: 주체=SecurityContext(isAdmin 클레임 활용), 쓰기정책(ADMIN_ONLY / AUTHENTICATED)별 create/update/delete 게이팅.
2. **erd.md** — `board`·`post`·`comment`(+ 이미지 첨부 테이블) 스키마 + 인덱스 + Flyway 버전 예약. 시드(커뮤니티·공지·이벤트) 반영.
3. **api-contract.md** — 게시판 목록·게시글 CRUD·커서 목록·댓글 CRUD·이미지 업로드 API 계약.
4. **게이트2 상신 3건 확정**:
   - (a) **이미지 저장 위치** — 로컬 디스크 vs 오브젝트 스토리지(S3/MinIO). 로컬 개발(Docker)·배포 방식 대조해 방식 확정 + 근거.
   - (b) **공지(notice) 흡수 전략** — 기존 notice 데이터 이관 방법 + notice 도메인 제거 범위 + 프론트 공지 페이지 전환 경로. CLAUDE.md가 notice를 "참조 구현"으로 명시 → 컨벤션 쇼케이스 소실 여부 판단 포함.
   - (c) **게시판 옵션 모델 범위** — 쓰기 권한·댓글 허용·게시판 유형(일반/이벤트) 등 어디까지 옵션화할지 확정.
