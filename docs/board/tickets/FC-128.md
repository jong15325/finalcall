## 목표
6자리 인증 코드의 Redis 저장소를 신설한다(RefreshTokenStore 스킴 준용).

## DoD
- `EmailVerificationCodeStore`(infra/security 또는 infra/mail): 발송 시 코드 SHA-256 해시·`emailHash`(정규화 이메일 해시)·`attempts=0` 세팅(TTL 600s) + 쿨다운 키(TTL 60s).
- 검증 Lua 원자 스크립트: (1)키 없음→만료 (2)emailHash 불일치→키삭제·만료통일 (3)attempts+1>상한→키삭제·초과 (4)상수시간 비교 불일치→attempts 증가·불일치 (5)일치→키삭제. RefreshTokenStore `ROTATE_SCRIPT` 선례.
- 평문 코드 미저장(해시만). 정책값은 주입받는 형태(FC-130 Properties 연동 전제, 상수 하드코딩 금지).
- 단위 테스트(동시 검증 시도카운트 누수 없음·emailHash 바인딩).

## 구현 노트 (FC-132 매핑용)
- 배치 `com.finalcall.infra.security`(무-애노테이션 순수 클래스, 정책값 생성자 primitive 주입 — FC-130이 @Bean 배선).
- 검증 결과 enum = **`VerifyOutcome`**{EXPIRED, ATTEMPTS_EXCEEDED, MISMATCH, SUCCESS}. `*Result` 접미사는 V2 규약상 bid/settlement 전용이라 회피. FC-132 매핑: MISMATCH→EMAIL_001, EXPIRED(만료·미발송·emailHash불일치 통일)→EMAIL_002, ATTEMPTS_EXCEEDED→EMAIL_003, issue의 `Optional.empty()`(쿨다운)→EMAIL_004.
- 메서드: `Optional<String> issue(userId, normalizedEmail)`(코드 생성·반환) / `VerifyOutcome verify(userId, code, normalizedEmail)` / `clear(userId)`(TOCTOU 주 방어).
