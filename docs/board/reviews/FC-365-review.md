## 확인 범위

- 신규 활성 시드 매물의 레벨·스킬1·스킬2·스킬 퍼센트·골드포스 다양화
- 스킬 코드 범위와 마법 카드(`sub_group=3`)의 스킬1 구조적 부재
- 레벨별 스킬 퍼센트 상한과 미래 골드포스 만료 시각
- 기존 `SEEDLIST` 중 LISTED·ACTIVE·미만료·옵션 전체 공란 데이터만 보정하는 조건
- 사용자 생성 매물과 다른 데모 접두 데이터의 비변경
- 기존 레벨 보존 및 `item_instance`와 `shop.item_spec_snapshot`의 동일 문장 갱신
- 조건부 UPDATE의 재실행 멱등성과 경합 시 재검증
- MySQL 다중 테이블 UPDATE의 변경 행 수를 보정 아이템 건수로 정규화한 계수
- named lock 획득부터 트랜잭션 완료 후 해제까지의 생명주기
- 고정 시드 기반 결정론과 관련 단위 테스트

## 검증 증거

- `./gradlew.bat :backend:test --tests com.finalcall.support.LocalActiveShopSeederTest` 통과
- 실제 로컬 MySQL에서 다중 테이블 조건부 UPDATE 문법과 `item_instance`·`shop` 동시 갱신을 트랜잭션 롤백으로 확인
- 다중 테이블 UPDATE가 두 테이블 변경 시 반환하는 `2`를 보정 아이템 `1건`으로 계수하는 단위 테스트 통과
- UPDATE 대상 조건에 `SEEDLIST%`, `LISTED`, 전 옵션 공란, `ACTIVE`, 미만료 조건이 모두 재검증됨을 확인
- 기존 레벨을 후보 조회값으로 유지하고 동일 레벨로 스냅샷을 재생성함을 확인

## 판정 근거

최초 리뷰에서 발견한 라이브 아이템 특성과 `shop.item_spec_snapshot`의 불일치는 해소됐다. 보정은 기존 레벨을 변경하지 않으며, 아이템 특성과 스냅샷을 하나의 MySQL 다중 테이블 UPDATE로 함께 갱신한다. UPDATE 시점에도 로컬 시드 접두·활성 상태·미만료·공란 조건을 다시 검사하므로 중복 실행과 경합에 안전하다. 다중 테이블 UPDATE의 반환값은 성공 여부로만 판정해 후보 아이템당 한 번 증가하므로 로그의 보정 건수도 정확하다. 신규 데이터의 스킬 코드·마법 카드 제약·퍼센트 상한·골드포스 조건도 기존 스펙과 일치해 발견 없이 통과 판정한다.
