## FC-011 (money 도메인 — 핵심)
- **오버플로 경계 정확**: `@Max(Long.MAX_VALUE / 1_000_000L)` = 9,223,372,036,854. `× 1,000,000 = 9,223,372,036,854,000,000 ≤ Long.MAX_VALUE`(여유 775,807) → 오버플로 직전 최대값 정확. `max+1`은 @Valid에서 400 차단.
- **부수효과 순서 실증**: 400은 @Valid(컨트롤러 진입 전)→ ExchangeWriter 트랜잭션 미진입. 테스트가 잔액 불변·`moneyExchangeRepository.count()==0`(멱등키 미소비)로 확인.
- **계약 정합**: 400/COMMON_001/errors[] 기존 검증 패턴, 새 에러코드·EXC 변경 없음. 400(vs 422) 타당(형식 검증).
- **문서화된 한계(정보성)**: `@Max` 리터럴이 기본 rate(1,000,000)와 결합 — 운영이 rate override 시 어긋날 수 있으나 `ExchangeWriter` `Math.multiplyExact` backstop 유지로 극단 방어(500). javadoc 명시.
- **경미**: 경계 성공 케이스(정확히 max) 미커버(DoD는 초과 1건만 요구, 충족). 누적 잔액 오버플로는 기존 동작·범위 밖.

## FC-018 (ThemeToggle no-op)
- store 기본 'light' ↔ 항상 라이트 렌더 ↔ `data-theme="light"` 3자 일치. `[data-theme="dark"]` 신규 없음(**다크값 미창작**, U-005 대기 규율). `Theme` 타입 'dark'·setTheme/toggleTheme·컴포넌트 보존(U-005 복구 자리). 레이아웃 4종 import 미편집. 숨긴 토글은 원래 no-op라 a11y 회귀 없음.
- **nit**: ThemeToggle 주석이 "주석 처리된 본문 복구"라 하나 실제는 삭제(git 이력 보존) — 부활 시 혼동 소지. 비차단.
